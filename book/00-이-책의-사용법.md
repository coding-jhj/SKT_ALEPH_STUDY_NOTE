# 이 책의 사용법

SKT ALEPH IT 인프라·보안 과정의 수업 노트를 한 권으로 엮은 것입니다.
수업이 진행되는 대로 장을 추가합니다.

## 무엇이 들어 있고 무엇이 없는가

| 구분 | 상태 |
|---|---|
| 수업 노트 | 6편 · 43만자. 실습 명령·출력·에러까지 그대로 기록하고 공식 문서와 대조한 것 |
| 핵심키워드 원문 | **188강 전부 · 70만자.** 과정에서 배포된 슬라이드 본문을 그대로 옮긴 것 |
| 커리큘럼 지도 | 188강을 주제별로 묶고 수업 노트와 연결한 표 |
| `it인프라의이해_*.pdf` | 텍스트 레이어가 없는 이미지 슬라이드. 3장에 판독본으로 실었습니다 |

수업 노트와 핵심키워드는 성격이 다릅니다.

- **수업 노트** — 내가 직접 친 명령과 그때 난 에러까지 남긴 기록. 왜 그랬는지가 적혀 있습니다.
- **핵심키워드** — 과정에서 배포된 표준 설명. 빠짐없이 훑을 때 씁니다.

같은 주제라도 두 곳의 설명이 다를 수 있습니다. 실습 중 실제로 확인한 것은 수업 노트 쪽입니다.

마지막 항목은 확인이 필요합니다. 해당 PDF 4개는 텍스트 레이어가 없어(추출 결과 99~431자)
내용을 읽을 수 없습니다. 필요하면 원본 발표 파일이나 캡처를 따로 주셔야 합니다.

## 표기 규칙

노트마다 다음 표시를 씁니다. 원본 노트에 이미 붙어 있는 것을 그대로 유지했습니다.

| 표시 | 뜻 |
|---|---|
| ✅ | 수업 중 실제로 실행하고 출력까지 확인한 것 |
| ⚠️ | 실제로 발생한 오류, 또는 빠지기 쉬운 함정 |
| 📘 | 수업에서 다루지 않았으나 이해에 필요해 공식 문서에서 보강한 것 |
| ★ | 시험·실무에서 자주 틀리는 지점 |

**출처가 불확실한 내용은 적지 않습니다.** 기억으로 채우지 않고, 확인이 필요하면
"확인 필요"라고 남깁니다.

## 읽는 순서

처음 읽는다면 순서대로 읽는 것을 권합니다. 뒤 장이 앞 장의 환경을 그대로 씁니다.

1. **커리큘럼 지도** — 전체 과정에서 지금 어디에 있는지 확인
2. **1부 네트워크** — 라우팅이 되어야 그다음 서버 실습이 성립합니다
3. **2부 리눅스 서버** — Rocky 서버랩이 기준 환경입니다. 이후 노트가 이 환경을 전제합니다
4. **3부 데이터베이스** — 웹·DB 연동까지

특정 명령어를 찾을 때는 부록의 **명령어 색인**을 쓰십시오. 노트별로 어디에 나오는지 모아 두었습니다.

## 파일 구조

```
notes/        수업 노트 원본. 이 책의 본문입니다
book/         목차·지도·부록 등 연결 자료
curriculum/   배포 슬라이드 원본 목록
build.py      notes + book -> site/index.html 한 권으로 조립
site/         빌드 결과 (HTML 한 파일. 오프라인에서 열립니다)
```

같은 내용을 두 곳에 복사하지 않습니다. `notes/`가 원본이고 책은 조립 결과입니다.
노트를 고치면 다시 빌드하는 것만으로 책에 반영됩니다.

## 갱신 방법

수업이 끝나면 이렇게 추가합니다.

```bash
# 1) 새 노트를 notes/ 에 넣는다 (파일명: 날짜_주제.md)
# 2) build.py 의 ORDER 목록에 한 줄 추가한다
# 3) 다시 빌드한다
python build.py
```

`build.py`는 다음을 자동으로 처리합니다.

- 각 노트의 첫 `#` 제목을 장 제목으로 올리고 나머지 제목 단계를 한 칸씩 내림
- 장별로 겹치지 않는 앵커 id 생성 (한글 그대로)
- 사이드바 목차·검색·현재 위치 표시
- 코드 강조, 표 가로 스크롤, 인쇄용 배치
- 부록의 명령어 색인 재생성

## 이 책을 만들 때 지킨 것

- **원본을 고치지 않는다.** 노트는 `notes/`에 그대로 두고 조립만 합니다.
- **중복을 숨기지 않는다.** 같은 주제가 여러 노트에 나오면 부록에 어디에 무엇이 있는지 적습니다.
- **모르면 모른다고 적는다.** 추측으로 빈칸을 메우지 않습니다.
