## 001. IPv6 네트워크 관리 모델

IPv6/네트워크 관리 모델

### 1. 서브네팅 (Subnetting) 개요

상세 실습은 추후 별도 진행 예정 서브넷 마스크 값을 조정하여 네트워크 부분을 나누는 작업 서브넷 마스크 값에 따라 네트워크 범위가 달라짐 효율적인 IP 주소 할당, 보안 구역 분리 등의 장점이 생김 CMD에서 ipconfig 로 확인 가능한 Subnet Mask 값과 연관

### 2. 네트워크 관리 모델 — FCAPS

ISO(국제표준협회)가 제정한 통신 관리망 모델로, 네트워크 관리의 5가지 영역을 나타낸다.

각 영역의 앞 글자를 시계 방향으로 따서 FCAPS 라고 줄여 부른다.


| 약자 | 영역 | 설명 |
|---|---|---|
| F | Fault Management (장애 관리) | 네트워크 장애를 탐지·복구하는 관리 |
| C | Configuration Management (구성<br>관리) | 네트워크 설정 및 구성 정보를 관리 |
| A | Accounting Management (계정/과금<br>관리) | 계정 정책, 과금 정보 확인 및 설정 |
| P | Performance Management (성능 관<br>리) | 네트워크 성능(퍼포먼스) 모니터링 및<br>관리 |
| S | Security Management (보안 관리) | 네트워크 장비의 보안 설정으로 보안<br>성 향상 |

이 과목(IT 인프라)에서는 장애 관리부터 보안 관리까지 전반적인 내용을 다룬다

## 003. TCP UDP 비교 및 IP 주소 체계

TCP/UDP 비교 및 IP 주소 체계

### 1. TCP vs UDP 비교

TCP와 UDP 모두 OSI 4계층(전송 계층)에서 동작하는 전송 프로토콜이다.

좋고 나쁨의 문제가 아니라, 상황에 따라 적합한 프로토콜을 선택하는 것이 핵심이다.


| 구분 | TCP | UDP |
|---|---|---|
| 정식 명칭 | Transmission Control Protocol | User Datagram Protocol |
| 전송 제어 | 있음 (확인 응답, 재전송) | 없음 (그냥 전송) |
| 신뢰도 | 높음 | 낮음 |
| 속도 | 상대적으로 느림 | 빠름 |
| 주요 사용 예 | 웹(HTTP), FTP, 원격 접속 | 스트리밍, 멀티미디어, 실시간 영상 전<br>송 |

TCP의 전송 제어 과정

### 2. 포트 번호 (Port Number)

각 서비스(애플리케이션)에 접근하기 위한 최종 관문 서비스 구축과 모든 설정이 완료되어도, 포트가 방화벽 등에 의해 막혀 있으면 접근 불가 TCP/IP 모델 애플리케이션 계층의 각 서비스마다 고유한 포트 번호를 가짐 TCP/UDP 비교 및 IP 주소 체계

### 3. 네트워크 계층 프로토콜


| 프로토콜 | 설명 |
|---|---|
| IP | 인터넷 주소 통신 규약, 3계층에서 동작 |
| ICMP | Internet Control Message Protocol, 인터넷 제어 메시지 프로토콜 |
| IGMP | Internet Group Message Protocol, 그룹(멀티캐스트) 대상에게 메시지를<br>전달 |

ICMP는 단일 시스템, IGMP는 그룹 대상에게 전달한다는 차이가 있음

### 4. IPX/SPX 프로토콜

TCP/IP와 유사하게 주소 + 전송을 담당하는 프로토콜 조합 IPX: 주소 담당 (IP와 동일한 역할)

SPX: 전송 담당 (TCP와 동일한 역할)

IPX = InterPacket eXchange (패킷 교환 프로토콜)

과거 게임방 내부 네트워크(예: 스타크래프트 IPX 연결) 등에 활용 현재는 TCP/IP의 빠른 발전으로 사용 범위가 점차 축소되는 추세

### 5. 계층별 데이터 표현 단위


| 계층 | 데이터 단위 |
|---|---|
| 1계층 (물리) | 비트 (Bit) — 0과 1의 전기적 신호 |
| 2계층 (데이터링크) | 프레임 (Frame) |
| 3계층 (네트워크) | 패킷 (Packet) |
| 4계층 (전송) | 세그먼트 (Segment) |
| 5~7계층 (상위) | 데이터 (Data) |

실무에서는 계층 구분 없이 대부분 "패킷" 이라고 통칭하는 경우가 많음

### 6. IP 버전 4 (IPv4) 주소 체계

#### 6-1. 기본 구조

32비트 구조 TCP/UDP 비교 및 IP 주소 체계 4개의 옥텟(Octet) 으로 구성 (예: 192.168.0.1 )

옥텟 1개 = 8비트 → 2⁸ = 256가지 경우의 수 → 범위: 0 ~ 255 점( . )을 초과하는 256, 300 같은 값은 입력 불가 → 통신 안 됨 비트와 경우의 수 공식 경우의 수 = 2ⁿ  (n = 비트 수)

예) 1비트 → 2¹ = 2가지 (0, 1)

2비트 → 2² = 4가지 (00, 01, 10, 11) 3비트 → 2³ = 8가지 8비트 → 2⁸ = 256가지 (0 ~ 255)

#### 6-2. IP 클래스 구분 (시작 옥텟 기준)


| 클래스 | 시작 옥텟 범위 | 용도 |
|---|---|---|
| A | 1 ~ 126 | 일반 사용 |
| B | 128 ~ 191 | 일반 사용 |
| C | 192 ~ 223 | 일반 사용 |
| D | 224 ~ 239 | 멀티캐스팅 용도 예약 |
| E | 240 ~ 255 | 실험·연구 용도 예약 |

D, E 클래스는 일반 시스템에서 사용 불가 실무 현장에서는 클래스를 엄격히 구분하지 않음 (클래스리스 방식)

내 IP 클래스 확인 방법 (Windows)

CMD 창 → ipconfig 입력 → IPv4 주소 확인 → 시작 옥텟으로 클래스 판별

#### 6-3. 예약 주소


| 주소 | 용도 |
|---|---|
| 127.x.x.x | 루프백(Loopback) — 자기 자신과의 통신 테스트용 예약 주소 |
| 169.254.x.x | APIPA — DHCP 서버로부터 IP를 제대로 할당받지 못했을 때 자동 부여 → 인터<br>넷 불가 |
| 각 대역의 첫 번째<br>주소 | 네트워크 주소 (대역 식별용, 시스템 할당 불가) |

TCP/UDP 비교 및 IP 주소 체계


| 주소 | 용도 |
|---|---|
| 각 대역의 마지막<br>주소 | 브로드캐스트 주소 (같은 네트워크 내 전체 전송용, 시스템 할당 불가) |

루프백 테스트 실습 CMD 창 → ping 127.0.0.1 응답 있음 → 내 시스템 네트워크 설정 정상 Request Timed Out  등의 오류 → 내 시스템 네트워크 문제 가능성

#### 6-4. 공인 IP vs 사설 IP


| 구분 | 공인 IP | 사설 IP (비공인 IP) |
|---|---|---|
| 의미 | 비용을 지불하고 구매하는 주소 | 허가 없이 누구나 자유롭게 사용 가능한 주소 |
| 인터넷 | 가능 | 직접 불가 (NAT 필요) |

사설 IP 대역 (Private Address)


| 클래스 | 사설 대역 | 실제 사용 범위 |
|---|---|---|
| A | 10.0.0.0/8 | 10.0.0.1 ~ 10.255.255.254 |
| B | 172.16.0.0/12 | 172.16.0.1 ~ 172.31.255.254 |
| C | 192.168.0.0/16 | 192.168.0.1 ~ 192.168.255.254 |

가정에서 사용하는 공유기(IP 062 등)가 사설 IP를 자동 배포 공인 IP 1개로 여러 기기(노트북, 스마트폰, TV 등)를 연결하기 위해 공유기 사용

### 7. IP 버전 6 (IPv6) 주소 체계

#### 7-1. 등장 배경

IPv4 주소 부족 문제 해결 IoT (사물인터넷) 확산 → 자동차, TV, 조명, 세탁기 등 모든 사물에 IP 필요 효율성·보안성 향상 목적 IPv5는 개발 중 빠르게 IPv6로 넘어감 TCP/UDP 비교 및 IP 주소 체계

#### 7-2. 주요 특징


| 항목 | IPv4 | IPv6 |
|---|---|---|
| 비트 수 | 32비트 | 128비트 |
| 주소 수 | 2³² | 2¹²⁸ (훨씬 많음) |
| 표기 방식 | 10진수, 점( . ) 구분 | 16진수, 콜론( : ) 구분 |

#### 7-3. IPv6 주소 종류


| 종류 | 설명 |
|---|---|
| 링크 로컬 | 같은 네트워크 내부 시스템 간 통신용, 자동 생<br>성 |
| 사이트 로컬 | 사이트 내부 통신용 |
| 글로벌 | 외부 인터넷 통신용 |

#### 7-4. IPv6 장점


| 장점 | 설명 |
|---|---|
| 보안성 (IPSec 내장) | IP Security(IPSec) 기능이 기본으로 내장 → IPv4보다 보안성이 훨씬 뛰<br>어남 |
| 자동 구성 (Auto<br>Configuration) | 수동 설정 없이 자동으로 IP 주소를 구성하는 기능 → 관리 편의성 향상 |
| 주소 확장성 | 128비트 구조로 사실상 무한에 가까운 주소 제공 |

IPv6 주소 확인 실습 CMD 창 → ipconfig /all → "링크-로컬 IPv6 주소" 항목 확인 (16진수로 표기됨)

#### 7-5. 현재 운용 방식

IPv4와 IPv6 혼용 중 외부 통신 → IPv4 주로 사용 내부 통신 또는 IPv6 전용 네트워크 연결 시 → IPv6 사용 IPv6 전환이 느린 이유 IPv6를 지원하는 장비·소프트웨어로의 교체 비용 발생 TCP/UDP 비교 및 IP 주소 체계 네트워크 단 설정 변경 필요 IPv4와 IPv6는 주소 체계가 달라 직접 호환 불가 두 버전을 함께 쓰려면 터널링(Tunneling) 기술 등을 사용해야 함 → 한 번에 전환하지 못하고 점진적으로 확대 중

### 8. MAC 주소 (물리적 주소)

정식 명칭: MAC (Media Access Control) Address 다른 이름: 물리적 주소 (Physical Address), 하드웨어 주소 제조 단계에서 하드웨어에 마킹되어 나오는 고유 주소 16진수 표기 (예: 00-1A-2B-3C-4D-5E )

일반적인 방법으로는 변경 불가 (IP 주소와 다른 점)

MAC 주소 확인 방법 CMD 창 → ipconfig /all → "물리적 주소" 항목 확인

## 004. 네트워크 보안 기초

### 1. 정보보안의 3대 요소 (CIA)

정보보안을 공부할 때 가장 기본이 되는 세 가지 요소로, 흔히 기·무·가 또는 영어 약자 CIA 로 부른다.


| 요소 | 영문 | 설명 |
|---|---|---|
| 기밀성<br>(Confidentiality) | Confidentiality | 비인가자가 시스템의 정보를 열람하거나 접근하지 못하<br>도록 하는 것 |
| 무결성 (Integrity) | Integrity | 데이터나 정보가 훼손·변조·삭제되지 않아야 하는 것 |
| 가용성 (Availability) | Availability | 사용이 가능한 시점에 언제든지 시스템이 사용 가능한<br>상태로 존재해야 하는 것 |

### 2. 정보보안의 5대 요소

3대 요소(CIA)에 아래 두 가지를 추가하면 5대 요소가 된다.

부인 방지 (Non-repudiation)

어떤 행위를 했음에도 "나는 하지 않았다"고 부인하는 것을 방지 예: 이메일 발신자가 전자서명을 통해 보낸 사실을 증명 → 수신자가 "받지 않았다"고 부인 불가 인증 (Authentication)

허가된 사용자만이 사용하고자 하는 시스템에 접근할 수 있도록 하는 것

### 3. 정보보안의 3대 분류

정보보안은 크게 아래 세 가지가 톱니바퀴처럼 유기적으로 맞물려야 완전한 보안이 이루어진다.

#### 3-1. 물리적 보안

자산을 물리적으로 보호하는 모든 수단 예: 공항 보안검색대, 스피드게이트, 휴대용 금속탐지기, 담장, 아파트 주차 차단기 등

#### 3-2. 관리적 보안

인적 보안을 포함한 문서 기반의 보안 체계 책임자 지정, 퇴사자 관리, 신규 직원 권한 부여 기준 등 모든 지침을 문서화 시스템 구현 과정·문제점·개선 내역 등의 기록이 해당

#### 3-3. 기술적 보안

실습을 통해 직접 배우는 영역 주요 분야:

시스템(서버) 보안 웹 보안 (애플리케이션 보안의 일종)

애플리케이션 보안 — FTP, 메일 서버(SMTP) 등 다양한 서비스 포함 웹 보안이 특히 자주 다루어지는 이유: 현재 서비스 중 웹 애플리케이션이 가장 많은 비중 을 차지하기 때문

### 4. ISMS-P (정보보호 관리체계 인증)

ISMS: 정보보호 관리체계 PIMS: 개인정보보호 관리체계 현재는 두 인증을 통합한 ISMS-P로 운영 법령으로 지정된 의무 인증 대상: 네이버, 다음 등 대규모 개인정보를 보유한 기업 인증 심사는 ISMS-P 인증심사원이 물리적·관리적·기술적 보안 체크리스트를 점검 후 평가위원회에서 최종 결정 인증 취득 시 기업의 신뢰도 향상 (KS 인증 마크와 유사한 개념)

경력 6년 이상이면 ISMS 인증심사원 응시 자격 취득 가능

### 5. OSI 표준 모델

#### 5-1. 개요

OSI: Open Systems Interconnection (개방형 시스템 간의 유기적 연결)

제정 기관: ISO (International Standards Organization, 국제표준협회)

1970년대 초반 제정, 현재까지도 7계층 구조로 동작 제정 배경: 서로 다른 환경(장비·소프트웨어·프로토콜)을 가진 기관들 간의 연결이 어려 워 표준 필요성 대두 표준 제정 이후 소프트웨어·하드웨어·네트워크 모든 분야가 비약적으로 발전 → 각 개발 분야의 선택과 집중이 가능해졌기 때문

#### 5-2. OSI 7계층 구조


| 계층 번호 | 계층 이름 | 주요 역할 | 관련 장비/프로토콜 예<br>시 |
|---|---|---|---|
| 7 | 애플리케이션 계<br>층 | 사용자에게 인터페이스 제공 | HTTP, FTP, SMTP 등 |
| 6 | 프레젠테이션 계<br>층 | 데이터 압축·암호화·변환 | — |
| 5 | 세션 계층 | 통신 연결(세션) 관리 | — |
| 4 | 전송 계층 | 실제 데이터 전송 제어 | TCP, UDP |
| 3 | 네트워크 계층 | 경로 설정 (라우팅) | 라우터, L3 스위치 |
| 2 | 데이터링크 계층 | 내부 네트워크 전송, 흐름 제어 | L2 스위치 |
| 1 | 물리 계층 | 전송 매체의 물리적 인터페이스<br>규정 | UTP 케이블, 잭 |

상위 계층 (5~7층): 사용자 지원 계층 (어퍼 레이어)

하위 계층 (1~3층): 실제 전송 및 경로 처리

### 6. 캡슐화와 역캡슐화

#### 6-1. 캡슐화 (Encapsulation) — 송신 측

데이터가 상위 계층 → 하위 계층으로 이동할 때, 각 계층마다 헤더(Header) 정보가 추가됨 원본 데이터보다 실제 전송되는 데이터의 크기가 더 커짐 비유: 알약 캡슐 — 약효 분말(원본 데이터)을 캡슐(헤더)로 감싸는 과정, 또는 포장이사 시 그릇을 신문지·뽁뽁이로 겹겹이 싸는 것

#### 6-2. 역캡슐화 (Decapsulation) — 수신 측

수신 측에서는 하위 계층 → 상위 계층으로 이동하며, 각 계층의 헤더를 하나씩 제거 최종적으로 원본 데이터를 복원 비유: 이사한 집에서 신문지·뽁뽁이를 벗겨내고 원래 그릇을 꺼내는 것

#### 6-3. 통신 예시 (이메일 송수신)

[송신 측] 네이버 메일 사용자 └─ 메일 작성 → 보내기 클릭 (7계층: 애플리케이션) └─ 파일 압축/암호화 (6계층: 프레젠테이션)

└─ 세션 생성 (5계층: 세션) └─ TCP 전송 제어 (4계층: 전송)

└─ 경로 설정 (3계층: 네트워크)

└─ 내부 전송 (2계층: 데이터링크) └─ UTP 케이블 → ISP(KT, LG U+ 등) 전송 (1계층: 물리)

[수신 측] 다음 메일 사용자 └─ 1계층부터 수신 → 각 계층에서 헤더 제거 └─ 압축 해제 / 암호 복호화 └─ 원본 메일 수신

### 7. TCP/IP 모델

OSI 모델과 대응 관계를 이루는 실용 모델 인터넷 및 데이터 전송에 실제로 사용되는 프로토콜 체계


| TCP/IP 계층 | 대응 OSI 계층 |
|---|---|
| 애플리케이션 계층 | 5, 6, 7계층 |
| 전송 계층 | 4계층 |
| 인터넷 계층 | 3계층 |
| 네트워크 액세스 계층 | 1, 2계층 |

주요 프로토콜 정리


| 프로토콜 | 풀네임 | 의미 |
|---|---|---|
| TCP | Transmission Control Protocol | 전송 제어 통신 규약 |
| IP | Internet Protocol | 인터넷 주소 통신 규약 |
| UDP | User Datagram Protocol | 비연결형 전송 프로토콜 |
| FTP | File Transfer Protocol | 파일 전송 통신 규약 |
| SMTP | Simple Mail Transfer Protocol | 메일 전송 통신 규약 |


| 프로토콜 | 풀네임 | 의미 |
|---|---|---|
| HTTP | HyperText Transfer Protocol | 웹 통신 규약 |

P (Protocol) = 통신 규약. 대부분의 통신 관련 약자 끝에 붙는 P는 Protocol의 약자 TCP/IP에서 TCP가 대표로 쓰이는 이유: 대부분의 데이터 전송이 TCP를 사용하기 때문 전송 계층에서는 TCP 외에 UDP도 사용 (차이점은 추후 설명)

IP 주소 예시: 192.168.100.1 , 210.100.100.100

## 005. 시스코 장비 CLI 기본 설정

CLI: Command Line Interface — 명령어를 직접 입력하여 장비를 설정하는 환경 Packet Tracer에서 장비 클릭 → CLI 탭 선택하여 진입 Config 탭(GUI 설정)은 사용하지 않고, CLI로만 설정 네트워크·리눅스·모의해킹 등 대부분의 수업이 영어 명령어 기반 → 영타 연습 권장 장비 간 연결선이 처음에 빨간 불로 표시되며, 시간이 지나면 녹색으로 바뀜 일정 시간 후에도 녹색이 안 되면 선을 삭제하고 자동 연결로 다시 연결

## 006. VTP

### 1. 트러블슈팅(Troubleshooting) 마인드셋

통신이 안 될 때 → "왜 안 되지?" 를 찾는 과정이 곧 실제 필드의 장애 처리 show running-config  명령어로 설정 내용을 확인하며 구성도와 비교 안 됐을 때를 스킬을 키울 기회로 생각할 것

### 2. VTP (VLAN Trunking Protocol) 개요

#### 2-1. 등장 배경

스위치가 여러 대(예: 10대)인 환경에서 VLAN이 변경될 때마다 모든 스위치에 일일이 접속해서 동기화해야 하는 문제 부서 신설·폐지·통폐합 등 VLAN 구성은 수시로 변경됨 → VLAN 정보를 자동으로 동기화해주는 프로토콜이 필요 → VTP

#### 2-2. VTP 동작 조건


| 조건 | 설명 |
|---|---|
| VTP 도메인 이름 동일 | 같은 도메인 이름을 가진 스위치끼리만 정보를 동기화 |
| VTP 패스워드 동일 | 패스워드가 일치할 때만 동기화 허용 |
| 스위치 간 연결 포트가<br>Trunk | VLAN 정보가 트렁크 포트를 통해 전달됨 |

### 3. VTP 동작 모드 (3가지)


| 모드 | 역할 | VLAN 생성/삭제/<br>변경 | 정보 동기화 |
|---|---|---|---|
| Server (서버) | VLAN 정보를 생성·관리·제공 | 가능 | 정보를 전송 |
| Client (클라이언트) | 서버로부터 VLAN 정보를 수<br>신 | 불가 | 정보를 수신 |


| 모드 | 역할 | VLAN 생성/삭제/<br>변경 | 정보 동기화 |
|---|---|---|---|
| Transparent (투<br>명) | 독립적으로 동작 | 가능 | 영향을 받지도 주지도<br>않음, 단 연결된 스위치<br>에 정보는 전달 |

기본값은 Server 모드 Transparent 모드를 사용하는 이유 특정 부서의 VLAN이 다른 VLAN과 공유·통신되면 안 되는 경우 보안성 확보를 위해 독립적으로 운용할 때 사용

### 4. Revision Number (리비전 넘버)

VTP 동기화에 사용되는 버전 번호 VLAN 관련 명령어를 내릴 때마다 1씩 증가 클라이언트는 서버의 Revision Number가 자신보다 높으면 → 최신 정보를 요청하여 동기화 장비 전원을 껐다 켜면 Revision Number가 초기화됨 예시:

A 스위치(서버): vlan 100 → Revision 1 name test  → Revision 2 B 스위치(클라이언트): Revision 0 → 서버의 2를 받아 동기화 → Revision 2

### 5. VTP 설정 과정

#### 5-1. 토폴로지 구성

[Switch A] ── [Switch B] ── [Switch C] ── [Switch D]

Server       Client      Transparent     Client 2960 스위치 4대 사용 스위치 간 연결 포트는 모두 Trunk 설정 필요

#### 5-2. VTP 상태 확인 (이네이블 모드)

Switch# show vtp status 현재 동작 모드, 도메인 이름, Revision Number 확인 가능 Config 모드에서 실행하려면: do show vtp status

#### 5-3. VTP 설정 명령어 (Config 모드)

Switch(config)# vtp domain [도메인이름] Switch(config)# vtp password [패스워드]

Switch(config)# vtp mode [server | client | transparent]

실습 예시 ! A 스위치 (Server)

Switch(config)# vtp domain test Switch(config)# vtp password 1234 Switch(config)# vtp mode server       ← 기본값이므로 생략 가능 ! B 스위치 (Client)

Switch(config)# vtp domain test Switch(config)# vtp password 1234 Switch(config)# vtp mode client ! C 스위치 (Transparent) Switch(config)# vtp domain test Switch(config)# vtp password 1234 Switch(config)# vtp mode transparent ! D 스위치 (Client) Switch(config)# vtp domain test Switch(config)# vtp password 1234 Switch(config)# vtp mode client

#### 5-4. 트렁크 포트 설정 (스위치 간 연결 포트 전체)

Switch(config)# interface fa0/1 Switch(config-if)# switchport mode trunk Switch(config)# interface fa0/2        ← 연결된 포트가 2개인 경우 Switch(config-if)# switchport mode trunk ⚠️ 포트 이름은 구성도에서 직접 확인 후 입력 (장비·버전마다 다를 수 있음)

#### 5-5. VTP 동기화 확인

! 서버에서 VLAN 생성 Switch(config)# vlan 100 Switch(config-vlan)# name test ! 서버에서 Revision Number 확인 Switch# show vtp status          ← Revision이 2로 증가했는지 확인 ! 클라이언트에서 동기화 확인 Switch# show vtp status          ← Revision이 서버와 동일한지 확인 Switch# show vlan                ← VLAN 100이 자동으로 생성됐는지 확인

### 6. 동기화 안 될 때 체크리스트


| 항목 | 확인 방법 |
|---|---|
| 트렁크 포트 설정 여부 | show interfaces [포트명] switchport |

| 포트 이름이 구성도와 일치하는지 | 구성도와 직접 비교 |

### 7. 유용한 CLI 팁

## 007. VTP 트러블슈팅

### 1. VTP 트러블슈팅 체크리스트

동기화가 안 될 때 아래 순서로 하나씩 확인한다.


| 순서 | 확인 항목 | 확인 명령어 |
|---|---|---|
| 1 | 스위치 간 연결 포트가 트렁크 모드로 동작 중인<br>지 | show interfaces<br>trunk |
| 2 | VTP 도메인 이름이 모든 스위치에서 동일한지 | show vtp status |
| 3 | VTP 패스워드가 일치하는지 | show vtp password |
| 4 | Revision Number가 동기화되었는지 | show vtp status |

동기화 확인 방법: 서버 스위치에서 VLAN을 생성한 뒤 클라이언트 스위치에서 show vlan 으로 자동 반영 여부 확인

### 2. 시스코 장비 모델 번호 이해

모델 번호가 높을수록 → 운영체제(IOS) 버전이 높고, 지원 명령어·기능이 더 많음 가격도 높아지는 것이 일반적 실습에서는 라우터: 2901, 스위치: 2960 모델 사용 (다른 모델도 기본 명령어는 동일)

### 3. 종합 예제 — 3개 VLAN 전체 설정

#### 3-1. 토폴로지 구성

[라우터 2901]

│ [A 스위치 2960] ── [B 스위치 2960]

│        │              │ PC1      PC2            PC3 (VLAN 100) (VLAN 300)  (VLAN 200)

VLAN 100: CCNA 그룹 VLAN 200: CCNP 그룹 VLAN 300: CCIE 그룹 할당받은 네트워크: 192.168.200.0/24

#### 3-2. Step 1 — 서브네팅 (주소 설계)

조건: 3개 VLAN 필요 → 2² = 4 네트워크로 분할 (비트 2개 변경)

변경 전: /24 → 255.255.255.0    (마지막 옥텟: 00000000)

변경 후: /26 → 255.255.255.192  (마지막 옥텟: 11000000) → 128 + 64 = 192 네트워크 수:  2² = 4개 (3개 사용 + 1개 예비)

할당 가능 IP: 2⁶ - 2 = 62개 (각 네트워크당)

4개 네트워크 대역 범위:


| 네트워크 | 전체 범위 | 할당 가능 범위 | 용도 |
|---|---|---|---|
| 1번 | 200.0 ~ 200.63 | 200.1 ~ 200.62 | VLAN 100 (CCNA) |
| 2번 | 200.64 ~ 200.127 | 200.65 ~ 200.126 | VLAN 200 (CCNP) |
| 3번 | 200.128 ~ 200.191 | 200.129 ~ 200.190 | VLAN 300 (CCIE) |

## 009. 서브넷 마스크 상세 서브네팅 공식

서브넷 마스크 상세/서브네팅 공식

### 1. 프리픽스 표기법 (/숫자)의 의미

/24  처럼 슬래시 뒤에 숫자로 서브넷 마스크를 간략하게 표기 숫자 = 서브넷 마스크를 2진수로 변환했을 때 비트 1의 개수 /24 → 1의 비트 24개 → 11111111.11111111.11111111.00000000 → 255.255.255.0 /16 → 1의 비트 16개 → 11111111.11111111.00000000.00000000 → 255.255.0.0 /26 → 1의 비트 26개 → 11111111.11111111.11111111.11000000 → 255.255.255.192 /26 계산 예시 마지막 옥텟: 11000000 → 128 + 64 = 192 → 서브넷 마스크: 255.255.255.192 서브넷 마스크는 반드시 1이 연속으로 나오고 그 뒤에 0이 이어짐 중간에 0과 1이 섞이는 경우는 없음

### 2. 네트워크 ID / 호스트 ID

서브넷 마스크를 2진수로 표현했을 때:


| 비트 구간 | 의미 |
|---|---|
| 1로 시작 ~ 1로 끝나는<br>부분 | 네트워크 ID — 같은 집(네트워크)임을 나타내는 부분, 집 안 모든 장비가 동<br>일 |
| 0으로 시작 ~ 0으로 끝<br>나는 부분 | 호스트 ID — 장비에 할당 가능한 주소 범위 |

### 3. 예약 주소

하나의 네트워크 대역에서 첫 번째와 마지막 주소는 시스템에 할당 불가 서브넷 마스크 상세/서브네팅 공식


| 위치 | 이름 | 용도 |
|---|---|---|
| 대역의 첫 번째 주소 | 네트워크 주소 | 대역 전체를 나타내는 식별 주소 |
| 대역의 마지막 주소 | 브로드캐스트 주소 | 같은 네트워크 내 전체 전송(1:N 통신)용 예약 주<br>소 |

예) 192.168.100.0/24 대역 → 100.0(네트워크), 100.255(브로드캐스트)

실제 할당 가능 범위: 100.1 ~ 100.254 (총 254개)

### 4. 서브네팅 공식

서브넷 마스크의 0 비트를 1 비트로 변경하여 네트워크를 분할하는 작업 공식 1 — 생성되는 네트워크(집)의 수 네트워크 수 = 2ⁿ     (n = 변경된 비트 1의 개수)

공식 2 — 각 네트워크에서 할당 가능한 IP 수 할당 가능한 IP 수 = 2ⁿ - 2     (n = 남아 있는 비트 0의 개수) (- 2 = 네트워크 주소 + 브로드캐스트 주소 제외)

서브네팅 예제 — /24를 /26으로 분할 원본 네트워크: 192.168.100.0/24 변경 전: 11111111.11111111.11111111.00000000  (/24) 변경 후: 11111111.11111111.11111111.11000000  (/26)

→ 변경된 비트: 2개 → 네트워크 수 = 2² = 4개 → 남은 0 비트: 6개 → 할당 가능 IP = 2⁶ - 2 = 62개 4개 네트워크 대역 범위:


| 네트워크 | 전체 범위 | 할당 가능 범위 |
|---|---|---|
| 1번 | 100.0 ~ 100.63 | 100.1 ~ 100.62 |
| 2번 | 100.64 ~ 100.127 | 100.65 ~ 100.126 |
| 3번 | 100.128 ~ 100.191 | 100.129 ~ 100.190 |

서브넷 마스크 상세/서브네팅 공식


| 네트워크 | 전체 범위 | 할당 가능 범위 |
|---|---|---|
| 4번 | 100.192 ~ 100.255 | 100.193 ~ 100.254 |

각 대역의 범위는 할당 가능 IP 수(64)씩 더해가면 구할 수 있음 실습 예제 — 7개 부서 서브네팅 조건: 192.168.150.0/24 네트워크를 7개 부서용 VLAN으로 서브네팅 풀이 과정:

1단계: 필요한 네트워크 수 = 7 → 2ⁿ ≥ 7 → 2³ = 8 (n=3)

2단계: 서브넷 마스크 마지막 옥텟: 11100000 → 128+64+32 = 224 → 서브넷 마스크: 255.255.255.224 3단계: 남은 0 비트 = 5개 → 할당 가능 IP = 2⁵ - 2 = 30개 각 네트워크 범위 (32씩 증가): ① 150.0   ~ 150.31  (할당: 150.1  ~ 150.30)

② 150.32  ~ 150.63  (할당: 150.33 ~ 150.62) ③ 150.64  ~ 150.95  (할당: 150.65 ~ 150.94)

④ 150.96  ~ 150.127 (할당: 150.97 ~ 150.126)

⑤ 150.128 ~ 150.159 (할당: 150.129 ~ 150.158) ⑥ 150.160 ~ 150.191 (할당: 150.161 ~ 150.190)

⑦ 150.192 ~ 150.223 (할당: 150.193 ~ 150.222) ⑧ (여유분으로 보관)

같은 스위치에 선생님 PC + 학생 PC가 연결된 경우 같은 네트워크에 있으면 학생이 선생님 PC에 접근하기 쉬움 → 보안 취약 물리적 분리 vs VLAN


| 방법 | 장점 | 단점 |
|---|---|---|
| 물리적 분리 (별도 인터페이스) | 보안성 최고 | 추가 인터페이스·회선 비용 발생 |
| VLAN 설정 | 비용 없이 논리적으로 분리 | 라우터(L3 장비) 설정 필요 |

VLAN의 효과 물리적으로 같은 스위치에 있어도 논리적으로 완전히 다른 네트워크처럼 동작 다른 VLAN끼리 통신하려면 반드시 L3 장비(라우터) 를 거쳐야 함 → 보안성 향상 비용 증가 없이 보안성·관리성 모두 향상

### 4. 서브넷 기초 — 이진수 변환

#### 4-1. 10진수 → 2진수

14를 2진수로 변환: 14 ÷ 2 = 7 나머지 0 7 ÷ 2 = 3 나머지 13 ÷ 2 = 1 나머지 11 ÷ 2 = 0 나머지 1 → 역순으로 읽기: 1110

#### 4-2. 2진수 → 10진수

각 자릿수의 값: 128 | 64 | 32 | 16 | 8 | 4 | 2 | 1 설정 저장/CLI 팁/VLAN/서브넷 1110 0000 → 128 + 64 + 32 = 224 1000 0000 → 128 1111 1111 → 255 (모든 비트가 1)0000 0000 → 0   (모든 비트가 0)

#### 4-3. 경우의 수 공식

n비트로 나올 수 있는 경우의 수 = 2ⁿ 예) 1비트 → 2¹ = 2가지 (0, 1)

8비트 → 2⁸ = 256가지 (0 ~ 255)

### 5. 서브넷 마스크 기초

하나의 옥텟 = 8비트 → 2⁸ = 256가지 → 범위 0 ~ 255 IP 주소 입력 시 256, 300 등 255를 초과하는 값은 사용 불가 주소를 할당할 때 서브넷 마스크가 반드시 필요 → 어떤 네트워크에 속하는지 구분 설정 저장/CLI 팁/VLAN/서브넷

## 012. 트렁킹 서브인터페이스 다른 VLAN 간 통신

트렁킹/서브인터페이스/다른 VLAN 간 통신

### 1. 트렁킹 (Trunking) 개념

트렁킹: VLAN 정보가 포함된 데이터들이 다닐 수 있는 전용 통로를 만드는 것 스위치↔스위치, 스위치↔라우터 구간에 설정 트렁킹이 없으면 VLAN 정보가 전달되지 않아 다른 스위치의 동일 VLAN끼리도 통신 불가 VLAN 태깅 (802.1q)

트렁크 구간에서 데이터에 VLAN 번호를 식별하는 태그를 붙여 전송 받는 쪽에서 태그를 확인하여 어느 VLAN에서 온 데이터인지 구분 캡슐화 방식: IEEE 802.1q (dot1q)

비유: 옷에 붙은 태그처럼, 각 VLAN 데이터에 식별 정보를 마킹 네이티브 VLAN (Native VLAN)

태그가 없는 데이터가 속하는 VLAN 기본값: VLAN 1 A 스위치와 B 스위치의 네이티브 VLAN은 반드시 일치해야 함 (불일치 시 통신 오류)

기본값 1로 맞춰져 있으므로 별도 설정하지 않아도 됨

### 2. 트렁킹 확인 명령어

Switch# show interfaces trunk 트렁크로 동작 중인 포트 목록 확인 캡슐화 방식(802.1q), 상태(trunking) 확인 트렁킹/서브인터페이스/다른 VLAN 간 통신 트렁크 설정한 포트가 show vlan 에서 빠져 있어야 정상 링크가 죽어 있으면(빨간 불) 트렁크 포트로 인식 안 됨

### 3. 동일 VLAN 통신 vs 다른 VLAN 통신


| 구분 | 통신 여부 | 필요 장비 |
|---|---|---|
| 동일 VLAN | 가능 | L2 스위치만으로 통신 |
| 다른 VLAN | 불가 | 반드시 L3 장비(라우터) 필요 |

물리적으로 같은 스위치에 있어도 VLAN이 다르면 → 다른 집(네트워크) = 통신 불가 다른 VLAN 간 통신을 원하면 라우터에서 서브인터페이스 설정 필요

### 4. 서브인터페이스 (Sub-interface) 설정

물리적 인터페이스 하나를 논리적으로 여러 개로 분할하여 각 VLAN의 게이트웨이 역할을 하도록 설정

#### 4-1. 물리 인터페이스 활성화 (IP 없이 no shutdown만)

Router(config)# interface gi0/0          ← 실제 물리 인터페이스 Router(config-if)# no shutdown           ← IP 없이 활성화만 필요 Router(config-if)# exit

#### 4-2. VLAN별 서브인터페이스 생성

! VLAN 10용 서브인터페이스 Router(config)# interface gi0/0.10       ← 물리인터페이스명.브랜번호 (점으로 구분)

Router(config-subif)# encapsulation dot1q 10        ← 캡슐화 방식 + VLAN 번호 지정 Router(config-subif)# ip address 192.168.100.1 255.255.255.128   ← 게이트웨이 IP ! VLAN 20용 서브인터페이스 Router(config)# interface gi0/0.20 Router(config-subif)# encapsulation dot1q 20 Router(config-subif)# ip address 192.168.100.129 255.255.255.128 명령어 요약:

트렁킹/서브인터페이스/다른 VLAN 간 통신


| 명령어 |  | 설명 |
|---|---|---|
| interface [인터페이스명].[번 |  | 서브인터페이스 생성 (번호는 VLAN 번호와 일치 권장) |
| 호] |  |  |
| encapsulation dot1q [VLAN번 |  | 802.1q 캡슐화 방식 및 담당 VLAN 지정 ( encap 으로 축약 가<br>능) |
|  | encapsulation dot1q [VLAN번 |  |
| 호] |  |  |

서브인터페이스 번호는 범위 내 자유롭게 지정 가능 (약 42억 개)

VLAN 번호와 맞추면 관리하기 쉬움

### 5. 게이트웨이 설정 (각 PC)

서브인터페이스 설정 후 각 PC에도 게이트웨이를 지정해야 다른 VLAN과 통신 가능


| PC | VLAN | 게이트웨이 |
|---|---|---|
| VLAN 10 PC들 | 10 | 192.168.100.1 |
| VLAN 20 PC들 | 20 | 192.168.100.129 |

게이트웨이 미설정 또는 오설정 시 → 다른 네트워크와 통신 불가 대부분 첫 번째 또는 마지막 IP를 게이트웨이로 사용 (관리 편의상)

### 6. 통신 테스트 결과

! VLAN 10 PC에서 같은 VLAN 10 서버로 핑 ping 192.168.100.110 → 성공 ✓ ! VLAN 10 PC에서 다른 VLAN 20 PC로 핑 (라우터 설정 전) ping 192.168.100.200 → 실패 ✗ ! 서브인터페이스 + 게이트웨이 설정 완료 후 ping 192.168.100.200 → 성공 ✓ (첫 번째 패킷은 로스 날 수 있음)

첫 번째 패킷이 로스 나도 바로 단정 짓지 말 것 — 두 번째부터 정상이면 설정 완료

### 7. 전체 통신 구조 정리

트렁킹/서브인터페이스/다른 VLAN 간 통신 [VLAN 10 PC] ──access── [A 스위치] ──trunk── [B 스위치] ──access── [VLAN 20 PC]

│ trunk │ [라우터 gi0/0] ├── gi0/0.10 → VLAN 10 게이트웨이 (100.1)

└── gi0/0.20 → VLAN 20 게이트웨이 (100.129)

같은 VLAN 내 통신: 스위치만으로 처리 다른 VLAN 통신: 스위치 → 라우터 서브인터페이스 → 다시 스위치로 전달

## 015. EIGRP 설정과 기본 구조

### 1. EIGRP의 개념 및 역할

#### 1-1. EIGRP 프로토콜 개요

Enhanced Interior Gateway Routing Protocol EIGRP는 IGRP의 개선된 버전으로, RIP의 단순한 홉 카운트 기반 메트릭을 극복하고 대역폭, 지연, 신뢰성 등 다중 요소를 고려하여 더 정확한 경로 선택이 가능한 다이나믹 라우팅 프로토콜이다. 대규모 네트워크 환경에서 효율적으로 동작한다.

### 2. EIGRP 설정 필수 요소

#### 2-1. AS(Autonomous System) Number의 정의

EIGRP 설정의 핵심은 AS Number라는 식별자이다:

router eigrp <AS_NUMBER> AS Number의 특성:


| 특성 | 설명 |
|---|---|
| 범위 | 1~65,535 |
| 역할 | 같은 AS Number를 가진 라우터들만 라우팅 정보 교환 |
| 중요성 | 모든 EIGRP 라우터는 동일한 AS Number 사용 필수 |
| 네트워크 정의 | 하나의 라우팅 도메인을 정의 |

AS Number의 의미:

하나의 네트워크 도메인 정의 같은 AS Number가 아니면 이웃 라우터 관계(Neighbor Relationship) 형성 불가 내부 테스트 네트워크에서는 임의로 설정 가능 ⚠️ 이웃 라우터 관계 형성의 필수 조건: 동일한 AS Number

### 3. EIGRP 설정 단계별 절차

#### 3-1. EIGRP 라우팅 프로토콜 진입

router eigrp 10      ← AS Number 10 지정 AS Number 선택 원칙:

같은 도메인의 모든 라우터는 동일한 AS Number 사용 예: 라우터 A, B, C 모두 AS 10

#### 3-2. 네트워크 광고 설정: Wildcard Bit 사용

RIP과의 가장 큰 차이점은 Wildcard Bit 필수:

network <네트워크주소> <와일드카드비트> Wildcard Bit 계산 공식:

와일드카드 비트 = 255 - 서브넷마스크의 각 옥테트 계산 예시:


| 서브넷마스크 | 계산 과정 | 와일드카드 비트 |
|---|---|---|
| 255.255.255.0 | 255-255, 255-255, 255-255, 255-0 | 0.0.0.255 |
| 255.255.0.0 | 255-255, 255-255, 255-0, 255-0 | 0.0.255.255 |
| 255.0.0.0 | 255-255, 255-0, 255-0, 255-0 | 0.255.255.255 |

#### 3-3. 자동축약 비활성화

no auto-summary      ← 세분화된 경로 광고를 위해 필수 RIP v2와 마찬가지로 자동축약을 비활성화하여 세분화된 서브넷 정보 광고 가능

### 4. EIGRP 설정 구성 예시

#### 4-1. 라우터별 설정 내용

라우터 A 설정 (AS 10):

router eigrp 10 network 10.0.0.0 0.0.0.255 network 30.0.0.0 0.0.0.255 network 192.168.100.0 0.0.0.255 no auto-summary 라우터 B 설정 (AS 10):

router eigrp 10 network 10.0.0.0 0.0.0.255 network 20.0.0.0 0.0.0.255 network 30.0.0.0 0.0.0.255 network 192.168.150.0 0.0.0.255 no auto-summary 라우터 C 설정 (AS 10):

router eigrp 10 network 20.0.0.0 0.0.0.255 network 192.168.200.0 0.0.0.255 no auto-summary

#### 4-2. RIP과 EIGRP 설정 비교


| 설정 항목 | RIP | EIGRP |
|---|---|---|
| 라우팅 프로토콜 진입 | router rip | router eigrp <AS Number><br>_ |
| 네트워크 광고 형식 | network 10.0.0.0 | network 10.0.0.0 0.0.0.255 |
| 필수 정보 | 네트워크 주소만 | 네트워크 + Wildcard Bit |
| 자동축약 제어 | RIP v2에서만 지원 | 모든 EIGRP 버전에서 지원 |
| 도메인 정의 | 없음 | AS Number 필수 |
| AD (신뢰도) | 120 | 90 |

### 5. EIGRP 이웃 라우터 관계 형성

#### 5-1. 이웃 라우터(Neighbor) 형성 필수 조건

EIGRP에서 두 라우터가 이웃 관계를 형성하기 위한 필수 조건:


| 조건 | 설명 | 확인 방법 |
|---|---|---|
| 1. 동일한 AS Number | 반드시 같아야 함 | show ip protocols |
| 2. 직접 연결된 인터페이<br>스 | 물리적 연결 필요 | 네트워크 다이어그램 |
| 3. 네트워크 광고 | 해당 네트워크를 network 명령어로 광<br>고 | show run |
| 4. 인터페이스 활성화 | 양쪽 인터페이스 모두 no shutdown | show ip interface |
|  |  | brief |

#### 5-2. 이웃 라우터 상태 확인

show ip eigrp neighbors 출력 정보:

이웃 IP 주소: 연결된 이웃 라우터의 인터페이스 IP 상태: 이웃 관계 수립 여부 (UP/DOWN)

홀드 타임(Hold Time): 이웃 라우터 응답 대기 시간 시퀀스 번호: 업데이트 순서 추적 ⚠️ 이웃 목록이 비어있으면 4가지 조건 중 하나 이상을 확인하지 않음

### 6. EIGRP의 다중 메트릭(Metric) 시스템

#### 6-1. RIP과 EIGRP의 메트릭 차이


| 구분 | RIP | EIGRP |
|---|---|---|
| 메트릭 기준 | 홉 카운트만 사용 | 다중 요소 종합 계산 |
| 회선 속도 반영 | 불가능 | 대역폭(Bandwidth)으로 반영 |
| 지연시간 반영 | 불가능 | 지연(Delay)으로 반영 |
| 신뢰성 반영 | 불가능 | 신뢰성(Reliability)으로 반영 |
| 현재 사용률 | 불가능 | 부하(Load)로 반영 |


| 구분 | RIP | EIGRP |
|---|---|---|
| 최적성 | 부정확 | 더욱 정확함 |

#### 6-2. EIGRP 메트릭 구성 요소

메트릭 계산에 참고되는 5가지 요소 (K1~K5 상수로 조절):

### 1. BW (Bandwidth)     ← 대역폭 (링크 최저 속도)

### 2. D (Delay)          ← 지연시간 (누적 지연)

### 3. R (Reliability)    ← 신뢰도 (링크 안정성)

### 4. L (Load)           ← 부하량 (현재 사용률)

### 5. M (MTU)            ← 최대 전송 단위

기본 설정에서 적용되는 메트릭:

BW (대역폭): 경로상 최저 대역폭 사용 D (지연): 경로상 모든 링크의 지연 누적 R, L, M: 기본 설정에서 미적용

### 7. EIGRP의 장점과 특징

#### 7-1. RIP과 비교한 EIGRP의 개선 사항


| 특징 | RIP | EIGRP | 개선도 |
|---|---|---|---|
| 경로 선택 정확도 | 낮음 (홉 카운트만) | 높음 (다중 메트릭) | 큼 |
| 네트워크 변화 반응 시<br>간 | 느림 (30초~3분) | 빠름 (수 초) | 큼 |
| 대역폭 효율성 | 낮음 (주기적 전체 테이<br>블) | 높음 (변화 기반 업데이<br>트) | 큼 |
| 확장성 | 소규모만 가능 | 중대형 네트워크 지원 | 큼 |
| 설정 복잡도 | 낮음 | 중간~높음 | 소 |
| 신뢰도(AD) | 120 | 90 | 높음 |

#### 7-2. EIGRP 라우팅 테이블 확인

show ip route EIGRP 학습 경로 식별:

경로 코드: D  (D = EIGRP)

메트릭 값: RIP의 단순한 홉 수와 달리 복잡한 계산값 표시 AD 값: 120(RIP)과 달리 90으로 표시 (더 높은 우선순위)

라우팅 테이블 예시:

D  10.0.0.0/8 [90/156160] via 10.10.10.10, 00:05:23, FastEthernet0/0 AD값: 90, 메트릭값: 156160, 이웃: 10.10.10.10

## 016. RIP 버전 1과 버전 2의 차이점 및 호환성 검증

환성 검증

### 1. RIP 버전별 특성 비교

#### 1-1. RIP Version 1의 송수신 특성

#### 1-2. RIP Version 1의 동작 방식

Hello 패킷 송수신:


| 동작 | 설정값 | 설명 |
|---|---|---|
| 송신 포맷 | RIP v1 | RIP version 1 포맷으로 Hello 패킷 전송 |
| 수신 포맷 | Any Version | 모든 버전의 패킷 수신 가능 |

메이저 네트워크 자동축약(Auto Summary):

클래스풀(Classful) 방식으로만 동작 관리자가 서브네팅으로 세분화한 네트워크도 메이저 네트워크로 자동 축약 세분화된 경로 정보 광고 불가능 입력 명령어: network 20.20.20.0 실제 광고: 20.0.0.0/8 (클래스 A 범위로 자동 축약)

⚠️ 관리자가 아무리 서브네팅으로 네트워크를 쪼개도 RIP v1은 클래스 기반의 메이저 네트워크로 축약하여 광고한다.

### 2. RIP Version 2의 개선된 특성

#### 2-1. RIP v2의 송수신 방식


| 동작 | 설정값 | 설명 |
|---|---|---|
| 송신 포맷 | RIP v2 | RIP version 2 포맷으로만 Hello 패킷 전송 |


| 동작 | 설정값 | 설명 |
|---|---|---|
| 수신 포맷 | v2 버전만 | v2 포맷의 패킷만 수신, v1 패킷 수신 불가 |

#### 2-2. 자동축약(Auto Summary) 제어

RIP v1 vs RIP v2 비교:


| 특성 | RIP v1 | RIP v2 |
|---|---|---|
| 자동축약 | 강제 (비활성화 불가) | 선택적 (비활성화 가능) |
| 제어 명령어 | 없음 | no auto-summary |
| 광고 정보 | 메이저 네트워크만 | 세분화된 서브넷 가능 |

RIP v2 설정 예시:

router rip version 2 no auto-summary          ← 자동축약 기능 비활성화 network 20.20.20.0 network 40.40.40.0

### 3. RIP 버전 간 호환성 문제

#### 3-1. 버전 불일치로 인한 통신 실패

테스트 구성: C 라우터 (RIP v1) ↔ E 라우터 (RIP v2)


| 방향 | 송신 형식 | 수신 결과 | 설명 |
|---|---|---|---|
| C → E | v1 포맷 | 수신 불가 | E는 v2만 수신하므로 v1 패킷 거부 |
| E → C | v2 포맷 | 수신 가능 | C는 Any Version 수신하므로 v2 패킷<br>수락 |
| 결과 | - | 단방향만 통신 | 양방향 통신 불가로 경로 학습 실패 |

#### 3-2. 라우팅 테이블에서의 확인

C 라우터 (v1) 관점:

show ip route E로부터 받은 v2 패킷 정보로 40.0.0.0 경로 인식 (R 코드 표시)

E 라우터 (v2) 관점:

show ip route C로부터 v1 패킷 미수신으로 C의 경로 정보 부재 R 코드가 나타나지 않음 ⚠️ C 라우터의 v1 패킷을 E가 수신하지 않으므로, E는 C를 이웃 라우터로 인식하지 못한 다.

### 4. 다이나믹 라우팅 프로토콜 신뢰도 비교

#### 4-1. 라우팅 프로토콜별 코드 표기

show ip route  명령어에서 사용되는 프로토콜 코드:


| 코드 | 프로토콜명 | 경로 타입 |
|---|---|---|
| S | Static | 정적 라우팅 |
| R | RIP | RIP 프로토콜 |
| D | EIGRP | EIGRP 프로토콜 |
| O | OSPF | OSPF 프로토콜 |
| B | BGP | BGP 프로토콜 |

#### 4-2. Administrative Distance(AD) 신뢰도 등급

라우팅 프로토콜의 신뢰도를 수치로 나타낸 값 (낮을수록 신뢰도 높음):


| 프로토콜/경로 타입 | AD 값 | 신뢰도 평가 |
|---|---|---|
| Static Route | 1 | 가장 신뢰도 높음 |
| EIGRP Internal | 90 | 신뢰도 높음 |
| IGRP | 100 | 신뢰도 중간 |
| RIP v1, v2 | 120 | 신뢰도 낮음 |
| EIGRP External | 170 | 신뢰도 매우 낮음 |
| Unknown Protocol | 255 | 신뢰 불가 |

AD가 낮은 라우팅 프로토콜이 높은 것보다 우선 적용된다.

### 5. 라우팅 테이블 최적화와 성능

#### 5-1. 라우팅 테이블 크기의 성능 영향

문제 상황 분석:


| 라우팅 테이블 규모 | 경로 검색 시간 | 라우터 부하 | 영향도 |
|---|---|---|---|
| 100줄 | 빠름 | 낮음 | 기준값 |
| 1000줄 | 느림 | 높음 | 약 10배 느려짐 |
| 10000줄 | 매우 느림 | 매우 높음 | 라우터 응답성 급격히 하락 |

#### 5-2. RIP v2 자동축약 비활성화의 효과

효과:

세분화된 경로 정보 광고로 불필요한 중복 경로 제거 동일한 통신 성능 유지 시 테이블 크기 감소 라우터의 경로 검색 시간 단축 시스템 부하 감소

### 6. RIP의 한계와 EIGRP 필요성

#### 6-1. RIP 프로토콜의 근본적 한계


| 한계 사항 | 구체적 문제 | 영향 |
|---|---|---|
| 홉 카운트만 사용 | 회선 대역폭 무시 | 느린 회선이 우선될 수 있음 |
| 인터페이스 타입 미반영 | Gigabit과 Fast Ethernet 구분 없음 | 부정확한 경로 선택 |
| 최대 15홉 제한 | 16홉 이상 경로 불가능 | 대규모 네트워크 확장성 제한 |
| 높은 대역폭 오버헤드 | 주기적으로 전체 라우팅 테이블 전송 | 네트워크 트래픽 증가 |

#### 6-2. EIGRP 도입의 필요성

RIP의 단순성을 극복하기 위해 EIGRP 또는 OSPF 같은 고급 라우팅 프로토콜 필요:

EIGRP의 개선 사항:

- IGRP의 Enhanced(개선) 버전 - 회선 속도, 지연, 신뢰성 등 다중 메트릭 반영 - 대규모 네트워크 환경 지원 - 네트워크 변화에 빠른 수렴 - AD 90으로 RIP보다 높은 신뢰도

## 017. RIP 설정과 동적 라우팅의 기초

### 1. RIP 다이나믹 라우팅 프로토콜 개요

#### 1-1. RIP(Routing Information Protocol)의 정의와 역할

정적 라우팅 설정을 모두 삭제한 후, 다이나믹 라우팅 프로토콜인 RIP을 사용하여 라우터 간 자동 경로 학습을 구성한다. RIP은 각 라우터가 자신의 직접 연결 네트워크 정보를 이웃 라우터에게 주기적으로 광고하여 전체 네트워크 경로를 동적으로 구성한다.

#### 1-2. 정적 라우팅 삭제 후 라우팅 테이블 상태


| 네트워크 대역 | 상태 표시 | 설명 |
|---|---|---|
| 10.0.0.0, 30.0.0.0, 100.0.0.0 | C (Connected) | 직접 연결된 네트워크만 인식 |
| 150.0.0.0, 200.0.0.0 | 미표시 | 경로 정보 부재로 통신 불가 |

경로 정보가 없으면 해당 네트워크로의 Ping 통신은 실패하며, 패킷이 목적지에 도달할 수 없다.

### 2. RIP 라우팅 프로토콜 설정

#### 2-1. RIP 설정 모드 진입

router rip          ← RIP 라우팅 프로토콜 설정 모드 진입 router ?  명령어로 사용 가능한 다이나믹 라우팅 프로토콜 확인:

router ? bgp          Border Gateway Protocol (BGP)

eigrp        EIGRP ospf         Open Shortest Path First (OSPF)

rip          Routing Information Protocol

#### 2-2. RIP 설정 모드의 주요 명령어

RIP 설정 모드에서 ?  명령어 입력 시 사용 가능한 명령어:


| 명령어 | 기능 설명 |
|---|---|
| network | 광고할 네트워크 대역 지정 |
| version | RIP 버전 선택 (1 또는 2) |
| auto-summary | 자동축약 설정 (RIP v2 관련) |
| distance | Administrative Distance 설정 |
| redistribute | 다른 라우팅 프로토콜 경로 재배포 |
| timer | 타이머 값 조정 (Hello Time, Update 등) |

### 3. 라우터별 네트워크 광고 설정

#### 3-1. 광고 대상 네트워크 선정 기준

show ip route  명령어에서 C (Connected) 코드로 표시된 직접 연결 네트워크만 광고한다. 이는 각 라우터가 자신에게 직접 연결된 인터페이스의 네트워크만 신뢰할 수 있기 때문이다.

#### 3-2. 라우터별 설정 구성

라우터 A 설정:

router rip version 1 network 10.10.10.0 network 30.30.30.0 network 192.168.100.0 라우터 B 설정:

router rip version 1 network 10.10.10.0 network 20.20.20.0 network 30.30.30.0 network 192.168.150.0 라우터 C 설정:

router rip version 1 network 20.20.20.0 network 192.168.200.0

### 4. RIP 설정 결과 확인

#### 4-1. 라우팅 테이블 조회

show ip route 라우팅 테이블의 코드 표기:


| 코드 | 의미 | 설명 |
|---|---|---|
| C | Connected | 직접 연결된 네트워크 |
| R | RIP | RIP으로 학습된 경로 |

#### 4-2. 최적 경로 결정 기준: 홉 카운트(Hop Count)

RIP은 목적지까지 거쳐가는 라우터 장비 개수를 유일한 메트릭으로 사용한다:

직접 연결: 비용 1 한 라우터 거침: 비용 2 두 라우터 거침: 비용 3

#### 4-3. 라우팅 테이블의 메트릭 값 해석


| 항목 | 값 | 의미 |
|---|---|---|
| AD (Administrative<br>Distance) | 120 | RIP의 신뢰도 (프로토콜별 신뢰도 비교 시 낮을<br>수록 우선) |
| 메트릭 (Cost) | 1~15 | 홉 카운트 값 |

경로 예시:

150.0.0.0 목적지: AD 120 [1] ← 비용 1 (한 라우터 거침)

200.0.0.0 목적지: AD 120 [2] ← 비용 2 (두 라우터 거침)

대역폭이 높아도 홉 수가 많으면 낮은 홉의 경로를 선택하므로 회선 속도를 반영하지 못한 다.

### 5. RIP의 한계와 제약사항

#### 5-1. 메트릭의 단순성으로 인한 비효율


| 문제점 | 영향 |
|---|---|
| 회선 속도 미반영 | Gigabit과 저속 회선(1.544Mbps) 구분 불가 |
| 인터페이스 타입 무시 | Fast Ethernet과 Gigabit 속도 차이 무시 |
| 대규모 네트워크 비효율 | 라우터 수 증가 시 성능 저하 |

구체적 예:

경로 1: 저속 회선(1.544Mbps) 2홉 → RIP은 비용 2로 선택 경로 2: 고속 회선(Gigabit) 3홉 → RIP은 비용 3으로 배제 실제 성능: 경로 2가 훨씬 빠르지만 RIP은 인식 불가

#### 5-2. 홉 카운트 제한

최대 15홉 제한 15홉까지만 경로 인식 가능 16홉 이상: 도달 불가능한 네트워크로 간주 대규모 네트워크 확장성 제한

### 6. RIP 설정 통신 검증

#### 6-1. Ping 통신 테스트

ping 192.168.200.10 정상 응답 패턴:


| 순서 | 상태 | 설명 |
|---|---|---|
| 첫 번째 ping | . (타임아웃) | 정상 (첫 ping에서 ARP 학습 시간) |
| 이후 ping | ! (응답 성공) | 완전 정상 상태 |

## 018. 라우터 기본 설정 - 라우터 간 시리얼 연결, IP 주소 설정, 다중 인터페이스 구성

연결, IP 주소 설정, 다중 인터페이스 구성

### 1. 라우터 간 연결 기본

#### 1-1. 라우터 연결 방식

라우터를 연결할 때 선택할 수 있는 방식:


| 항목 | 설명 |
|---|---|
| DC 선택 | Data Circuit 방식, 어느 것을 선택해도 상관없음 |
| DT 선택 | Data Transmission 방식, 어느 것을 선택해도 상관없<br>음 |

두 개 중 하나를 선택한 후 원하는 라우터와 시리얼(Serial) 인터페이스에 연결한다.

#### 1-2. 시리얼 인터페이스 추가 (모듈 설치)

시리얼 인터페이스를 장비에 설치하기 위한 순서:

### 1. 전원 종료 ← 장비의 전원을 완전히 끔

### 2. 모듈 설치 ← Physical 섹션에서 비어있는 슬롯에 모듈 삽입

### 3. 전원 재시작 ← 전원을 다시 켬

모듈을 설치한 후 전원을 다시 시작해야 인터페이스가 인식된다.

### 2. 라우터 기본 설정

#### 2-1. 포트 라벨 표시 설정

포트 이름이 보이지 않을 경우 다음과 같이 설정한다.

설정 경로:

Option → Preference → Always show port labels 체크 라벨 표시 옵션:


| 항목 | 설정 |
|---|---|
| 장비 이름 표시 | 체크 해제 (불필요) |
| 모델 이름 표시 | 체크 해제 (복잡함) |
| 포트 라벨 표시 | 체크 (필수) |

#### 2-2. 포트 표시의 중요성

포트 표시 옵션 설정으로 다음이 가능하다.

현재 어떤 장비인지 명확히 파악 가능 어떻게 연결되어 있는지 시각적으로 확인 가능 여러 라우터 간의 연결 구조 파악 용이

### 3. IP 주소 설정

#### 3-1. 설정의 기본 원칙

모든 네트워크 장비 설정에서 첫 번째 단계는 IP 주소 설정이다.

#### 3-2. 설정 명령어 구조

configure terminal ← 설정 모드 진입 interface [인터페이스명] ← 특정 인터페이스 선택 ip address [IP주소] [서브넷마스크] ← IP 주소와 서브넷마스크 설정 no shutdown ← 해당 인터페이스 활성화 exit ← 현재 모드 종료

#### 3-3. 라우터 간 연결 인터페이스 설정 예시

A 라우터와 연결된 B 라우터의 시리얼 인터페이스:

configure terminal interface serial 0/3/0 ip address 10.10.10.20 255.255.255.0 no shutdown exit


| 항목 | 값 |
|---|---|
| 인터페이스 | serial 0/3/0 (A 라우터와의 연결 인터페이<br>스) |
| IP 주소 | 10.10.10.20 |
| 서브넷마스크 | 255.255.255.0 (/24) |

#### 3-4. 링크 상태 확인

설정 완료 후:


| 항목 | 설명 |
|---|---|
| 링크 상태 | 초록색 링크 표시 (정상 연결) |
| 메시지 | "업(Up)"으로 설정 완료 표시 |
| 통신 준비 | 링크 상태 확인 후 통신 가능 |

### 4. 다중 인터페이스 설정

#### 4-1. 라우터의 다중 인터페이스 구성

라우터에서 일반적으로 다음과 같은 여러 인터페이스 설정이 필요하다.


| 인터페이스 | 용도 | 타입 |
|---|---|---|
| 인터페이스 1 | 다른 라우터와의 연결 | Serial |
| 인터페이스 2 | 또 다른 라우터와의 연결 | Serial |
| 인터페이스 3 | 내부 네트워크 게이트웨이 | GigabitEthernet |

#### 4-2. 각 인터페이스별 설정 순서

각 인터페이스마다 동일한 절차로 설정한다.

configure terminal interface [해당 인터페이스명] ip address [해당 IP] [해당 서브넷마스크]

no shutdown exit

#### 4-3. 내부 네트워크 게이트웨이 설정 예시

GigabitEthernet 인터페이스 (내부 게이트웨이):

configure terminal interface gi 0/0 ip address 192.168.150.254 255.255.255.0 no shutdown exit


| 항목 | 값 |
|---|---|
| 인터페이스 | GigabitEthernet 0/0 |
| IP 주소 | 192.168.150.254 |
| 서브넷마스크 | 255.255.255.0 (/24) |
| 역할 | 내부 네트워크의 기본 게이트웨이 |

#### 4-4. 라우터 호스트명 설정

각 라우터를 구분하기 위해 호스트명을 설정한다.

configure terminal hostname [라우터명] ← 라우터 이름 설정 exit 호스트명 예시:

R-A (A 라우터)

R-B (B 라우터)

R-C (C 라우터)

### 5. 네트워크 주소 대역 관리

#### 5-1. 네트워크 간 주소 대역 분리

다중 라우터 구성에서는 각 네트워크에 다른 주소 대역을 할당한다.


| 네트워크 | IP 대역 | 용도 |
|---|---|---|
| 라우터 A-B 간 | 10.10.10.0/24 | 라우터 간 시리얼 연결 |
| 라우터 B-C 간 | 20.20.20.0/24 | 라우터 간 시리얼 연결 |


| 네트워크 | IP 대역 | 용도 |
|---|---|---|
| 라우터 A 내부 | 192.168.100.0/24 | A 라우터 네트워크 |
| 라우터 B 내부 | 192.168.150.0/24 | B 라우터 네트워크 |
| 라우터 C 내부 | 192.168.200.0/24 | C 라우터 네트워크 |

#### 5-2. 주소 대역 분리의 필요성

같은 네트워크 내에서 중복된 주소 대역을 사용하면 주소 충돌(overlap)이 발생한다.

## 019. 라우팅의 개념과 스태틱 다이나믹 라우팅

라우팅의 개념과 스태틱/다이나믹 라우팅

### 1. 라우팅(Routing) 개념

#### 1-1. 라우팅의 정의

라우팅은 데이터가 출발지에서 목적지까지 도달할 수 있도록 경로를 설정하는 프로세스이 다.

#### 1-2. 라우팅의 필요성

라우팅이 없는 경우:

경로 부재: 다른 네트워크 간의 통신 불가능 통신 단절: 인터넷 접속 및 다른 곳으로의 접속 불가능 라우팅이 설정된 경우:

서로 다른 네트워크 간의 데이터 이동 가능 인터넷을 통한 원격 접속 실현

#### 1-3. 라우팅 프로토콜의 분류

라우팅 방식은 두 가지 주요 유형으로 나뉜다.


| 유형 | 스태틱(Static) | 다이나믹(Dynamic) |
|---|---|---|
| 정의 | 관리자가 직접 경로를 설정 | 프로토콜이 자동으로 경로 학습 |
| 특징 | 수동 경로 입력 | 자동 경로 설정 |
| 알고리즘 | 작동하지 않음 | 프로토콜 알고리즘 작동 |
| 자원 소비 | 최소화 | 프로토콜 오버헤드 발생 |
| 경로 결정 | 고정적 | 프로토콜 기준에 따른 최적 경로 |

#### 1-4. 스태틱 라우팅의 특징

스태틱(Static) 라우팅은 관리자가 직접 경로를 설정하는 방식이다.

라우팅의 개념과 스태틱/다이나믹 라우팅


| 특징 | 설명 |
|---|---|
| 정의 | 관리자가 직접 라우팅 경로를 입력 |
| 수동 설정 | 경로를 명시적으로 지정 |
| 알고리즘 미적용 | 라우팅 프로토콜의 알고리즘이 작동하지 않음 |
| 자원 효율성 | 라우터 자원 소비 최소화 |
| 경로 계산 불필요 | 미리 정해진 경로만 사용 |

#### 1-5. 다이나믹 라우팅의 특징

다이나믹(Dynamic) 라우팅은 라우팅 프로토콜을 사용하여 자동으로 경로를 학습하는 방식이다.


| 특징 | 설명 |
|---|---|
| 자동 경로 학습 | 프로토콜이 경로를 자동으로 설정 |
| 프로토콜 지정 | 관리자는 프로토콜만 지정 |
| 최적 경로 결정 | 각 프로토콜의 기준에 따라 최적 경로 결정 |
| 프로토콜 오버헤드 | 라우팅 프로토콜 작동으로 인한 자원 소비 |

#### 1-6. 라우팅 프로토콜 주요 요소

라우팅 프로토콜 관련 주요 개념들:


| 요소 | 설명 |
|---|---|
| RIP(Routing Information Protocol) | 거리와 방향 기반 프로토콜 |
| Distance Factor | 거리와 방향을 나타내는 지표 |
| Classful/Classless | 주소 분류 방식 |
| 확장성 | 네트워크 확장 가능성 |

각 프로토콜의 실제 동작 방식은 실습을 통해 확인할 수 있다.

## 020. 스태틱 라우팅 설정 - 라우팅 테이블, 경로 지정, 네트워크 통신 검증

경로 지정, 네트워크 통신 검증

### 1. 라우팅 테이블 분석

#### 1-1. 라우팅 테이블의 개념

*라우팅 테이블(Routing Table)**은 각 네트워크 주소에 대한 경로 정보를 저장하는 테이블이다.

#### 1-2. 주소 표기법 분석

CIDR 표기법의 의미


| 표기 | 의미 | 설명 |
|---|---|---|
| /32 | 32비트 일치 | 자기 자신(단일 호스트) |
| /24 | 24비트 일치 | 네트워크 주소 |
| /16 | 16비트 일치 | 더 큰 네트워크 |

/32 표기의 의미 /32 = 32비트가 일치하는 주소 = 자기 자신 특징:


| 항목 | 설명 |
|---|---|
| 32비트 전체 일치 | 개별 호스트 주소 |
| 단일 IP | 네트워크 주소가 아닌 단일 호스트 |
| 로컬(Local) 표시 | 로컬 인터페이스를 나타냄 |

/24 표기와의 비교


| 표기 | 일치 범위 | 타입 |
|---|---|---|
| /24 | 24비트 일치 | 네트워크 주소 |
| /32 | 32비트 일치 | 단일 호스트 |

예시:

/24 : 192.168.100.0/24 (192.168.100.0 ~ 192.168.100.255)

/32 : 192.168.100.1/32 (192.168.100.1 하나만)

### 2. 스태틱 라우팅(Static Routing)

#### 2-1. 스태틱 라우팅의 기본

정의: 관리자가 직접 라우팅 경로를 설정하는 방식이다.

#### 2-2. 라우팅 경로 설정 명령어

configure terminal ← 설정 모드 진입 ip route [목적지네트워크] [서브넷마스크] [경유지] ← 경로 설정 exit ← 설정 모드 종료 설정 예시:

ip route 192.168.100.0 255.255.255.0 10.10.10.10 ← 192.168.100.0/24 네트워크로는 10.10.10.10으로 보낸다

#### 2-3. 라우팅 설정의 핵심 개념

목적지 네트워크 지정


| 항목 | 설명 |
|---|---|
| 네트워크 주소 사용 | 개별 호스트가 아닌 전체 네트워크 주소 |
| 예시 | 192.168.100.0 (192.168.100.0/24 대역 모든 호스트 포함) |
| 포함 범위 | 192.168.100.1 ~ 192.168.100.254 |

경유지(Next Hop) 지정 경유지의 정의: 목적지로 가기 위해 패킷을 보낼 다음 장비의 IP 주소 설정 원칙:

목적지 방향으로의 다음 장비 = 경유지로 지정 최종 목적지의 IP를 경유지로 지정하면 안 된다. 바로 연결된 다음 라우터의 IP를 경유지로 지정해야 한다.

올바른 설정 예:


| 상황 | 경유지 | 이유 |
|---|---|---|
| A → B → C | B의 IP | B가 다음 장비이므로 |
| B에서 C로 | C의 IP | C가 다음 장비이므로 |

#### 2-4. 라우팅 과정의 이해

패킷의 이동 흐름:

출발지 라우터 ↓ 자신의 라우팅 테이블 확인 ↓ 경유지로 패킷 전송 ↓ 다음 라우터에서 다시 자신의 라우팅 테이블 확인 ↓ 경유지로 패킷 전송 ↓ (반복...)

↓ 목적지 도달 핵심 원칙:


| 항목 | 설명 |
|---|---|
| 각 라우터의 책임 | 다음 장비까지만 관심 |
| 다음 일의 책임 | 다음 라우터가 담당 |
| 경로 설정 | 모든 라우터에서 정확해야 함 |

#### 2-5. 라우팅 설정 실패의 예

경로가 중간에 끊긴 경우:

상황: A → B → C 경로에서 B 라우터가 경로를 모를 때 A 라우터: C로 가려면 B로 보낸다 (정상)

B 라우터: C로 가는 경로를 모른다 (문제!)

결과: C로 도달 불가 결론: 모든 라우터에서 정확한 경로 설정이 필수이다.

### 3. 라우팅 테이블 확인

#### 3-1. 라우팅 테이블 조회 명령어

show ip route ← 현재 라우팅 테이블 표시

#### 3-2. 라우팅 테이블 읽기

라우팅 테이블 출력 예:

S 192.168.100.0/24 [1/0] via 10.10.10.10 항목별 의미:


| 항목 | 의미 | 설명 |
|---|---|---|
| S | Static | 스태틱 라우팅 |
| 192.168.100.0/24 | 목적지 네트워크 | 가는 네트워크 대역 |
| [1/0] | 신뢰도/메트릭 | 경로 우선순위 |
| via 10.10.10.10 | 경유지 주소 | 다음 장비의 IP |

#### 3-3. 새 경로 추가 확인

라우팅 설정 후 show ip route 로 확인:

이전에 없던 네트워크가 추가됨 S (Static) 표시로 스태틱 경로 확인 가능 경유지 정보로 경로 설정 검증

### 4. 스태틱 라우팅의 사용 사례

#### 4-1. 스태틱 라우팅 사용 시점

단일 경로(Single Path) 구조 예시: 게임방 → KT 인터넷 장비 특징:


| 항목 | 설명 |
|---|---|
| 갈 수 있는 경로 | 오직 하나 |
| 패킷 이동 | 모든 패킷이 같은 곳으로만 나감 |
| 다른 경로 | 상대방 장비에서 관리 |

적용 사례:

소규모 게임방 중소 규모 사무실 건물 전용선 서비스 받는 소규모 네트워크

#### 4-2. 스태틱 라우팅의 장점

자원 효율성:


| 항목 | 효과 |
|---|---|
| 라우팅 계산 | 알고리즘 미실행 |
| 라우터 부하 | 최소화 |
| 시스템 자원 | 절약 |

성능:

경로가 이미 정해짐 빠른 전달 예측 가능한 성능

#### 4-3. 스태틱 라우팅의 단점

확장성 부족:


| 문제 | 설명 |
|---|---|
| 경로 설정 | 네트워크가 많으면 일일이 설정 필요 |


| 문제 | 설명 |
|---|---|
| 오류 영향 | 경로 오류 시 라우팅 전체 손상 가능 |
| 관리 복잡성 | 관리 난이도 증가 |

네트워크가 많으면 관리자가 일일이 경로를 설정하기 어렵다.

### 5. 다이나믹 라우팅의 필요성

#### 5-1. 스태틱 vs 다이나믹 선택 기준


| 특성 | 스태틱 | 다이나믹 |
|---|---|---|
| 경로 설정 | 수동 | 자동 |
| 적용 규모 | 소규모 | 중·대규모 |
| 리소스 소비 | 낮음 | 높음 |
| 설정 복잡도 | 낮음 | 높음 |
| 확장성 | 낮음 | 높음 |

#### 5-2. 다이나믹 라우팅 사용 시점

대규모 네트워크 구조:


| 네트워크 | 특징 |
|---|---|
| 대학교 캠퍼스 네트워크 | 다수의 건물, 많은 라우터 |
| 기업 전체 네트워크 | 여러 부서, 복잡한 구조 |
| 다수 라우터 존재 | 경로 설정이 복잡함 |

사용 이유:

라우터 개수가 많으면 스태틱으로 일일이 설정 불가능 자동 경로 학습으로 효율성 극대화 네트워크 변화에 자동 대응

### 6. 네트워크 통신 검증

#### 6-1. 핑(Ping) 테스트

ping [목적지IP주소] ← 목적지 주소로 핑 전송 핑의 목적:

네트워크 경로 확인 목적지 도달 가능 여부 확인 라우팅 경로 검증

#### 6-2. 통신 성공 조건

2개 라우터 간 통신 (A ↔ B)

A 라우터 하위 PC → B 라우터 하위 PC 필요 경로 설정:


| 라우터 | 설정 필요 사항 |
|---|---|
| A 라우터 | B 네트워크로의 경로 설정 |
| B 라우터 | A 네트워크로의 경로 설정 |

3개 라우터 간 통신 (A ↔ B ↔ C)

추가 경로 설정:


| 라우터 | 설정 필요 사항 |
|---|---|
| A 라우터 | C 네트워크로의 경로 설정 |
| B 라우터 | C 네트워크로의 경로 설정 (중간 라우터 역할) |
| C 라우터 | A, B 네트워크로의 경로 설정 |

#### 6-3. 첫 번째 패킷 손실(Loss)

현상: 첫 번째 핑은 실패, 이후는 성공 원인: ARP(Address Resolution Protocol) 요청


| 단계 | 설명 |
|---|---|
| 1차 통신 | MAC 주소를 모르므로 ARP 요청 소요 |
| 이후 통신 | 캐시에 저장되어 정상 통신 |

첫 번째 패킷이 손실되는 것은 정상이다. ARP 요청을 위해 시간이 필요하기 때문이다.

### 7. 라우팅 설정의 중요성

#### 7-1. 통신 가능의 필수 조건

통신이 성공하려면 다음 모든 조건이 만족되어야 한다.


| 조건 | 내용 |
|---|---|
| 주소 설정 정확성 | IP 주소와 서브넷마스크 정확 |
| 경로 설정 정확성 | 모든 라우터에서 올바른 경로 설정 |
| 인터페이스 활성화 | no shutdown 설정 |

하나라도 틀리면 통신이 불가능하다.

#### 7-2. 설정 오류 확인 방법

주소 설정 오류 확인:

show running-config ← 현재 실행 중인 설정 전체 표시 확인 사항:

각 인터페이스의 IP 주소 확인 서브넷마스크 정확성 확인 no shutdown 설정 여부 확인

#### 7-3. 경로 설정 확인 방법

경로 설정 확인:

show ip route ← 라우팅 테이블 표시 확인 사항:

목적지 네트워크가 테이블에 추가되었는지 확인 경유지 주소가 정확한지 확인 Static(S) 표시로 스태틱 경로 확인
