# 핵심키워드 · 리눅스 서버 (1/2)

## 038. Rocky Linux IP 주소 수동 설정 및 원격 접속 도구(PuTTY) 소개

### 1. 브릿지 모드에서 IP 자동/수동 할당

#### 1-1. IP 자동 할당이 이루어지는 경우

VirtualBox의 브릿지 모드를 적용하면, VM이 호스트 컴퓨터의 네트워크 정보를 가져와 연 결하므로 대부분 IP가 자동으로 할당된다.

#### 1-2. IP 자동 할당이 이루어지지 않는 경우

다음 상황에서는 IP가 자동으로 할당되지 않을 수 있다.


| 원인 | 설명 |
|---|---|
| 호스트 IP 수동 설정 | 호스트 컴퓨터가 IP를 수동(정적)으로 설정한 경우 |
| 브릿지 연결 문제 | 호스트로부터 주소 정보를 브릿지로 전달받지 못하는 경우 |

이 경우 VM 안에서 IP 주소를 수동으로 설정해야 한다.

### 2. 리눅스 IP 주소 수동 설정 — NMTUI

#### 2-1. 네트워크 매니저(Network Manager) 사용 권장

Rocky Linux 9부터는 네트워크 설정 파일을 직접 편집하는 방식을 권장하지 않는다. 대신 **네트워크 매니저(NM, Network Manager)**를 통한 설정을 권장한다.

네트워크 매니저를 통한 설정 방법은 두 가지이다.


| 명령어 | 설명 |
|---|---|
| nmtui | 텍스트 기반 메뉴 UI (방향키·스페이스바로 설정) |
| nmcli | 명령어 기반 설정 |

예전에는 /etc/network/scripts/  하위의 인터페이스 설정 파일(ifcfg-인터페이스명)을 직접 편집하는 방식을 사용했으나, Rocky Linux 9부터는 이 방식을 권장하지 않는다.

#### 2-2. 수동 IP 설정 시 입력 항목

VM에 수동으로 IP를 설정할 때 필요한 정보는 호스트 컴퓨터의 네트워크 정보를 기준으로한다.


| 항목 | 설명 |
|---|---|
| IP 주소 | 범위 내에서 사용 중이지 않은 주소 선택 |
| 서브넷 마스크 | 호스트 컴퓨터와 동일하게 설정 |
| 게이트웨이 | 호스트 컴퓨터와 동일하게 설정 |
| DNS 서버 | 호스트 컴퓨터와 동일하게 설정 |

⚠️ IP 주소를 제외한 서브넷 마스크, 게이트웨이, DNS 서버는 호스트 컴퓨터의 값과 동일하게 설정해야 한다. 임의로 변경하면 인터넷 연결이 되지 않는다.

#### 2-3. 사용 가능한 IP 주소 확인 방법

VM에 할당할 IP 주소가 이미 사용 중인지 확인하려면 윈도우 명령 프롬프트에서 ping을 사용한다.

```
ping [할당하고자 하는 IP]
```

응답이 없으면(Request Timeout) → 사용 중이지 않으므로 할당 가능

응답이 오면(Reply from) → 이미 사용 중이므로 다른 IP 선택

⚠️ 동일 네트워크에서 같은 IP를 두 장비에 할당하면 IP 충돌이 발생한다. 반드시 사용 중이지 않은 주소를 확인하고 할당해야 한다.

#### 2-4. 호스트 컴퓨터 네트워크 정보 확인

호스트(윈도우) 컴퓨터의 IP, 서브넷, 게이트웨이, DNS 확인 방법:

```
ipconfig /all
```

ipconfig 만 입력하면 기본 정보만 표시되고, /all  옵션을 추가하면 DNS 서버 주소까지 포함한 전체 정보를 확인할 수 있다.

### 3. IP 설정 완료 후 확인

설정이 완료되면 리눅스 터미널에서 다음 명령으로 적용된 IP 주소를 확인한다.

```
ip address    ← 인터페이스별 IP 주소 확인
```

이후 인터넷 연결 여부를 확인한다.

```
ping 8.8.8.8       ← 외부 IP로 통신 테스트
ping www.google.com ← 도메인 이름으로 통신 테스트
```

확인 후 Ctrl + C 로 ping을 중지한다.

### 4. 원격 접속 도구 — PuTTY

#### 4-1. PuTTY란

PuTTY는 무료 원격 접속 도구로, Telnet·SSH 등을 통해 원격 장비에 접속할 때 사용한다.


| 특성 | 내용 |
|---|---|
| 비용 | 무료 |
| 용도 | Telnet, SSH 원격 접속 |
| 장점 | 용량이 적고 다양한 접속 환경 지원 |

#### 4-2. PuTTY를 사용하는 이유

VirtualBox VM 화면 내에서 직접 작업할 경우 글자 크기 조절 등이 불편하다. PuTTY로 원격 접속하면 글자 크기, 색상 등을 자유롭게 설정하여 편리하게 작업할 수 있다.

Rocky Linux 설치 시 root 사용자의 SSH 원격 접속 허용 옵션을 체크해야 PuTTY로 root 계정 접속이 가능하다.

### 5. VM 서버 구축을 위한 전제 조건

VM을 서버로 활용하려면 인터넷 연결이 가능한 상태여야 한다. 이는 서버 구축에 필요한 패키지를 인터넷으로 내려받아야 하기 때문이다.


| 조건 | 내용 |
|---|---|
| IP 주소 설정 완료 | 자동 또는 수동으로 IP 할당 |
| 인터넷 연결 확인 | 외부 IP로 ping 응답 확인 |

## 039. Rocky Linux 로그인 및 기본 명령어 사용

### 1. Rocky Linux 설치 완료 후 초기 접속

#### 1-1. 계정 체계

Rocky Linux 설치 완료 후 사용할 수 있는 기본 계정은 root 계정이다.


| 계정명 | 특성 |
|---|---|
| root | 최고 관리자 계정. 시스템의 모든 권한 보유 |
| 일반 사용자 | 별도 추가 가능. 권한 제한됨 |

로그인 시 비밀번호를 입력해도 화면에 아무것도 표시되지 않는다(별표 등 없음). 이는 정상 동작이며, 보안을 위한 리눅스의 기본 특성이다.

#### 1-2. 미니멀 버전의 인터페이스

미니멀(Minimal) 버전은 그래픽(GUI)이 제외된 버전이다. 따라서 마우스 포인터가 화면에 표시되지 않으며, 모든 작업은 키보드로 입력하는 명령어(CLI) 방식으로 수행된다.

### 2. 리눅스 기본 명령어

#### 2-1. IP 주소 확인 명령어


| 운영체제 | 명령어 |
|---|---|
| Windows | ipconfig |
| Linux | ip address |

```
ip address    ← 현재 네트워크 인터페이스 및 IP 주소 확인
```

ifconfig  명령어는 구형 리눅스에서 사용하던 명령어이다. 최신 버전에서는 ip address 를 사용한다.

#### 2-2. 통신 테스트 명령어

Windows와 동일하게 ping  명령어를 사용한다.

```
ping 8.8.8.8          ← 특정 IP로 통신 테스트
ping www.google.com   ← 도메인 이름으로 통신 테스트
```

⚠️ 리눅스에서 ping은 관리자가 중지하지 않으면 계속 실행된다. 중지하려면 Ctrl + C를 누른다.

#### 2-3. 명령어 확인(쇼) 방식 비교


| 장비·OS | 설정 내용 확인 명령어 |
|---|---|
| 시스코 라우터 | show run |
| 리눅스 | 각 항목별 명령어 사용 ( ip address , ping 등) |

### 3. 리눅스 명령어 학습 방법

리눅스에는 매우 많은 명령어와 옵션이 있다. 이를 모두 암기하는 것은 불필요하다.


| 학습 방법 | 내용 |
|---|---|
| 반복 사용 | 자주 사용하는 명령어는 자연스럽게 익혀진다 |
| 도움말(Help) 활용 | 명령어 사용법이나 옵션을 모를 경우 도움말로 확인 |
| 필요할 때 찾아보기 | 새로운 명령어나 옵션은 그때그때 검색·확인 |

라우터 명령어를 처음에는 외우려고 했지만, 반복하다 보면 자연스럽게 익혀지는 것과 동일하다. 리눅스 명령어도 같은 방식으로 습득하면 된다.

### 4. VirtualBox 네트워크 모드 — 브릿지(Bridge)

#### 4-1. 브릿지 모드란

VirtualBox VM의 네트워크 설정에서 브릿지(Bridge) 모드를 선택하면, VM이 호스트 컴퓨터와 동일한 네트워크에 연결된다. 즉, 호스트 컴퓨터가 사용하는 네트워크 대역에서 VM도 독립적인 IP를 할당받아 사용한다.


| 브릿지 모드 결과 | 내용 |
|---|---|
| VM의 네트워크 대역 | 호스트 OS와 동일한 네트워크 대역 |


| 브릿지 모드 결과 | 내용 |
|---|---|
| IP 할당 방식 | 자동(DHCP) 또는 수동(정적) |
| 외부 인터넷 접속 | 가능 |
| 호스트와의 통신 | 가능 |

#### 4-2. 브릿지 모드에서 IP 자동 할당이 안 될 경우

호스트 컴퓨터의 네트워크 설정이 **수동(정적)**으로 되어 있는 경우, VM에 IP가 자동으로 할당되지 않을 수 있다. 이 경우 VM에서 수동으로 IP를 설정해야 한다.

브릿지 모드가 정상 동작하면 ip address  명령 결과에 IPv4 형식의 주소가 표시된다.

### 5. VM 내 마우스 사용 관련

미니멀 버전은 그래픽이 없어 마우스 포인터가 VM 화면 내에 표시되지 않는다.


| 상황 | 방법 |
|---|---|
| VM 내부에서 작업 | VM 창 위쪽 영역 클릭 후 키보드 입력 |
| VM 밖으로 나오기 | 설정한 호스트 키(단축키) 누름 |
| VM 안으로 들어가기 | VM 창 클릭 |

## 040. VirtualBox 가상 머신 생성 및 Rocky Linux 설치

### 1. 가상 머신 생성 절차

VirtualBox에서 새 가상 머신을 생성할 때 설정하는 항목은 다음과 같다.

#### 1-1. VM 생성 시 주요 설정 항목


| 항목 | 내용 |
|---|---|
| VM 이름 | 관리자가 원하는 이름으로 지정. 동일한 이름의 VM이 이미 존재하면 생성 불가 |
| VM 저장 위치 | 지정된 디렉토리 하위에 VM 이름의 폴더가 생성되고, VM 관련 파일이 저장됨 |
| ISO 이미지 | 설치에 사용할 운영체제 이미지 파일 선택 |
| 운영체제 종류 | Linux → Red Hat(64-bit) 선택 |
| 하드디스크 크기 | 미니멀 버전 기준 10GB 권장 (20GB 불필요) |
| CPU | 기본값 유지 가능 |
| 메모리 | 1024MB(1GB) 권장 |

⚠️ ISO 이미지를 VM 생성 시 바로 지정하면 자동으로 설치가 시작된다. 설정을 먼저 완료한 후 이미지를 연결하는 것이 관리에 유리하다.

#### 1-2. 호스트 OS와 게스트 OS 구분


| 구분 | 설명 |
|---|---|
| 호스트 OS | 현재 실제로 사용 중인 운영체제 (예: Windows 64-bit) |
| 게스트 OS | VirtualBox 안에 설치되는 운영체제 (예: Rocky Linux) |

호스트가 64비트이므로 게스트 운영체제도 64비트로 설정하면 된다.

### 2. VM 설정 변경

VM 생성 후 설정 항목을 변경해야 할 경우, VirtualBox 내 해당 VM을 선택하고 설정 (Settings) 메뉴를 통해 수정할 수 있다. 단, 하드디스크 크기는 생성 후 변경이 어려우므로

처음에 적절하게 설정해야 한다.

### 3. 시스템 탭 — 부팅 순서 설정

VM 설정에서 시스템(System) 탭의 부팅 디바이스 순서를 확인·조정한다.


| 설정 내용 | 권장 사항 |
|---|---|
| 플로피 디스크 | 체크 해제 (사용하지 않음) |
| 하드 디스크 | 1순위로 설정 |

플로피 디스크는 현재 사용하지 않으므로 부팅 순서에서 제외한다.

### 4. 리눅스 배포판 분류

VirtualBox 운영체제 선택 항목에서 확인할 수 있듯이 리눅스에는 다양한 배포판이 존재한다.


| 계열 | 주요 배포판 |
|---|---|
| 레드햇(Red Hat) 계열 | Rocky Linux, CentOS(구), Oracle Linux, Fedora 등 |
| 데비안(Debian) 계열 | Ubuntu, Debian 등 |
| 기타 | Gentoo, Mandriva 등 |

Rocky Linux는 레드햇(Red Hat) 계열이다. 레드햇 계열이 가장 널리 사용되며, 리눅스 마스터 자격증의 명령어 출제 기준도 레드햇 계열을 기반으로 한다.

CentOS는 과거 레드햇 계열의 대표 배포판이었으나, 라이선스 변경으로 인해 현재는 잘 사용하지 않는다.

### 5. Rocky Linux 미니멀 버전의 특성

미니멀(Minimal) 버전은 최소 구성 버전이다.


| 특성 | 내용 |
|---|---|
| 그래픽(GUI) | 없음 |
| 운용 방식 | 명령어(CLI) 기반 |
| 용량 | 적음 |
| 설치 시간 | DVD 버전보다 빠름 |

그래픽이 없기 때문에 마우스 포인터가 표시되지 않으며, 모든 작업은 키보드 명령어로 수행한다.

### 6. VirtualBox 호스트 키(Host Key) 설정

호스트 키는 VirtualBox VM 창 내부와 외부(호스트 OS) 사이에서 마우스·키보드 제어를 전환할 때 사용하는 단축키이다.


| 구분 | 설명 |
|---|---|
| 호스트 키 | 파일 → 환경설정 → 익스퍼트 → 입력 → 가상 머신 탭에서 설정 |
| 기능 | VM 내부 ↔ 호스트 OS 간 마우스·키보드 제어 전환 |

## 044. APM 패키지 설치, systemctl 서비스 관리, 방화벽 설정

### 1. DNF 패키지 관리 도구

최신 버전의 리눅스에서는 기존 YUM 외에 DNF라고 하는 새로운 패키지 관리 도구가 추가 되었다. YUM과 DNF 모두 사용 가능하며, 본 수업에서는 DNF를 기준으로 진행한다.

```
dnf install -y 패키지명    ← 패키지 설치 (-y는 모든 확인에 YES
자동 응답)
dnf remove -y 패키지명     ← 패키지 삭제
```

-y  옵션을 사용하지 않으면 설치 중 "이 정도 공간이 필요한데 설치하시겠습니까? (yes/no)" 와 같은 확인 질문이 반복적으로 나타난다. -y 는 이 모든 과정에 yes로 자동 응답하는 옵션이다.

옵션의 위치는 순서와 무관하다. dnf install 패키지명 -y 와 dnf -y install 패키지명 모두 동일하게 동작한다.

### 2. APM 패키지 설치

APM은 Apache + PHP + MariaDB의 조합이다. 리눅스용은 LAMP, 윈도우용은 WAMP 라고도 한다.


| 구성 요소 | 역할 | 패키지 이름 |
|---|---|---|
| A (Apache) | 웹 서버 | httpd |
| P (PHP) | 웹 프로그래밍 언어 | php |
| M (MariaDB) | 데이터베이스 서버 | mariadb-server |

```
dnf install -y httpd php mariadb-server    ← APM 패키지 일괄
설치
```

설치가 완료되면 Complete!  메시지가 출력된다. 패키지 설치 시 의존성 패키지(Python, Perl 등)가 함께 자동으로 설치된다.

### 3. 설치된 버전 확인

```
httpd -v          ← Apache 버전 확인 (소문자 v)
httpd -V          ← Apache 버전 및 옵션 상세 확인 (대문자 V)
php -v            ← PHP 버전 확인
mysql --version   ← MariaDB 버전 확인 (mysql 명령어 사용 가능)
mariadb --version ← MariaDB 버전 확인
```

MariaDB는 MySQL과 동일하다. MySQL을 다룰 줄 알면 MariaDB도 다룰 수 있으며, 반대의 경우도 마찬가지이다.

### 4. systemctl — 서비스 관리 명령어

systemctl 은 System Control의 줄임말로, 리눅스에서 서비스(데몬)를 시작·중지·상태 확인하기 위한 명령어이다.


| 명령 | 동작 |
|---|---|
| systemctl start 서비스명 | 서비스 시작 |
| systemctl stop 서비스명 | 서비스 중지 |
| systemctl restart 서비스명 | 서비스 재시작 |
| systemctl status 서비스명 | 서비스 현재 상태 확인 |

```
systemctl status httpd    ← 웹 서비스 상태 확인
systemctl start httpd     ← 웹 서비스 시작
systemctl status httpd    ← 시작 후 상태 재확인
```

상태 확인 시 주요 메시지


| 메시지 | 의미 |
|---|---|
| active (running) | 서비스 정상 실행 중 |
| inactive (dead) | 서비스 중지 상태 |

서비스가 중지 상태(dead)이면 외부 클라이언트가 해당 서비스에 접속할 수 없다.

systemctl status  실행 중 종료하려면 Ctrl+C 를 누른 후 엔터를 입력한다.

서비스 파일이 특정 경로에 존재하지 않으면 systemctl로 제어가 불가능하다. 이 경우 관리자가 직접 서비스 파일을 해당 경로에 등록해야 한다.

### 5. 방화벽 개념과 포트

#### 5-1. 포트(Port)란

포트는 항구와 유사한 개념이다. 데이터가 목적지 서버까지 정상적으로 도착했더라도, 서버 관리자가 해당 서비스의 포트를 막아 놓으면 클라이언트는 접속할 수 없다.


| 프로토콜 | 기본 포트 번호 |
|---|---|
| HTTP | 80 |
| HTTPS (HTTP over SSL) | 443 |
| SSH | 22 |

HTTPS는 HTTP에 보안성을 높인 프로토콜이다.

#### 5-2. 방화벽(firewalld) 상태 확인

리눅스에서는 firewalld 가 기본값으로 실행 중이다.

```
systemctl status firewalld    ← 방화벽 서비스 상태 확인
```

firewalld가 기본으로 실행 중이기 때문에, 별도로 열어주지 않은 포트는 모두 차단된 상태이다. SSH(22번 포트)는 기본값으로 허용되어 있다.

서비스 이름 뒤에 붙는 d 는 데몬(Daemon) 을 의미한다. 데몬은 백그라운드에서 동작하는 프로세스의 일종이다.

#### 5-3. 방화벽 포트 허용 — firewall-cmd

firewall-cmd 는 셸에서 방화벽 정책을 설정하는 명령어이다.

```
# 서비스 이름으로 허용
firewall-cmd --permanent --add-service=http
# 포트 번호로 허용
firewall-cmd --permanent --add-port=80/tcp
# 방화벽 설정 적용 (변경사항 저장)
firewall-cmd --reload
# 현재 방화벽 정책 목록 확인
firewall-cmd --list-all
```


| 옵션 | 의미 |
|---|---|
| --permanent | 영구 적용 (재부팅 후에도 유지) |
| --add-service | 서비스 이름으로 허용 추가 |
| --add-port | 포트 번호/프로토콜로 허용 추가 |
| --reload | 변경사항 저장 및 적용 |
| --list-all | 현재 방화벽 정책 전체 목록 표시 |

--permanent  옵션 없이 설정하면 현재 상태에서는 적용되지만, 시스템 재부팅 후 설정이 초기화된다. 영구 적용을 위해 --permanent 를 함께 사용한다.

방화벽 설정 변경 후 반드시 --reload 로 적용해야 --list-all 에 반영된다.

오류 메시지에 'unrecognized argument'가 표시되면 옵션 철자가 잘못된 것이다. 에러 메시지에 잘못된 부분이 함께 표시된다.

### 6. 웹서버 접속 확인

서비스 시작과 방화벽 설정 완료 후, 호스트 브라우저에서 웹서버에 접속하여 테스트 페이지가 뜨는지 확인한다.

```
http://[서버IP주소]
예) <http://192.168.100.101>
```

⚠️ 주소 입력 시 반드시 http:// 로 시작해야 한다. 기본값으로 https:// 로 변환될 수 있으므로 직접 http:// 를 명시해야 한다.

Apache 패키지를 설치하면 기본으로 HTTP 서버 테스트 페이지가 제공된다. 별도의 HTML 파일을 올리지 않아도 이 페이지가 뜨면 웹서버가 정상 동작 중임을 의미한다.

웹서버 접속 불가 시 확인 사항


| 확인 항목 | 명령어 |
|---|---|
| 서비스 실행 여부 | systemctl status httpd |
| 방화벽 80포트 허용 여부 | firewall-cmd --list-all |
| 서버 IP 주소 확인 | ip address |
| 프로토콜 확인 | 브라우저 주소에 http:// 사용 여부 |

## 047. VirtualBox 복제, 홈 디렉토리, 파일 유형과 권한 체계

### 1. VirtualBox 가상머신 복제

여러 대의 리눅스 서버가 필요한 경우, 매번 처음부터 설치하는 것 외에 복제 기능을 활용할 수 있다. 복제는 어느 정도 작업에 익숙해진 후 사용을 권장한다.

복제 방법: 대상 머신 우클릭 → 복제 (또는 머신 메뉴 → 복제) → 이름 지정 → 완전한 복제 선택 → MAC 주소 정책에서 새 MAC 주소 생성 선택 → 완료


| 항목 | 복제 후 상태 |
|---|---|
| MAC 주소 | 새로 생성 (다름) |
| IP 주소 | 원본과 동일 (충돌 가능) |

⚠️ 복제한 머신을 동시에 실행하면 IP 주소가 동일하여 충돌이 발생한다. 복제 후 반드시 NMTUI로 접속하여 사용하지 않는 IP로 변경해야 한다. Gateway, DNS 등은 그대로 유 지하고 IP 주소만 수정하면 된다.

### 2. 리눅스 로그인과 셸 프롬프트

root 사용자로 로그인하면 다음과 같은 프롬프트가 표시된다.

```
[root@localhost ~]#
```


| 구성 요소 | 의미 |
|---|---|
| root | 현재 접속한 사용자 계정명 |
| localhost | 호스트 이름 (시스템 이름) |
| ~ | 현재 홈 디렉토리에 있음을 의미 |

호스트 이름은 관리자가 변경할 수 있다.

### 3. 홈 디렉토리

각 사용자가 로그인 시 처음 진입하는 디렉토리이다. 사용자 생성 시 자동으로 생성된다.


| 사용자 | 홈 디렉토리 |
|---|---|
| root | /root |
| 일반 사용자 (예: test) | /home/test |

ls -l  결과에서 ~  기호는 현재 홈 디렉토리를 나타낸다.

### 4. 기본 명령어 심화

#### 4-1. pwd — 현재 디렉토리 확인

```
pwd    ← Print Working Directory, 현재 위치 출력
```

#### 4-2. cd — 디렉토리 이동

```
cd /          ← 최상위 디렉토리로 이동
cd /home      ← 절대 경로로 home 디렉토리 이동
cd home       ← 상대 경로로 home 이동 (현재 디렉토리에 home이 있
어야 함)
```

절대 경로와 상대 경로


| 종류 | 설명 | 특징 |
|---|---|---|
| 절대 경로 | / 로 시작하는 경로 | 현재 위치와 무관하게 항상 동일 |
| 상대 경로 | 현재 위치 기준 경로 | 현재 위치에 따라 값이 달라짐 |

"No such file or directory" 오류가 발생하면, 현재 위치에 해당 이름의 파일이나 디렉토리가 없다는 의미이다. 절대 경로를 사용하면 해결된다.

#### 4-3. ls — 목록 조회

```
ls          ← 기본 목록
ls -a       ← 숨김 파일 포함 (all)
ls -l       ← 상세 정보 포함 (long)
ls -al      ← 숨김 파일 + 상세 정보
```


| 리눅스 숨김 파일 규칙 | 설명 |
|---|---|
| . | 현재 디렉토리 |
| .. | 상위 디렉토리 |
| .파일명 | 점(.)으로 시작하는 파일은 숨김 처리 |

### 5. 사용자 생성과 홈 디렉토리 자동 생성

```
useradd test    ← test 사용자 생성 → /home/test 디렉토리 자동
생성
passwd test     ← test 사용자 비밀번호 설정
```

사용자를 생성하면 /home  디렉토리 안에 사용자 이름과 동일한 디렉토리가 자동으로 생성된다. 이 디렉토리가 해당 사용자의 홈 디렉토리가 된다.

### 6. 파일 유형 구분 (ls -al)

ls -al  실행 시 각 항목의 맨 왼쪽 기호로 파일 유형을 확인할 수 있다.


| 기호 | 유형 | 색상(기본) |
|---|---|---|
| - | 일반 파일 | 흰색 |
| d | 디렉토리 | 보라색 |
| l | 링크 파일 | 하늘색 |

링크 파일은 다른 경로에 있는 파일과 연결되어 있는 파일이다. 리눅스에서는 하드 링크와 소프트 링크 두 가지가 있다.

### 7. 파일 권한 체계

#### 7-1. 권한의 3요소


| 기호 | 의미 | 숫자 값 |
|---|---|---|
| r | read (읽기) | 4 |
| w | write (쓰기 / 편집) | 2 |
| x | execute (실행) | 1 |
| - | 해당 권한 없음 | 0 |

#### 7-2. 권한 구역 3분류

권한 필드는 소유자(owner) — 그룹(group) — 기타(other) 순서로 표기된다.

```
rwx  r-x  r-x
↑    ↑    ↑
소유자 그룹  기타
```

예: rwx r-x r-x  = 755, rw- r-- r--  = 644

읽는 방법 예시

```
drwxr-xr-x  root  root  NetworkManager
```

→ NetworkManager 디렉토리에 대해 root 소유자는 읽기·쓰기·실행, root 그룹 사용자는 읽기·실행, 기타 사용자는 읽기·실행 권한을 가진다.

그룹 이름이 'root'라도 root 사용자만 해당되는 것이 아니라, 관리자가 그 그룹에 소속시 킨 모든 사용자가 그룹 권한을 가진다.

#### 7-3. 권한 변경 — chmod

```
chmod 755 test.txt    ← test.txt를 755 권한으로 변경
chmod 644 test.txt    ← test.txt를 644 권한으로 변경
```

⚠️ 보안 관점에서 무조건 높은 권한을 부여하는 것은 바람직하지 않다. 계정 보안의 핵심은 사용자별로 적절한 권한을 관리하는 것이다.

### 8. 디렉토리 및 파일 생성

```
mkdir test        ← test 디렉토리 생성 (Make Directory)
touch test.txt    ← 내용 없는 빈 파일 생성
```

파일/디렉토리 생성 시 기본 권한이 자동으로 부여된다.


| 대상 | 기본 권한 |
|---|---|
| 디렉토리 | 755 (rwx r-x r-x) |
| 파일 | 644 (rw- r-- r--) |

### 9. etc 디렉토리와 설정 파일

```
cd /etc       ← 최상위 디렉토리 밑의 etc 디렉토리로 이동
ls -al        ← 상세 목록 조회
```

/etc  디렉토리 안에는 시스템 환경 설정 파일들이 모여 있다. 확장자가 .conf 로 끝나는 파일들이 대부분 환경 설정 파일이다.

## 048. 리눅스 패키지 관리와 기본 명령어

### 1. YUM 패키지 관리 도구

YUM은 리눅스에서 패키지를 설치·관리하기 위한 도구이다. 어떤 프로그램이 실행되기 위해서는 해당 프로그램 하나만 동작하는 것이 아니라, 그 프로그램을 실행하기 위한 수많은 다른 패키지들이 함께 실행되어야 한다. YUM은 이러한 의존성 관계를 자동으로 파악하고 버전 호환성을 맞춰 가며 패키지를 관리할 수 있는 도구이다.

YUM이 없던 초창기에는 관리자가 모든 패키지 버전 호환성을 직접 확인하며 일일이 설치해야 했기 때문에 리눅스가 어렵게 느껴졌다. YUM의 등장 이후 패키지 설치가 크게 간편해졌 다.

```
yum update -y   ← 패키지 전체 업데이트 (-y는 모든 확인 질문에 YES
자동 응답)
```

⚠️ YUM 업데이트는 시간이 많이 걸리므로, 수업 완전히 마친 후 진행하는 것을 권장한다.

### 2. 리눅스 기본 명령어

#### 2-1. 현재 디렉토리 확인 — pwd

현재 작업 중인 디렉토리의 경로를 출력한다. pwd 는 Print Working Directory의 줄임말이다.

```
pwd   ← 현재 작업 디렉토리 경로 출력
```

#### 2-2. 디렉토리 이동 — cd

cd 는 Change Directory의 줄임말로, 다른 디렉토리로 이동할 때 사용한다.

```
cd /          ← 최상위(루트) 디렉토리로 이동
cd /home      ← 최상위 밑의 home 디렉토리로 이동 (절대 경로)
cd home       ← 현재 디렉토리 기준으로 home 이동 (상대 경로)
```

절대 경로 vs 상대 경로

절대 경로: 최상위 디렉토리( / )부터 시작하는 경로로, 현재 위치와 무관하게 항상 동일하다.

상대 경로: 현재 작업 디렉토리를 기준으로 하는 경로로, 현재 위치에 따라 값이 달라진다.

경로를 찾을 수 없다는 에러 메시지가 뜰 경우, 현재 위치에 해당 파일이나 디렉토리가 존재하지 않는다는 의미이다.

#### 2-3. 디렉토리 목록 조회 — ls

현재 디렉토리 안에 있는 파일과 디렉토리 목록을 출력한다. ls 는 List의 줄임말이다.

```
ls          ← 기본 목록 조회
ls -a       ← 숨김 파일 포함 모두 표시 (-a: all)
ls -l       ← 상세 정보 포함 표시 (-l: long format)
ls -al      ← 숨김 파일 포함 상세 정보 표시
```


| 기호 | 의미 |
|---|---|
| . | 현재 디렉토리 |
| .. | 상위 디렉토리 |

### 3. 사용자 관리

#### 3-1. 사용자 생성 — useradd  / adduser

새로운 사용자 계정을 생성한다. 사용자를 생성하면 /home/[사용자명]  디렉토리가 자동으로 생성된다. 이것이 해당 사용자의 홈 디렉토리이다.

```
useradd test    ← test라는 사용자 생성
adduser test    ← 동일하게 사용 가능
```

root 사용자의 홈 디렉토리는 /root 이며, 일반 사용자의 홈 디렉토리는 /home/[사용자명]

이다.

#### 3-2. 비밀번호 설정 — passwd

사용자의 비밀번호를 설정하거나 변경한다.

```
passwd test    ← test 사용자의 비밀번호 설정
```

⚠️ 비밀번호는 최소 8글자 이상으로 설정하도록 권고된다. 짧게 설정할 경우 BAD

PASSWORD  메시지가 뜨지만 설정 자체는 가능하다.

### 4. 디렉토리와 파일 생성

#### 4-1. 디렉토리 생성 — mkdir

mkdir 은 Make Directory의 줄임말이다.

```
mkdir test    ← test라는 이름의 디렉토리 생성
```

다른 디렉토리 안에 같은 이름의 디렉토리를 만드는 것은 가능하다. 디렉토리가 존재하는 위치(경로)가 다르기 때문이다.

#### 4-2. 빈 파일 생성 — touch

내용이 없는 빈 파일을 생성한다.

```
touch test.txt    ← test.txt라는 빈 파일 생성
```

### 5. 파일 및 디렉토리 유형과 권한

#### 5-1. 파일 유형 확인

ls -al  명령 실행 시 맨 왼쪽에 표시되는 기호로 파일의 유형을 구분할 수 있다.


| 기호 | 유형 | 색상(기본) |
|---|---|---|
| - | 일반 파일 | 흰색 |
| d | 디렉토리 | 보라색 |
| l | 링크 파일 | 하늘색 |

#### 5-2. 권한 체계 (rwx)

권한은 읽기(r), 쓰기(w), 실행(x) 세 가지로 구성되며, 각각 숫자 값을 가진다.


| 권한 기호 | 의미 | 숫자 값 |
|---|---|---|
| r | read (읽기) | 4 |
| w | write (쓰기 / 편집) | 2 |
| x | execute (실행) | 1 |
| - | 해당 권한 없음 | 0 |

권한 필드는 소유자(owner) — 그룹(group) — 기타(other) 세 구역으로 나뉜다.

```
rwx r-x r-x
↑   ↑   ↑
소  그  기
유  룹  타
자
```

예: rwx r-x r-x  → 755, rw- r-- r--  → 644

#### 5-3. 권한 변경 — chmod

chmod 는 Change Mode의 줄임말이다.

```
chmod 755 test.txt    ← test.txt의 권한을 755로 변경
chmod 644 test.txt    ← test.txt의 권한을 644로 변경
```

⚠️ 보안을 위해 무조건 높은 권한을 부여하는 것은 바람직하지 않다. 사용자별로 적절한 권한을 관리하는 것이 계정 보안의 핵심이다.

특정 파일이나 디렉토리에 작업 시 "권한 없음" 에러가 발생하면, 현재 사용자가 소유자 인지, 그룹에 속한 사용자인지, 기타 사용자인지를 확인하여 권한 여부를 파악해야 한다.

### 6. ls -al 상세 출력 구조

ls -al  명령어를 실행하면 각 항목에 대해 다음 정보가 표시된다.


| 필드 | 의미 |
|---|---|
| 첫 번째 기호 | 파일 유형 (-, d, l) |
| rwxrwxrwx | 소유자 / 그룹 / 기타 권한 |
| 링크 수 | 해당 파일/디렉토리에 걸린 링크 개수 |
| 소유자명 | 파일 소유자 |


| 필드 | 의미 |
|---|---|
| 그룹명 | 파일이 속한 그룹 |
| 크기 | 파일 크기 (바이트) |
| 날짜 | 생성 또는 수정 날짜 |
| 이름 | 파일/디렉토리 이름 |

### 7. vi 편집기 기초

vi 편집기는 리눅스에서 텍스트 파일을 편집하기 위한 기본 편집기이다. 윈도우의 메모장처 럼 별도 설치 없이 모든 리눅스 배포판에서 사용할 수 있다. 서버 설정 파일을 편집하기 위해 vi 사용법 숙지가 필수이다.

```
vi test.txt    ← test.txt 파일을 vi로 열기
```

vi에는 두 가지 모드가 있다.


| 모드 | 전환 방법 | 특징 |
|---|---|---|
| 명령 모드 | Esc 키 | 명령어 입력 가능, 문자 직접 입력 불가 |
| 입력(편집) 모드 | i , a , o 키 | 문자 입력 및 편집 가능, 하단에 INSERT 표시 |

vi 종료 명령어

```
:wq!    ← 저장 후 강제 종료
:wq     ← 저장 후 종료
:q      ← 종료 (변경사항 있으면 오류)
:q!     ← 변경사항 무시하고 강제 종료
```

! (느낌표)는 강제(force)를 의미한다. 변경사항이 있어도 무시하고 강제로 실행한다.

## 049. 웹 Document Root, PHP 연동 테스트, Apache 환경 설정 파일

### 1. 모든 서버 서비스 점검의 기본 원칙

앞으로 배우는 모든 서버 서비스에서 반드시 확인해야 할 사항은 두 가지이다.


| 확인 항목 | 명령어 |
|---|---|
| 서비스 현재 상태 | systemctl status 서비스명 |
| 방화벽에서의 허용 여부 | firewall-cmd --list-all |

이 두 가지가 정확하다면 서비스는 정상적으로 동작한다. 서비스 접속 불가 시 반드시 이 두 가지부터 확인한다.

### 2. 웹 Document Root

#### 2-1. Document Root란

클라이언트에게 보여줄 웹 페이지 파일을 올리는 기본 디렉토리이다. 외부에서 접근하는 모든 웹 문서는 이 디렉토리에 위치해야 한다.

```
/var/www/html
```

이 디렉토리를 웹 서비스의 Document Root(다큐멘트 루트) 라고 한다. 웹에서 보여지는 문서가 들어가는 기본 디렉토리이다.

#### 2-2. 웹 URL과 Document Root의 관계

브라우저 주소창에 http://[서버IP] 를 입력하면, 이는 /var/www/html  디렉토리를 가리킨다.

```
http://[서버IP]          →  /var/www/html/
http://[서버IP]/test.php →  /var/www/html/test.php
http://[서버IP]/test/    →  /var/www/html/test/
```

### 3. PHP 연동 테스트

#### 3-1. PHP 테스트 파일 생성

PHP 파일의 확장자는 .php 이다. PHP 코드는 <?php 로 시작하고 ?> 로 닫는다.

```
vi /var/www/html/test.php
<?php phpinfo(); ?>
```

#### 3-2. phpinfo() 함수

phpinfo() 는 현재 시스템에 설치된 PHP의 정보를 출력해 주는 함수이다. 설정 파일 경로, 활성화된 기능, 비활성화된 기능 등 PHP 설치 정보 전체가 표시된다.

⚠️ phpinfo() 는 보안상 프로덕션 환경에서 사용하면 안 된다. 서버의 내부 설정 정보가 외부에 그대로 노출되기 때문이다. 본 실습에서는 PHP 연동 여부 확인 용도로만 사용한다.

#### 3-3. 브라우저에서 접속 확인

```
http://[서버IP]/test.php
```

phpinfo 페이지가 정상적으로 표시되면 PHP와 Apache 웹 서버의 연동이 올바르게 동작하고 있는 것이다.

#### 3-4. PHP — 서버 측 언어

PHP, ASP와 같은 언어는 서버 측 언어(Server-Side Language) 이다. 클라이언트 측 언 어와 달리, 서버에서 실행되어 결과물(HTML)을 클라이언트에게 전달하는 방식으로 동작한다.

### 4. Apache 환경 설정 파일 — httpd.conf

#### 4-1. 파일 경로

Apache를 설치하면 환경 설정 파일이 자동으로 생성된다.

```
/etc/httpd/conf/httpd.conf
```

/etc/httpd 가 Apache 웹 서버의 ServerRoot(서비스 루트 디렉토리)이다. 이 디렉토리는 httpd  패키지를 설치해야 생성된다.

```
vi /etc/httpd/conf/httpd.conf
```

#### 4-2. 라인 번호 표시 설정

설정 파일 편집 시 줄 번호를 표시하면 특정 라인을 찾기 쉽다.

```
:set nu
```

#### 4-3. 주석(#)의 의미

설정 파일에서 # 으로 시작하는 줄은 주석이다.


| 상태 | 설명 |
|---|---|
| # 없음 | 현재 적용 중인 설정 |
| # 있음 | 주석 처리 — 설정에 영향 없음 (설명문 또는 미적용 설정) |

적용 중인 설정을 비활성화하려면 앞에 # 을 추가한다. 반대로 주석 처리된 설정을 활성화하려면 # 을 제거한다.

#### 4-4. 주요 설정 항목


| 라인 번호 | 설정 항목 | 설명 |
|---|---|---|
| 21~22번 | access log<br>_ | 접속 로그 파일 경로 |
| 34번 | ServerRoot | 웹 서비스 관련 파일의 기본 루트 디렉토리<br>( /etc/httpd ) |
| 47번 | Listen 80 | 서비스 포트 번호 (기본값: 80) |
| 61번 | Include<br>conf.modules.d/*.conf | 웹 서버 시작 시 로드할 모듈 설정 파일 경로 |
| 71~72번 | User , Group | Apache 서비스 실행 사용자/그룹 (기본값:<br>apache) |
| 91번 | ServerAdmin | 서버 관리자 이메일 주소 |
| 124번 | DocumentRoot | 클라이언트에게 보여줄 문서의 루트 디렉토리<br>( /var/www/html ) |
| 187번 | ErrorLog | 에러 로그 파일 경로 |

Listen 포트(47번 라인)를 변경하면 방화벽에서도 변경된 포트를 허용해야 한다. 예를 들어 Listen 8080 으로 변경하면 firewall-cmd --permanent --add-port=8080/tcp  후 reload 가 필요하다.

#### 4-5. httpd.conf와 서비스 구동의 관계

systemctl start httpd  실행 시 Apache는 httpd.conf 를 가장 먼저 참조하고, 이 파일의 설 정대로 서비스가 구동된다. 설정 파일에 오류가 있으면 서비스 구동에 문제가 발생할 수 있다.

## 050. 파일 기본 권한과 VIM 편집기 사용법

### 1. 파일과 디렉토리의 기본 생성 권한

파일이나 디렉토리를 새로 생성하면 시스템에서 기본 권한이 자동으로 부여된다.


| 대상 | 기본 권한 기호 | 숫자 표현 |
|---|---|---|
| 디렉토리 | rwx r-x r-x | 755 |
| 파일 | rw- r-- r-- | 644 |

이 기본 권한은 시스템에 설정된 기본값에 의해 결정된다. 나중에 시스템 보안 학습 시 이 기 본값을 설정하는 방법을 확인할 수 있다.

### 2. 권한 변경 — chmod

#### 2-1. 기본 사용법

```
chmod 755 test.txt    ← test.txt의 권한을 755로 변경
```

권한 변경 후 ls -al 로 확인하면, 권한이 달라진 파일은 색깔이 변경되는 것으로도 확인할 수 있다.

#### 2-2. 특수 권한 기호

ls -al 에서 rwx 외에 t  또는 s  기호가 표시되는 경우가 있다.


| 기호 | 위치 | 의미 |
|---|---|---|
| t | 기타(other) 실행 권한 자리 | 스티키 비트 (sticky bit) |
| s | 소유자 또는 그룹 실행 권한 자리 | setuid / setgid |

이 특수 권한들의 상세 의미는 보안 수업 시간에 학습한다.

### 3. VIM 편집기

#### 3-1. VIM이란

VIM은 Visual IMproved의 약자로, 기존 vi 편집기를 시각적으로 개선한 편집기이다. 모든 리눅스 배포판에 기본으로 설치되어 있으며, 별도 설치 없이 사용할 수 있다.

윈도우의 메모장처럼, 리눅스에서 어떤 배포판(Rocky Linux, Ubuntu, CentOS 등)을 사 용하더라도 VIM을 사용할 수 있다. 서버 설정 파일 편집에 필수적인 도구이다.

리눅스에는 nano, gedit 등 다른 편집기도 존재하지만, VIM은 모든 버전의 리눅스에서 공통으로 사용할 수 있다는 장점이 있다.

#### 3-2. VIM 실행

```
vi test.txt    ← test.txt 파일을 vi로 열기 (파일이 없으면 새 파
일 생성)
```

파일이 없는 경우 실행하면 New File 이라는 메시지와 함께 새 파일 편집 상태로 열린다.

### 4. VIM 모드 체계

VIM에는 두 가지 주요 모드가 있다.


| 모드 | 전환 방법 | 화면 표시 | 기능 |
|---|---|---|---|
| 명령 모드 (Command Mode) | Esc 키 | 하단 표시 없음 | 명령어 입력, 이동 가능 |
| 입력 모드 (Insert Mode) | i , a , o | 하단에 INSERT 표시 | 문자 입력 및 편집 가능 |

하단에 INSERT  표시가 없으면 입력 모드가 아니므로, 문자를 입력해도 텍스트로 입력되지 않는다.

#### 4-1. 입력 모드 전환 키

입력 모드로 전환하는 키에 따라 커서의 초기 위치가 달라진다.


| 키 | 커서 위치 |
|---|---|
| i | 현재 커서 위치 앞 |
| a | 현재 커서 위치 뒤 |
| o | 현재 줄 아래에 새 줄 |

### 5. VIM 종료 명령어

명령 모드에서 : 를 입력한 후 명령어를 입력한다.


| 명령 | 동작 |
|---|---|
| :wq | 저장 후 종료 (write + quit) |
| :wq! | 강제 저장 후 종료 |
| :q | 종료 (변경사항 있으면 오류 발생) |
| :q! | 변경사항 무시하고 강제 종료 |

```
# 저장 후 종료
Esc → :wq → Enter
# 변경사항 무시하고 강제 종료
Esc → :q! → Enter
```

! (느낌표)는 강제(force) 의 의미이다. 변경사항이 있어도 무시하고 강제로 실행한다.

:q 만 입력하면 변경사항이 있을 경우 "E37: No write since last change" 또는 이와 유사한 오류 메시지가 발생한다. 이때 :q! 를 사용하면 강제로 나갈 수 있다.

### 6. 파일 내용 확인 — cat

저장된 파일의 내용을 터미널에 출력한다.

```
cat test.txt    ← test.txt 파일 내용 출력
```

vi로 저장한 파일을 cat으로 확인하여 내용이 정상적으로 저장되었는지 검증할 수 있다.

### 7. 앞으로 구축할 서버 목록

오후부터 실제 서버 구축을 진행한다. 서버는 정보를 제공하는 쪽이며, 클라이언트는 정보를 요청하는 쪽이다.


| 서버 종류 | 패키지 이름 | 역할 |
|---|---|---|
| 웹 서버 (Apache) | httpd | 웹 페이지 제공 |
| 웹 프로그래밍 언어 | php | PHP 언어 실행 |
| 데이터베이스 서버 | mariadb-server | DB 서비스 |
| 파일 전송 서버 | vsftpd | FTP 서비스 |
| DNS 서버 | bind | 도메인 이름 서비스 |


| 서버 종류 | 패키지 이름 | 역할 |
|---|---|---|
| 파일 공유 서버 | nfs | NFS 공유 |
| 파일 공유 서버 | samba | Samba 공유 |

APM이란 Apache + PHP + MariaDB 의 조합을 의미한다. LAMP(Linux + APM)로 도 불린다.

## 051. DNS 네임서버 패키지 구성 및 존 파일 개념

### 1. BIND 패키지 설치

#### 1-1. BIND란

*BIND(Berkeley Internet Name Domain)**는 DNS 네임서버를 구축할 때 가장 많이 사용하는 패키지이다. 설치 시 두 개의 패키지를 함께 설치한다.


| 패키지 | 역할 |
|---|---|
| bind | 네임서버 구축 패키지 |
| bind-utils | 네임서버 테스트 및 점검 도구 패키지 |

```
dnf install bind bind-utils    ← bind와 bind-utils 두 패키지 동시 설치
```

BIND를 설치하면 웹 서버(httpd)나 FTP 서버(vsftpd)처럼 /etc/  아래에 설정 파일이 생성된다.

### 2. named.conf 설정

#### 2-1. named.conf 개요

BIND의 주 설정 파일은 /etc/named.conf 이다. 이 파일에서 네임서버의 동작 방식, 질의 허용 범위, 존 파일 등을 설정한다.

```
vi /etc/named.conf    ← BIND 설정 파일 편집
```

파일 안에서 // 로 시작하는 행은 주석이다. # 과 동일한 역할이다.

#### 2-2. 주요 설정 항목


| 라인 | 설정 항목 | 기본값 | 변경값 | 설명 |
|---|---|---|---|---|
| 11번 | listen-on port<br>53 { } | 127.0.0.1 | 네임서버 IP | 53번 포트를 통해<br>수신할 IP 주소 지<br>정. 자기 자신<br>(127.0.0.1)이 아닌<br>실제 네임서버 IP<br>로 변경 |
| 12번 | listen-on-v6 | - | 변경 불필요 | IPv6 주소에 대한<br>설정으로 변경하<br>지 않아도 된다 |
| 13번 | directory | /var/named | 변경 불필요 | 네임서버 관련 파<br>일이 저장되는 디<br>렉토리 경로 |
| 19번 | allow-query {<br>} | localhost | any | 네임서버에 질의<br>를 허용할 대상.<br>localhost 이면<br>외부 질의가 허용<br>되지 않으므로<br>any 로 변경 |
| 31번 | recursion | yes | no | 캐싱 서버 역할 여<br>부. 주 DNS로만<br>동작하므로 no 로<br>변경 |

⚠️ 설정 파일 편집 시 세미콜론( ; )이나 중괄호( { } )를 삭제하면 에러가 발생한다. 주소 값만 정확하게 수정해야 한다.

#### 2-3. 11번 라인 — listen-on port 53 설정

```
listen-on port 53 { 192.168.100.101; };    ← 127.0.0.1을 네임서버 역할을 할 시스템의 IP로
변경
```

127.0.0.1 은 자기 자신(localhost)을 가리키는 주소이다. 외부 클라이언트가 이 네임서버에 질의할 수 있으려면 실제 네임서버 IP로 변경해야 한다.

#### 2-4. 19번 라인 — allow-query 설정

```
allow-query { any; };    ← localhost를 any로 변경하여 누구나 이 네임서버에 질의 가능
```

localhost 로 설정되어 있으면 외부에서 질의하더라도 허가되지 않아 DNS 조회가 불가능하다.

### 3. 주 DNS와 보조 DNS

#### 3-1. 주 DNS (Primary / Master)

여러분이 설정하고 있는 DNS 서버는 주 DNS(Primary DNS, 1차 DNS) 이다. 클라이언트의 도메인 질의를 받아 응답하는 역할을 한다.

#### 3-2. 보조 DNS (Secondary / Slave)

*보조 DNS(Secondary DNS, 2차 DNS)**는 주 DNS를 백업하는 역할을 한다.


| 구분 | 설명 |
|---|---|
| 주 DNS (Master) | 1차 DNS, 클라이언트의 질의에 응답 |
| 보조 DNS (Slave) | 2차 DNS, 주 DNS를 백업 |

보조 DNS는 주 DNS와 정보가 동기화되어 있어야 하며, 이 동기화 과정을 **존 전송(Zone Transfer)**이라고 한다. 주 DNS가 문제가 발생하거나 점검 중일 때 보조 DNS가 대신 응 답한다.

allow-update { none; }  설정은 보조 DNS와의 존 전송 허용 여부를 지정한다. 보조 DNS가 없는 경우 none 으로 설정한다.

### 4. 존(Zone) 파일 개념

#### 4-1. 존 파일 종류

DNS 네임서버의 존(Zone, 영역)에는 두 가지 방향이 있다.


| 존 종류 | 설명 |
|---|---|
| 정방향 존 (Forward Zone) | 도메인 → IP 주소로 변환 (도메인으로 IP를 찾을 때) |
| 역방향 존 (Reverse Zone) | IP 주소 → 도메인으로 변환 (IP로 도메인을 찾을 때) |

#### 4-2. 존 파일 경로

BIND 설치 시 존 파일은 /var/named/  디렉토리 아래에 위치한다. 네임서버 관련 모든 파일이 이 디렉토리 아래에 저장된다.

```
/var/named/    ← BIND 존 파일 저장 디렉토리
```

#### 4-3. named.conf에 존 설정 추가

named.conf 파일 하단에 존 설정 항목을 추가한다.

```
zone "test.com" {               ← 관리할 도메인 이름
    type master;                ← 주 DNS이므로 master, 보조 DNS이면 slave
    file "test.com.zone";       ← 실제 존 파일 이름 (named.conf에서 지정한 이름과 동일해야
함)
    allow-update { none; };     ← 보조 DNS로의 존 전송 허용 여부 (없으면 none)
};
```

⚠️ file 에 지정한 파일 이름과 실제로 생성하는 존 파일의 이름이 반드시 일치해야 한다. 이름이 다르면 오류가 발생한다.

### 5. 레코드(Record) 개요

#### 5-1. 레코드란

존 파일 안에 들어가는 한 줄 한 줄을 레코드라고 한다. 도메인과 IP를 매핑하거나 네임서버에 관련된 정보를 담는다.


| 레코드 종류 | 설명 |
|---|---|
| SOA | 네임서버의 기본 정보. 존 파일에 반드시 포함되어야 하는 필수 레코드 |
| NS | 네임서버를 지정하는 레코드. 존 파일에 반드시 포함되어야 하는 필수 레코드 |
| A | 도메인을 실제 IP 주소로 연결하는 레코드 |
| MX | 메일 서버를 지정하는 레코드 |
| CNAME | 도메인의 별칭을 지정하는 레코드 |
| PTR | 역방향 존에서 IP를 도메인으로 연결하는 레코드 |

#### 5-2. 도메인 구매

실제 서비스에서 사용하는 도메인은 가비아 등 호스팅 사이트에서 비용을 지불하고 구매해 야 한다. 내부 실습에서는 현재 사용되지 않는 도메인(예: test.com )으로 테스트가 가능하다.

내부 네임서버에만 등록된 도메인은 외부의 공용 DNS에서 조회되지 않는다. 따라서 해당 네임서버를 DNS로 설정한 클라이언트에서만 도메인으로 접속이 가능하다.

## 052. DNS 서버 개념과 구축 환경 준비

### 1. DNS 개념 및 구성요소

#### 1-1. DNS란

*DNS(Domain Name System)**는 IP 주소와 도메인 간에 서로 매핑된 정보를 가지고 있는 시스템이다.

시스템이 인지하는 주소는 IP 주소이고, 사람이 편리하게 인식하는 주소는 도메인(예: 네이버 닷컴, 구글 닷컴)이다. DNS는 이 두 가지를 연결하는 역할을 한다.

#### 1-2. DNS 구성요소


| 구성요소 | 설명 |
|---|---|
| IP 주소 | 시스템이 인식하는 주소 |
| 도메인 | 사람이 편리하게 사용하는 주소 (예: naver.com, google.com) |
| 네임서버(NS) | IP와 도메인의 매핑 정보를 레코드화하여 관리하는 서버 |

#### 1-3. DNS 서버 구축 전제 조건

DNS 서버를 구축하기 전에 HTTP 웹 서버가 정상적으로 구축되어 있고 IP 주소로 접속이 가능한 상태여야 한다. IP 주소로 접속이 되지 않으면 도메인으로도 접속이 불가능하다.

IP 주소로 접속이 되는 상태에서 DNS 서버를 구축하면, 동일한 서버에 도메인 이름으로 도 접속할 수 있게 된다.

### 2. 호스트 파일 (Hosts File)

#### 2-1. 호스트 파일의 개념

예전에는 접속해야 할 사이트가 많지 않았기 때문에, 메모장과 같은 호스트 파일을 만들어 IP와 도메인을 직접 관리하였다. 현재도 윈도우 시스템에 호스트 파일이 존재한다.

호스트 파일의 형태는 다음과 같다.

```
# 예시
140.xxx.xxx.xxx    www.google.com    ← IP와 도메인을 한 줄씩 매핑하여 관리
```

현재는 접속해야 할 외부 주소가 매우 많아졌기 때문에, 이러한 목록들을 레코드화하여 관리하는 시스템이 네임서버이고, 이를 전체적으로 DNS라고 한다.

#### 2-2. DNS 조회 순서 (재귀적 질의)

도메인을 입력하면 시스템은 다음 순서대로 IP 주소를 찾는다.


| 순서 | 조회 대상 | 설명 |
|---|---|---|
| 1 | 호스트 파일 | 로컬에 저장된 도메인-IP 매핑 파일을 가장 먼저 참조 |
| 2 | 캐시 | 이전에 조회한 결과가 저장된 캐시를 참조 |
| 3 | 로컬 DNS | 설정된 1차 DNS 서버에 질의 |
| 4 | 재귀적 질의 | 로컬 DNS에 없을 경우 루트 DNS부터 순차적으로 질의 |

재귀적 질의 과정에서는 로컬 DNS가 전 세계 모든 도메인 정보를 가지고 있지 않기 때문에, 루트 DNS부터 TLD, 권한 네임서버 순으로 단계적으로 질의한다.

#### 2-3. TLD (Top Level Domain)

*TLD(Top Level Domain)**는 최상위 도메인을 의미한다. 도메인에서 오른쪽에 위치한 부분이 범위가 큰 쪽이다.

예: www.naver.com.kr 에서 오른쪽 부분( kr , com )이 최상위 도메인에 해당한다.

루트 DNS는 가장 오른쪽에 있는 범위가 큰 최상위 도메인에 대한 정보를 가지고 있으며, 하위 도메인으로 단계적으로 질의가 이루어진다.

### 3. 호스트 파일 변조 공격

#### 3-1. 공격 원리

악성 프로그램이 호스트 파일을 변조할 경우, 정상적인 도메인에 접속하더라도 공격자가 만들어 놓은 피싱 사이트로 연결된다.

공격 예시:


| 구분 | 설명 |
|---|---|
| 정상 상태 | www.naver.com → 정상 서버 IP (예: 100.100.100.100) |
| 변조 후 | www.naver.com → 피싱 사이트 IP (예: 200.200.200.200) |

클라이언트는 www.naver.com 을 입력하면 호스트 파일을 가장 먼저 참조하기 때문에, 변조된 IP로 라우팅되어 피싱 사이트에 접속하게 된다. 피싱 사이트는 네이버 사이트와 유사하게 만들어져 있어 일반 사용자가 구별하기 어렵고, 아이디와 비밀번호를 입력하는 순간 정보가 공격자에게 유출된다.

⚠️ 인터넷에서 파일을 다운받거나 프로그램을 실행할 때 백신 툴에서 "호스트 파일을 변 조하려고 합니다"라는 경고 메시지가 표시될 경우, 이는 호스트 파일 변조를 통한 DNS 연결 조작 시도임을 의미하므로 주의해야 한다.

### 4. DNS 서버 구축 환경 구성

#### 4-1. 두 대 VM 구성

DNS 서버 구축 실습에서는 두 대의 가상머신이 필요하다.


| 머신 | 역할 | IP 예시 |
|---|---|---|
| HTTP 서버 | 웹 서버 역할 (기존 구축 머신) | 192.168.100.101 |
| DNS 서버 | 네임서버 역할 (복제 또는 새로 생성한 머신) | 192.168.100.102 |

두 머신이 동일한 IP로 설정되어 있으면 주소 충돌이 발생하므로, DNS 서버의 IP를 변경해야 한다.

#### 4-2. OVA 파일 (가상 시스템 내보내기/가져오기)

VirtualBox에서 가상 시스템 복제가 되지 않을 경우, OVA 파일을 이용하는 방법이 있다.


| 구분 | 설명 |
|---|---|
| 내보내기 | VirtualBox 파일 메뉴 → 가상 시스템 내보내기 → 포맷 설정에서 모던 네트워크<br>어댑터 MAC 주소 포함 선택 → 완료 |
| 결과 파일 | 확장자 .ova 인 파일이 생성됨 |
| 가져오기 | 파일 메뉴 → 가상 시스템 가져오기 → 생성된 OVA 파일 선택 → 완료 |

OVA 파일은 가상 머신을 이미지화하여 저장한 것으로, 다른 장소에서 동일한 환경을 이어서 사용할 때도 활용할 수 있다.

### 5. IP 주소 설정 — nmtui

#### 5-1. nmtui란

nmtui는 Rocky Linux에서 IP 주소 설정에 사용하는 도구이다. 복제된 VM의 IP가 기존 서버와 동일한 경우 nmtui로 IP를 변경한다.

```
nmtui    ← IP 주소 설정 도구 실행
```

#### 5-2. NetworkManager 재시작

nmtui로 IP 주소를 변경한 후, 변경된 IP를 즉시 적용하려면 NetworkManager 서비스를 재시작해야 한다.

```
systemctl restart NetworkManager    ← 변경된 IP 주소 즉시 적용
```

NetworkManager 재시작 후에도 IP가 변경되지 않으면 물리적으로 리부팅이 필요할 수 있다.

각 시스템의 IP 주소가 다르게 설정되어 있어야 두 머신 간 통신이 정상적으로 이루어진다. IP 주소 설정 후 두 머신 간 핑(ping) 테스트를 통해 통신이 되는지 확인해야 한다.

## 053. FTP 기본 구조, 동작 방식, vsftpd 설정 파일 이해

### 1. HTTPS 접속 확인

#### 1-1. 셀프 인증서 접속 시 동작

공인 기관으로부터 발급받지 않은 셀프 서명 인증서로 HTTPS를 구축한 경우, 웹 브라우저 접속 시 "인증서를 신뢰할 수 없음" 경고 메시지가 표시된다. 이는 서버가 비정상적인 것이 아니라, 브라우저가 해당 인증서를 공인 기관에서 발급된 것으로 인식하지 못하기 때문이다.

경고 메시지를 무시하고 "안전하지 않음으로 이동"을 선택하면 접속 가능하다.

주소 표시줄의 인증서 정보에서 발급된 인증서의 세부 정보(버전, 유효기간, 발급 기관 정보 등)를 확인할 수 있다.

⚠️ 공인 인증서가 없는 사이트 또는 인증서가 올바르지 않은 사이트는 접속하지 않는 것이 보안상 안전하다. 도용의 위험이 존재하기 때문이다.

### 2. FTP 개요

#### 2-1. FTP란

*FTP(File Transfer Protocol)**는 파일 전송 프로토콜의 약자로, 서버와 클라이언트 사이에서 파일을 업로드하거나 다운로드할 때 사용하는 통신 규약이다.

FTP 서버에 파일(영화, 음악, 문서 등)을 저장해두고, 외부에서 해당 서버에 접속하여 파일을 다운로드하거나 서버로 업로드하는 방식으로 활용된다.

#### 2-2. FTP의 보안 문제

FTP는 HTTP, Telnet과 마찬가지로 데이터를 **평문(암호화 없음)**으로 전송한다. 따라서 데이터 전송 중 도청 위험이 존재한다.

이 문제를 해결하기 위해 보안이 강화된 두 가지 방식이 존재한다.


| 프로토콜 | 설명 |
|---|---|
| FTPS | FTP에 SSL/TLS 보안을 추가한 방식 |
| SFTP | SSH 기반의 파일 전송 프로토콜 (SSH 서버가 있으면 별도 설정 불필요) |

현재는 FTP와 Telnet을 사용하지 않는 것을 권장한다. 반드시 FTPS 또는 SFTP를 사용해야 한다.

### 3. FTP 포트 및 동작 방식

#### 3-1. FTP 기본 포트

FTP 서비스는 내부적으로 두 개의 포트를 사용한다.


| 포트 번호 | 역할 |
|---|---|
| 21번 | 제어 채널 — 전송 중 발생하는 문제를 제어하는 역할 |
| 20번 | 데이터 채널 — 실제 파일 데이터가 전송되는 채널 |

통상적으로 "FTP의 기본 포트는 21번"이라고 말하며, 내부에서 20번 포트도 함께 동작한다.

#### 3-2. 액티브 모드와 패시브 모드

FTP는 전송 방식에 따라 액티브(Active) 모드와 패시브(Passive) 모드 두 가지로 구분된다.


| 구분 | 설명 |
|---|---|
| 액티브 모드 | FTP가 기본적으로 제공하는 포트(20, 21번)를 통해 파일을 주고받는 방식 |
| 패시브 모드 | 클라이언트 네트워크 환경(방화벽, UTM 정책 등)에 의해 기본 포트 접속이 차단<br>될 경우, 1024번 이상의 포트를 사용하여 서버에 접속할 수 있도록 하는 방식 |

서버 설정은 정상이지만 특정 클라이언트 네트워크에서만 접속이 안 될 경우, 클라이언트 측의 방화벽 또는 UTM 정책 문제일 가능성이 높다. 이때 패시브 모드로 전환하여 테스트 해볼 수 있다.

FTP 클라이언트 프로그램에서는 액티브/패시브 모드를 선택하는 옵션을 제공하는 경우가 많다.

### 4. vsftpd 패키지

#### 4-1. vsftpd란

*vsftpd(Very Secure FTP Daemon)**는 리눅스에서 많이 사용되는 FTP 서버 소프트웨어 패키지이다. ProFTPD 등 여러 패키지가 존재하지만, 그 중 vsftpd가 널리 사용된다.

```
dnf install vsftpd -y    ← vsftpd 패키지 설치
```

설치 후 /etc/vsftpd/  디렉토리가 자동으로 생성되며, 해당 디렉토리 아래에 vsftpd.conf  환경 설정 파일이 위치한다.

### 5. vsftpd.conf 주요 설정 항목

vsftpd 설치 후 환경 설정 파일에서 주석이 해제된(활성화된) 항목들을 중심으로 주요 설정 내용을 확인한다.

#### 5-1. 기본 접근 설정


| 설정 항목 | 기본값 | 설명 |
|---|---|---|
| local enable<br>_ | YES | 서버에 등록된 로컬 사용자의 로그인 허용 여부 |
| write enable<br>_ | YES | 클라이언트의 쓰기(파일 업로드, 디렉토리 생성 등) 허용 여<br>부 |

#### 5-2. umask 설정

local_umask  항목은 FTP를 통해 생성되는 파일과 디렉토리의 기본 권한을 결정한다.

디렉토리 기본 권한: 777에서 umask 값을 빼면 결정된다.

파일 기본 권한: 666에서 umask 값을 빼면 결정된다.

⚠️ 보안 점검 시 umask 값이 변경되어 있으면, 누군가 의도적으로 파일/디렉토리 권한을 높이기 위해 수정했을 가능성이 있으므로 확인이 필요하다.

#### 5-3. 익명 사용자 설정

주석 처리되어 기본 비활성화되어 있으나, 아래 항목으로 익명 사용자의 권한을 제어할 수 있다.


| 설정 항목 | 설명 |
|---|---|
| anon upload enable<br>_ _ | 익명 사용자의 파일 업로드 허용 여부 |


| 설정 항목 | 설명 |
|---|---|
| anon mkdir write enable<br>_ _ _ | 익명 사용자의 디렉토리 생성 허용 여부 |

#### 5-4. 기타 설정


| 설정 항목 | 기본값 | 설명 |
|---|---|---|
| dirmessage enable<br>_ | YES | FTP 서비스 접속 시 디렉토리/파일 메시지 표시 여<br>부 |
| xferlog enable<br>_ | YES | FTP 서비스 로그 기록 여부 |
| connect from port 20<br>_ _ _ | YES | 20번 포트(데이터 채널) 활성화 여부 |
| ftpd banner<br>_ | (주석) | FTP 서버 접속 시 사용자에게 보여줄 배너 메시지 |

로그 파일은 기본적으로 /var/log/  디렉토리 하위에 저장되며, 해당 로그를 통해 FTP 서버의 접속 기록을 확인할 수 있다.

## 054. FTPS 구축과 패시브 모드

### 1. SFTP 개요

#### 1-1. SFTP와 숨김 파일

*SFTP(SSH File Transfer Protocol)**는 SSH 프로토콜 기반의 파일 전송 방식이다. SSH 서버가 이미 운영 중이라면 별도 패키지 설치 없이 SFTP를 사용할 수 있다.

FileZilla에서 SFTP로 접속하면 파일 목록 중 이름 앞에 점( . )이 붙은 항목이 표시될 수 있다. 리눅스에서 파일명 앞에 점( . )이 붙은 것은 숨김 파일이다. 터미널에서 숨김 파일을 포함하여 목록을 보려면 ls -a  옵션을 사용한다.

```
ls -a    ← 숨김 파일을 포함한 전체 목록 표시
```

### 2. FTPS 개요 및 HTTPS와의 차이점

#### 2-1. FTPS란

*FTPS(FTP Secure)**는 FTP에 SSL/TLS 보안을 추가한 방식으로, HTTPS와 동일한 개념이다. 그러나 HTTPS 구성 방식과 비교했을 때 몇 가지 차이점이 있다.


| 항목 | HTTPS | FTPS |
|---|---|---|
| 인증서 구성 | 키 파일( .key )과 인증서 파일( .crt )<br>분리 | 키와 인증서가 하나의 파일( .pem )에<br>포함 |
| SSL 모듈 설치 | mod ssl 별도 설치 필요<br>_ | 별도 SSL 모듈 설치 불필요 |
| 설정 방법 | ssl.conf 파일에서 키/인증서 경로 지정 | vsftpd.conf에 SSL 설정 항목 직접<br>추가 |

FTPS에서 사용하는 .pem  파일 하나에 키와 인증서 정보가 모두 포함되어 있다.

### 3. FTPS 인증서 생성

FTPS를 위한 인증서는 OpenSSL 명령을 통해 생성하며, 생성된 파일은 /etc/vsftpd/  디렉토리에 저장한다.

```
openssl req -x509 -nodes -days 365 -newkey rsa:2048 \\
  -keyout /etc/vsftpd/vsftpd.pem \\
  -out /etc/vsftpd/vsftpd.pem    ← 키와 인증서를 하나의 .pem 파일로 생성
```

인증서 생성 시 입력하는 정보(국가, 지역, 조직, 부서, 도메인 등)는 테스트 목적이므로 임의 값을 입력해도 무방하다.

### 4. vsftpd.conf SSL 설정 추가

vsftpd.conf 파일에는 기본적으로 SSL 관련 설정 항목이 포함되어 있지 않으므로, 파일 하단에 직접 추가해야 한다.

#### 4-1. 추가할 SSL 설정 항목

```
ssl_enable=YES                          ← SSL 활성화
rsa_cert_file=/etc/vsftpd/vsftpd.pem   ← 인증서 파일 경로 지정
force_local_logins_ssl=YES              ← 로컬 사용자 로그인 시 SSL 강제 적용
force_local_data_ssl=YES                ← 로컬 사용자 데이터 전송 시 SSL 강제 적용
ssl_tlsv1=YES                           ← TLS 버전 1 사용 허용
allow_anon_ssl=NO                       ← 익명 사용자의 SSL 접속 비허용
pasv_enable=YES                         ← 패시브 모드 활성화
pasv_min_port=50000                     ← 패시브 모드 사용 포트 시작 범위
pasv_max_port=55000                     ← 패시브 모드 사용 포트 종료 범위
```

#### 4-2. 주요 설정 항목 설명


| 설정 항목 | 설명 |
|---|---|
| ssl enable=YES<br>_ | FTPS(SSL) 기능 활성화. NO로 설정하면 SSL이 적용되지 않는<br>다. |
| rsa cert file<br>_ _ | 생성한 .pem 인증서 파일의 절대 경로를 지정한다. |
| force local logins ssl<br>_ _ _ | 로컬 사용자 로그인 시 반드시 SSL을 사용하도록 강제한다. |
| force local data ssl<br>_ _ _ | 로컬 사용자 데이터 전송 시 반드시 SSL을 사용하도록 강제한다. |
| ssl tlsv1=YES<br>_ | TLS 1.0 버전 사용을 허용한다. 웹 브라우저마다 지원하는 TLS 버<br>전이 다르므로 하위 호환성이 있는 버전 1을 사용한다. |
| allow anon ssl=NO<br>_ _ | 보안상 익명 사용자의 SSL 연결을 허용하지 않는다. |
| pasv enable=YES<br>_ | 패시브 모드 활성화. 클라이언트 네트워크 환경에 따라 필요하다. |
| pasv min port /<br>_ _<br>pasv max port<br>_ _ | 패시브 모드에서 사용할 포트 범위를 지정한다. |

### 5. 패시브 모드 포트 방화벽 허용

패시브 모드를 활성화하면 클라이언트가 지정된 포트 범위(예: 50000~55000)를 통해 서버에 접속한다. 따라서 방화벽에서 해당 포트 범위를 허용해야 한다.

연속된 포트 범위를 지정할 때는 **하이픈( - )**을 사용하여 한 번에 허용할 수 있다.

```
firewall-cmd --permanent --add-port=50000-55000/tcp    ← 포트 범위 지정 허용 (FTP는 TCP
기반)
firewall-cmd --reload                                   ← 방화벽 정책 재적용
firewall-cmd --permanent --list-all                     ← 허용 목록 확인
```

FTP는 TCP 기반 서비스이므로 포트 허용 시 반드시 /tcp 를 지정해야 한다.

### 6. 서비스 에러 진단 방법

설정 파일 수정 후 서비스 재시작 시 에러가 발생할 수 있다. 이때 에러 원인을 파악하는 방법은 다음과 같다.

```
systemctl status vsftpd    ← 서비스 상태 및 간략한 에러 메시지 확인
journal.ctl -xe            ← 상세 에러 로그 확인 (에러 원인이 빨간색으로 표시됨)
```

journal.ctl -xe  명령을 사용하면 에러 원인(철자 오류, 잘못된 설정값 등)이 빨간색으로 강 조 표시되어 문제를 파악하기 용이하다.

⚠️ 에러 메시지가 나타났을 때 당황하지 않고, 에러 메시지의 내용을 확인하여 원인을 찾는 습관이 중요하다. 설정 파일의 철자 오류, 경로 오류, YES/NO 설정 오류 등이 대부분의 원인이다.

### 7. FileZilla에서 FTPS 접속

#### 7-1. 명시적 FTPS와 묵시적 FTPS

FileZilla에서 FTPS 접속 시 프로토콜 선택 옵션이 있다.


| 접속 방식 | 설명 |
|---|---|
| 명시적 FTPS(Explicit FTP over<br>TLS) | FTP 연결 후 명시적으로 TLS 암호화를 요청하는 방식. 가장 많<br>이 사용된다. |
| 묵시적 FTPS(Implicit FTP over<br>TLS) | 서버 설정과 관계없이 입력 즉시 연결을 시도하는 방식. 상대적으<br>로 덜 사용된다. |


| 접속 방식 | 설명 |
|---|---|
| 가능한 경우 사용(Use if<br>available) | 서버에 SSL 설정이 있을 경우에만 FTPS로 접속하는 방식 |

#### 7-2. 최초 접속 시 인증서 확인

FTPS로 최초 접속하면 HTTPS와 마찬가지로 서버 인증서 정보를 보여주는 창이 표시된다. 셀프 서명 인증서이기 때문에 "알 수 없는 서버 인증서"라는 경고가 뜨며, 확인을 누르면 정상적으로 접속된다. "이후에도 이 인증서를 항상 신뢰"를 선택하면 이후 접속 시에는 해당 창이 표시되지 않는다.

### 📌 핵심 정리

FTPS는 FTP에 SSL/TLS 보안을 추가한 방식으로, 키와 인증서가 하나의 .pem  파일에 포함된다.

vsftpd.conf 파일 하단에 ssl_enable , rsa_cert_file , force_local_logins_ssl  등의 항목을 직접 추가하여 SSL을 설정한다.

패시브 모드 포트 범위(예: 50000~55000)는 방화벽에서 TCP로 허용해야 하며, 하이 픈()으로 범위를 지정할 수 있다.

서비스 에러 발생 시 journal.ctl -xe  명령으로 상세 에러 로그를 확인할 수 있다.

파일질라에서 FTPS 접속 시 명시적 FTPS 방식이 일반적으로 사용된다.

## 055. HTTP와 HTTPS의 차이, 서버 인증서의 개념과 구조

### 1. HTTP와 HTTPS 개요

#### 1-1. HTTP란

HTTP는 Hypertext Transfer Protocol의 약자로, 웹 브라우저와 서버 사이에 데이터를 전송할 때 사용하는 통신 규약이다.

HTTP 연결에서는 데이터가 Plain Text(평문) 형식으로 주고받아진다. 평문이란 암호화가 되지 않은 상태로 전송되는 데이터를 의미하며, 제3자가 해당 데이터를 도청하거나 내용을 쉽게 파악할 수 있다는 문제점이 있다.

#### 1-2. HTTPS란

HTTPS는 HTTP에서 보안성을 높인 프로토콜로, HTTP 뒤에 보안성을 높였다는 의미가 붙은 형태이다.

HTTPS는 TLS(Transport Layer Security) 또는 SSL(Secure Sockets Layer) 프로토콜을 통해 인증과 암호화 기능을 활성화한다. 서버 인증서를 통해 서버가 공인된 기관으로부터 인증서를 발급받은 경우에만 데이터 통신이 이루어지도록 하여 보안성을 확보한다.

현재 대부분의 웹사이트는 HTTPS가 구현되어 있으며, HTTP만 지원하거나 인증서에 문제가 있는 사이트에 접속할 경우 웹 브라우저에서 경고 메시지가 표시된다.


| 항목 | HTTP | HTTPS |
|---|---|---|
| 데이터 전송 방식 | 평문 (암호화 없음) | TLS/SSL을 통한 암호화 |
| 보안성 | 낮음 (도청 위험) | 높음 |
| 서버 인증 | 없음 | 서버 인증서 필요 |
| 웹 브라우저 표시 | 주의 요함 | 정상 연결 |

### 2. 서버 인증서

#### 2-1. 서버 인증서의 역할

HTTPS를 구현하려면 서버에 서버 인증서를 설치해야 한다. 서버 인증서는 마치 개인이 사용하는 공동인증서나 금융인증서와 유사한 개념이다.

서버 인증서는 아무 곳에서나 발급받을 수 없으며, 공인된 기관으로부터 발급받아야 한다. 발급 비용과 유효기간은 규모와 내용에 따라 수십만 원에서 수천만 원까지 다양하다.

서버 인증서 발급 절차는 다음과 같다.

1. 서버 관리자가 인증서 발급 기관에 서버 정보를 포함한 발급 요청을 제출한다.

2. 인증서 발급 기관이 해당 정보를 확인하고 서버 인증서를 발급한다.

3. 서버 관리자가 발급된 인증서를 웹 서버 설정에 등록한다.

4. 이후 HTTPS 프로토콜을 통해 암호화된 데이터 전송이 이루어진다.

#### 2-2. 인증서 유효기간

인증서에는 유효기간이 존재한다. 유효기간은 비용에 따라 1년, 3년 등으로 구분되며, 실제 환경에서는 비용에 따라 서버 인증서의 유효기간이 달라진다.

⚠️ 셀프로 발급한 인증서는 공인된 기관으로부터 발급받은 것이 아니기 때문에, 웹 브라우저에서 "인증서를 신뢰할 수 없음" 또는 "연결이 안전하지 않음" 경고 메시지가 표시된다. 내부 테스트 목적으로만 사용 가능하다.

### 3. OpenSSL을 이용한 셀프 인증서 생성 개념

#### 3-1. OpenSSL이란

OpenSSL은 비용을 들이지 않고 셀프로 테스트용 인증서를 만들 수 있는 도구이다. 공인된 기관에서 발급받은 인증서가 아닌 셀프 방식으로 인증서를 만들기 때문에, 내부 테스트 환경에서만 유효하다.

#### 3-2. 인증서 파일의 구성

HTTPS 구성을 위해서는 두 가지 파일이 필요하다.


| 파일 종류 | 확장자 | 설명 |
|---|---|---|
| 키 파일 (Key File) | .key | RSA 알고리즘으로 생성된 암호화 개인 키. 패스워드로<br>보호된다. |
| 인증서 파일<br>(Certificate File) | .crt | X.509 알고리즘을 사용하며, 키 파일을 기반으로 생성<br>된다. 유효기간, 국가, 조직명 등 서버 정보를 포함한다. |

인증서 파일에는 다음과 같은 정보가 포함된다.

인증서 버전 및 시리얼 번호

서명 알고리즘

발급 기관 정보 (국가, 지역, 조직, 부서, 도메인)

유효기간 (시작일 ~ 만료일)

공개 키 알고리즘 및 비트 크기

#### 3-3. 도메인과 IP 주소의 관계

실제 웹 서비스에서는 도메인 이름(예: www.google.com)으로 접속하지만, 모든 시스템은 IP 주소를 통해 통신한다. 도메인은 사람이 사용하기 편하도록 만들어 놓은 것이며, IP 주소로 직접 접속하는 것도 가능하다.

하나의 도메인에 여러 IP 주소가 연결될 수 있는데, 이는 대규모 서비스(예: 구글, 네이버)의 경우 단일 서버가 아닌 다수의 웹 서버가 운영되고 있음을 의미한다.

IP 통신에 참여하는 모든 시스템은 IP 주소가 있기 때문에, 도메인이 없더라도 IP 주소를 통해 접속이 가능하다.

## 056. VirtualBox 가상머신 설정 복습

### 1. VirtualBox 가상머신 설정

#### 1-1. 운영체제 이미지 설정 (일반)

가상머신을 생성할 때 설치하고자 하는 운영체제 이미지와 설정이 일치해야 한다. 이미지 파일과 설정이 맞지 않으면 설치가 진행되지 않는다.

Rocky Linux(로키): Red Hat 계열, 64비트로 설정

Ubuntu: Ubuntu 항목으로 설정

Kali Linux: Debian 계열로 설정

운영체제마다 선택해야 하는 항목이 다르므로, 설치하고자 하는 이미지에 맞는 타입과 버전을 정확히 선택해야 한다.

#### 1-2. 시스템 설정


| 설정 항목 | 내용 |
|---|---|
| CPU 가상화 기능 | 하드웨어 → 프로세서 항목에서 가상화 기능 체크 옵션이 있으면 활성화한다. 운<br>영체제 종류에 관계없이 공통 적용한다. |
| CPU 개수 | 호스트 컴퓨터의 사양과 생성할 가상머신 수를 고려하여 설정한다. |
| 메모리 용량 | 호스트의 남은 메모리와 가상머신에 필요한 용량을 고려하여 설정한다. |
| 디스크 용량 | 호스트의 남은 디스크에서 가상머신에 할당한 만큼 실제로 사용되므로, 호스트 용<br>량을 감안하여 설정한다. |

가상머신에 할당하는 메모리, CPU, 디스크 용량은 호스트 컴퓨터에서 빌려오는 것이다. 호스트에 100GB가 남아 있을 때 가상머신에 10GB를 할당하면 호스트에는 90GB가 남 는다.

#### 1-3. 저장소 설정 (CD-ROM 이미지)

가상머신을 처음 만들면 CD-ROM에 이미지 파일이 연결되어 있지 않다. 설치할 운영체제 이미지 파일을 다음과 같이 등록한다.

1. 저장소 항목에서 CD-ROM 아이콘을 선택한다.

2. 연결할 이미지 파일을 목록에서 선택하거나 직접 경로로 지정한다.

3. 이미지가 등록되면 CD-ROM 항목에 선택한 이미지 이름이 표시된다.

4. 잘못 선택한 경우 Remove로 제거 후 다시 선택한다.

#### 1-4. 네트워크 설정


| 설정 항목 | 내용 |
|---|---|
| 어댑터 종류 | 브릿지(Bridge) 어댑터로 설정한다. 브릿지 모드에서는 가상머신이 호스트와 동<br>일한 네트워크에 연결된다. |
| 케이블 연결 | 체크 상태를 확인한다. |
| 어댑터 활성화 | 체크 상태를 확인한다. |

#### 1-5. 불필요한 기능 비활성화

가상머신에서 사용하지 않는 기능(오디오, USB 등)은 체크를 해제하여 비활성화하는 것이 권장된다.

### 2. CPU 가상화 관련 문제 해결

#### 2-1. 바이오스에서 CPU 가상화 기능 확인

가상화 관련 오류가 발생할 경우, 호스트 컴퓨터의 바이오스 화면에서 CPU 가상화 기능이 활성화(Enable)되어 있는지 확인해야 한다.

#### 2-2. Windows 기능 충돌 문제

CPU 가상화 기능이 바이오스에서 활성화되어 있음에도 가상머신 설치 시 에러가 발생하는 경우, Windows 시스템 내부에 설치된 기능과 충돌하는 경우가 있다. 이 경우 Windows 기능 켜기/끄기에서 해당 기능을 비활성화하면 해결될 수 있다.

### 3. 가상머신 부팅 순서 설정

운영체제 설치 완료 후 재부팅 시 CD-ROM이 부팅 1순위로 설정되어 있으면, 재부팅할 때마다 CD-ROM의 설치 이미지를 다시 읽어 설치 과정이 반복된다.

이를 방지하려면 설치 완료 후 부팅 순서를 하드 디스크(HDD) 1순위, 광학 디스크(CDROM) 2순위로 변경해야 한다.


| 순서 | 설정 |
|---|---|
| 1순위 | 하드 디스크 (HDD) |


| 순서 | 설정 |
|---|---|
| 2순위 | 광학 디스크 (CD-ROM) |

### 4. 웹 서버 구축 시 문서 루트 경로

HTTP/HTTPS 웹 서버에서 웹 브라우저에 표시되는 페이지 파일은 반드시 Document Root 디렉토리에 위치해야 한다. Apache(HTTPD)의 기본 Document Root 경로는 다음과 같다.

```
/var/www/html/    ← Apache 웹 서버 Document Root 디렉토리
```

웹 페이지 파일(HTML 등)을 이 디렉토리 하위에 생성해야 외부 브라우저에서 접근이 가능하다. ssl.conf 는 HTTPS 설정을 위한 파일이며, 웹 페이지 파일과는 별개이다.

## 057. vsftpd 세부 설정과 서비스 운용

### 1. vsftpd.conf 세부 설정 항목 (계속)

#### 1-1. 세션 타임아웃 설정


| 설정 항목 | 기본값 | 설명 |
|---|---|---|
| idle session timeout<br>_ _ | 600 (초) | 유휴 세션 타임아웃 — FTP 서버에 접속한 후 아<br>무런 작업을 하지 않을 경우 자동으로 세션을 끊<br>는 시간 (600초 = 10분) |
| data connection timeout<br>_ _ | 120 (초) | 데이터 연결 타임아웃 — 데이터 연결에 대한 제<br>한 시간 (120초 = 2분) |

인터넷 뱅킹 사이트에서 일정 시간 동안 아무런 작업을 하지 않으면 로그인이 자동으로 끊 기는 것과 동일한 원리이다. 이 설정값에 따라 FTP 서버도 유휴 시간이 초과되면 세션을 자동으로 종료한다.

#### 1-2. ASCII 모드 설정

ascii_upload_enable , ascii_download_enable  항목은 기본적으로 주석 처리되어 있다. 이 항목들은 파일을 ASCII 모드로 업로드하거나 다운로드할 것인지 설정하는 항목이다.

구축한 FTP 서버에 접속이 잘 안 될 경우, 이 두 항목의 주석을 제거하면 해결되는 경우가 있다.

#### 1-3. 배너 메시지 설정

ftpd_banner  항목은 기본적으로 주석 처리되어 있으며, 활성화하면 FTP 서버에 접속할 때 사용자에게 보여줄 메시지(배너)를 설정할 수 있다.

#### 1-4. ch root 설정 (홈 디렉토리 제한)


| 설정 항목 | 설명 |
|---|---|
| chroot local user<br>_ _ | YES로 설정하면 FTP 접속 사용자가 자신의 홈 디렉토리 밖으로 이동하지<br>못하도록 제한한다. |
| chroot list enable<br>_ _ | 위 제한에서 예외 사용자 목록을 사용할지 설정한다. |

ch root 설정이 활성화되면 FTP에 접속한 사용자는 본인의 홈 디렉토리를 벗어나지 못하 며, 시스템의 다른 디렉토리로 이동할 수 없다.

#### 1-5. IPv6 및 PAM 서비스 설정


| 설정 항목 | 설명 |
|---|---|
| listen ipv6<br>_ | IPv6를 통한 FTP 접속 허용 여부 |
| pam service name<br>_ _ | 인증에 사용할 PAM 서비스 이름 지정. 기본값은 vsftpd 이다. |

### 2. vsftpd 서비스 시작 및 자동 시작 설정

#### 2-1. 서비스 시작

패키지 설치 후 서비스를 시작해야 FTP 서버가 동작한다.컨탐

```
systemctl start vsftpd    ← vsftpd 서비스 시작
```

#### 2-2. 재부팅 후 자동 시작 설정 (enable)

systemctl enable  명령은 서비스를 재부팅 후에도 자동으로 시작되도록 등록하는 명령이다. 방화벽 설정에서 --permanent  옵션을 주는 것과 동일한 역할을 한다.

```
systemctl enable vsftpd    ← 재부팅 후에도 vsftpd 자동 시작 등록
```


| 명령 | 역할 | 유사한 개념 |
|---|---|---|
| systemctl start | 현재 서비스를 즉시 시작 | 방화벽 규칙 즉시 적용 |
| systemctl enable | 재부팅 후에도 서비스 자동 시작 | 방화벽 --permanent 옵션 |

웹 서버(HTTPD)도 마찬가지로 systemctl enable httpd 를 설정하면 서버 재부팅 시마다 서비스를 수동으로 시작할 필요가 없다.

### 3. 방화벽 FTP 서비스 허용

FTP 서비스를 외부에서 접속하려면 방화벽에서 FTP를 허용해야 한다.

```
firewall-cmd --permanent --add-service=ftp    ← 방화벽에 FTP 서비스 영구 허용
firewall-cmd --reload                          ← 방화벽 정책 재적용
```

서비스 이름 대신 포트 번호로 허용하는 방법도 동일한 결과를 낸다.

```
firewall-cmd --permanent --add-port=21/tcp    ← 포트 번호로 허용하는 방법 (동일 효과)
```

### 4. FTP 접속 사용자 생성

FTP 서버에 접속할 사용자 계정을 생성하고 패스워드를 설정한다.

```
user add ftptest        ← ftptest 사용자 계정 생성
passwd ftptest          ← ftptest 사용자 패스워드 설정
```

사용자를 생성하면 /home/사용자명 디렉토리가 자동으로 생성된다. FTP 서버에 해당 계정으로 접속하면 이 홈 디렉토리로 이동하게 되며, 이 디렉토리 안에 있는 파일과 디렉토리가 클라이언트에게 표시된다.

### 5. FTP 클라이언트 프로그램 — 파일질라

#### 5-1. 파일질라 개요

FTP 서버에 접속하여 파일을 업로드·다운로드하기 위해서는 FTP 클라이언트 프로그램을 사용하는 것이 편리하다. 파일질라는 많이 사용되는 FTP 클라이언트 프로그램 중 하나이다.

파일질라는 클라이언트 버전과 서버 버전으로 구분된다.


| 구분 | 설명 |
|---|---|
| 파일질라 Client | FTP 서버에 접속하여 파일을 주고받는 클라이언트 프로그램 |
| 파일질라 Server | 윈도우 PC를 FTP 서버로 동작하게 하는 서버 프로그램 |

리눅스 서버가 이미 FTP 서버 역할을 하고 있으므로, 윈도우 호스트 PC에는 클라이언트 버전을 설치하면 된다.

파일질라는 무료 버전과 유료 버전으로 구분되며, 무료 버전으로도 기본적인 FTP/SFTP/FTPS 접속 테스트가 모두 가능하다.

#### 5-2. FTP 접속 시 주의사항

일반 FTP로 접속하면 파일질라가 다음과 같은 경고 메시지를 표시한다.

"TLS 기반 FTP를 지원하지 않는다. 계속할 경우 비밀번호와 파일이 인터넷을 통해 **일 반(평문)**으로 전송된다."

이 경고는 현재 연결이 암호화되지 않았음을 의미한다. 따라서 FTP를 반드시 사용해야 하는 환경이라면, 보안을 위해 SFTP 또는 FTPS를 통해 접속해야 한다.

## 058. 존 파일 작성과 DNS 서비스 완성

### 1. nslookup — 네임서버 확인 명령어

#### 1-1. nslookup이란

*nslookup(NS Lookup)**은 네임서버의 정보를 조회하는 명령어이다. 윈도우 명령 프롬프트에서 실행한다.

```
nslookup    ← 현재 시스템에 설정된 DNS 서버 및 도메인 정보 확인
```

실행하면 현재 클라이언트에 설정된 DNS 서버의 IP와 도메인 이름이 표시된다. 예를 들어

168.116.63.1 이라는 IP가 KNS.CONET.NET 이라는 도메인과 연결되어 있음을 확인할 수 있다.

### 2. 존 파일 작성

#### 2-1. 존 파일 경로 및 이름

존 파일은 /var/named/  디렉토리 아래에 생성한다. 파일 이름은 named.conf 에서 file  항목에 지정한 이름과 반드시 일치해야 한다.

```
vi /var/named/test.com.zone    ← named.conf에서 지정한 이름과 동일한 이름으로 생성
```

#### 2-2. 주요 레코드 설명


| 레코드 | 역할 | 필수 여부 |
|---|---|---|
| SOA | 네임서버의 기본 정보 (시리얼 번호, 갱신 시간 등) | 필수 |
| NS | 네임서버를 지정 | 필수 |
| A | 도메인과 IP 주소를 연결 | 상황에 따라 |
| MX | 메일 서버 지정 | 상황에 따라 |
| CNAME | 도메인 별칭 지정 | 상황에 따라 |
| PTR | 역방향 조회 (IP → 도메인) | 상황에 따라 |

SOA 레코드와 NS 레코드는 존 파일에 반드시 포함되어야 한다.

#### 2-3. 존 파일 작성 예시

```
$TTL 86400                              ← TTL 기본값 (86400초)
@   IN  SOA ns.test.com. root.test.com. (    ← @ : 자기 자신(로컬), SOA 레코드 시작
            20260402    ; 시리얼 넘버 (날짜 형식 권장, 2차 DNS 연동 시 인식)
            86400       ; 갱신 시간 (refresh) — 24시간
            900         ; 재시도 시간 (retry) — 15분
            172800      ; 만료 시간 (expire) — 48시간
            86400       ; 최소 TTL (minimum)
)
@   IN  NS  ns.test.com.                ← NS 레코드: 네임서버 이름 지정 (끝에 점 필수)
ns  IN  A   192.168.100.101             ← A 레코드: 네임서버 도메인과 IP 연결
www IN  A   192.168.100.101             ← A 레코드: www 도메인과 웹서버 IP 연결
```

#### 2-4. 레코드 작성 시 주의사항


| 주의 항목 | 설명 |
|---|---|
| 도메인 끝 점( . ) | ns.test.com. — 완전한 도메인 이름에는 마지막에 점( . )을 반드시 붙인다 |
| 골뱅이( @ ) | 자기 자신(현재 존의 도메인)을 나타낸다 |
| 달러( $TTL ) | 존 파일 시작 시 TTL 값을 정의하는 기호 |
| 세미콜론( ; ) | 주석 표시 |

⚠️ 점( . ), 세미콜론( ; ), 중괄호( { } ) 등의 기호가 빠지면 오류가 발생한다. 특히 도메인 끝에 점이 빠지지 않도록 주의해야 한다.

### 3. TTL (Time To Live) 개념

#### 3-1. TTL이란

*TTL(Time To Live)**은 패킷이 네트워크에서 살아있는 시간을 나타내는 값이다. 핑 (ping)을 때렸을 때 응답 메시지 마지막에 TTL 값이 표시된다.

패킷이 라우터(홉)를 하나씩 거칠 때마다 TTL 값이 1씩 감소한다. TTL 값이 0이 되면 패킷이 드롭(폐기)된다.

#### 3-2. TTL 제한을 두는 이유

TTL 제한이 없으면 경로를 찾지 못한 패킷이 루핑(Looping)을 계속하면서 전체 네트워크에 부하를 일으킨다. TTL 제한은 이러한 상황을 방지하기 위한 장치이다.

운영체제(리눅스, 윈도우 등)에 따라 기본 TTL 값이 다르다.

### 4. SOA 레코드 상세 항목

#### 4-1. SOA 레코드 구성 요소


| 항목 | 설명 |
|---|---|
| 시리얼 넘버 (Serial) | 날짜 형식으로 작성하는 것이 권장된다 (예: 20260402). 2차 DNS와 연동 시<br>이 값으로 데이터 변경 여부를 인식한다 |
| 갱신 시간 (Refresh) | 2차 DNS가 1차 DNS에 접속하여 정보를 갱신하는 주기 |
| 재시도 시간 (Retry) | 2차 DNS가 1차 DNS 접속 실패 시 재시도하기까지의 대기 시간 |
| 만료 시간 (Expire) | 2차 DNS가 지정된 시간 동안 1차 DNS와 연결되지 않으면 보유 데이터를 삭<br>제 |
| 최소 TTL<br>(Minimum) | TTL 값의 보관 시간 |

### 5. A 레코드 활용 — 여러 서비스 도메인 등록

#### 5-1. 여러 서비스에 도메인 연결

A 레코드를 추가하면 동일한 도메인 아래에 여러 서비스를 도메인 이름으로 접속할 수 있도록 설정할 수 있다.

```
www IN  A   192.168.100.101    ← www.test.com → 웹 서버 IP
ftp IN  A   192.168.100.200    ← ftp.test.com → FTP 서버 IP (예시)
waz IN  A   192.168.100.210    ← waz.test.com → 웹 애플리케이션 서버 IP (예시)
```

클라이언트가 www.test.com 을 입력하면 네임서버가 해당 도메인에 매핑된 IP를 조회하여 알 려주고, 클라이언트는 그 IP를 가진 시스템으로 접속한다.

FTP 클라이언트(파일질라)에서도 IP 주소 대신 ftp.test.com 처럼 도메인 이름으로 호스트를 입력하면 동일하게 동작한다. 도메인에 대한 IP 주소를 네임서버에서 조회한 후 해당 IP로 접속한다.

### 6. 설정 파일 점검 명령어

#### 6-1. named-checkconf — 설정 파일 점검

bind-utils 패키지에 포함된 도구로, named.conf  설정 파일에 문법 오류가 있는지 점검한다.

```
named-checkconf /etc/named.conf    ← named.conf 파일 문법 점검
```

아무것도 출력되지 않으면 정상이다. 오류가 있으면 해당 라인 번호와 오류 내용이 표시된다.

#### 6-2. named-checkzone — 존 파일 점검

존 파일에 오류가 있는지 점검하는 명령어이다.

```
named-checkzone test.com /var/named/test.com.zone    ← test.com 도메인의 존 파일 점검
```

정상이면 시리얼 넘버가 로드되고 OK가 출력된다. 오류가 있으면 라인 번호와 함께 오류 내용이 표시된다.

⚠️ 오류 발생 시 대부분의 원인은 점( . ), 세미콜론( ; ), 중괄호( { } )가 빠진 경우 또는 철자 오류이다. 표시된 라인 번호 근처를 확인한다.

### 7. DNS 서비스 시작 및 방화벽 허용

#### 7-1. 방화벽에서 DNS 허용

DNS 서비스에 외부 클라이언트가 질의할 수 있도록 방화벽에서 허용한다. DNS의 기본 서비스 포트는 53번이며, 주로 UDP를 통해 동작한다.

```
firewall-cmd --permanent --add-service=dns    ← 방화벽에 DNS 서비스 영구 허용
firewall-cmd --reload                          ← 방화벽 정책 재적용
firewall-cmd --permanent --list-all            ← 허용 목록 확인 (DNS가 포함되어 있어야 함)
```

포트 번호로 허용할 경우: 53/udp

#### 7-2. DNS 서비스 시작

named는 BIND 서비스의 이름이다.

```
systemctl start named     ← named 서비스 즉시 시작
systemctl enable named    ← 재부팅 후에도 named 서비스 자동 시작 등록
```


| 명령 | 역할 |
|---|---|
| systemctl start named | 지금 즉시 서비스를 시작 |
| systemctl enable named | 서버 재부팅 시 서비스가 자동으로 시작되도록 등록 |

### 8. 클라이언트 DNS 설정 변경 (윈도우)

#### 8-1. DNS 서버 주소 변경 방법

클라이언트(윈도우 PC)에서 내가 구축한 네임서버로 도메인 질의를 하려면, 윈도우의 DNS 서버 주소를 구축한 VM의 IP로 변경해야 한다.

설정 경로: 어댑터 옵션 변경 → 해당 네트워크 어댑터 우클릭 → 속성 → IPv4 속성 → 기본 설정 DNS 서버


| 설정 항목 | 변경 값 |
|---|---|
| 기본 설정 DNS 서버 | 구축한 DNS 서버(네임서버) VM의 IP 주소 |
| 보조 DNS 서버 | 보조 DNS가 없으면 비워둔다 |

DNS 서버 주소를 변경하면 www.test.com  입력 시 변경된 네임서버에 질의하고, 해당 네임서버에 등록된 IP를 응답받아 웹 서버에 접속된다.

테스트 완료 후 원래의 DNS 서버 주소로 되돌려야 인터넷 접속이 정상적으로 동작한다. DNS를 구축한 VM의 IP로 변경된 상태에서는 외부 인터넷 접속에 문제가 발생할 수 있다.

## 059. NFS 서버 구축

### 1. NFS 개요

#### 1-1. NFS란

NFS(Network File System)는 리눅스와 리눅스 간에 특정 디렉토리(자원)를 네트워크를 통해 공유할 수 있도록 해주는 파일 시스템이다.

#### 1-2. NFS 핵심 구성 요소


| 서비스 | 역할 |
|---|---|
| nfs-server | NFS 파일 공유의 핵심 서비스 |
| nfs-lock | 공유 파일에 대한 잠금(Lock) 처리 서비스 |
| rpc-bind | 원격(Remote)에서 프로시저 호출(Procedure Call)이 들어왔을 때 NFS에 연결<br>되는 포트를 결정하는 바인딩/맵핑 서비스 |

RPC(Remote Procedure Call)는 원격에서 호출이 들어왔을 때 연결되는 포트를 실제로 결정하는 역할을 한다.

### 2. 실습 환경 구성

두 대의 시스템을 사용하여 한 대는 서버, 한 대는 클라이언트 역할로 구성한다.

```
서버 (예: IP 192.168.100.101)   ←→   클라이언트 (예: IP 192.168.100.102)
```

⚠️ 서버에서 해야 할 작업을 클라이언트에서 수행하거나, 그 반대의 경우가 발생하지 않도록 작업 중 현재 시스템의 역할을 반드시 확인한다.

### 3. 호스트네임 설정

#### 3-1. 현재 호스트네임 확인 및 변경

```
hostnamectl status              ← 현재 호스트네임 확인
hostnamectl set-hostname <이름>  ← 호스트네임 변경
```

설정 후 바로 반영되지 않을 경우, 다른 계정으로 전환했다가 다시 root로 돌아오면 변경된 호스트네임이 적용된다.

```
su <일반계정명>   ← 일반 계정으로 전환
su -             ← 다시 root로 복귀
```

호스트네임이 구분되어 있으면 서버/클라이언트 혼동을 방지할 수 있다.

### 4. NFS 패키지 설치

서버와 클라이언트 모두에 nfs-utils 패키지를 설치한다.

```
# 서버 및 클라이언트 공통
dnf install -y nfs-utils    ← NFS 유틸리티 패키지 설치
```

### 5. 서버 설정

#### 5-1. 서비스 시작

```
# 서버에서 실행
systemctl start nfs-server   ← NFS 서버 서비스 시작
systemctl start rpc-bind     ← RPC 바인드 서비스 시작
```

#### 5-2. 공유 디렉토리 생성 및 권한 설정

```
mkdir /nfs-server            ← 최상위 디렉토리 아래에 공유용 디
렉토리 생성
chmod 757 /nfs-server        ← 권한 설정 (클라이언트에서 접근 가
능하도록)
```

권한 숫자 의미:


| 숫자 | 의미 |
|---|---|
| 4 | read (읽기) |
| 2 | write (쓰기) |
| 1 | execute (실행) |
| 7 | read + write + execute (모든 권한) |
| 5 | read + execute |

#### 5-3. /etc/exports 파일 설정

/etc/exports  파일은 NFS 서버에서 어떤 클라이언트가 어떤 디렉토리에 어떤 권한으로 접근할 수 있는지를 지정하는 설정 파일이다.

```
vi /etc/exports
# /etc/exports 설정 형식
/nfs-server  192.168.100.102(rw,sync,no_root_squash)
#  ↑ 서버 공유 디렉토리 경로
#               ↑ 접근 허용할 클라이언트 IP
#                              ↑ 괄호 안: 접근 권한 옵션 (IP와
붙여서 작성)
```

#### 5-4. exports 주요 옵션


| 옵션 | 설명 |
|---|---|
| rw | 읽기/쓰기 허용 |
| ro | 읽기 전용 |
| sync | 변경 사항을 실시간으로 동기화 |
| async | 비동기 방식으로 동기화 |
| no root squash<br>_ _ | 클라이언트의 root 사용자를 서버의 root 사용자로 맵핑 |
| root squash<br>_ | 클라이언트의 root 사용자를 일반 사용자로 맵핑 |
| secure | 1024 포트 이하에서만 연결 허용 |
| insecure | 1024 포트 이상도 연결 허용 |

#### 5-5. exports 파일 적용

```
exportfs -a    ← /etc/exports 설정 내용을 적용
exportfs       ← 현재 적용된 exports 내용 확인
```

### 6. 방화벽 설정

NFS 기본 포트인 2049번(TCP)을 방화벽에서 허용한다.

```
firewall-cmd --permanent --add-port=2049/tcp   ← NFS 포트 영
구 허용
# 또는 서비스명으로 허용
firewall-cmd --permanent --add-service=nfs
firewall-cmd --reload                           ← 설정 적용
firewall-cmd --list-all                         ← 허용 목록
확인
```

## 060. NFS 클라이언트 설정, 마운트 및 Samba 서버 구축 준비

### 1. NFS 클라이언트 설정

#### 1-1. 클라이언트 서비스 시작

클라이언트에서는 nfs-server 서비스는 필요하지 않으며, rpc-bind 서비스만 시작한다.

```
# 클라이언트에서 실행
systemctl start rpc-bind    ← RPC 바인드 서비스 시작
```

#### 1-2. 클라이언트 측 공유 디렉토리 생성

서버의 공유 디렉토리와 동기화할 디렉토리를 클라이언트에 생성한다.

```
mkdir /nfs-client    ← 최상위 디렉토리 아래에 동기화용 디렉토리
생성
```

### 2. mount 명령어 — NFS 마운트

#### 2-1. mount 개념

mount  명령어는 시스템에 외부 장치(DVD, USB 등)나 네트워크 자원을 연결할 때 사용한다. 반대로 연결을 해제할 때는 umount  명령어를 사용한다.

#### 2-2. NFS 마운트 명령어

```
# 클라이언트에서 실행
mount -t nfs 192.168.100.101:/nfs-server /nfs-client
#       ↑ 타입: nfs
#                 ↑ 서버 IP          ↑ 서버 공유 디렉토리 경로
#                                                ↑ 클라이언
트 마운트 포인트
```


| 구성 요소 | 설명 |
|---|---|
| -t nfs | 마운트 타입을 NFS로 지정 |
| 서버IP:/서버디렉토리 | 서버 IP와 공유 디렉토리를 콜론( : )으로 구분하여 지정 |
| /nfs-client | 클라이언트에서 연결될 로컬 디렉토리 경로 |

⚠️ exports 파일에는 서버의 IP가 들어갔고, mount 명령어에는 서버의 IP가 들어간다. 혼동하지 않도록 주의한다.

### 3. 마운트 확인 — df 명령어

마운트가 정상적으로 이루어졌는지 디스크 사용 현황 명령어로 확인한다.

```
df      ← 디스크 마운트 현황 확인
df -h   ← 용량 단위로 가독성 있게 출력 (예: 8G, 2.3G)
```

df  출력 결과에서 서버IP:/nfs-server  형태로 마운트된 항목이 표시되면 연결이 성공한 것이다.

### 4. 마운트 오류 시 점검 항목

마운트 실패 또는 접속 거부 오류가 발생할 경우 다음 세 가지를 확인한다.


| 점검 항목 | 확인 내용 |
|---|---|
| 방화벽 | 서버에서 2049/tcp 포트 허용 및 reload 적용 여부 |
| /etc/exports | 클라이언트 IP, 공유 디렉토리 경로, 권한 옵션 작성 정확성 |
| 디렉토리 권한 | 서버 공유 디렉토리 권한이 757 등으로 적절히 설정되어 있는지 여부 |

### 5. NFS 활용 개념

NFS는 통상적으로 리눅스와 리눅스 간에 자원을 공유하기 어려운 환경에서, 네트워크 파일 시스템을 통해 특정 디렉토리를 공유하여 실시간 동기화를 가능하게 한다. 업무용 문서나 데이터를 다른 시스템에 동기화하여 백업 용도로 활용할 수도 있다.

### 6. Samba 서버 개요

#### 6-1. Samba란

Samba는 리눅스와 윈도우 간에 파일 및 자원을 공유하기 위해 사용하는 서버이다.

#### 6-2. Samba 핵심 프로세스 및 포트


| 프로세스 | 사용 포트 | 역할 |
|---|---|---|
| nmbd | UDP 137, 138 / TCP 139 | 네트워크 제어 및 재설정 처리 |
| smbd | TCP 445 | 삼바 서버의 대부분 기능 처리 (파일 공유, 인증 등) |

### 7. Samba 패키지 설치

삼바 서버 역할을 할 리눅스 시스템에 다음 세 개의 패키지를 설치한다.

```
dnf install -y samba samba-common samba-client    ← 삼바 서
버 구축용 패키지 설치
```

### 8. 공유 디렉토리 생성 및 권한 설정

```
mkdir /samba-test              ← 최상위 디렉토리 아래에 공유용
디렉토리 생성
chmod 777 /samba-test          ← 윈도우에서 접근 가능하도록 최고
권한 부여
```

### 9. Samba 사용자 생성 및 계정 관리

#### 9-1. 리눅스 계정 생성

```
useradd samba-user             ← 삼바 접속에 사용할 리눅스 계정
생성
```

#### 9-2. Samba 전용 패스워드 설정

리눅스 시스템 로그인 패스워드와 삼바 서버 접속 패스워드는 별개이다.

```
passwd samba-user              ← 리눅스 시스템 로그인용 패스워드
설정
smbpasswd -a samba-user        ← 삼바 서버 접속용 패스워드 설정
(-a: 추가)
```

동일한 사용자라도 시스템 로그인 패스워드와 삼바 접속 패스워드는 달라도 된다. 윈도우에서 삼바 서버에 접속할 때는 smbpasswd로 설정한 패스워드를 사용한다.

#### 9-3. smbpasswd 주요 옵션


| 옵션 | 설명 |
|---|---|
| -a | 삼바 계정 추가 및 패스워드 설정 |
| -x | 삼바 계정 삭제 |
| -d | 삼바 계정 비활성화 (Disable) |
| -e | 삼바 계정 활성화 (Enable) |
| -n | 패스워드 없이 로그인 허용 (smb.conf에서 null passwords = yes 설정 필요) |

## 061. Samba 설정 파일 구성, 서비스 운영 및 윈도우 접속 테스트

### 1. Samba 설정 파일 — smb.conf

#### 1-1. 파일 위치 및 구조

```
vi /etc/samba/smb.conf    ← Samba 환경 설정 파일 편집
```

설정 파일은 크게 전역(global) 설정 영역과 공유 섹션으로 구성된다. 주석( comment )은 세미콜론( ; ) 또는 # 으로 표시된다.

#### 1-2. 기본 제공 공유 섹션

설치 후 기본으로 공유되는 섹션이 포함되어 있다.


| 섹션 이름 | 설명 |
|---|---|
| [homes] | 사용자 홈 디렉토리를 자동으로 공유. 삼바 사용자 계정의 홈 디렉토리(/home/사<br>용자명)가 자동으로 공유된다. |
| [printers] | 프린터를 공유 |
| [print$] | 프린터 드라이버를 공유 |

### 2. 공유 섹션 추가

#### 2-1. 공유 섹션 설정 항목

smb.conf 파일에 공유 섹션을 추가하는 방법은 다음과 같다.

```
[samba-share]            ← 외부(윈도우)에서 보여지는 공유 이름
    comment = 설명문      ← 공유 이름에 대한 설명 (주석)
    path = /samba-test   ← 실제 공유되는 디렉토리 경로
    browseable = yes     ← 탐색기에서 공유 디렉토리가 보여지도록 설정
    writable = yes       ← 쓰기(서기) 가능 여부
    guest ok = yes       ← 일반 사용자(게스트)의 접근 허용 여부
    create mask = 0777   ← 윈도우 사용자가 파일 생성 시 적용되는 권한
    directory mask = 0777← 윈도우 사용자가 디렉토리 생성 시 적용되는 권한
```

#### 2-2. 주요 옵션 설명


| 옵션 | 설명 |
|---|---|
| path | 실제 공유되는 디렉토리 경로 |
| browseable | 탐색기(네트워크 드라이브 등)에서 공유 디렉토리가 보여지는지 여부 |
| writable | 쓰기 가능 여부 |
| guest ok | 게스트(일반) 계정의 접근 허용 여부 |
| create mask | 파일 생성 시 적용 권한 |
| directory mask | 디렉토리 생성 시 적용 권한 |
| comment | 공유 이름에 대한 설명 |

⚠️ 설정 파일 수정 후에는 반드시 :wq! (강제 저장 후 종료)로 저장하고 빠져나와야 한다.

### 3. 설정 파일 검증 — testparm

DNS 구축 시 named-checkconf 를 사용하듯, Samba는 testparm  명령어로 설정 파일의 오류를 점검한다.

```
testparm    ← smb.conf 설정 파일 유효성 검사
```

정상적으로 로드되면 Loaded services file OK.  메시지가 출력되며, 이어서 현재 정의된 공유 서비스 목록이 표시된다.

### 4. Samba 서비스 시작 및 상태 확인

#### 4-1. 서비스 시작

```
systemctl start smb    ← smbd 서비스 시작
systemctl start nmb    ← nmbd 서비스 시작
```

재부팅 후에는 서비스가 중지된 상태로 돌아온다. 부팅 시 자동 시작이 필요하면

systemctl enable  명령어를 추가로 사용해야 한다.

#### 4-2. Samba 상태 확인

```
smbstatus    ← 현재 Samba 서버 버전, 연결 정보, 공유 사용 현황 출
력
```

파일 공유 작업이 이루어진 이후 smbstatus 를 확인하면 어떤 사용자가 어떤 디렉토리에서 작업하고 있는지 상세 정보가 표시된다.

### 5. SELinux 설정

Samba 서버와 윈도우 간 접속이 원활하게 이루어지려면 SELinux를 비활성화(Disabled) 상태로 설정해야 한다.

```
sestatus    ← 현재 SELinux 상태 확인
```

설정 파일에서 Disabled로 변경한 후 재부팅하면 적용된다.

⚠️ 모든 테스트가 끝나고 시스템 종료 전에 SELinux 설정을 Disabled로 변경하면, 다음 부팅 시 자동으로 적용된다.

### 6. 방화벽 설정

```
firewall-cmd --permanent --add-service=samba    ← Samba 서
비스 영구 허용
firewall-cmd --reload                            ← 적용
firewall-cmd --list-all                          ← 허용 목록
확인
```

방화벽에서 Permanent 옵션으로 설정된 항목은 재부팅 후에도 자동으로 유지된다.

### 7. 윈도우에서 Samba 서버 접속

#### 7-1. 접속 방법

윈도우에서 실행창(Win + R)을 열고 다음과 같이 Samba 서버의 IP를 입력한다.

```
\\\\192.168.100.101    ← Samba 서버 IP 입력 후 확인
```

접속 성공 시 smb.conf에서 설정한 공유 이름(예: samba-share )이 탐색기에 표시되며, 더블클릭하면 공유 디렉토리 내부로 진입한다.

#### 7-2. 양방향 동기화 확인


| 작업 | 결과 |
|---|---|
| 리눅스에서 파일 내용 수정 | 윈도우 탐색기에서 수정된 내용 즉시 반영 |
| 윈도우에서 파일 내용 수정 | 리눅스에서 cat 명령어로 확인 시 수정 내용 반영 |
| 윈도우에서 폴더/파일 생성 | 리눅스 공유 디렉토리에서 ls 명령어로 확인 가능 |

이처럼 윈도우에서 접속하여 파일을 생성, 수정, 삭제하는 모든 작업이 리눅스 삼바 서버의 공유 디렉토리와 실시간으로 동기화된다.

### 8. 자원 공유 체계 정리


| 공유 방식 | 운영 체제 조합 | 서버 역할 | 클라이언트 역할 |
|---|---|---|---|
| NFS | 리눅스 ↔ 리눅스 | NFS 서버 | NFS 클라이언트 |
| Samba | 리눅스 ↔ 윈도우 | 리눅스(Samba 서버) | 윈도우 |

자원 공유에서 자원은 디렉토리(폴더)뿐 아니라 USB, DVD 등 다양한 장치도 포함하는 개념이다.

## 062. 리눅스 서비스 구축 흐름과 DNS 레코드 체계

### 1. 서비스 구축 전체 흐름

#### 1-1. 다중 서버 구성 개요

NAME 서버, 웹 서버, FTP 서버가 각각 별도의 IP 주소를 가지고 운영된다고 가정할 때, 각 서비스는 공통된 절차를 따라 구축된다.


| 단계 | 내용 |
|---|---|
| 1단계 | 관련 패키지 설치 |
| 2단계 | 설정 파일 구성 |
| 3단계 | 서비스 상태 확인 |
| 4단계 | 방화벽에서 해당 포트 또는 서비스 허용 및 적용 |

### 2. 서비스 관리 명령어 (systemctl)

#### 2-1. 주요 명령어

```
systemctl status <서비스명>   ← 서비스 상태 확인
systemctl start <서비스명>    ← 서비스 시작
systemctl restart <서비스명>  ← 서비스 재시작
systemctl enable <서비스명>   ← 부팅 시 자동 시작 등록
systemctl disable <서비스명>  ← 부팅 시 자동 시작 해제
```

### 3. 오류 진단 — journalctl

서비스 시작 또는 재시작 시 오류가 발생할 경우, 다음 명령어로 오류 내용을 확인할 수 있다.

```
journalctl -xe   ← 오류 발생 위치와 원인을 빨간색으로 표시하여 출
력
```

빨간색으로 표시된 부분을 확인하면 설정 파일의 철자 오류나 누락된 항목 등을 파악할 수 있다.

⚠️ 처음에는 오류 메시지의 내용을 파악하기 어렵지만, 반복적으로 오류를 수정해 나가 다 보면 메시지만 보고도 원인을 빠르게 파악할 수 있게 된다.

### 4. 방화벽 설정 (firewall-cmd)

#### 4-1. 기본 흐름

서비스가 정상적으로 시작된 이후에는 방화벽에서 해당 포트 또는 서비스가 허용되어 있는지 확인해야 한다.

```
firewall-cmd --list-all               ← 현재 방화벽 허용 목록
확인
firewall-cmd --permanent --add-port=<포트번호>/tcp   ← 포트
영구 허용
firewall-cmd --permanent --add-service=<서비스명>    ← 서비스
명으로 영구 허용
firewall-cmd --reload                 ← 변경 사항 적용 (reloa
d 필수)
```

방화벽에서 허용만 하고 reload를 하지 않으면 적용되지 않는다.

### 5. IP 주소 기반 서비스 동작 확인

방화벽까지 설정이 완료되면 각 서비스는 IP 주소 기반으로 동작하는 상태가 된다. IP 주소로 동작이 확인되지 않으면 NAME 서버와의 연결 상태를 검증할 수 없다.

### 6. DNS 레코드 체계

#### 6-1. DNS Zone 파일 구성 요소

존 파일에는 최소한 SOA 레코드와 NS 레코드가 포함되어야 한다.


| 레코드 종류 | 역할 |
|---|---|
| SOA (Start of Authority) | 해당 존의 권한 정보, 기본 포함 레코드 |
| NS (Name Server) | 도메인의 네임서버를 지정 |
| A | 도메인명과 IPv4 주소를 맵핑 |
| CNAME (Canonical<br>Name) | 도메인의 별칭(Alias)을 다른 도메인으로 연결 |
| MX (Mail Exchanger) | 메일 서버를 지정 |
| PTR (Pointer) | IP 주소를 도메인명으로 맵핑 (역방향 조회, Reverse Zone에서 사<br>용) |
| AAAA | 도메인명과 IPv6 주소를 맵핑 |

#### 6-2. A 레코드 설정 예시

```
# 정방향 Zone 파일 예시
NS      IN  A     <네임서버 IP>
www     IN  A     <웹서버 IP>
ftp     IN  A     <FTP서버 IP>
hong    IN  A     <웹서버 IP>     ← CNAME 대신 A 레코드로 별칭
처럼 사용 가능
```

#### 6-3. 역방향 Zone (PTR 레코드)

```
# 역방향 Zone 파일 예시
<IP 끝 자리>  IN  PTR  <도메인명>.
```

PTR 레코드는 역방향 존(Reverse Zone)에서 IP 주소를 기준으로 도메인명을 조회할 때 사용된다.

이 외에도 다양한 레코드 유형이 존재하며, 구축 환경과 목적에 따라 추가적인 레코드를 사용해야 하는 경우가 있다.

### 7. 패스워드 관리

현재 비밀번호를 알고 있는 상태에서 root 계정 또는 다른 계정의 패스워드를 변경하려면 다음 명령어를 사용한다.

```
passwd          ← 현재 로그인한 계정의 패스워드 변경
passwd <계정명>  ← 특정 계정의 패스워드 변경 (관리자 권한 필요)
```
