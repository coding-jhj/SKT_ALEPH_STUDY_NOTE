## 063. LogAnalyzer 웹 설치, HTTP 오류 코드와 SELinux 파일 권한

코드와 SELinux 파일 권한

### 1. LogAnalyzer 웹 설치 과정 개요

#### 1-1. 설치 파일 역할 구분


| 파일명 | 역할 |
|---|---|
| install.php | 최초 설치 시 웹 브라우저에서 단계별로 진행하는 설치 스크립트 |
| index.php | 설치 완료 후 LogAnalyzer 메인 화면 진입점 |
| config.php | 설치 과정에서 생성되는 환경설정 파일 |
| config.sh | config.php 파일을 생성하고 권한을 설정하는 셸 스크립트 |

설치 중 오류가 발생하여 처음부터 다시 시작하려면 config.php  파일을 삭제한 후 config.sh  스크립트를 다시 실행하면 된다.

### 2. HTTP 오류 코드

#### 2-1. HTTP 500 오류

HTTP 500 오류는 서버 측 오류를 의미한다. 클라이언트(브라우저)가 아닌 서버 자체에서 문제가 발생한 경우에 반환된다.


| 오류 코드 | 의미 | 원인 |
|---|---|---|
| 500 Internal Server Error | 서버 측 오류 | 설정 오류, DB 연결 실패, 권한 문제 등 |

HTTP 500 오류 발생 시 httpd 서비스와 MariaDB 서비스를 재시작하고 설정을 재확인 해야 한다.

### 3. SELinux 파일 권한 — chcon 명령어

#### 3-1. chcon 개요

일반적인 파일 권한( chmod )과 별도로, SELinux(보안 모듈)는 파일에 대한 추가적인 보안 컨 텍스트를 관리한다. 웹 서비스가 특정 파일에 쓰기 작업을 수행하려면 SELinux 컨텍스트 권 한도 적절하게 설정되어야 한다.

chcon -t httpd_sys_script_rw_t config.php    ← 웹 서비스에 config.php 읽기·쓰기 권한 부여


| 옵션 | 의미 |
|---|---|
| -t | SELinux 타입 지정 |
| httpd sys script rw t<br>_ _ _ _ | 웹 서비스(httpd)가 읽기·쓰기 가능한 타입 |

chmod 로 파일 권한을 변경해도 SELinux 컨텍스트가 맞지 않으면 웹 서비스에서 파일에 쓸 수 없다. 이 경우 chcon  명령으로 SELinux 컨텍스트를 추가로 설정해야 한다.

### 4. LogAnalyzer 웹 화면 구성

#### 4-1. 로그 목록 화면

LogAnalyzer 설치 완료 후 메인 화면에는 수집된 로그가 시간 순서로 표시된다. 위로 갈수 록 최신 로그다.

각 로그 항목에는 다음 정보가 표시된다.


| 항목 | 설명 |
|---|---|
| 날짜/시간 | 로그 발생 시각 |
| 호스트 이름 | 로그가 발생한 시스템 (클라이언트 호스트 네임) |
| Facility | 로그의 분류 (cron, sshd 등) |
| Severity | 로그의 심각도 (Priority) |
| 메시지 | 로그 내용 |

#### 4-2. 로그 화면 설정

페이지당 표시할 로그 메시지 수를 설정할 수 있다.

자동 새로고침(Auto-reload) 주기를 설정할 수 있다.

## 064. LogAnalyzer, wget 명령어, 압축 파일 형식, 쉘 스크립트 개념

파일 형식, 쉘 스크립트 개념

### 1. LogAnalyzer 개요

#### 1-1. LogAnalyzer란

LogAnalyzer는 PHP 기반의 웹 애플리케이션으로, MariaDB에 저장된 rsyslog 로그 데이터를 웹 인터페이스에서 시각화하여 보여준다.

#### 1-2. 필요 구성 요소

LogAnalyzer가 정상적으로 동작하려면 다음 요소가 갖춰져 있어야 한다.


| 요소 | 설명 |
|---|---|
| APM (Apache, PHP, MariaDB) | 웹 서버 기반 환경 |
| PHP-MySQL 연결 패키지 | PHP와 데이터베이스를 연결하기 위한 패키지 |
| httpd (Apache) 서비스 | 웹 서비스가 실행 중이어야 웹 페이지 접근 가능 |

### 2. wget 명령어 — 셸에서 파일 다운로드

#### 2-1. wget 개요

wget 은 웹 브라우저 없이 셸(CLI)에서 파일을 다운로드할 수 있는 명령어다. GUI 환경이 없는 서버에서 파일을 내려받을 때 사용한다.

dnf install -y wget           ← wget이 없을 경우 설치 wget [다운로드 URL]           ← 현재 작업 디렉토리에 다운로드 wget -P /tmp [다운로드 URL]   ← 다운로드 경로를 /tmp로 지정 -P  옵션을 사용하면 다운로드 경로를 직접 지정할 수 있다. 지정하지 않으면 현재 작업 디렉토리에 저장된다.

### 3. 압축 파일 형식 — tar와 gz

#### 3-1. tar 파일

tar 는 여러 개의 파일이나 디렉토리를 하나의 파일로 묶는 것이다. 압축은 아니며, 묶기만한다.

#### 3-2. gz (gzip) 파일

.gz  확장자는 gzip 형식으로 압축된 파일을 의미한다.

#### 3-3. tar.gz 파일


| 확장자 | 의미 |
|---|---|
| .tar | 여러 파일/디렉토리가 하나로 묶여 있음 |
| .gz | gzip으로 압축되어 있음 |
| .tar.gz | 묶기(tar) + 압축(gz)이 동시에 적용된 아카이브 |

### 4. 셸 스크립트(Shell Script)

#### 4-1. 셸 스크립트 개요

.sh  확장자로 끝나는 파일은 셸 스크립트 파일이다. SQL 스크립트와 마찬가지로, 스크립트 란 파일 안에 있는 명령어들을 위에서부터 한 줄씩 순서대로 일괄 처리하는 것을 의미한다.

#### 4-2. 쉬뱅(Shebang)

셸 스크립트 파일의 맨 첫 줄에는 #!/bin/sh  또는 #!/bin/bash 와 같이 사용할 셸을 정의하는 구문이 온다. 이를 쉬뱅(shebang) 또는 c 방(#!) 이라고 한다.

#!/bin/sh      ← 사용할 셸 정의 (shebang) # 이후 스크립트 내용

#### 4-3. config.sh의 역할

LogAnalyzer 설치 패키지 안의 config.sh  스크립트를 실행하면 config.php  파일을 생성하고 적절한 권한을 자동으로 설정한다.

### 5. LogAnalyzer의 웹 디렉토리 구조

#### 5-1. 웹 서비스 루트 디렉토리

웹 서비스의 파일은 기본적으로 /var/www/html/  경로 아래에 위치해야 한다.

/var/www/html/loganalyzer/    ← LogAnalyzer 파일이 위치할 디렉토리

#### 5-2. 주요 파일


| 파일명 | 역할 |
|---|---|
| install.php | 최초 설치 시 웹 브라우저에서 실행하는 설치 스크립트 |
| index.php | 설치 완료 후 LogAnalyzer 시작 페이지 |
| config.php | LogAnalyzer 환경설정 파일 (config.sh 실행으로 생성됨) |

웹 서버(httpd) 서비스가 실행 중이어야 웹 브라우저에서 해당 파일에 접근할 수 있다. httpd가 동작하지 않으면 웹 페이지 자체가 열리지 않는다.

## 066. rsyslog-mysql 패키지(DB 설정)

### 1. 로그 저장을 위한 데이터베이스 구조

#### 1-1. 로그 저장에 필요한 DB 구조

로그 데이터를 MariaDB에 저장하려면 다음과 같은 구조가 필요하다.

데이터베이스 이름 (syslog)

└── 테이블 (SystemEvents, SystemEventsProperties)

└── 필드 (id, facility, priority, message ...) └── 실제 로그 데이터

#### 1-2. createdb.sql 스크립트

rsyslog-mysql  패키지를 설치하면 DB 구조를 자동으로 생성하는 SQL 스크립트가 함께 제공된다.

/usr/share/doc/rsyslog-mysql/createDB.sql    ← DB 자동 생성 스크립트 위치 기본적으로 패키지 설치 시 usr/share/doc/  경로에 관련 파일들이 저장된다.

스크립트는 위에서부터 한 줄씩 순서대로 처리되며, 이와 같이 일괄적으로 처리되는 파일을 스크립트라고 한다.

### 2. 생성되는 데이터베이스 구조

#### 2-1. 생성 SQL 개요

CREATE DATABASE syslog;        ← syslog 데이터베이스 생성 USE syslog;                    ← syslog 데이터베이스로 이동 CREATE TABLE SystemEvents ...  ← 로그 저장용 테이블 생성 CREATE TABLE SystemEventsProperties ...  ← 이벤트 속성 저장 테이블 생성

#### 2-2. 생성되는 테이블 구조


| 테이블명 | 주요 필드 | 설명 |
|---|---|---|
| SystemEvents | id, customerID, facility, priority, message | 로그 메시지 본체 저<br>장 |
| SystemEventsProperties | id, systemEventID, paramName,<br>paramValue | 이벤트 부가 속성 저<br>장 |

#### 2-3. auto-increment 개념

SQL에서 AUTO_INCREMENT 를 지정하면 id 값이 레코드가 추가될 때마다 자동으로 증가한다(1 → 2 → 3 → ...). 이를 통해 중복 없이 고유한 식별자를 유지할 수 있다.

increment 는 증가, decrement 는 감소를 의미한다. AUTO_INCREMENT 는 자동 증가를 나타낸다.

### 3. MariaDB 사용자 권한 설정

#### 3-1. rsyslog 전용 사용자 생성

rsyslog가 MariaDB에 접속하여 로그를 저장하려면 전용 사용자 계정을 생성하고 적절한 권한을 부여해야 한다.

GRANT ALL PRIVILEGES ON syslog.* TO 'rsyslog'@'localhost' IDENTIFIED BY 'password';


| 구성 요소 | 의미 |
|---|---|
| ALL PRIVILEGES ON syslog.* | syslog 데이터베이스의 모든 권한 부여 |
| 'rsyslog'@'localhost' | 사용자 이름은 rsyslog, 로컬에서만 접속 가능 |
| IDENTIFIED BY 'password' | 해당 사용자의 패스워드 설정 |

⚠️ 실제 운영 환경에서는 패스워드를 충분히 복잡하게 설정해야 한다.

#### 3-2. 로그 서버와 DB 서버가 분리된 경우

로그 서버와 DB가 서로 다른 시스템에 있다면 @'localhost'  대신 DB 서버의 IP 주소를 지정해야 한다.

GRANT ALL PRIVILEGES ON syslog.* TO 'rsyslog'@'[DB서버IP]' IDENTIFIED BY 'password';

### 4. rsyslog 출력 모듈 설정 (MySQL 연동)

#### 4-1. rsyslog.conf 출력 모듈 추가

rsyslog가 MariaDB로 로그를 보내도록 설정 파일에 출력 모듈을 추가한다.

# /etc/rsyslog.conf 파일 수정 $ModLoad ommysql              ← MySQL 출력 모듈 로드 *.*   :ommysql:[DB서버IP],syslog,rsyslog,password    ← 모든 로그를 DB로 전송


| 구성 요소 | 의미 |
|---|---|
| ommysql | rsyslog의 MySQL 출력 모듈 이름 |
| [DB서버IP] | DB가 로컬이면 localhost , 원격이면 해당 IP 입력 |
| syslog | 로그가 저장될 데이터베이스 이름 |
| rsyslog | DB 접속 사용자 이름 |
| password | DB 사용자 패스워드 |

#### 4-2. MySQL 포트 방화벽 허용

firewall-cmd --permanent --add-port=3306/tcp    ← MySQL 기본 포트 허용 firewall-cmd --reload                           ← 방화벽 설정 적용

## 067. rsyslog를 활용한 로그 전송

### 1. 중앙 집중형 로그 서버의 필요성

#### 1-1. 로컬 로그 관리의 한계

로그는 해킹 분석 및 시스템 분석 시 가장 필요한 데이터다. 그러나 각 시스템에서만 로그가 저장된다면 다음과 같은 문제가 발생한다.

cat , last  등의 명령어를 통해 그때그때마다 개별 시스템에서 직접 확인해야 하므로 관리가 어렵다.

로그가 분산되어 있어 통합 분석이 불가능하다.

#### 1-2. 중앙 집중형 로그 서버의 구조

이러한 문제를 해결하기 위해 로그 서버를 별도로 구축하여 클라이언트에서 발생하는 로그를 실시간으로 수집한다. 구성 흐름은 다음과 같다.


| 단계 | 구성 요소 | 역할 |
|---|---|---|
| 1단계 | 클라이언트 (rsyslog) | 이벤트 발생 → 로그를 서버로 전송 |
| 2단계 | 로그 서버 (rsyslog) | 클라이언트 로그를 수신하여 DB에 저장 |
| 3단계 | 데이터베이스 (MariaDB) | 로그를 구조화하여 저장 |
| 4단계 | 웹 인터페이스 (LogAnalyzer) | DB의 로그를 시각화하여 제공 |

#### 1-3. 로그 서버 활용의 장점

DB에 저장되므로 SQL 질의나 웹 인터페이스를 통해 언제든지 로그를 조회·검색할 수 있다. 또한 로그를 시각화하여 관리자가 더 효율적으로 로그를 분석할 수 있다. 향후 SIEM(보안 정보 및 이벤트 관리) 솔루션으로 발전 가능하다.

⚠️ 1단계(클라이언트 → 서버) 연결이 확인되지 않으면 이후 DB 저장, 웹 시각화 작업이 모두 의미 없다. 단계별 확인이 필수다.

#### 1-4. 백업 로그 서버

로그는 중요하기 때문에 주 로그 서버 외에 백업 로그 서버를 추가로 구성하여 이중화하는 것이 일반적이다.

### 2. rsyslog 서비스

#### 2-1. 개요

rsyslog는 클라이언트와 서버 간에 로그를 전송하는 서비스다. 서버와 클라이언트 양쪽 모 두에 공통으로 설치 및 실행되어야 한다.

#### 2-2. 설치 패키지

dnf install -y rsyslog rsyslog-doc    ← 서버·클라이언트 공통 설치

#### 2-3. 서비스 관리

systemctl start rsyslog     ← rsyslog 서비스 시작 systemctl enable rsyslog    ← 재부팅 후에도 자동 실행 (영구 적용)

enable 은 재부팅 이후에도 해당 서비스가 자동으로 시작되도록 등록한다. permanent 와 같은 의미다.

### 3. rsyslog 서버 설정

#### 3-1. 설정 파일 위치

/etc/rsyslog.conf    ← rsyslog 주 환경설정 파일 설정 파일은 다음과 같은 섹션으로 구성된다.


| 섹션 | 설명 |
|---|---|
| GLOBAL DIRECTIVES | 전역 설정 |
| MODULES | 입출력 모듈 설정 |
| RULES | 로그 저장 규칙 설정 |

#### 3-2. 서버 입력 모듈 설정

서버에서 클라이언트의 로그를 수신하려면 MODULES  섹션에 아래 내용을 추가한다.

$ModLoad imtcp               ← TCP 입력 모듈 로드 $InputTCPServerRun 514       ← TCP 514번 포트로 로그 수신 대기 $ModLoad imudp               ← UDP 입력 모듈 로드 $UDPServerRun 514            ← UDP 514번 포트로 로그 수신 대기 ⚠️ 대소문자를 정확하게 입력해야 한다. $ModLoad , imtcp , $InputTCPServerRun  모두 대소문자 구분이 있다.

#### 3-3. rsyslog 전송 포트

rsyslog는 기본적으로 514번 포트를 사용하며 TCP와 UDP 두 가지 프로토콜을 지원한다. 서버의 방화벽에서 해당 포트를 허용해야 한다.

firewall-cmd --permanent --add-port=514/tcp    ← TCP 514번 허용 firewall-cmd --permanent --add-port=514/udp    ← UDP 514번 허용 firewall-cmd --reload                          ← 방화벽 설정 적용

### 4. rsyslog 클라이언트 설정

#### 4-1. 클라이언트 설정 내용

클라이언트도 동일하게 /etc/rsyslog.conf  파일의 맨 마지막 줄에 다음 내용을 추가하여 어느 서버로 로그를 보낼지 지정한다.

*.*    @@[서버IP]:514    ← 모든 로그를 서버로 TCP 전송 *.*    @[서버IP]:514     ← 모든 로그를 서버로 UDP 전송

#### 4-2. 설정 문법 의미


| 구성 요소 | 의미 |
|---|---|
| *.* | 모든 Facility(분류)의 모든 Priority(심각도) 로그 |
| @@ | TCP 프로토콜 사용 |
| @ | UDP 프로토콜 사용 |
| [서버IP]:514 | 로그를 전송할 서버 IP와 포트 번호 |

### 5. 네트워크 연결 확인 명령어

#### 5-1. lsof 명령어

열려 있는 파일 및 포트 목록을 확인한다.

lsof -i tcp::514    ← TCP 514번 포트 상태 확인 lsof -i udp::514    ← UDP 514번 포트 상태 확인

#### 5-2. netstat 명령어

net-tools  패키지를 설치해야 사용 가능하다. Windows에서는 기본으로 내장되어 있으나, 리눅스에서는 별도 설치가 필요하다.

dnf install -y net-tools    ← netstat 사용을 위한 패키지 설치 netstat -natp               ← 현재 네트워크 연결 상태 확인 netstat -natp | grep 514    ← 514번 포트만 필터링

#### 5-3. 연결 상태 구분


| 상태 | 의미 |
|---|---|
| LISTEN | 연결을 기다리는 상태 (접속 대기) |
| ESTABLISHED | 연결이 성립된 상태 |

서버에서 0.0.0.0:514 로 LISTEN 상태가 확인되면, 모든 네트워크로부터 514번 포트로 수신 대기 중임을 의미한다.

### 6. 파이프(|) 명령어

두 개 이상의 명령어를 연결할 때 사용하는 특수 문자다. 앞 명령어의 실행 결과를 뒤 명령어의 입력값으로 전달한다.

netstat -natp | grep 514    ← netstat 결과 중 514가 포함된 줄 만 출력 키보드에서 Shift + \\  (또는 Enter  키 위의 |  키)로 입력한다. 내용이 많은 출력 결과에서 필요한 부분만 빠르게 확인할 때 자주 활용된다.

### 7. 실시간 로그 모니터링

tail -f /var/log/messages    ← 서버에서 실시간 로그 수신 확인 서버에서 위 명령을 실행한 후 클라이언트에서 이벤트를 발생시키면(예: systemctl restart sshd ), 클라이언트의 로그가 서버 /var/log/messages 에 실시간으로 기록된다.

## 068. Syslog Facility Priority의 개념, 로그 레벨 이해

Syslog Facility/Priority의 개념, 로그 레벨 이해

### 1. Syslog 개요

#### 1-1. Syslog의 구성 요소

Syslog는 로그 메시지를 분류하고 관리하기 위해 두 가지 주요 요소로 구성된다:

Facility: 로그가 발생한 출처나 카테고리 Priority: 로그의 우선순위 또는 심각도

### 2. Facility (시설/카테고리)

#### 2-1. Facility의 정의

Facility는 로그가 어디서 발생했는지를 나타내는 분류 항목이다. 로그 메시지의 출처를 식 별하는 데 사용된다.

#### 2-2. 주요 Facility 종류


| Facility | 설명 |
|---|---|
| AUTH | 인증과 관련된 로그 (사용자 로그인, 비밀번호 관련) |
| LPR | 프린터 서비스와 관련된 로그 |
| Syslog | Syslog 대몬 자체에서 발생하는 로그 |
| Local 0-7 | 사용자 정의 목적으로 사용 가능한 로그 카테고리 |

#### 2-3. Facility의 역할

어떤 로그가 AUTH로 지정되어 있으면 인증 관련 로그임을 알 수 있다. 마찬가지로 LPR이 면 프린트 관련 기록임을 식별할 수 있다. 따라서 로그를 빠르게 분류하고 원하는 항목을 찾는 데 도움이 된다.

### 3. Priority (우선순위/심각도)

Syslog Facility/Priority의 개념, 로그 레벨 이해

#### 3-1. Priority의 개념

Priority는 로그의 우선순위 또는 심각도(Severity Level)를 나타낸다. 발생한 문제가 시스템에 미치는 영향의 정도를 표현한다.

#### 3-2. Priority 레벨 (0-7)


| 레벨 | 이름 | 설명 | 영향도 |
|---|---|---|---|
| 0 | Emergency (이머젠시) | 시스템 사용 불가능한 긴급 상황 | 매우 높음 |
| 1 | Alert | 즉시 조치가 필요한 상황 | 매우 높음 |
| 2 | Critical | 심각한 상황 | 높음 |
| 3 | Error | 오류 발생 | 중간 |
| 4 | Warning | 경고 상황 | 중간 |
| 5 | Notice | 일반적인 알림 | 낮음 |
| 6 | Informational | 정보성 메시지 | 낮음 |
| 7 | Debug | 디버깅 정보 | 최하위 |

#### 3-3. 심각도의 의미

어떤 일이 발생했을 때, 그 문제가 시스템에 얼마만큼 영향을 미칠 것인가를 나타내는 것이 심각도이다. Emergency 레벨이 발생하면 시스템에 아주 긴급한 문제가 있다는 의미이고, 적극적인 조치를 하지 않으면 시스템이 정상적으로 동작하지 않는다.

#### 3-4. Warning 레벨의 일반적 사용

대부분의 서비스가 구동될 때, 로그 관련 심각도는 기본적으로 Warning 레벨로 정해져 있다. 이는 일반적인 운영 환경에서의 표준 레벨이다.

#### 3-5. Debug 레벨의 특징

Debug 레벨은 가장 낮은 우선순위를 가지므로, 개발 또는 문제 해결 시 상세한 정보를 확인할 때 사용된다.

### 4. Facility와 Priority의 조합

#### 4-1. 로그의 완전한 분류

로그 메시지는 Facility와 Priority의 조합으로 완전하게 분류된다:

Facility는 로그의 출처(어디서)를 나타낸다

Priority는 로그의 중요도(얼마나 심각한지)를 나타낸다

Syslog Facility/Priority의 개념, 로그 레벨 이해

#### 4-2. 로그 처리의 실제 적용

로그 관리 정책에서:

특정 Facility의 특정 Priority 이상만 기록하도록 설정할 수 있다

Emergency 레벨의 로그는 즉시 관리자에게 알림을 보낼 수 있다

낮은 Priority의 로그는 보존 기간을 짧게 설정할 수 있다

### 5. Syslog 설정 원리

#### 5-1. 로그 분류의 중요성

로그는 대량으로 생성되기 때문에 Facility와 Priority를 통해 체계적으로 분류해야 한다. 이를 통해 필요한 정보를 빠르게 찾고, 중요한 로그에 우선순위를 부여할 수 있다.

#### 5-2. 설정값 변경의 영향

Syslog 설정 파일에서 설정값을 변경하면 기록되는 로그의 내용과 형식이 변경될 수 있다. 따라서 로그 관리 정책을 조정할 때는 신중하게 변경해야 한다.

## 069. 시스템 로그 관리 및 분석(리눅스 웹 서버)

서버)

### 1. 로그 관리의 중요성

#### 1-1. 로그의 정의와 보안적 가치

시스템에서 발생하는 모든 사건과 작업은 로그라고 불리는 기록에 저장된다. 로그는 단순한 기록을 넘어 보안적으로도 중요한 부분이다.

#### 1-2. 법적 규제와 로그 보존

법적으로 일정 수준 이상의 시스템에서는 로그를 마음대로 삭제할 수 없도록 규정되어 있다. 어떤 일이 일어났는지 확인할 수 있는 중요한 정보들이 포함되어 있기 때문이다. 개인이나 소규모 시스템에서는 삭제가 가능하지만, 기본적으로 시스템이나 장비에서 발생하는 모든 작업은 기록된다.

### 2. 웹 서버 로그 구조

#### 2-1. 웹 서버 디렉토리 구조

웹 서버의 설정과 로그는 /etc/httpd/  경로 아래에 위치한다. 이 디렉토리 내에 웹 서비스와 관련된 모든 내용이 저장된다.

#### 2-2. 로그 파일의 위치 및 심볼릭 링크

/etc/httpd/logs  디렉토리는 심볼릭 링크이며, 실제 로그 파일은 /var/log/  경로에 저장되어 있다. 이러한 구조를 통해 웹 서비스와 관련된 다양한 로그 파일들을 관리한다.

### 3. HTTP 웹 서비스 로그

#### 3-1. 로그 파일의 종류


| 파일명 | 용도 | 설명 |
|---|---|---|
| access.log | 정상 접속 기록 | HTTP를 통한 모든 정상 접속 정보 |


| 파일명 | 용도 | 설명 |
|---|---|---|
| access_log | HTTPS 접속 | SSL/TLS를 통한 보안 접속 기록 |
| error.log | 접속 오류 | 접속 시 발생한 오류 정보 |
| ssl_error.log | HTTPS 오류 | 보안 접속 관련 오류 |

#### 3-2. Access Log의 구조

접속 로그는 다음 정보를 포함한다:

클라이언트의 IP 주소 접속 시간 및 날짜 HTTP 요청 방식 (GET, POST 등)

요청한 리소스 경로 HTTP 상태 코드 User-Agent (브라우저 정보)

#### 3-3. 로그 파일 분석

로그 파일은 시간 순서로 기록되며, 맨 아래의 최신 항목부터 위로 올라갈수록 이전 기록이 다. 각 접속에 대해 IP 주소, 접속 시간, 요청 방식, User-Agent 값 등의 정보를 확인할 수 있다.

#### 3-4. Error Log의 역할

오류 로그에는 접속 시도 중에 발생한 오류 정보가 기록된다. 옵션 불일치, 설정 오류 등 다양한 접속 실패 원인을 파악할 수 있다.

### 4. 기타 서비스 로그

#### 4-1. 데이터베이스 로그

MariaDB 같은 데이터베이스도 /var/log/  하위의 별도 디렉토리에서 관리되며, DB와 관련된 여러 로그들이 존재한다.

#### 4-2. FTP 서비스 로그

FTP 서비스는 xferlog  파일에 로그가 기록된다. FTP 업로드, 다운로드 등의 기록이 여기에 저장된다.

#### 4-3. Samba 로그

Samba 서비스는 별도의 디렉토리에서 관리되며, Samba와 관련된 기록이 저장된다.

### 5. 사용자 로그인 기록 파일

#### 5-1. WTMP 파일 (로그인/로그아웃 기록)


| 특징 | 설명 |
|---|---|
| 저장 위치 | /var/log/wtmp |
| 파일 형식 | 바이너리 데이터 파일 |
| 기록 내용 | 사용자 로그인, 로그아웃 |
| 추가 기록 | 시스템 부팅, 종료, 리부팅 |
| 조회 명령어 | last |

WTMP 파일은 사용자가 로그인했거나 로그아웃했을 때의 정보를 저장한다. 일반 텍스트 파일이 아니라 바이너리 데이터 형식으로 저장되므로 직접 읽을 수 없다. last  명령어를 사용하여 읽을 수 있다.

#### 5-2. BTMP 파일 (로그인 실패 기록)


| 특징 | 설명 |
|---|---|
| 저장 위치 | /var/log/btmp |
| 파일 형식 | 바이너리 데이터 파일 |
| 기록 내용 | 원격 접속 실패 기록 |
| 조회 명령어 | last -b |

BTMP 파일에는 SSH나 기타 원격 접속 시도 중 실패한 기록이 저장된다. SSH 접속 실패, 로그인 오류 등이 기록된다.

#### 5-3. UTMP 파일 (현재 로그인 세션)


| 특징 | 설명 |
|---|---|
| 파일 형식 | 바이너리 데이터 파일 |
| 기록 내용 | 현재 시스템에 로그인한 사용자 정보 |
| 조회 명령어 | w , who , finger |

UTMP 파일은 현재 시스템에 로그인한 사용자들의 정보를 포함한다.

#### 5-4. Lastlog 파일 (최근 로그인 정보)


| 특징 | 설명 |
|---|---|
| 저장 위치 | /var/log/lastlog |
| 기록 내용 | 각 사용자의 가장 최근 로그인 정보 |
| 조회 명령어 | lastlog |

각 사용자의 가장 최근 로그인 시간, 터미널, 로그인 위치 등을 나타낸다.

### 6. 명령어 히스토리

#### 6-1. Bash History 파일

각 사용자가 내린 명령어는 해당 사용자의 홈 디렉토리에 .bash_history  파일로 저장된다. 숨김 파일(점으로 시작)이므로 ls -a  명령으로만 볼 수 있다.

#### 6-2. 히스토리 파일의 특징

사용자별로 별도의 히스토리 파일이 존재한다

명령어 실행 시간 정보는 포함되지 않는다

명령어 목록만 저장된다

터미널에서 위/아래 화살표 키로 과거 명령어를 확인할 수 있다

#### 6-3. 히스토리 파일 위치

Root 사용자: /root/.bash_history 일반 사용자: /home/[username]/.bash_history

#### 6-4. 보안 관점의 주의사항

침입자는 자신의 명령어를 은폐하기 위해 히스토리 파일을 삭제하거나, 심볼릭 링크를 변경할 수 있다.

### 7. Secure 로그 파일

#### 7-1. 정의와 저장 위치

Secure 로그는 원격 접속 및 사용자 인증과 관련된 모든 기록을 저장한다. 저장 위치는 /var/log/secure 이다.

#### 7-2. 기록 내용


| 항목 | 설명 |
|---|---|
| SSH 접속 | sshd 서비스를 통한 원격 접속 기록 |
| FTP 접속 | FTP 서비스를 통한 인증 기록 |
| 사용자 인증 | 모든 사용자 인증 과정과 결과 |
| 패스워드 변경 | 사용자 패스워드 변경 기록 |
| 새 사용자 생성 | 새 사용자 계정 생성 기록 |

#### 7-3. 로그 분석

Secure 로그는 일반 텍스트 파일이므로 cat  명령어로 직접 읽을 수 있다. 시간 순서로 기록 되며, 아래쪽부터 최신 기록이다.

#### 7-4. 보안 감시 중요성

이 파일을 통해 비정상적인 접속 시도, 비인가 로그인, 패스워드 공격 등을 감지할 수 있다.

### 8. Messages 로그 파일

#### 8-1. 역할과 중요성

Messages 로그는 로그인 기록, 디바이스 정보, 시스템 설정 오류, 파일 시스템 네트워크 연결 기록 등 매우 다양한 내용을 포함한다. 상당히 중요한 로그 파일이다.

#### 8-2. 기록 내용의 범위

시스템 시작(Booting) 및 종료 기록 패키지 설치/업그레이드 기록 네임 서비스(DNS) 관련 기록 FTP, SSH 등 주요 서비스 기록 시스템 오류 및 경고

#### 8-3. 파일 형식

텍스트 형식으로 저장되므로 cat  명령어로 직접 읽을 수 있다.

#### 8-4. 대용량 로그 검색

로그 파일이 매우 크면 grep  명령어를 사용하여 필요한 부분만 빠르게 검색할 수 있다.

grep "검색문자열" /var/log/messages  ← 특정 문자열 검색 grep "192.168.100.91" /var/log/messages  ← 특정 IP 검색

### 9. 시스로그(Syslog) 관리

#### 9-1. 시스로그의 역할

Syslog는 시스템 로그 관리를 담당하는 프로세스다. 로그 파일에 기록되는 내용과 형식을 제어한다.

#### 9-2. 설정 파일

## 074. 리눅스 계정 파일 구조, Salt, 파일 권한과 umask

한과 umask

### 1. 리눅스 계정 관리 개요

시스템 보안에서 로그 관리, 계정 관리, 권한 관리는 핵심 요소이다. 이 중 계정과 권한 관리는 보안 점검 시 가장 기본이 되는 항목에 해당한다.

계정과 관련된 정보는 /etc/passwd 와 /etc/shadow  두 파일에 나뉘어 저장된다.

### 2. /etc/passwd  파일 구조

cat /etc/passwd 각 레코드(행)는 콜론( : )으로 구분된 7개의 필드로 구성된다.


| 필드 번호 | 필드명 | 설명 |
|---|---|---|
| 1 | 사용자 계정명 | 시스템에 로그인할 때 사용하는 계정 이름 |
| 2 | 패스워드 | x 는 암호가 /etc/shadow 에 암호화되어 저장되어 있음을<br>의미 |
| 3 | UID (User ID) | 사용자 식별 번호. 관리자(root)는 0 , 일반 사용자는 1000<br>부터 부여 |
| 4 | GID (Group ID) | 사용자가 속한 그룹 식별 번호. root의 기본값은 0 |
| 5 | 사용자 설명(이름) | 시스템에 영향 없는 사용자 설명 정보. 통상 계정명과 동일하<br>게 기입 |
| 6 | 홈 디렉토리 | 해당 사용자가 로그인 시 이동하는 기본 디렉토리 경로 |
| 7 | 기본 셸 | 로그인 시 실행되는 셸 경로 (예: /bin/bash ) |

⚠️ UID와 GID 값이 0 인 계정은 root와 동일한 권한을 가진다. 일반 사용자 계정이라도 UID/GID를 0 으로 변경하면 관리자 권한을 획득하게 되므로, 정기적으로 이 값을 점검해야 한다.

리눅스 버전에 따라 일반 사용자 UID 시작값이 다를 수 있다. Rocky Linux 등 최신 계열은 1000 부터, 일부 구버전(CentOS 7 이전 등)은 500 부터 부여하는 경우도 있다.

### 3. /etc/shadow  파일 구조

cat /etc/shadow /etc/shadow  파일에는 계정별 암호화된 패스워드와 패스워드 정책 정보가 저장된다.


| 필드 번호 | 설명 |
|---|---|
| 1 | 사용자 계정명 |
| 2 | 암호화된 패스워드 (알고리즘 식별자 + 솔트 + 해시값) |
| 3 | 1970년 1월 1일부터 마지막 패스워드 변경일까지의 경과 일수 |
| 4 | 패스워드를 변경한 후 변경 전 사용 기간(일수) |
| 5 | 패스워드 최대 사용 기간. 이 일수가 경과하면 변경을 요구. (기본값: 9999 ) |
| 6 | 패스워드 만료 전 경고 통지 일수 (예: 7 이면 만료 7일 전 경고) |
| 7 | 패스워드 만료 후 계정 사용 불가 전까지의 유예 기간(일수) |
| 8 | 1970년 1월 1일부터 계정 완전 비활성화 날짜까지의 일수 |
| 9 | 관리자 임의 설정 필드(예약) |

패스워드 만료 기간을 60일로 설정하더라도, 만료 이후에 갑자기 통보하는 것이 아니라 만료 전 7일 등 미리 경고 메시지를 통해 사용자에게 변경을 안내해야 한다.

### 4. 패스워드 암호화 알고리즘과 솔트(Salt)

#### 4-1. 암호화 알고리즘 식별자

/etc/shadow  두 번째 필드의 패스워드 문자열은 $알고리즘식별자$솔트$해시값 형식으로 구성된다.


| 식별자 | 알고리즘 |
|---|---|
| $1$ | MD5 |
| $5$ | SHA-256 |
| $6$ | SHA-512 (현재 대부분의 최신 리눅스 시스템 기본값) |

비트 수가 클수록 해독이 어렵다. 최신 리눅스 버전은 대부분 $6$ (SHA-512)를 사용하며, 구버전(CentOS 7 이전 등)일수록 낮은 알고리즘이 사용될 수 있다.

#### 4-2. 솔트(Salt)의 역할

솔트는 동일한 패스워드라도 암호화된 결과값이 달라지도록 랜덤하게 추가되는 값이다.

솔트 없이 동일한 알고리즘으로 동일한 문자열을 해시하면 결과값이 항상 동일하다.

공격자가 알고리즘을 알고 있으면, 미리 계산한 해시값 목록(레인보우 테이블)으로 패스워드를 역추적할 수 있다.

솔트를 적용하면, 동일한 패스워드라도 계정마다 솔트 값이 달라 해시 결과가 다르게 나와 역추적이 어렵다.

⚠️ 솔트(Salt) 개념은 정보보안기사 시험에서 출제되는 항목이다.

### 5. 파일 및 디렉토리 유형 표기

ls -al  명령어 출력의 첫 번째 문자는 파일 유형을 나타낸다.


| 표기 | 유형 | 설명 |
|---|---|---|
| d | 디렉토리 | 일반 디렉토리 |
| - | 일반 파일 | 일반 파일 |
| l | 심볼릭 링크 | 다른 파일/디렉토리에 링크된 파일 |
| c | 캐릭터 특수 파일 | 버퍼에 저장되지 않는 특수 파일 (예: 터미널 파일) |
| b | 블록 특수 파일 | 버퍼링된 특수 파일 (예: 디스크 드라이버) |
| s | 소켓 파일 | 네트워크 연결을 위한 소켓 파일 |
| p | 파이프 파일 | 파이프 기능을 수행하는 파일 |

### 6. 파일 권한과 umask

#### 6-1. 기본 생성 권한

파일과 디렉토리가 생성될 때 부여되는 기본 권한은 umask 값에 의해 결정된다.

umask        ← 현재 umask 값 확인 기본 umask 값은 0022 이며, 각 유형별 기본 권한 계산 방식은 다음과 같다.


| 유형 | 최대 권한 | umask 값 | 기본 생성 권한 |
|---|---|---|---|
| 디렉토리 | 777 | 022 | 755 |
| 파일 | 666 | 022 | 644 |

#### 6-2. umask 값 변경과 보안

umask 0027    ← umask 값 변경 (예시)

umask 0022    ← 원래 값으로 복구 ⚠️ umask 값이 임의로 변경되어 있으면, 이후 생성되는 파일과 디렉토리가 예기치 않은 권한을 가지게 된다. 정기적인 보안 점검 시 umask 값 변경 여부를 반드시 확인해야 한다.

### 7. 파일 권한 변경 (chmod)

파일이나 디렉토리의 권한은 chmod  명령어로 변경할 수 있다.

chmod 777 test.txt    ← test.txt에 rwxrwxrwx 권한 부여

### 8. 소유주 및 그룹 변경 (chown, chgrp)

파일의 소유주와 그룹도 루트 계정에서 변경할 수 있다.

chown root ttt.txt    ← ttt.txt의 소유주를 root로 변경 chgrp root ttt.txt    ← ttt.txt의 그룹을 root로 변경 chown : change owner (소유주 변경)

chgrp : change group (그룹 변경)

### 9. 계정 관리와 스크립트 활용

계정 현황 점검을 위해 /etc/passwd 나 /etc/shadow  파일을 매번 수동으로 확인하는 것은 비 효율적이다. 실무에서는 관리에 필요한 명령어들을 스크립트로 작성하여 실행함으로써 결과를 자동으로 확인하는 방식을 사용한다.

## 075. 리눅스 기본 명령어, 도움말·시스템·탐색 명령어

탐색 명령어

### 1. 리눅스 명령어 구조

리눅스 명령어는 기본적으로 명령어 [옵션] [인자(argument)]  형태로 구성된다.

짧은 옵션(한 글자)은 하나의  뒤에 묶어 사용할 수 있다.

예: ls -al 은 ls -a -l 과 동일 인자(argument)는 하나 이상 여러 개를 지정할 수 있다.

예: ls -la /etc /home  → /etc 와 /home  두 디렉토리 내용을 함께 출력 대부분의 명령 실행 중 Ctrl+C 를 누르면 명령을 중단할 수 있다.

### 2. 도움말 명령어

관리자라도 모든 명령어와 옵션을 외우지 않는다. 필요할 때 도움말 명령어를 활용한다.


| 명령어 | 설명 |
|---|---|
| 명령어 --help 또는 명령어 -h | 해당 명령어의 간단한 사용법과 옵션 목록 출력 |
| man 명령어 | 명령어의 상세 매뉴얼 페이지 출력. q 를 눌러 종료 |
| apropos 키워드 | 키워드와 관련된 명령어 목록과 설명 출력 |
| whatis 명령어 | 명령어의 짧은 한 줄 설명 출력 |

### 3. 시스템 종료 및 재부팅

shutdown          ← 시스템 종료 shutdown -h now   ← 즉시 셧다운 (halt) shutdown -r       ← 셧다운 후 재부팅 reboot            ← 시스템 재부팅 셧다운 명령 시 특정 시간 이후 종료하거나 사용자에게 메시지를 전달하는 옵션도 존재한다.

### 4. history 명령어

history 는 사용자가 입력했던 명령어 목록을 표시한다. 명령어 이력은 홈 디렉토리의 숨김 파일 .bash_history 에 저장된다.

history           ← 현재 세션 명령어 이력 출력 history -w        ← 현재 세션 이력을 .bash_history 파일에 저장 history -c        ← 현재 세션의 임시 이력만 삭제 (파일 내용은 유지) cat ~/.bash_history   ← 저장된 이력 파일 직접 확인 history -c 로 삭제되는 것은 현재 세션의 임시 이력뿐이며, .bash_history  파일에 저장된 내용은 삭제되지 않는다.

### 5. echo 명령어

echo 는 지정한 문자열을 터미널에 출력한다. 셸 스크립트 작성이나 웹 연동 작업에서 자주 사용된다.

echo "test"       ← "test" 문자열을 터미널에 출력

### 6. date 명령어

date 는 시스템의 현재 날짜와 시간 정보를 출력하거나 변경할 때 사용한다.

date              ← 현재 날짜·시간 출력 date -d "20260407"    ← 특정 날짜 정보 출력 date -s "20260407 10:27"  ← 시스템 날짜·시간 변경 우리나라 표준 연구원의 타임 서버는 전 세계 최고 수준의 정밀도를 보유하며, 시스템 설치 시 Asia/Seoul로 설정하면 해당 타임 서버를 통해 시간이 동기화된다.

### 7. 계정 및 접속 정보 확인 명령어


| 명령어 | 설명 |
|---|---|
| id | 현재 사용자의 UID, GID, 소속 그룹 정보 출력. CTF 등에서 루트 권한 탈취 여부<br>확인에 사용 |
| who | 현재 시스템에 로그인한 사용자 목록과 접속 시간, 접속 터미널 유형 출력 |
| whoami | 현재 접속 중인 사용자 이름만 출력 |
| pwd | 현재 작업 디렉토리의 절대 경로 출력 |

#### 7-1. TTY와 PTS 구분

who  명령 출력에서 접속 터미널 유형을 통해 접속 방식을 확인할 수 있다.


| 표기 | 의미 |
|---|---|
| tty | 로컬 터미널에서 직접 접속 |
| pts/숫자 | 가상 콘솔(원격 접속 또는 가상 터미널). 숫자는 가상 콘솔 번호 |

동시에 여러 원격 접속이 이루어지면 pts/0 , pts/1  등으로 순서가 부여된다.

### 8. find 명령어

find 는 파일이나 디렉토리를 조건에 따라 검색하는 명령어로, 실무에서 자주 사용된다.

find /경로 -name "파일명"         ← 파일 이름으로 검색 find / -name "sshd_config"        ← 최상위 디렉토리부터 sshd_config 검색 find / -perm 4000                 ← 특정 권한(4000)을 가진 파일 검색 find /etc -name "파일명" -perm 4000   ← 이름과 권한 조건을 함께 사용 두 가지 이상의 조건을 동시에 사용할 수 있다.

### 9. ls 명령어 주요 옵션


| 옵션 | 설명 |
|---|---|
| -l | 목록 형식으로 자세히 출력 |
| -a | 숨김 파일 포함 출력 |
| -tr | 마지막 수정 날짜 역순(오래된 것 먼저)으로 정렬하여 출력 |
| -d | 디렉토리 자체의 정보를 출력 (내용이 아닌 디렉토리 항목 자체) |
| -S | 파일 크기 큰 것부터 정렬 출력 |
| --hide=*.확장자 | 지정한 확장자 파일을 출력에서 제외 |

기본 정렬은 알파벳 또는 숫자 순이다.

### 10. mkdir 명령어 - 하위 디렉토리 일괄 생성

mkdir 디렉토리명           ← 단일 디렉토리 생성 mkdir -p test3/test4/test5 ← 중간 경로가 없어도 하위 디렉토리까지 한꺼번에 생성 p  옵션이 없으면 상위 디렉토리가 존재하지 않을 경우 생성에 실패한다.

### 11. rmdir 명령어 - 빈 디렉토리 삭제

rmdir 디렉토리명    ← 비어있는 디렉토리만 삭제 가능 디렉토리 안에 파일이 하나라도 존재하면 rmdir 은 실패한다. 이 경우 rm  명령어를 사용해야 한다.

## 077. 파일 조작·검색·출력 명령어, 표준 입출력과 리디렉션

출력과 리디렉션

### 1. rm 명령어 (파일·디렉토리 삭제)

rmdir 은 빈 디렉토리만 삭제할 수 있다. 내부에 파일이 존재하는 디렉토리를 삭제하려면 rm  명령어를 사용한다.

rm -rf 디렉토리명    ← 내용물이 있는 디렉토리 강제 삭제 rm -ri 디렉토리명    ← 삭제 여부를 대화형으로 묻고 삭제


| 옵션 | 설명 |
|---|---|
| -r | 디렉토리와 하위 내용 모두 삭제 |
| -f | 삭제 여부를 묻지 않고 강제 삭제 |
| -i | 대화형(interactive)으로 삭제 여부를 묻고 진행 |

옵션은 명령어 뒤에 위치해야 하며, 명령어 앞에는 둘 수 없다.

### 2. mv 명령어 (이동 및 이름 변경)

mv 는 파일 또는 디렉토리를 이동하거나 이름을 변경할 때 사용한다. 이동 시 원본 위치에서 는 삭제된다.

mv 원본파일 대상경로/파일명    ← 이동 (이름을 동일하게 유지) mv 원본파일 새이름             ← 이름 변경 mv 원본파일 대상경로/새이름    ← 이동과 이름 변경 동시 수행

### 3. file 명령어 (파일 유형 확인)

file  명령어는 파일의 종류(텍스트 파일, 바이너리, 디렉토리 등)를 출력한다. 악성코드 분석 등에서도 활용된다.

file /etc/passwd              ← 단일 파일 유형 확인 file /etc/passwd /etc/shadow  ← 여러 파일 유형 동시 확인

### 4. tac 명령어 (역순 출력)

tac 은 cat 의 역방향 동작으로, 파일 내용을 마지막 줄부터 역순으로 출력한다.

cat /var/log/messages    ← 파일 내용을 정순 출력 tac /var/log/messages    ← 파일 내용을 역순 출력 (최신 로그가 먼저 표시)

로그 파일처럼 양이 많고 최신 내용을 먼저 확인하고 싶을 때 유용하다.

### 5. sort 명령어 (정렬)

sort 는 파일 내용을 정렬하여 출력한다. 기본값은 알파벳·숫자 오름차순이다.

sort /etc/passwd        ← 알파벳 오름차순 정렬 sort -r /etc/passwd     ← 역순 정렬 다양한 정렬 기준(알파벳, 숫자, 역순, 특정 열 기준 등)을 옵션으로 지정할 수 있다.

### 6. nmcli 명령어 (네트워크 설정 CLI)

nmcli 는 네트워크 설정을 명령행(CLI) 방식으로 수행하는 도구이다. nmtui (텍스트 UI 방식)와 같은 역할을 수행한다.

nmcli connection up 인터페이스명    ← 특정 인터페이스 활성화 ⚠️ nmtui 와 nmcli  두 도구를 동시에 사용하여 주소를 설정하면, 동일 주소가 중복 등록 되거나 통신 오류가 발생할 수 있다. 반드시 하나의 도구로만 설정한다.

### 7. find 명령어 심화 — 다중 조건 검색

find 에서 여러 조건을 동시에 지정하여 검색할 수 있다.

find / -name "파일명" -perm 4000 -user root ← 최상위 디렉토리부터, 이름이 '파일명'이고, 권한이 4000이며, 소유주가 root인 파일 검색


| 조건 옵션 | 설명 |
|---|---|
| -name | 파일 이름으로 검색 |
| -perm | 파일 권한으로 검색 |
| -exec | 실행 파일(이진파일) 검색 |
| -user | 특정 소유주를 가진 파일 검색 |

### 8. whereis 명령어 (명령어 위치 검색)

whereis 는 명령어의 실행 파일, 소스, 매뉴얼 페이지 경로를 출력한다.

whereis ls       ← ls 명령어의 위치 확인 whereis -b ls    ← 이진파일(실행파일) 경로만 확인 ls  명령어를 내리면, whereis 로 확인한 경로의 실행 파일이 실행되어 결과가 출력된다.

### 9. grep 명령어 (문자열 검색)

grep 은 파일 내에서 특정 문자열을 검색한다. 일부 문자열만 입력해도 관련 내용이 모두 출력된다. 로그 파일처럼 내용이 방대한 경우 특히 유용하다.

grep "root" /etc/passwd         ← /etc/passwd에서 "root" 포함 행 출력 grep -i "root" /etc/passwd      ← 대소문자 구분 없이 검색 grep -w "root" /etc/passwd      ← 정확히 "root"라는 단어만 검색


| 옵션 | 설명 |
|---|---|
| -i | 대소문자 무시(case-insensitive) |
| -w | 정확한 단어(word) 단위 검색 |

### 10. 표준 입출력 스트림

리눅스(유닉스 계열)에서는 세 가지 표준 스트림(채널)을 통해 입출력이 이루어진다.


| 스트림 | 채널 번호 | 기본 장치 | 설명 |
|---|---|---|---|
| stdin (표준 입력) | 0 | 키보드 | 명령 및 데이터를 입력받는 채널 |
| stdout (표준 출력) | 1 | 모니터(화면) | 명령 실행 결과를 출력하는 채널 |
| stderr (표준 에러) | 2 | 모니터(화면) | 에러 메시지를 출력하는 채널 |

### 11. 리디렉션(Redirection)

리디렉션이란 표준 입출력의 방향을 관리자가 원하는 방향으로 바꾸는 것을 말한다.


| 기호 | 종류 | 설명 |
|---|---|---|
| < | 입력 리디렉션 | 키보드 대신 파일에서 입력을 읽어들임 |
| > | 출력 리디렉션 | 화면 대신 파일로 결과를 출력(기존 내용 덮어씀) |
| >> | 추가 출력 리디렉션 | 파일 끝에 내용을 추가하여 출력 |

echo "test" > echo.txt     ← "test" 문자열을 echo.txt 파일에 출력(저장) 명령어 < 입력파일          ← 키보드 대신 파일에서 입력을 받아 명령 실행 리디렉션 기호의 방향을 반대로 사용하면 의도치 않은 결과가 발생할 수 있으므로, 방향을 정확히 확인하고 사용해야 한다.

## 089. Linux 패스워드 정책 파라미터 설정

### 1. Windows DNS 연동 테스트 확인

#### 1-1. IP 접속 확인 후 도메인 테스트

이전 시간에 이어 도메인 접속 테스트를 진행한다. 호스트 컴퓨터의 DNS 주소를 현재 설정 중인 윈도우 서버 IP로 변경한 상태에서 브라우저에 www.도메인명.com 을 입력하면 DNS 서버에 질의하여 정상적으로 웹페이지에 접속된다.

호스트 컴퓨터 DNS 변경 경로:

네트워크 및 인터넷 설정 열기 → 어댑터 옵션 변경 → 사용 중인 어댑터 우클릭 > 속성 → TCP/IP 버전4 > DNS 서버 주소를 윈도우 서버 IP로 변경 ⚠️ DNS 주소 변경 후에도 접속이 안 되는 경우, 네트워크 설정이 정상인지 확인한다.

#### 1-2. DNS 캐시 초기화

DNS 변경 직후에도 접속이 되지 않는 경우, 이미 캐시된 DNS 정보가 남아 있을 수 있다. 네트워크 어댑터를 비활성화했다가 다시 활성화하거나 DNS 캐시를 초기화하면 된다.

### 2. Linux 머신 전환 및 패스워드 정책 파일 확인

#### 2-1. 패스워드 정책 파일 경로

Linux에서 기본적인 패스워드 정책은 아래 파일을 통해 설정한다.

/etc/security/pwquality.conf    ← 패스워드 품질 정책 설정 파일이 파일에서 패스워드 복잡도, 길이, 문자 종류 등의 규칙을 설정할 수 있다. 각 옵션 앞에 # 이 붙어 있으면 주석 처리된 것이므로 해당 기능은 적용되지 않는다.

### 3. pwquality.conf 주요 파라미터

#### 3-1. difok — 유사성 검사

# difok = 1


| 항목 | 내용 |
|---|---|
| 의미 | 예전 패스워드와 새 패스워드 간에 반드시 달라야 하는 문자 수 |
| 예시 | 값이 6이면 예전 패스워드 6글자가 모두 새 패스워드에서 달라야 함 |
| 비활성화 | 값을 0으로 설정하거나 주석 처리 |

예전 패스워드가 123456 이고 difok가 6일 경우, 순서를 바꾼 654321 이나 일부만 변경한 패스워드도 사용할 수 없다. 6개의 문자가 모두 달라야 한다.

#### 3-2. minlen — 최소 길이

# minlen = 8


| 항목 | 내용 |
|---|---|
| 의미 | 패스워드의 최소 길이 |
| 예시 | 값이 8이면 8글자 미만의 패스워드는 사용 불가 |
| 비활성화 | 주석 처리 |

### 4. 문자 종류별 최소 개수 설정 (Credit 파라미터)

#### 4-1. dcredit — 숫자(Digit) 최소 개수

# dcredit = 1 패스워드에 포함되어야 하는 숫자(0~9)의 최소 개수이다. 값이 2이면 숫자가 최소 2개 이상 포함되어야 한다.

#### 4-2. ucredit — 대문자(Uppercase) 최소 개수

# ucredit = 1 패스워드에 포함되어야 하는 영문 대문자의 최소 개수이다. 값이 1이면 대문자가 최소 1개 이상 포함되어야 한다.

#### 4-3. lcredit — 소문자(Lowercase) 최소 개수

# lcredit = 1 패스워드에 포함되어야 하는 영문 소문자의 최소 개수이다. 값이 1이면 소문자가 최소 1개 이상 포함되어야 한다.

#### 4-4. ocredit — 특수문자(Other Character) 최소 개수

# ocredit = 1 패스워드에 포함되어야 하는 특수문자의 최소 개수이다. 값이 2이면 특수문자가 최소 2개 이상 포함되어야 한다.

Credit 파라미터 전체 요약:


| 파라미터 | 대상 문자 종류 | 비고 |
|---|---|---|
| dcredit | 숫자 (Digit) | 0~9 |
| ucredit | 영문 대문자 (Uppercase) | A~Z |
| lcredit | 영문 소문자 (Lowercase) | a~z |
| ocredit | 특수문자 (Other Character) | !, @, # 등 |

### 5. 추가 복잡도 설정 파라미터

#### 5-1. minclass — 최소 문자 종류 수

# minclass = 0 패스워드를 만들 때 반드시 포함해야 하는 문자 종류(숫자, 대문자, 소문자, 특수문자)의 최소 수이다.


| 값 | 의미 |
|---|---|
| 1 | 숫자, 대문자, 소문자, 특수문자 중 최소 1가지 포함 |


| 값 | 의미 |
|---|---|
| 2 | 최소 2가지 포함 (예: 숫자와 대문자) |
| 4 | 숫자·대문자·소문자·특수문자 모두 포함 |

특정 종류만 지정하고 싶은 경우에는 minclass 대신 ucredit, lcredit 등의 Credit 파라미터를 사용한다.

#### 5-2. maxrepeat — 연속 반복 문자 최대 개수

# maxrepeat = 0 동일한 문자가 연달아 나올 수 있는 최대 개수이다. 값이 2이면 aa 는 허용되지만 aaa 는 허 용되지 않는다. 연속이 아닌 경우(예: a3a4a )는 각각 1개로 취급한다.

#### 5-3. maxclassrepeat — 동일 종류 연속 반복 최대 개수

# maxclassrepeat = 0 같은 문자 종류(숫자, 대문자, 소문자, 특수문자)가 연속으로 나올 수 있는 최대 개수이다. 값이 2이면 1A  다음에 같은 종류의 문자가 2번 이상 연달아 오면 안 된다. 패스워드의 문자 종 류가 매번 달라져야 한다.

#### 5-4. gecoscheck — GECOS 필드 검사

# gecoscheck = 0 /etc/passwd  파일의 GECOS 필드(계정 정보 필드)에 포함된 3글자 이상의 단어가 새 패스워드에 포함되어 있는지 검사한다. 잘 사용하지 않는 옵션이다.

/etc/passwd  파일 안에는 각 계정별 여러 필드가 있으며, 이 필드들을 GECOS 필드라고한다.

#### 5-5. dictcheck — 사전 단어 검사

# dictcheck = 1 사전(Dictionary)에 있는 단어가 패스워드로 사용되는 것을 방지한다. 예를 들어 flower 와 같이 사전에 있는 단어를 패스워드로 설정하면 거부된다. 값을 0으로 설정하면 검사를 비활성화한다.

사전 단어 범위가 워낙 넓기 때문에 실제 운영에서는 잘 사용하지 않는 경우도 있다.

| gecoscheck | /etc/passwd GECOS 필드 단어 검사 | 잘 사용 안 함 |
| dictcheck | 사전 단어 사용 금지 검사 | 0: 비활성화 |

주석( # )이 있는 항목은 해당 기능이 적용되지 않는다. 설정을 활성화하려면 주석을 제거하고 원하는 값을 지정한다.

## 090. PAM 인증 설정 및 auth-select 명령어

령어

### 1. /etc/pam.d 디렉토리 개요

#### 1-1. PAM 인증 관련 디렉토리 구조

Linux에서 패스워드 인증과 관련된 추가 설정은 /etc/pam.d  디렉토리에서 관리한다.

cd /etc/pam.d ls 이 디렉토리 안에는 패스워드 인증 및 인증 방식과 관련된 다양한 파일들이 포함되어 있다. 이 중 인증 방식을 설정하는 주요 파일은 다음과 같다.


| 파일명 | 역할 |
|---|---|
| system-auth | 시스템 전반의 인증 방식 설정 |
| password-auth | 패스워드 인증 방식 설정 |

#### 1-2. password-auth 파일 내용 확인

cat /etc/pam.d/password-auth 이 파일을 확인하면 현재 시스템에서 인증에 적용되는 기본 구성 목록을 볼 수 있다. 각 줄은 크게 세 개의 필드로 구성된다.

### 2. pam_pwquality 모듈 추가

#### 2-1. 단순 패스워드 거부 설정

만약 단순한 패스워드(복잡도가 낮은 패스워드)를 사용하지 못하도록 하려면 /etc/pam.d/password-auth  파일에 다음 내용을 추가한다.

password    require    pam_pwquality    ← 복잡도 낮은 패스워드 거부 VI 편집기로 파일을 열어 password 로 시작하는 항목에 위 내용을 추가하면, 이후 시스템에 들어오는 모든 인증에서 복잡도가 낮은 패스워드는 거부된다.

⚠️ 기본적으로는 /etc/security/pwquality.conf  파일을 통해 패스워드 정책을 설정하는 것이 우선이다. /etc/pam.d 는 특별한 추가 인증이 필요한 경우에만 사용한다.

### 3. auth-select 명령어

#### 3-1. 현재 인증 설정 확인

현재 시스템의 인증 구성 상태를 확인하는 명령어는 다음과 같다.

authselect current --raw    ← 현재 인증 설정 확인 구성 파일이 없거나 탐지되지 않는 경우 "기존의 구성이 탐지되지 않았다"는 메시지가 출력된다. 이것은 오류가 아니며, 현재 기본 구성 상태임을 나타낸다.

#### 3-2. auth-select 도움말

명령어만 입력하면 사용 가능한 옵션들이 출력된다.

authselect

#### 3-3. 서비스별 패스워드 정책 일관 적용

특정 서비스에 패스워드 품질 정책을 강제로 일관되게 적용할 수 있다.

authselect select sshd with pw-quality-force    ← sshd 서비스에 패스워드 품질 정책 강제 적용


| 구성 요소 | 의미 |
|---|---|
| select sshd | sshd 서비스에 대해 인증 방식을 선택 |
| with pw-quality | 패스워드 품질 정책(pwquality.conf)과 함께 적용 |
| force | 강제로 일관되게 적용 |

이 명령어는 실행 단계가 아니라 설정 방법 설명 수준으로 제시된 것이다. 실제 적용 시에는 해당 서비스와 정책을 정확히 지정한다.

### 4. 패스워드 정책 적용 권장 방식

#### 4-1. 기본 설정 파일 우선 사용

일반적인 패스워드 복잡도 정책은 다음 파일을 통해 설정한다.

/etc/security/pwquality.conf    ← 기본 패스워드 품질 정책 파일이 파일 하나로 대부분의 패스워드 정책 설정이 가능하다.

#### 4-2. 추가 인증이 필요한 경우

특별한 인증 방식이나 추가적인 인증 요구가 필요한 경우에만 다음 방법을 사용한다.


| 방법 | 경로 |
|---|---|
| PAM 모듈 추가 | /etc/pam.d/ 디렉토리 내 파일 편집 |
| 인증 프로파일 선택 | authselect select 명령어 사용 |

기본적으로는 pwquality.conf 파일을 통한 설정을 먼저 검토하고, 추가 인증이나 특수한 정책 적용이 필요한 경우에만 PAM 및 authselect를 활용한다.

## 097. 우분투 서버 개요 및 VirtualBox 설치 준비

치 준비

### 1. 우분투 버전 구분

우분투는 데스크탑 버전과 서버 버전으로 구분된다.


| 구분 | 설명 | 비교 대상 |
|---|---|---|
| 데스크탑 버전 | GUI 환경 포함, 서버로도 사용 가능하나 서버 최적<br>화 기능은 부족 | Windows 10/11과 유사 |
| 서버 버전 | 서버 구축에 최적화된 패키지 포함, GUI 없음 | Windows Server 2022와<br>유사 |

우분투 서버 버전에는 로키 리눅스의 '미니멀' 설치 옵션과 유사하게 Ubuntu Server (minimized) 옵션이 제공된다. 최소한의 패키지만 설치하여 자원을 절약한다.

### 2. 우분투와 로키 리눅스의 주요 차이점


| 항목 | 로키 리눅스 | 우분투 서버 |
|---|---|---|
| 계열 | Red Hat 계열 | Debian 계열 |
| 패키지 관리 | dnf | apt |
| root 계정 | 설치 중 root 패스워드 설정 가능 | root 직접 로그인 비권장; sudo 명령 사용 |
| 미니멀 설치 | 미니멀 ISO 이미지로 제공 | 설치 과정 중 'Minimized' 옵션 선택 |

우분투에서 관리자 권한이 필요한 작업은 sudo  명령어를 앞에 붙여 실행한다. root 계정으로 직접 로그인하는 방식보다 sudo 를 사용하는 것이 보안상 더 안전하다.

### 3. VirtualBox 가상 머신 생성 시 주의사항

여러 대의 가상 머신을 동시에 실행하면 호스트 시스템의 디스크 용량, CPU, 메모리 등 모든 자원을 공유하여 소모한다. 향후 보안 솔루션 실습 환경 구성 시 가상 머신의 수가 늘어나므 로 아래 사항을 미리 점검해야 한다.

호스트 PC의 여유 디스크 용량 확인 불필요한 가상 머신 삭제 또는 파일 정리 각 가상 머신의 디스크 용량을 필요한 최소 수준으로 설정

### 4. 우분투 서버 네트워크 설정

우분투 서버 설치 과정에서 네트워크 설정 방식을 선택할 수 있다.


| 방식 | 설명 |
|---|---|
| DHCP (자동) | 공유기·네트워크 장비에서 IP를 자동 할당받음 |
| Manual (수동) | IP 주소, 서브넷, 게이트웨이, 네임서버를 직접 입력 |

수동 설정 시 필요한 정보는 호스트 PC에서 ipconfig /all  명령으로 확인한 후, 동일 대역의 사용하지 않는 IP를 지정한다.

설정 후 IP 할당 방식은 DHCP  또는 static 으로 표시된다.

### 5. 오픈 SSH 서버

우분투 서버 설치 과정에서 OpenSSH 서버 설치를 선택할 수 있다. 설치하면 외부 시스템에서 SSH로 원격 접속이 가능해진다. 선택하지 않더라도 설치 후 apt install opensshserver  명령으로 별도 설치할 수 있다.

### 6. LXD / 도커(Docker) 소개

설치 과정 중 추가 소프트웨어 목록에 LXD가 포함된다.


| 도구 | 설명 |
|---|---|
| Docker | 컨테이너 기반 가상화 도구. 경량 가상 환경을 빠르게 생성·삭제 가능 |
| LXD | Docker와 유사한 리눅스 컨테이너 관리 도구 |

이러한 가상화 도구는 필요 시 설치 과정에서 선택하거나, 설치 후 apt 로 수동 설치할 수 있다.

## 098. 우분투 서버 기본 명령 환경 및 네트워크 설정

크 설정

### 1. 리눅스 배포판 계열 비교

리눅스 배포판은 계열에 따라 패키지 관리 방식이 다르다.


| 배포판 | 계열 | 패키지 관리 명령 |
|---|---|---|
| 로키 리눅스(Rocky Linux) | Red Hat 계열 | dnf |
| 우분투(Ubuntu) | Debian 계열 | apt / apt-get |
| 칼리 리눅스(Kali Linux) | Debian 계열 | apt / apt-get |

우분투와 칼리 리눅스는 동일한 Debian 계열이므로 패키지 관리 명령이 동일하다.

### 2. apt 명령어

우분투(Debian 계열)에서 패키지를 설치·삭제·업데이트할 때 사용하는 명령어는 apt  또는 apt-get 이다. 로키 리눅스의 dnf 에 해당하는 명령이다.

apt install 패키지명      ← 패키지 설치 apt-get install 패키지명  ← apt와 동일 (구버전 방식)

### 3. sudo 명령어

우분투 서버에서는 root 계정으로 직접 로그인하는 대신, 일반 사용자 계정에서 sudo  명령을 앞에 붙여 관리자 권한으로 명령을 실행한다.

sudo 명령어   ← 해당 명령을 관리자(root) 권한으로 실행 sudo  없이 관리자 권한이 필요한 명령을 실행하면 Permission denied 오류가 발생한다. 이 경우 명령 앞에 sudo 를 추가하면 된다.

sudo 는 관리자 권한이 필요한 작업에만 사용하고, 일반 작업은 일반 사용자 권한으로 수행하는 것이 보안상 안전하다.

### 4. ping 유틸리티 설치

우분투 서버 최소 설치 환경에서는 ping  명령이 기본으로 설치되어 있지 않을 수 있다. 이 경우 iputils-ping  패키지를 설치해야 한다.

sudo apt install iputils-ping   ← ping 명령 사용을 위한 패키지 설치

### 5. 파일 권한과 sudo의 관계

리눅스에서 파일 권한은 ls -l  명령으로 확인할 수 있다. 파일 소유자가 root이고 일반 사용자에게 쓰기 권한이 없는 경우, 해당 파일을 편집하려면 sudo 가 필요하다.

ls -l 파일경로   ← 파일 권한 확인 (rw- 등으로 표시)

권한이 root에게만 부여된 파일(예: 네트워크 설정 파일)은 반드시 sudo 로 편집해야 한다.

### 6. 우분투 서버 네트워크 설정 파일

우분투 서버의 네트워크 설정은 /etc/netplan/  디렉토리의 YAML 형식 파일로 관리한다.

/etc/netplan/50-cloud-init.yaml   ← 우분투 서버 네트워크 설정 파일이 파일은 root 소유이므로 편집 시 sudo 가 필요하다.

sudo vi /etc/netplan/50-cloud-init.yaml   ← 네트워크 설정 파일 편집

### 7. ICMP와 ping 개념

ping  명령은 ICMP(Internet Control Message Protocol) 프로토콜을 사용하여 네트워크 연결 상태를 확인한다.


| 구분 | 설명 |
|---|---|
| ICMP Echo Request | 출발지에서 목적지로 보내는 ping 요청 패킷 |
| ICMP Echo Reply | 목적지에서 출발지로 돌아오는 ping 응답 패킷 |

ping 명령을 실행하면 ICMP Echo Request를 보내고, 대상 시스템이 살아 있으면 ICMP Echo Reply로 응답한다.

### 8. DoS / DDoS 공격 개념

#### 8-1. DoS와 DDoS


| 공격 유형 | 설명 |
|---|---|
| DoS (Denial of<br>Service) | 단일 공격자가 대량의 트래픽·요청을 전송하여 대상 시스템의 서비스를 마<br>비시키는 공격 |
| DDoS (Distributed<br>DoS) | 여러 대의 시스템이 분산되어 동시에 DoS 공격을 수행하는 방식 |

#### 8-2. Ping of Death (죽음의 핑)

Ping of Death는 ICMP를 이용한 DoS 공격의 대표적인 유형이다. 비정상적으로 크거나 변형된 ping 패킷을 전송하여 대상 시스템을 다운시키는 공격 방식이다.

⚠️ Ping of Death는 오래된 공격 기법으로, 현재 대부분의 운영체제에서 방어 기능이 내장되어 있다.

### 9. VirtualBox 가상 머신 복제

기존 가상 머신을 복제하여 동일한 환경의 새 가상 머신을 빠르게 생성할 수 있다. 복제 방식은 **완전한 복제(Full Clone)**를 사용한다.


| 설정 항목 | 권장 값 | 설명 |
|---|---|---|
| 복제 유형 | 완전한 복제 | 원본과 완전히 독립된 가상 디스크 생성 |
| MAC 주소 정책 | 새 MAC 주소 생성 | 네트워크 충돌 방지를 위해 반드시 새 MAC 주소 지정 |

⚠️ 복제 시 MAC 주소를 원본과 동일하게 유지하면, 같은 네트워크에서 두 가상 머신이 동일한 MAC을 가지게 되어 네트워크 충돌이 발생할 수 있다. 반드시 새 MAC 주소를 할당해야 한다.

### 10. 복제 후 정적 IP 설정 변경

가상 머신을 복제한 경우, 원본 머신과 IP 주소가 동일하게 복사된다. 정적 IP(static)로 설정된 가상 머신을 복제하면, 복제본에서 반드시 IP 주소를 변경해야 한다.

sudo vi /etc/netplan/50-cloud-init.yaml   ← IP 주소 변경을 위해 설정 파일 편집 변경 후 네트워크 설정을 적용해야 변경사항이 반영된다.

⚠️ 복제된 가상 머신과 원본 가상 머신이 동일한 IP를 사용하면 IP 충돌이 발생하여 양쪽 모두 네트워크 통신이 불가능해진다.

## 115. 셸 스크립트 기본 문법 및 AWK·SED 텍스트 처리 도구

텍스트 처리 도구

### 1. 셸(Shell) 개요

#### 1-1. 셸의 정의

셸은 리눅스 커널과 사용자 사이에서 명령어를 읽고 해석하고 실행해 주는 프로그램이다.

#### 1-2. 셸의 종류


| 셸 이름 | 특징 |
|---|---|
| sh (Bourne Shell) | 초기에 사용하던 셸, 1977년 발표 |
| ksh (Korn Shell) | sh의 확장 버전 |
| csh (C Shell) | C 언어 문법과 유사한 구조 |
| bash (Bash Shell) | 현재 대부분의 리눅스 기본 셸, 위 셸들과 호환성<br>제공 |

현재 사용 중인 셸을 확인하는 명령어:

echo $SHELL              ← SHELL 환경변수 값 출력 (예: /bin/bash)

### 2. 셸 스크립트 개요

#### 2-1. 정의 및 목적

셸 스크립트는 셸에서 사용할 수 있는 명령어들을 모아서 첫 줄부터 순차적으로 실행시켜 주는 인터프리터 방식의 스크립트이다.

작성 목적:


| 목적 | 예시 |
|---|---|
| 반복 작업 자동화 | 로그 백업, 디스크 정리 주기적 수행 |


| 목적 | 예시 |
|---|---|
| 일괄 설치 자동화 | 소프트웨어 설치 과정을 스크립트 한 번 실행으로<br>처리 |
| 시스템 취약점 점검 | 점검 가이드 항목에 따라 자동 점검 수행 |

윈도우의 배치(Batch) 파일과 동일한 개념이다. 배치는 일괄 처리 프로그램으로, 반복적 인 작업을 모아서 한꺼번에 처리한다.

#### 2-2. 스크립트 파일 형식

확장자: .sh 파일 권한: 실행 권한이 없으면 실행 불가 → chmod +x <파일명>  으로 부여

#### 2-3. 스크립트 실행 방법

./test.sh                ← 현재 디렉토리임을 명시하여 실행 bash test.sh             ← 실행할 셸(bash)을 지정하여 실행 ⚠️ 스크립트 파일명만 입력하면 실행되지 않는다. 반드시 현재 디렉토리( ./ )를 명시하 거나 실행할 셸을 지정해야 한다.

### 3. 셸 스크립트 기본 구조

#### 3-1. Shebang(시방, #!)

스크립트의 첫 줄에 반드시 작성하며, 해당 코드를 실행할 셸의 경로를 지정한다.

#!/bin/bash              ← bash 셸로 아래 코드를 실행 모든 스크립트는 첫 번째 줄에 Shebang이 있어야 아래 명령어들이 어떤 셸로 실행될지 알 수 있다.

#### 3-2. 주석

# 이 줄은 주석이다 (실행되지 않음)

### 4. 변수

#### 4-1. 변수 규칙


| 규칙 | 설명 |
|---|---|
| 대소문자 구분 | name 과 NAME 은 서로 다른 변수 |
| 공백 금지 | name=value (등호 좌우에 공백 없어야 함) |
| 숫자로 시작 불가 | 0name 불가, name0 가능 |
| 자료형 미지정 | 기본적으로 문자열로 인식 |

#### 4-2. 변수 선언 및 사용

#!/bin/bash NAME="Ubuntu 24.04"      ← 문자열 변수 (따옴표 사용) VERSION=24.04            ← 숫자형 변수 (기본적으로 문자열로 인식)

echo "Welcome to $NAME"  ← 변수 사용 시 앞에 $ 붙임 변수를 가져올 때는 반드시 변수명 앞에 $ 를 붙인다.

### 5. 조건문 (if)

#### 5-1. 기본 문법

if [ 조건 ]; then # 조건이 참일 때 실행 else # 조건이 거짓일 때 실행 fi

#### 5-2. 비교 연산자


| 연산자 | 의미 |
|---|---|
| -eq | 같다 (Equal) |
| -gt | 크다 (Greater Than) |
| -lt | 작다 (Lower Than) |


| 연산자 | 의미 |
|---|---|
| -ne | 같지 않다 (Not Equal) |
| > , < , != | 부등호·부정 기호로도 조건 지정 가능 |

#### 5-3. 파일·디렉토리 조건


| 옵션 | 의미 |
|---|---|
| -d <경로> | 해당 디렉토리가 존재하는지 검사 |

#### 5-4. 예제

#!/bin/bash NUM=10 if [ $NUM -gt 5 ]; then echo "5 higher"         ← 10 > 5 이므로 참일 때 실행 else echo "5 or lower" fi

### 6. 사용자 입력 받기

echo -n "당신의 이름을 입력하세요: " read USERNAME            ← 사용자가 입력한 값을 USERNAME 변수에 저장 if [ $USERNAME = "ubuntu" ]; then echo "관리자 계정으로 로그인했습니다." else echo "환영합니다, ${USERNAME}님" fi read  명령어는 사용자가 입력한 값을 지정한 변수에 저장한다.

### 7. 반복문

#### 7-1. for 문

정해진 범위나 리스트의 크기만큼 반복할 때 사용한다.

for i in 1 2 3; do echo "number $i" done

#### 7-2. while 문

조건이 참인 동안 계속 반복한다.

COUNTER=1 while [ $COUNTER -lt 4 ]; do   ← COUNTER 값이 4보다 작은 동안 반복 echo $COUNTER COUNTER=$(( COUNTER + 1 ))   ← COUNTER 값 1씩 증가 done 연산(산술)을 수행할 때는 $(( 계산식 ))  형태를 사용한다.

⚠️ while 문에서 변수 값을 증가시키지 않으면 조건이 영원히 참이 되어 무한 루프가 발생한다.

### 8. AWK

#### 8-1. 개념

AWK는 텍스트 기반의 표·데이터를 공백(또는 지정 구분자)을 기준으로 필드(열)로 분리하여 분석하고 추출하는 프로그래밍 언어이다.

이름 유래: Aho(에이호), Weinberger(웬버거), Kernighan(커링한) — 세 개발자의 이름 첫 글자.

#### 8-2. 기본 문법

awk '{ 행동 }' 파일명 awk '조건 { 행동 }' 파일명

#### 8-3. 필드 참조

공백을 구분자로 사용하는 경우:

awk '{ print $1, $3 }' user.txt # $1: 첫 번째 필드, $3: 세 번째 필드 다른 구분자(예: : )를 사용하는 경우:

awk -F: '{ print $1 }' /etc/passwd # -F: 구분자 지정 (콜론을 구분자로 사용)

#### 8-4. 조건을 포함한 예제

# user.txt에서 세 번째 필드(나이)가 30 이상인 행의 1·3번째 필드만 출력 awk '$3 >= 30 { print $1, $3 }' user.txt

#### 8-5. 특정 문자열이 포함된 행 추출

ip address | awk '/inet / { print $2 }' # 'inet '이 포함된 행에서 두 번째 필드(IP 주소) 출력

### 9. SED

#### 9-1. 개념

SED는 **Stream Editor(스트림 에디터)**의 약자로, 파일이나 파이프 입력에서 특정 문자열을 삭제·추가·치환하기 위한 도구이다.

#### 9-2. 기본 문법

sed 's/찾을문자열/바꿀문자열/' 파일명


| 기호 | 의미 |
|---|---|
| s | Substitute(치환)의 약자 |
| g | Global — 파일 전체에서 모두 치환 |


| 기호 | 의미 |
|---|---|
| i | In-place — 원본 파일을 직접 수정 |

#### 9-3. 치환 예제

# server.conf 파일에서 'disabled'를 'enable'로 치환하여 출력 (원본 유지) sed 's/disabled/enable/g' server.conf # 원본 파일 자체를 수정하려면 -i 옵션 추가 sed -i 's/disabled/enable/g' server.conf ⚠️ -i  옵션 없이 실행하면 변경된 내용이 화면에만 출력되고 원본 파일은 수정되지 않는다.

#### 9-4. 특정 줄 삭제

sed '2d' server.conf     ← 두 번째 줄을 삭제하여 출력 (원본 유지)

#### 9-5. AWK와 SED 비교


| 도구 | 주요 용도 |
|---|---|
| AWK | 특정 열(필드) 추출, 수치 비교, 데이터 분석 |
| SED | 특정 문자열 치환·삭제·추가, 파일 편집 |

AWK와 SED는 셸 스크립트 작성 시 필수적으로 자주 사용되는 도구이다.

### 10. 셸 스크립트 매개변수(Argument)

스크립트 실행 시 인자(Argument)를 함께 전달할 수 있다.

./test.sh arg1 arg2 arg3 arg4


| 변수 | 의미 |
|---|---|
| $0 | 스크립트 파일명 자체 |


| 변수 | 의미 |
|---|---|
| $1 | 첫 번째 인자 |
| $2 | 두 번째 인자 |
| $4 | 네 번째 인자 |
| $# | 전체 인자 개수 |

### 11. 셸 스크립트 문법 검사 도구

작성한 셸 스크립트의 문법이 올바른지 확인하려면 온라인 도구를 활용할 수 있다.

사이트 예시: www.shellcheck.net 스크립트 붙여넣기 후 문법적으로 잘못된 부분과 개선 방향을 확인 가능
