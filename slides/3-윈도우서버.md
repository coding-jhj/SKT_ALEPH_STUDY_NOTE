## 070. IIS 웹·FTP 사이트 구성, 주요 설정 항목, 에러 코드 및 보안 설정

목, 에러 코드 및 보안 설정

### 1. IIS 웹 사이트 추가

IIS 관리자에서 Sites → 우클릭 → Add Website로 웹 사이트를 추가한다.


| 설정 항목 | 설명 |
|---|---|
| 사이트 이름 | 관리자가 임의로 지정 |
| 물리적 경로(Physical Path) | 웹에서 보여질 파일들이 위치할 디렉토리 경<br>로 |
| IP 주소 | 서버에 할당된 IP 주소 선택 |
| 포트 번호 | 기본값 80 (HTTP). 변경 시 클라이언트 접속<br>URL에 포트 번호를 반드시 포함해야 함 |
| 호스트 이름 | 도메인이 없는 경우 비워둠 |

웹에서 보여지는 파일의 기본 저장 경로는 C:\\inetpub\\wwwroot 이다. 리눅스 웹 서버의 문서 루트( /var/www/html )와 동일한 역할을 한다.

⚠️ HTTP만 사용 가능하다. HTTPS(암호화 통신)를 사용하려면 SSL 서버 인증서가 필요하다.

### 2. IIS 웹 서버 기본 테스트 페이지

웹 사이트 구성 후 브라우저에서 서버 IP 주소로 접속하면 IIS 기본 테스트 페이지가 표시된다.

리눅스(Apache) 설치 후 표시되는 Apache 테스트 페이지와 동일한 역할 테스트 페이지 파일명: iisstart.htm

### 3. Default Document (시작 페이지 우선순위)

클라이언트가 특정 파일명 없이 도메인 또는 IP만으로 접속했을 때 서버가 순서대로 찾아 응답하는 파일 목록이다.

기본 등록 파일 예시: default.htm , default.asp , index.htm , index.html , iisstart.htm  등 목록 위쪽 파일이 우선순위가 높다.

해당 파일이 존재하면 그 파일을 시작 페이지로 로드한다.

관리자가 새 파일을 추가하거나 우선순위를 위/아래로 변경할 수 있다.

웹 서버에 접속 시 등록된 파일이 존재해야 해당 파일이 시작 페이지로 로드된다. 목록에 없는 파일명은 시작 페이지로 동작하지 않는다.

### 4. IIS 주요 설정 항목


| 항목 | 설명 |
|---|---|
| Authentication (인증) | 익명 인증(Anonymous Authentication)이<br>기본 활성화. 인증 없이 웹 사이트에 접근 가<br>능 |
| Directory Browsing | 기본 비활성화(Disabled). 활성화 시 웹 서버<br>내 디렉토리 및 파일 목록이 클라이언트에 노<br>출됨 |
| Error Pages (에러 페이지) | HTTP 상태 코드별 에러 응답 페이지 설정 |
| Logging | 웹 서버 로그 파일 설정 (포맷, 저장 경로, 갱<br>신 주기) |
| MIME Types | 파일 확장자와 미디어 타입 간 매핑 정보 |
| Handler Mappings | 웹 서비스 구동에 필요한 모듈(DLL 등) 처리<br>설정 |
| Request Filtering | URL 스캔·헤더 값 기반의 요청 필터링 규칙<br>설정 |
| HTTP Response Headers | 서버 응답 헤더 값 사전 설정 |
| Compression | 응답 데이터 압축 여부 설정 |
| SSL Settings | HTTPS 인증서 설정 (인증서 필요) |
| Modules | 웹 서비스 내부에서 동작하는 모듈 목록 확인 |

#### 4-1. Directory Browsing (디렉토리 리스팅) 보안

활성화 시 클라이언트가 웹 서버 내 디렉토리 구조와 파일 전체를 브라우저에서 볼 수 있다.

웹 서버의 내부 구조가 외부에 노출되므로 보안상 기본 비활성화 상태로 유지해야 한다.

#### 4-2. HTTP 상태 코드


| 상태 코드 범위 | 의미 |
|---|---|
| 100번대 | 정보 응답 |
| 200번대 | 성공 응답 |
| 300번대 | 리다이렉션 |
| 400번대 | 클라이언트 오류 (예: 404 - 요청한 페이지<br>없음) |
| 500번대 | 서버 오류 |

404 오류: 클라이언트가 URL을 잘못 입력하거나 존재하지 않는 페이지를 요청할 때 서버가 전송한다. 실제 404.html  파일이 웹 서버에 존재하며 해당 파일이 브라우저에 렌더 링된다.

#### 4-3. 로그(Logging) 설정

기본 로그 포맷: W3C (웹 표준 로그 형식)

로그 파일 저장 경로: C:\\inetpub\\logs\\LogFiles\\ 로그 파일 갱신 주기: 일별, 주별, 월별, 용량 기준 등 설정 가능

#### 4-4. MIME Types

MIME 타입은 파일 확장자와 미디어 타입을 매핑하여 웹 브라우저가 해당 파일을 올바르게 처리하도록 한다.

대부분의 확장자가 자동으로 등록되어 있으며, 새로운 확장자가 있을 경우 수동으로 추가할 수 있다.

### 5. IIS FTP 사이트 추가

Sites → 우클릭 → Add FTP Site로 FTP 사이트를 추가한다.


| 설정 항목 | 설명 |
|---|---|
| 사이트 이름 | 관리자가 임의로 지정 |
| 물리적 경로 | FTP 파일이 저장될 디렉토리 경로 (기본:<br>C:\\inetpub\\ftproot ) |
| IP 주소·포트 | IP 선택, 기본 포트 21 |


| 설정 항목 | 설명 |
|---|---|
| SSL | 인증서 없으므로 No SSL 선택 → 평문 전송<br>FTP |

#### 5-1. FTP 접속 허용 사용자 설정


| 옵션 | 설명 |
|---|---|
| All Users | 모든 사용자 접속 허용 |
| Anonymous | 익명 사용자만 접속 허용 |
| Specified Roles or User Groups | 특정 역할 또는 그룹에 속한 사용자만 접속 허<br>용 |
| Specified Users | 특정 사용자만 접속 허용 |

접속 권한은 Read(다운로드만 가능)와 Write(업로드 포함)로 구분된다. 업로드까지 허용 하려면 Write 권한을 함께 부여해야 한다.

⚠️ FTP 사이트에서 지정한 사용자 계정은 컴퓨터 관리(Computer Management) → 로컬 사용자에서 별도로 생성해야 한다.

### 6. 웹 보안 계층 구조

웹 서버 보안은 단일 솔루션이 아닌 여러 계층의 보안 장비와 설정으로 구성된다.


| 계층 | 보안 수단 |
|---|---|
| 네트워크 계층 (L3) | ACL(접근 제어 목록), 방화벽(Firewall) |
| 응용 프로그램 계층 | WAF(Web Application Firewall) — 웹 서<br>비스 앞 단에서 HTTP 요청을 필터링 |
| 웹 서버 자체 | IIS Request Filtering 규칙 |

보안 솔루션은 하나만 운영하지 않고, 네트워크 상황과 시스템 및 데이터의 중요도에 따라 여러 장비를 혼합하여 운영한다.

## 071. Windows FTP 방화벽 허용 및 접속 테스트

테스트

### 1. 로컬 사용자 계정 옵션

컴퓨터 관리(Computer Management) → 로컬 사용자 및 그룹(Local Users and Groups) → Users에서 사용자 계정을 생성하거나 더블 클릭하여 속성을 편집할 수 있다.

#### 1-1. 계정 생성 시 주요 옵션


| 옵션 | 설명 |
|---|---|
| User must change<br>password at next logon | 사용자가 다음 로그인 시 반드시 패스워드를 변경하도록 요구한다. 기<br>본적으로 체크되어 있으며, 관리자가 지정한 패스워드를 사용자 스스<br>로 변경하게 된다. |
| User cannot change<br>password | 사용자가 패스워드를 변경할 수 없도록 제한한다. 위 항목을 체크 해제<br>시 활성화된다. |
| Password never expires | 패스워드 만료 기간을 적용하지 않는다. 위 항목을 체크 해제 시 활성<br>화된다. |
| Account is disabled | 해당 계정을 비활성화한다. |

**첫 번째 항목(User must change password)**을 체크 해제하면 두 번째·세 번째 옵션이 활성화된다. 관리자가 패스워드를 지정하고 사용자에게 변경을 요구하지 않을 경우, 이 항목을 해제한다.

#### 1-2. 계정 비활성화(Account is disabled)

계정을 완전히 삭제하지 않고 일시적으로 비활성화할 수 있다. 비활성화된 계정은 로그인이 불가능하며, 비활성화 해제만으로 즉시 복구된다.

활용 사례: 육아휴직 중인 직원의 계정을 삭제하면 복직 시 권한 설정을 처음부터 다시 구성해야 한다. 비활성화로 처리하면 복직 후 체크만 해제하면 이전 설정 그대로 사용할 수 있다.

### 2. 그룹 멤버십과 권한 상속

#### 2-1. 사용자 기본 그룹

로컬 사용자를 생성하면 기본적으로 Users  그룹에 소속된다. 사용자 속성 → Member Of 탭에서 소속 그룹을 확인하고 추가·제거할 수 있다.

그룹 추가 경로: Member Of 탭 → Add → Advanced → Find Now → 그룹 선택 → OK

#### 2-2. 복수 그룹 소속 시 권한 결정

한 사용자가 두 개 이상의 그룹에 속할 경우, 권한이 높은 그룹의 권한을 상속받는다.


| 소속 그룹 | 적용 권한 |
|---|---|
| Users + Administrators | Administrators 그룹 권한 적용 |
| Users만 | Users 그룹 권한 적용 |

실제 운영 환경에서는 부서별로 별도의 그룹(회계부, 관리부, 마케팅부 등)을 생성하고 각 그룹에 적절한 권한을 부여하여 운영한다. 한 사용자가 두 개 이상의 그룹에 속하는 경우는 일반적으로 드물다.

#### 2-3. 그룹 생성

컴퓨터 관리 → Local Users and Groups → Groups → 우클릭 → New Group에서 그룹을 생성하고 멤버를 추가하거나 제거할 수 있다.

### 3. FTP 서버 접속 테스트 준비

FTP 접속 시 클라이언트에서 확인할 수 있는 파일과 폴더를 FTP 루트 경로에 미리 생성한다.

FTP 루트 기본 경로: C:\\inetpub\\ftproot Windows 탐색기에서 해당 경로에 폴더 및 파일을 생성하면 FTP 클라이언트 접속 시 목록에 표시된다.

### 4. Windows Defender Firewall — FTP 트래픽 허용

#### 4-1. 웹 서버와 FTP 서버의 방화벽 처리 차이


| 서비스 | 방화벽 허용 방식 |
|---|---|
| 웹 서버 (HTTP, 포트 80) | IIS 역할 설치 시 자동으로 방화벽 허용 처리 |
| FTP 서버 (포트 21) | 수동으로 방화벽에서 FTP 트래픽을 허용해야<br>함 |

#### 4-2. Windows Defender Firewall 비활성화 방법

검색 창에 Windows Defender Firewall  입력 → Turn Windows Defender Firewall on or off 클릭 → 방화벽 비활성화(Turn off) 선택 → OK ⚠️ 방화벽을 전체 비활성화하는 것은 보안상 권장되지 않는다. 운영 환경에서는 방화벽 규칙에서 FTP 트래픽(포트 21)을 명시적으로 허용하는 방식을 사용해야 한다.

### 5. FTP 접속 테스트 (FileZilla)

호스트 컴퓨터에서 FileZilla를 실행하여 Windows Server의 FTP 서버에 접속한다.


| 접속 항목 | 값 |
|---|---|
| 호스트(서버 IP) | Windows Server IP 주소 입력 |
| 사용자 이름 | 생성한 FTP 사용자 계정명 |
| 패스워드 | 해당 계정의 패스워드 |
| 포트 | 21 (기본값이므로 입력하지 않아도 무방) |

FTP는 SSL 없이 평문으로 전송되므로, 접속 시 "안전하지 않은 연결"이라는 경고 메시지가 표시된다. 이는 No SSL 설정에 의한 것으로, 확인을 눌러 계속 진행한다.

접속 성공 시 FTP 루트 경로의 파일과 폴더 목록이 FileZilla 우측 패널에 표시된다. 다운로드 또는 업로드 작업을 수행할 수 있다.

### 6. IIS FTP 인증 및 인가 설정 확인

FTP 접속이 되지 않을 경우 IIS 관리자에서 다음 항목을 확인한다.

#### 6-1. FTP Authentication (인증)

IIS 관리자 → FTP 사이트 선택 → FTP Authentication 더블 클릭


| 항목 | 상태 |
|---|---|
| Anonymous Authentication | Enabled |
| Basic Authentication | Enabled |

#### 6-2. FTP Authorization Rules (인가)

IIS 관리자 → FTP 사이트 선택 → FTP Authorization Rules 더블 클릭 허용된 사용자(예: ftp user )가 Allow 상태로 등록되어 있어야 접속이 가능하다.

### 7. FTP 현재 세션 확인

IIS 관리자 → FTP 사이트 선택 → FTP Current Sessions에서 현재 접속 중인 세션 정보를 확인할 수 있다.

접속한 클라이언트의 IP 주소, 접속 시각 등 세션 정보가 표시된다.

여러 사용자가 동시에 접속 중이면 해당 수만큼 세션 목록이 나타난다.

## 072. Windows Server 소개, 설치 버전 구분, Administrator 계정

구분, Administrator 계정

### 1. Windows Server 활용 목적

Windows Server를 설치하는 목적은 Rocky Linux에서 구축했던 것과 동일한 서버 환경을 Windows 환경에서도 경험하는 것이다. 구체적으로 다음 항목들을 다룬다.

웹(Web), FTP, 네임(Name) 서버 구축 및 테스트 로컬 보안 정책(Local Security Policy) 설정 및 확인 사용자 계정 정책 관리 Windows 로그 확인 방법 Windows Server는 일상적으로 사용하는 Windows 운영체제와 동일한 기반이므로, 리눅스에서 구축한 경험과 결합하면 더 쉽게 이해할 수 있다.

### 2. Windows Server 2022 설치 버전 유형

Windows Server 2022 설치 시 다음 네 가지 버전 중 하나를 선택하게 된다.


| 버전 | 설명 |
|---|---|
| Windows Server 2022 Standard Evaluation | 평가판 표준 에디션. GUI 없이 터미널 명령어<br>로만 운영 |
| Windows Server 2022 Standard Evaluation<br>(Desktop Experience) | 평가판 표준 에디션 + 그래픽 UI 포함. 수업에<br>서 선택 |
| Windows Server 2022 Datacenter Evaluation | 데이터센터 전용 에디션. Standard보다 기능<br>이 많음. GUI 없음 |
| Windows Server 2022 Datacenter Evaluation<br>(Desktop Experience) | 데이터센터 에디션 + 그래픽 UI 포함 |

⚠️ 반드시 **"Desktop Experience"가 포함된 두 번째 항목(Standard Evaluation Desktop Experience)**을 선택해야 한다. 이를 선택하지 않으면 Rocky Linux처럼 터미널 명령어로만 조작해야 하며, 그래픽 화면이 표시되지 않는다.

Standard 에디션은 일반 서버 운영 목적에 적합하다.

Datacenter 에디션은 대규모 데이터센터 환경을 위한 추가 기능을 포함한다.

### 3. VirtualBox 가상 머신 주요 설정 항목

Windows Server 2022 가상 머신 생성 시 다음 설정이 적용된다.


| 설정 항목 | 권장 값 | 비고 |
|---|---|---|
| OS 유형 | Windows Server 2022 | 목록에서 선택 |
| 디스크 용량 | 30GB | 실제 운영 환경에서는 TB 단위 이상 필요 |
| 메모리 | 4096MB (4GB) | 여유가 된다면 이 값으로 설정 |
| 부팅 순서 | 하드 디스크 1순위, 광디스크 2<br>순위 | 설치 완료 후 재부팅 시 설치 과정이 반복되는<br>것을 방지 |
| CPU 가상화 기능 | 체크 가능한 항목 전부 활성화 | 프로세서 탭에서 설정 |
| 저장소 | ISO 파일을 CD-ROM에 마운<br>트 | 설치 이미지 파일 선택 |
| 오디오 | 비활성화 | 리소스 절감 |
| 네트워크 | 브리지 어댑터 | IP 자동 할당 또는 수동 지정 |
| USB | 비활성화 | 리소스 절감 |

실제 하드웨어에서 지정한 디스크 용량만큼의 여유 공간이 필요하다. 가상 머신 설정에서 지정하는 크기는 호스트 컴퓨터의 실제 저장공간을 사용한다.

### 4. VirtualBox에서 Ctrl+Alt+Del 입력 방법

Windows Server 로그인 화면에서는 Ctrl+Alt+Del 키를 눌러야 언락(unlock)이 된다. 그러나 VirtualBox에서 해당 키를 직접 누르면 호스트 컴퓨터의 작업 관리자가 열린다. 이를 해결하는 방법은 다음과 같다.

VirtualBox 메뉴 → 입력 → 키보드 → Ctrl+Alt+Del 입력 클릭

### 5. Administrator 계정

Windows Server에서 기본으로 제공되는 관리자 계정이다.

계정명: Administrator 역할: 리눅스의 root 와 동일하게 시스템 전체 권한을 보유한 관리자 계정 소속 그룹: Administrators 패스워드 설정 시 Windows Server의 기본 복잡성 요구사항을 충족해야 한다. 요구사항을 충족하지 못하면 설정이 거부된다. 패스워드 복잡성 정책은 이후 로컬 보안 정책 수업에서 상세히 다룬다.

관리자 패스워드는 10자 이상, 영문 대문자·소문자·숫자·특수문자를 혼합하여 설정한다. 분실 시 관리자 계정으로 로그인할 수 없다.

## 073. Windows Server 초기 네트워크 설정, 서버 관리자, IIS·DNS 역할 추가

정, 서버 관리자, IIS·DNS 역할 추가

### 1. Windows Server 로그인 후 네트워크 설정

로그인 직후 네트워크 상태에 따라 두 가지 상황이 발생한다.


| 상황 | 처리 방법 |
|---|---|
| 화면에 파란색 "네트워크에 참여하시겠습니까?" 팝<br>업이 뜨는 경우 | Yes 선택 → IP 자동 할당(브리지 방식), 추가<br>설정 불필요 |
| 팝업이 뜨지 않고 지구본 아이콘(인터넷 없음) 표시<br>되는 경우 | 수동으로 IP 주소 설정 필요 |

#### 1-1. 수동 IP 설정 방법

작업표시줄 지구본 아이콘 우클릭 → Open Network and Internet Settings → 이더넷 → Change Adapter Options → 어댑터 우클릭 → Properties → TCP/IPv4 Properties 설정 값:


| 항목 | 설정 방법 |
|---|---|
| IP 주소 | 호스트 컴퓨터와 동일 대역에서 사용 중이지 않은 주소 입력 |
| 서브넷 | 호스트 컴퓨터와 동일하게 입력 |
| 기본 게이트웨이 | 호스트 컴퓨터와 동일하게 입력 |
| DNS 서버 | 호스트 컴퓨터와 동일하게 입력 |

⚠️ IP 주소만 달라야 하며, 이미 사용 중인 IP인지 확인하려면 호스트 컴퓨터에서 해당 IP로 ping을 보내 응답 여부를 확인한다. 응답이 없으면 사용 가능한 IP이다.

⚠️ 윈도우 서버에서 인터넷이 되지 않으면 IIS, DNS 등의 역할을 추가할 때 필요한 구성 요소를 저장소(인터넷)에서 가져올 수 없어 설치가 실패한다. 리눅스에서 DNF 명령으로 패키지 설치 시 인터넷 연결이 필요한 것과 동일하다.

### 2. 서버 관리자(Server Manager)

서버 관리자는 Windows Server의 중앙 관리 도구이다. 로그인 시 자동으로 실행된다.

실행 방법: 시작 메뉴 → 서버 관리자(Server Manager)

서버 관리자 우측 상단 메뉴 구성:


| 메뉴 | 설명 |
|---|---|
| Manage | 역할(Role) 및 기능(Feature) 추가·제거, 서버 관리 |
| Tools | DNS, IIS 관리자, 이벤트 뷰어, 컴퓨터 관리 등 각종 관리 도구 접근 |

### 3. 역할(Role) 및 기능(Feature) 추가

Windows Server에서 서버 기능을 사용하려면 역할을 추가해야 한다.

진입 경로: 서버 관리자 → Manage → Add Roles and Features 추가 역할 항목:


| 역할 | 설명 |
|---|---|
| DNS Server | 네임 서버 구축용 |
| Web Server (IIS) | 웹 서버 및 FTP 서버 구축용 도구 |

IIS(Internet Information Services)는 웹 서버와 FTP 서버를 하나의 도구에서 함께 구축할 수 있는 Windows Server 전용 도구이다.

역할 추가 시 주의 사항:

서버 이름과 IP 주소가 올바르게 표시되는지 확인 후 Next를 진행한다.

"정적 IP 주소가 발견되지 않았다"는 메시지는 오류가 아닌 **경고(Warning)**이므로 Continue하면 된다.

IIS 역할 추가 시, 하위 항목에서 FTP Server 항목을 함께 체크하면 FTP 서비스도 동시에 구성된다.

설치가 완료되면 서버 관리자 메뉴와 Tools 목록에 DNS, IIS 관리자가 새로 추가된다.

### 4. IIS(Internet Information Services) 개요

IIS는 Windows Server에서 웹 및 FTP 서비스를 구축하는 전용 도구이다.

리눅스의 APM(Apache+PHP+MySQL) 환경과 대응하는 Windows Server의 웹 서비스 도구 웹 서비스 기반 언어: IIS는 ASP(Active Server Pages) 언어 기반으로 동작 리눅스 웹 서버는 PHP 언어 기반으로 동작 설치 완료 후 Tools → **IIS 관리자(Internet Information Services Manager)**에 서 실행

## 076. 이벤트 뷰어 보안 로그, 컴퓨터 관리, 로컬 보안 정책

로컬 보안 정책

### 1. 이벤트 뷰어(Event Viewer) — 보안 로그

이벤트 뷰어는 서버 관리자 → Tools → Event Viewer, 또는 컴퓨터 관리 내에서도 접근할 수 있다.

#### 1-1. 보안 로그 위치

이벤트 뷰어 → Windows Logs → Security

#### 1-2. 보안 로그에 기록되는 이벤트 유형


| 이벤트 유형 | 설명 |
|---|---|
| 로그온(Logon) | 시스템에 로그인한 이벤트 (누가, 언제, 어떤 방식으로 로<br>그인했는지) |
| 특별 로그온(Special Logon) | 특수 권한을 가진 로그인 이벤트 |
| 로그오프(Logoff) | 시스템 로그아웃 이벤트 |
| 사용자 계정 관리(User Account<br>Management) | 사용자 계정 생성, 변경, 그룹 멤버십 변경 등의 이벤트 |

로그인과 관련된 이벤트, 사용자 계정 관련 이벤트, 인증 관련 이벤트 등이 모두 보안 로그에 기록된다. 예를 들어, FTP 사용자 계정 생성이나 Administrators 그룹 추가 이력이 여기서 확인된다.

보안 로그는 필터링(Filter Current Log) 또는 검색 기능을 사용하여 원하는 이벤트를 찾을 수 있으며, 파일로 저장할 수도 있다.

### 2. 컴퓨터 관리(Computer Management) 구성

서버 관리자 → Tools → Computer Management 컴퓨터 관리는 이 시스템의 주요 관리 기능 대부분을 한 곳에서 수행할 수 있는 도구이다.


| 항목 | 설명 |
|---|---|
| 이벤트 뷰어(Event Viewer) | 이벤트 뷰어와 동일한 기능 |
| 공유 폴더(Shared Folders) | 공유된 폴더 목록과 세션 정보 확인 |
| 성능(Performance) | 성능 모니터 — 메모리, 네트워크, 물리적 디스크, CPU 사용량 실<br>시간 확인 |
| 장치 관리자(Device<br>Manager) | 시스템에 설치된 모든 장치 목록 확인 및 관리 |
| 디스크 관리(Disk<br>Management) | 파티션 생성·분할·통합 등 디스크 관련 작업 수행 |
| 서비스(Services) | 현재 시스템에서 동작 중인 서비스 목록 및 상태 확인·변경 |
| WMI Control | Windows 관리 명령어(WMI) 관련 설정 |

#### 2-1. 서비스(Services) 최적화

서비스 목록에서 실제로 사용하지 않는 서비스가 자동(Automatic) 상태로 실행 중인 경우, 이를 중지하고 시작 유형을 수동(Manual) 또는 사용 안 함(Disabled)으로 변경해야 한다.

⚠️ 사용하지 않는 서비스는 반드시 재부팅 후에도 시작되지 않도록 완전히 중지해야 한다. 미사용 서비스가 실행 중이면 시스템 성능이 저하되고 보안 취약점이 발생할 수 있다. 리눅스도 동일하게 적용된다.

### 3. 리소스 모니터(Resource Monitor)

서버 관리자 → Tools → Resource Monitor 현재 시스템에서 각 프로세스별 CPU, 디스크, 메모리, 네트워크 사용량을 실시간 그래픽으 로 확인할 수 있다.

상단 탭(CPU, 메모리, 디스크, 네트워크)별로 상세 보기 가능 IIS, DNS 등 서버 서비스의 동작 상태와 발생 이벤트 확인 가능

### 4. 로컬 보안 정책(Local Security Policy)

서버 관리자 → Tools → Local Security Policy Windows Server 계열에서 보안 정책을 설정하는 도구이다. 각 항목을 더블 클릭하여 Enable/Disable 또는 값을 변경할 수 있으며, Explain 탭에서 해당 정책의 상세 설명을 확인할 수 있다.

### 5. 로컬 정책 — 보안 옵션(Security Options)

경로: Local Security Policy → Local Policies → Security Options

#### 5-1. Interactive Logon (대화형 로그온)


| 정책 | 기본값 | 설명 |
|---|---|---|
| Interactive Logon: Do not<br>require Ctrl+Alt+Del | Disabled | 로그인 시 Ctrl+Alt+Del 키를 요구하지 않겠다<br>는 정책. 기본값이 Disabled이므로<br>Ctrl+Alt+Del이 요구된다. |

Ctrl+Alt+Del을 누르지 않아도 로그인 창이 바로 뜨도록 설정하려면 이 정책을 Enable 로 변경한다. 변경 후 재부팅하면 Ctrl+Alt+Del 요구 없이 로그인 화면이 표시된다.

### 6. 계정 정책 — 패스워드 정책(Password Policy)

경로: Local Security Policy → Account Policies → Password Policy


| 정책 | 설명 |
|---|---|
| Password must meet complexity<br>requirements | 패스워드 복잡성 요구 여부. Enable 시 영문 대·소문자, 숫<br>자, 특수문자 조합이 필요하다. |
| Minimum password length | 패스워드 최소 글자 수. 기본값 0. 예: 4로 설정 시 최소 4자<br>이상이어야 한다. |
| Maximum password age | 패스워드 최대 사용 기간(만료 기간) |
| Minimum password age | 패스워드 최소 유지 기간 |

Windows Server 설치 시 및 FTP 사용자 계정 생성 시 복잡한 패스워드(대·소문자·숫자 ·특수문자 조합)를 사용한 이유는 Password must meet complexity requirements 정책이 기본 Enable 상태이기 때문이다.

복잡성 요구를 Disable하면 1234 와 같은 단순 패스워드도 사용 가능하다. 단, Minimum password length에서 지정한 최소 글자 수는 여전히 충족해야 한다.

### 7. 계정 정책 — 계정 잠금 정책(Account Lockout Policy)

경로: Local Security Policy → Account Policies → Account Lockout Policy


| 정책 | 설명 |
|---|---|
| Account lockout threshold | 로그인 실패 허용 횟수. 이 횟수를 초과하면 계정이 잠긴다. 기<br>본값: 0(잠금 없음) |
| Account lockout duration | 계정 잠금 유지 시간(분). 설정 후 자동으로 30분으로 초기 설정<br>된다. |
| Reset account lockout<br>counter after | 로그인 실패 카운트를 초기화하는 시간(분). |

설정 예시: Threshold를 3으로 설정하면, 로그인 3회 실패 시 계정이 잠긴다. 잠금 시간 (duration)을 30분으로 설정하면 30분 동안 로그인을 시도할 수 없다. 리셋 시간을 60 분으로 설정하면 60분 후에 실패 카운트가 초기화되어 다시 로그인을 시도할 수 있다.

인터넷뱅킹에서 패스워드를 여러 번 잘못 입력하면 일정 시간 로그인이 차단되거나 계정이 잠기는 것이 이 계정 잠금 정책에 의한 동작이다.

### 8. IP 보안 정책(IP Security Policy)

경로: Local Security Policy → IP Security Policies on Local Computer L3 장비의 ACL(Access Control List)과 유사하게, 출발지·목적지 IP 주소, 프로토콜, 포트를 지정하여 트래픽을 필터링하는 정책을 설정할 수 있다.


| 설정 항목 | 설명 |
|---|---|
| 정책 이름 및 설명 | 정책을 식별하기 위한 이름과 설명 |
| 필터 목록(Filter List) | 출발지 IP, 목적지 IP, 프로토콜(TCP 등), 포트 번호 지정 |
| 필터 액션(Filter Action) | Permit(허용) 또는 Block(차단) 선택 |

IP 보안 정책의 구성 방식은 L3 장비에서 ACL을 설정할 때와 동일하다. 출발지와 목적지, 포트를 지정하고 허용 또는 차단 여부를 결정한다.

복수의 정책이 존재할 경우, 목록 상단에 위치한 정책부터 순서대로 트래픽과 비교하여 적용된다.

## 091. Windows Server DNS 서버 구축

### 1. Windows Server 로그인 및 이벤트 트래킹

#### 1-1. 이전 설정 확인

이전 시간에 로컬 보안정책에서 Ctrl+Alt+Del 비활성화를 설정했기 때문에, 로그인 화면에서 해당 안내 문구가 사라진 것을 확인할 수 있다. 어드민 계정으로 바로 로그인이 가능하며, 왼쪽에 설정된 사용자 목록이 표시된다.

#### 1-2. 이벤트 트래킹 (Shutdown Event Tracking)

서버는 셧다운이 발생해서는 안 되기 때문에, 셧다운 이벤트 발생 시 원인을 기록하고 추적하는 기능이 활성화되어 있다. 부팅 후 이벤트 트래킹 창이 뜨면 셧다운 분류(전력 부족, 보안 이슈, 시스템 이슈 등)와 관리자 주석을 기입하는 란이 나타난다. 직접 종료한 경우에는 Cancel로 닫으면 된다.

### 2. DNS 서버 구축 (Windows Server)

#### 2-1. DNS 관리자 실행

Tools 메뉴의 DNS 항목을 클릭하면 DNS 관리자가 실행된다. DNS가 설치되지 않은 경우 Server Manager > Manage > Add Roles에서 DNS를 체크하여 추가 설치한다.

DNS 관리자에는 다음 두 개의 주요 영역이 존재한다.


| 영역 | 설명 |
|---|---|
| Forward Lookup Zones (정방향 존) | 도메인 → IP 매핑 레코드를 보유하는 영역 |
| Reverse Lookup Zones (역방향 존) | IP → 도메인 매핑 레코드를 보유하는 영역 |

정방향 존만 있어도 DNS 서버로서의 역할은 충분히 수행할 수 있다.

### 3. Forward Lookup Zone 생성

#### 3-1. Zone 종류


| 종류 | 설명 |
|---|---|
| Primary Zone | 1차(주) 존. 직접 편집이 가능한 기본 존 |
| Secondary Zone | 보조 존. Primary Zone과 동기화하여 백업 역할을 수행 |
| Stub Zone | 독립적인 존. 다른 존과 동기화하지 않고 독립적으로 운영 |

Primary Zone과 Secondary Zone은 서로 존 내의 레코드 정보를 동기화한다. 보조 서버가 Primary가 동작하지 못할 때 백업 역할을 하기 위해 평상시에 정보가 동기화되어 있어야 하기 때문이다. Stub Zone은 다른 존과 연결할 필요 없이 해당 영역 안에서만 독립적으로 레코드를 관리할 때 사용한다.

#### 3-2. Forward Lookup Zone 생성 절차

Forward Lookup Zones에서 우클릭 > New Zone으로 마법사를 실행한다.

### 1. Primary Zone 선택 후 Next

### 2. Zone 이름 입력: 실제로 접속되지 않는 도메인을 사용 (브라우저에서 미리 확인)

### 3. Zone 파일명 자동 생성: 도메인명.dns  형식

### 4. Dynamic Update: 보조 서버가 없는 경우 기본값(None - 마지막 항목) 유지

### 5. Finish 후 존이 Running 상태로 생성됨

⚠️ Zone 이름으로 사용할 도메인은 반드시 호스트 브라우저에서 미리 확인하여 실제로 연결되지 않는 도메인을 사용한다.

### 4. SOA 및 NS 레코드 자동 생성

#### 4-1. SOA 레코드 (Start of Authority)

Windows에서 Zone을 생성하면 SOA 레코드와 NS 레코드가 자동으로 생성된다. Linux에서 수동으로 입력하던 항목들이 마법사로 자동 구성된다.

SOA 레코드에서 확인 가능한 주요 항목은 다음과 같다.


| 항목 | 설명 |
|---|---|
| Serial Number | 존 파일의 버전 번호 |
| DNS 서버명 | 이 존을 관리하는 DNS 서버 호스트명 |
| 관리자 이메일 | 존 관리자 연락처 |
| Refresh Time | 보조 서버가 주 서버에서 업데이트를 확인하는 주기 |
| Retry Interval | 업데이트 실패 후 재시도 간격 |


| 항목 | 설명 |
|---|---|
| Expire Time | 보조 서버의 존 데이터 만료 시간 |
| Minimum TTL | 최소 캐시 유지 시간 |

#### 4-2. NS 레코드 IP 연결

NS 레코드 더블클릭 > Name Servers 탭에서 IP를 연결한다. 기존에 언나운(Unknown) 상태로 표시된 항목을 선택하고 Edit을 누른 후, Resolve 버튼을 클릭하면 해당 DNS 서버의 IP가 자동으로 확인되어 등록된다. 불필요한 항목은 Remove로 삭제하고 한 줄만 유지한다.

SOA 레코드 또는 NS 레코드를 수정한 경우 반드시 Apply 후 OK를 눌러 적용한다.

SOA 레코드와 NS 레코드의 Name 필드에 "(same as parent folder)"로 표시되는 것은 상위 도메인(예: hoon777.com)과 동일한 도메인을 사용한다는 의미이다.

### 5. DNS 레코드 추가

#### 5-1. A 레코드 (IPv4 주소 매핑)

빈 공간에서 우클릭 > New Host (A or AAAA)를 선택한다.


| 레코드 종류 | 용도 |
|---|---|
| A | IPv4 주소와 도메인 매핑 |
| AAAA | IPv6 주소와 도메인 매핑 |

호스트 이름 입력란에 값을 입력하면 해당 서브도메인(예: www.hoon777.com )이 생성된다. 입 력란을 공백으로 두면 부모 도메인(예: hoon777.com )이 해당 IP와 직접 연결된다.

FTP 서버, 웹 서버 등 서비스별로 각각 A 레코드를 추가하면 된다. 모두 동일한 시스템에서 운영할 경우 IP 주소는 같아도 무방하다.

#### 5-2. CNAME 레코드 (별칭 레코드)

별칭(Alias)을 부여할 때 사용하는 레코드이다. 우클릭 > New Alias (CNAME)를 선택한다.

별칭 이름 입력 (예: web )

Browse 버튼으로 실제 연결될 호스트 선택 (예: www.hoon777.com )

결과: web.hoon777.com  접속 시 www.hoon777.com 으로 연결됨 A 레코드를 직접 추가하는 방식과 CNAME으로 별칭을 부여하는 방식 두 가지가 모두 가능하다.

#### 5-3. MX 레코드

메일 서버가 있을 경우 메일 서버와 도메인을 연결하는 레코드이다. 우클릭 > New Mail Exchanger (MX) 선택 후 메일 서버 호스트명을 지정한다.

#### 5-4. 기타 레코드

우클릭 > Other New Records에서 다양한 레코드 유형을 확인할 수 있다. 실제 운영 환경에서 가장 많이 사용되는 순서는 A 레코드, CNAME 레코드, MX 레코드이다.

### 6. Reverse Lookup Zone 생성

#### 6-1. 역방향 존 생성 절차

Reverse Lookup Zones에서 우클릭 > New Zone > Primary Zone 선택 후 IPv4 Reverse Lookup Zone을 선택한다. 네트워크 ID를 입력하면(예: 192.168.100 ) 존 파일명 이 자동으로 생성된다. 이후 Finish하면 역방향 존과 함께 SOA, NS 레코드가 자동으로 생성된다.

#### 6-2. PTR 레코드

PTR 레코드는 정방향의 A 레코드에 대응하는 역방향 레코드이다. IP를 입력하고 해당 IP와 연결될 도메인을 선택하여 생성한다. A 레코드를 추가할 때 "Create associated PTR record" 옵션을 체크하면 역방향 존이 존재할 경우 PTR 레코드가 자동으로 등록된다.

#### 6-3. WINS 서버

WINS(Windows Internet Naming Service)는 TCP/IP 초기 시절 컴퓨터 이름 인식을 위해 사용하던 프로토콜이다. 현재는 TCP/IP 기반으로 호스트명 연결이 가능하기 때문에 WINS 서버를 사용하는 환경은 거의 없다.

#### 6-4. Zone Transfer (존 전송)

주 서버와 보조 서버 간의 존 레코드 동기화 기능이다. 보조 서버의 IP를 추가하고 Allow Zone Transfer를 설정하면 자동으로 동기화가 이루어진다. 보조 서버가 없는 경우에는 설정할 필요가 없다.

### 7. DNS 테스트

#### 7-1. 테스트 전 확인 사항

도메인으로 접속하기 전 IP 주소로 먼저 접속이 되는지 확인한다. IP로 접속이 안 되면 도메 인으로도 접속이 되지 않는다.

⚠️ IP 접속이 확인된 이후에만 도메인 접속 테스트를 진행한다.

#### 7-2. 호스트 DNS 주소 변경

테스트를 위해 호스트 컴퓨터의 DNS 주소를 윈도우 서버 IP로 임시 변경한다.

경로: 네트워크 및 인터넷 설정 열기 → 이더넷(또는 Wi-Fi) > 어댑터 옵션 변경 → 사용 중인 어댑터 우클릭 > 속성 → TCP/IP 버전4 > 속성 → DNS 서버 주소를 윈도우 서버 IP로 변경 변경 후 브라우저에서 www.도메인명.com 을 입력하면 DNS 서버에 질의하여 해당 IP로 접속된다. 테스트 완료 후 DNS 주소를 원래대로 복원한다.
