# 네트워크·Cisco Packet Tracer 심화 공식 보강 노트

> 목적: 기존 수업 노트와 개인과제를 기반으로 네트워크를 **이해 → 구성 → 검증 → 장애 분석** 순서로 다시 학습합니다.
>
> 표기: `[원문]` 기존 노트 내용, `[공식 확인]` 공식 문서·RFC 대조, `[실습 관찰]` Packet Tracer 또는 수업 실습에서 확인할 항목, `[확인 필요]` 장비 IOS·Packet Tracer 버전에 따라 재검증할 항목.

## 0. 이 노트 사용법

각 Lab은 다음 순서로 진행합니다.

1. 토폴로지와 IP 주소표를 먼저 작성합니다.
2. 장비 이름·인터페이스·케이블을 고정합니다.
3. L1/L2 상태를 확인한 뒤 L3 주소를 넣습니다.
4. 인접 장비 간 ping을 통과시킵니다.
5. 라우팅·보안 정책을 한 단계씩 추가합니다.
6. `show` 명령으로 상태를 확인하고, 마지막에 전체 통신을 시험합니다.

Packet Tracer 명령이 실행된다는 사실은 실제 IOS XE 전체 기능을 보장하지 않습니다. 페이지마다 **Packet Tracer 실습 가능 문법**과 **실제 IOS XE 기준**을 나눠 기록합니다. `[확인 필요]`는 기억으로 채우지 않고 장비·버전으로 재검증합니다.

## 1. 패킷이 움직이는 전체 그림

### 1.1 캡슐화

애플리케이션 데이터는 전송계층에서 TCP segment 또는 UDP datagram이 되고, 네트워크계층에서 IP packet, 데이터링크계층에서 Ethernet frame이 됩니다. 라우터는 L2 header를 벗기고 목적지 IP를 기준으로 다음 홉을 선택한 뒤 새 L2 header를 붙입니다.

| 계층 | 핵심 식별자 | 장비·프로토콜 예 | 확인 질문 |
|---|---|---|---|
| Application | 이름·요청 | DNS, HTTP, SSH | 어떤 서비스인가? |
| Transport | port, TCP/UDP | 22, 53, 80, 443 | 어느 프로세스인가? |
| Network | source/destination IP | IPv4, IPv6, ICMP | 어느 네트워크인가? |
| Data Link | MAC, VLAN | Ethernet, 802.1Q | 같은 broadcast domain인가? |
| Physical | signal, cable | copper, fiber, serial | 링크가 올라왔나? |

### 1.2 같은 서브넷과 다른 서브넷

같은 서브넷이면 호스트는 목적지 IP를 ARP 또는 IPv6 Neighbor Discovery로 MAC에 매핑해 직접 전송합니다. 다른 서브넷이면 기본 게이트웨이의 MAC으로 frame을 보내고, 라우터가 목적지 네트워크를 라우팅합니다.

```text
PC-A -> (같은 subnet) -> PC-B
PC-A -> default gateway -> Router -> next hop -> 목적지 subnet
```

장애 발생 시 “ping이 안 된다”만 보지 않습니다. `IP 주소 → mask → ARP/MAC → gateway → routing table → ACL/NAT/VPN` 순서로 범위를 좁힙니다.

## 2. IPv4·서브네팅·CIDR

### 2.1 prefix 계산

`/n`은 앞에서부터 n개의 network bit가 1인 mask입니다. IPv4는 32 bit입니다.

| Prefix | Mask | 전체 주소 | 일반적인 사용 가능 호스트 |
|---:|---|---:|---:|
| /24 | 255.255.255.0 | 256 | 254 |
| /25 | 255.255.255.128 | 128 | 126 |
| /26 | 255.255.255.192 | 64 | 62 |
| /27 | 255.255.255.224 | 32 | 30 |
| /30 | 255.255.255.252 | 4 | 2 |
| /31 | 255.255.255.254 | 2 | point-to-point 특례 확인 |
| /32 | 255.255.255.255 | 1 | 단일 주소·host route |

일반적인 LAN 계산식은 `2^(32-prefix) - 2`입니다. `/31`, `/32`, 장비별 point-to-point 처리는 예외이므로 장비 문서와 실습 결과를 확인합니다.

### 2.2 block size와 AND

예: `192.168.16.0/25`의 마지막 octet block size는 `256 - 128 = 128`입니다. 네트워크는 `0`, `128`에서 시작합니다.

- `192.168.16.100/25` → `192.168.16.0/25`
- `192.168.16.200/25` → `192.168.16.128/25`
- 두 주소는 같은 `192.168.16.0/24` 안에 있지만 `/25` 기준 다른 subnet입니다.

계산 절차:

1. prefix를 mask로 바꿉니다.
2. IP와 mask를 bitwise AND 합니다.
3. host bit를 모두 0으로 만든 값이 network address입니다.
4. host bit를 모두 1로 만든 값이 broadcast address입니다.
5. 두 호스트의 network address가 같을 때만 직접 통신으로 판단합니다.

CIDR과 prefix aggregation의 표준 기준은 [RFC 4632](https://www.rfc-editor.org/info/rfc4632/)입니다. 사설 주소 대역은 [RFC 1918](https://www.rfc-editor.org/info/rfc1918/)을 기준으로 기록합니다.

### 2.3 VLSM 설계

부서별 요구 호스트 수를 큰 순서로 정렬합니다. 각 요구량에 맞는 최소 prefix를 배정한 뒤 다음 미사용 block으로 이동합니다. 주소표에는 반드시 `network / first usable / last usable / broadcast / gateway / VLAN`을 함께 기록합니다.

## 3. Cisco IOS CLI와 Packet Tracer

### 3.1 모드 전환과 저장

```text
Router> enable
Router# configure terminal
Router(config)# hostname R1
R1(config)# end
R1# copy running-config startup-config
```

핵심 상태 확인:

```text
show running-config
show startup-config
show ip interface brief
show interfaces description
show cdp neighbors detail
show version
```

`running-config`는 RAM, `startup-config`는 재부팅 후 읽는 설정입니다. 실습 종료 전 저장 여부를 확인합니다.

### 3.2 인터페이스 기본 구성

```text
interface gigabitEthernet0/0
 description LAN-A
 ip address 192.168.10.1 255.255.255.0
 no shutdown
exit
```

`administratively down`은 `shutdown` 상태입니다. `down/down`은 케이블·상대편·물리 링크를 먼저 확인합니다. `up/down`은 encapsulation, clocking, keepalive, 상대편 설정을 확인합니다.

Serial DCE/DTE 실습에서는 DCE 쪽에 clock rate가 필요할 수 있습니다.

```text
show controllers serial 0/0/0
interface serial0/0/0
 clock rate 64000
```

장비 모델과 Packet Tracer 버전에 따라 인터페이스 이름·지원 명령이 다릅니다. 명령이 없으면 무리하게 대체하지 말고 모델을 기록합니다.

## 4. Switching: VLAN·Trunk·STP·SVI

### 4.1 Access와 Trunk

```text
vlan 10
 name USERS
interface fastEthernet0/1
 switchport mode access
 switchport access vlan 10
 spanning-tree portfast
exit

interface gigabitEthernet0/1
 switchport mode trunk
 switchport trunk allowed vlan 10,20,30
```

검증:

```text
show vlan brief
show interfaces trunk
show spanning-tree
show mac address-table dynamic
```

Access port는 한 VLAN에 속하고, trunk는 여러 VLAN tag를 전달합니다. Native VLAN·allowed VLAN·양쪽 trunk 설정 불일치는 통신 실패 원인이 됩니다.

### 4.2 Inter-VLAN routing

Router-on-a-Stick:

```text
interface gigabitEthernet0/0.10
 encapsulation dot1Q 10
 ip address 192.168.10.1 255.255.255.0
interface gigabitEthernet0/0.20
 encapsulation dot1Q 20
 ip address 192.168.20.1 255.255.255.0
```

L3 switch:

```text
ip routing
interface gigabitEthernet1/0/1
 no switchport
 ip address 10.0.0.1 255.255.255.252
 no shutdown
interface vlan 10
 ip address 192.168.10.1 255.255.255.0
 no shutdown
```

SVI는 VLAN의 L3 인터페이스입니다. VLAN이 존재하지 않거나 access/trunk 경로가 없으면 SVI가 살아 있어도 호스트 통신은 되지 않습니다.

## 5. Routing: 정적·동적·RIP

### 5.1 라우팅 테이블 읽기

```text
show ip route
show ip route 192.168.30.0
show ip protocols
```

라우터는 목적지 prefix가 가장 긴 경로를 우선 선택합니다. 같은 prefix 후보가 여러 개면 administrative distance로 출처 신뢰도를 비교하고, 같은 프로토콜 안에서는 metric으로 최적 경로를 비교합니다.

정적·기본 경로:

```text
ip route 192.168.30.0 255.255.255.0 10.0.0.2
ip route 0.0.0.0 0.0.0.0 10.0.0.2
```

### 5.2 RIP v1/v2

RIP는 distance-vector 방식이며 hop count를 metric으로 사용합니다. RIPv2의 표준 정의는 [RFC 2453](https://www.rfc-editor.org/info/rfc2453/)입니다.

```text
router rip
 version 2
 no auto-summary
 network 10.0.0.0
 network 192.168.10.0
```

확인:

```text
show ip protocols
show ip route rip
debug ip rip
```

수업 노트의 `send version 1` 같은 문법은 인터페이스별 송신 버전 설정과 관련됩니다. 전체 라우터 모드의 `version`과 구분하고, `show ip protocols` 결과로 실제 동작을 확인합니다.

## 6. EIGRP·OSPF·Redistribution

### 6.1 EIGRP AS 100

```text
router eigrp 100
 network 10.0.0.0 0.0.0.3
 network 192.168.10.0 0.0.0.255
 no auto-summary
```

```text
show ip eigrp neighbors
show ip eigrp topology
show ip route eigrp
```

Wildcard mask는 subnet mask의 역입니다. `network` 범위를 너무 넓게 잡으면 의도하지 않은 인터페이스에서 adjacency가 형성될 수 있습니다.

### 6.2 OSPF Area 0

```text
router ospf 1
 router-id 1.1.1.1
 network 10.0.0.0 0.0.0.3 area 0
 network 192.168.10.0 0.0.0.255 area 0
```

```text
show ip ospf neighbor
show ip ospf interface brief
show ip ospf database
show ip route ospf
```

OSPF는 link-state 방식입니다. 인접 관계 → LSDB → SPF 계산 순서로 이해합니다. Broadcast network에서는 DR/BDR 선출이 발생합니다. router-id 변경 후에는 프로세스 재시작이 필요할 수 있으므로 실습 전후 상태를 기록합니다.

### 6.3 Redistribution 주의

EIGRP와 OSPF를 재분배할 때는 양방향 재분배가 loop·suboptimal path를 만들 수 있습니다. metric 변환, route tagging, filtering을 설계하지 않은 `redistribute ...`는 실습 성공처럼 보여도 운영 구성으로 사용할 수 없습니다.

## 7. DHCP·NAT·PAT·ACL

### 7.1 DHCP

```text
ip dhcp excluded-address 192.168.10.1 192.168.10.20
ip dhcp pool USERS
 network 192.168.10.0 255.255.255.0
 default-router 192.168.10.1
 dns-server 8.8.8.8
```

```text
show ip dhcp binding
show ip dhcp pool
```

DHCP server가 다른 subnet에 있으면 `ip helper-address`를 검토합니다. 클라이언트 IP·gateway·DNS를 각각 확인합니다.

### 7.2 NAT/PAT

```text
interface g0/0
 ip nat inside
interface g0/1
 ip nat outside

ip nat inside source static 192.168.10.10 203.0.113.10
access-list 10 permit 192.168.10.0 0.0.0.255
ip nat inside source list 10 interface g0/1 overload
```

```text
show ip nat translations
show ip nat statistics
clear ip nat translation *
```

NAT는 inside/outside 방향, 변환 대상 ACL, outside interface, return route를 함께 확인합니다. VPN traffic을 NAT하면 IPsec selector와 충돌할 수 있으므로 VPN exemption 또는 정책 순서를 별도 설계합니다.

### 7.3 ACL

ACL은 위에서 아래로 first match를 적용하고, 마지막에 implicit deny가 있습니다. wildcard mask와 적용 방향을 주소표에 함께 기록합니다.

```text
ip access-list extended WEB-IN
 permit tcp 198.51.100.0 0.0.0.255 host 192.168.10.10 eq 443
 deny ip any any log
interface g0/1
 ip access-group WEB-IN in
```

```text
show access-lists
show ip interface g0/1
```

`permit ip any any`는 앞의 차단 규칙을 무력화할 수 있습니다. 전체 허용은 격리된 진단 Lab에서만 임시 사용하고, 최종 ACL에는 필요한 source·destination·service만 남깁니다. Cisco ACL 공식 가이드는 [Cisco IOS XE ACL Configuration Guide](https://www.cisco.com/c/en/us/td/docs/switches/lan/c9000/security/acls/acls-configuration-guide/access-control-lists.html)를 기준으로 합니다.

## 8. HSRP·FHRP

```text
interface g0/0
 ip address 192.168.10.2 255.255.255.0
 standby 10 ip 192.168.10.1
 standby 10 priority 110
 standby 10 preempt
 standby 10 track g0/1 20
```

```text
show standby brief
show standby
```

호스트 default gateway는 실제 라우터 주소가 아니라 virtual IP를 사용합니다. Cisco 문서에서 `standby ip`가 HSRP를 활성화하고 virtual IP가 선출에 사용됩니다. [Cisco HSRP Guide](https://www.cisco.com/c/en/us/td/docs/routers/ios/config/17-x/ntw-servs/b-network-services/m_fhp-hsrp-0.html)

장애 Lab:

1. R1/R2에 같은 virtual IP를 구성합니다.
2. priority로 Active/Standby를 확인합니다.
3. Active uplink을 shutdown합니다.
4. tracking 감소와 재선출을 확인합니다.
5. PC의 gateway는 바꾸지 않고 ping 지속 여부를 기록합니다.

## 9. GRE·IPsec VPN

### 9.1 GRE

```text
interface tunnel 0
 ip address 10.255.0.1 255.255.255.252
 tunnel source g0/1
 tunnel destination 203.0.113.2
```

GRE는 라우팅 가능한 논리 터널을 만들지만 자체적으로 confidentiality·integrity·peer authentication을 제공하지 않습니다. `[공식 확인]` GRE over IPsec은 GRE를 IPsec으로 보호하는 별도 구성입니다.

```text
show interfaces tunnel 0
show ip route
traceroute 10.20.0.1
```

### 9.2 IPsec 구성 흐름

일반적인 site-to-site 흐름은 다음과 같습니다.

1. 흥미 트래픽 ACL 정의
2. IKE/ISAKMP policy 정의
3. PSK 또는 인증 방식 정의
4. IPsec transform/proposal 정의
5. crypto map에 peer·ACL·transform 연결
6. 외부 interface에 crypto map 적용
7. IKE/IPsec SA와 실제 통신 확인

```text
crypto isakmp policy 10
 encr aes
 authentication pre-share
 group 14
crypto isakmp key <LAB-PSK> address 203.0.113.2

access-list 110 permit ip 192.168.10.0 0.0.0.255 192.168.20.0 0.0.0.255
crypto ipsec transform-set LAB-SET esp-aes esp-sha-hmac
crypto map LAB-MAP 10 ipsec-isakmp
 set peer 203.0.113.2
 set transform-set LAB-SET
 match address 110
interface g0/1
 crypto map LAB-MAP
```

```text
show crypto isakmp sa
show crypto ipsec sa
show crypto session
```

실습 자료에 등장하는 `3des`, `md5` 등 legacy 알고리즘은 현재 권장 구성과 구분합니다. Packet Tracer 지원 여부는 버전별로 `[확인 필요]`입니다. Cisco IPsec 공식 문서는 [Cisco Security for VPNs with IPsec](https://www.cisco.com/c/en/us/td/docs/routers/ios/config/17-x/sec-vpn/b-security-vpn/m_sec-cfg-vpn-ipsec-0.html)를 사용합니다.

## 10. IPv6·NDP·SLAAC·OSPFv3

IPv6 주소는 128 bit입니다. 연속 zero group 축약, 각 group의 leading zero 제거 규칙을 연습합니다. link-local `fe80::/10`은 인접 통신과 routing protocol에 사용될 수 있으며 interface scope가 필요할 수 있습니다.

```text
ipv6 unicast-routing
interface g0/0
 ipv6 address 2001:db8:10::1/64
 ipv6 enable
 no shutdown
```

```text
show ipv6 interface brief
show ipv6 neighbors
show ipv6 route
```

IPv6는 ARP 대신 Neighbor Discovery를 사용합니다. RA를 통한 SLAAC, DHCPv6, 수동 주소 지정 차이를 구분합니다. 기준 문서는 [RFC 8200 IPv6](https://www.rfc-editor.org/info/rfc8200/), [RFC 4861 Neighbor Discovery](https://www.rfc-editor.org/rfc/rfc4861.html), [RFC 4862 SLAAC](https://www.rfc-editor.org/info/rfc4862/), [RFC 5952 표현 규칙](https://www.rfc-editor.org/info/rfc5952/)입니다.

OSPFv3는 구현에 따라 문법이 다릅니다.

```text
ipv6 router ospf 10
 router-id 1.1.1.1
interface g0/0
 ipv6 ospf 10 area 0
```

IOS XE address-family 문법 예:

```text
router ospfv3 10
 address-family ipv6 unicast
  router-id 1.1.1.1
interface g0/0
 ospfv3 10 ipv6 area 0
```

Cisco IOS XE 공식 문서는 OSPFv3의 IPv4/IPv6 unicast address family와 IPv6 unicast routing/interface IPv6 조건을 설명합니다. [Cisco IPv6 Routing: OSPFv3](https://www.cisco.com/c/en/us/td/docs/routers/ios/config/17-x/ip-routing/b-ip-routing/m_ip6-route-ospfv3-xe.html)

## 11. 개인과제 전체 구축 순서

개인과제는 한 번에 모든 기능을 넣지 않습니다.

1. R1–R6, L3-SW, 각 access switch 이름 고정
2. Serial DCE/DTE와 Ethernet 연결 확인

4. HSRP virtual IP 확인
5. VLAN/access/trunk/Router-on-a-Stick 통신 확인
6. EIGRP AS100 구성
7. OSPF Area 0 구성
8. EIGRP↔OSPF redistribution은 route table 확인 후 추가
9. DHCP 구성·lease 확인
10. C-S server와 정적 NAT/PAT 구성
11. ACL은 요구사항별로 한 줄씩 추가·검증
12. R4/R6 site-to-site VPN 구성
13. VPN과 NAT selector 충돌 확인
14. 전체 ping·traceroute·서비스 접근 표 작성
15. `.pkt` 저장 후 최종 검증표와 함께 보관

## 12. 트러블슈팅 결정표

| 증상 | 먼저 볼 것 | 명령 |
|---|---|---|
| 인터페이스 down | cable, shutdown, 상대 포트 | `show ip interface brief` |
| 같은 VLAN ping 실패 | VLAN/access/MAC | `show vlan brief`, `show mac address-table` |
| 다른 VLAN 실패 | trunk, SVI, gateway | `show interfaces trunk`, `show ip interface brief` |
| 다른 네트워크 실패 | route/next hop | `show ip route`, `traceroute` |
| DHCP 실패 | pool/excluded/helper | `show ip dhcp binding`, `show run` |
| NAT 변환 없음 | inside/outside/ACL/return route | `show ip nat translations` |
| ACL 차단 | 순서·방향·implicit deny | `show access-lists`, `show ip interface` |
| HSRP 전환 안 됨 | priority/preempt/track/VIP | `show standby brief` |
| VPN SA 없음 | peer, interesting ACL, IKE | `show crypto isakmp sa` |
| GRE tunnel down | source/destination/underlay route | `show interfaces tunnel` |
| IPv6 route 없음 | unicast routing/OSPFv3 AF | `show ipv6 route`, `show ospfv3` |

## 13. 최종 학습 체크

- [ ] IP와 mask만 보고 두 호스트가 같은 subnet인지 계산할 수 있습니다.
- [ ] access/trunk/SVI/Router-on-a-Stick 차이를 설명할 수 있습니다.
- [ ] routing table에서 longest prefix, AD, metric을 구분합니다.
- [ ] RIP v1/v2, EIGRP, OSPF의 동작 차이를 설명합니다.
- [ ] ACL first match와 implicit deny를 적용 순서로 설명합니다.
- [ ] NAT/PAT와 IPsec interesting traffic 충돌을 설명합니다.
- [ ] HSRP Active/Standby와 tracking 결과를 검증합니다.
- [ ] GRE가 암호화하지 않는 이유와 IPsec 결합 이유를 설명합니다.
- [ ] IPv6 NDP/SLAAC/OSPFv3를 IPv4 ARP/OSPFv2와 비교합니다.
