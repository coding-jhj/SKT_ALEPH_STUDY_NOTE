원문 01 · 260819 네트워크 수업 완전 정리

기준 자료: 260819-정환주.txt의 전체 실습 기록과 오늘 대화에서 확인한 IPv6/OSPFv3 흐름
목표: 명령어를 외우는 것이 아니라 왜 설정하는지 → 어떤 순서로 하는지 → 어떻게 확인하는지 → 오류가 나면 무엇을 보는지까지 이해하기

0. 오늘 수업 전체 흐름부터 보기

오늘 실습은 크게 다음 주제로 연결됩니다.

  1. GRE Tunnel - 떨어진 두 네트워크 사이에 논리적인 터널을 생성 - 터널 인터페이스에 별도 IP 주소를 부여 - 정적 라우팅을 터널 쪽으로 연결 - tracert로 실제 경로와 터널 경로 비교

  2. IPsec VPN - GRE 자체에는 암호화/인증 기능이 없다는 점 확인 - ISAKMP/IKE 정책 설정 - Pre-Shared Key 설정 - IPsec Transform Set 설정 - Crypto Map 생성 및 외부 인터페이스에 적용

  3. Telnet 원격 접속 - VTY 라인 암호 설정 - enable password 설정 - PC에서 라우터로 Telnet 접속

  4. FHRP / HSRP - 게이트웨이를 2대로 이중화 - Active / Standby 라우터 구성 - Virtual IP(VIP) 사용 - Priority / Preempt 이해 - Tracking으로 외부 회선 장애 감지

  5. IPv6 - IPv6 주소 형식과 축약 - /64의 의미 - ipv6 unicast-routing - 인터페이스에 IPv6 주소 설정

  6. OSPFv3 - IPv6에서 OSPF 사용 - 인터페이스에 OSPFv3 활성화 - Router-ID 설정 - Neighbor / Route 확인

  7. 스위치의 L2 / L3 차이 - no switchport - Routed Port - ip routing - L3 Switch에서 OSPF - L2 Switch에서는 SVI(interface vlan 1)와 ip default-gateway - Switch Telnet 관리

오늘 내용은 서로 독립적인 명령어 묶음이 아니라 다음과 같이 연결해서 이해하면 좋습니다.

⌘Text
기본 라우팅
   ↓
GRE로 논리적 터널 생성
   ↓
GRE는 암호화가 없으므로 IPsec으로 보호
   ↓
라우터/스위치를 원격으로 관리하기 위해 Telnet
   ↓
게이트웨이 장애에 대비하기 위해 HSRP
   ↓
IPv4뿐 아니라 IPv6 환경 구성
   ↓
IPv6에서 OSPFv3로 동적 라우팅

1. GRE Tunnel

1-1. 터널이란?

터널(Tunnel)은 실제 물리 케이블을 새로 연결하는 것이 아니라, 기존 IP 네트워크 위에 논리적인 가상 연결을 하나 더 만드는 것입니다.

예를 들어 실제 네트워크가 다음과 같다고 가정합니다.

⌘Cisco IOS
LAN A
192.168.100.0/24
      |
    Router A
1.1.1.1
      |
   중간망
      |
2.2.2.2
    Router B
      |
172.16.0.0/24
LAN B

Router A와 Router B 사이에는 원래 1.1.1.x, 2.2.2.x 등의 실제 네트워크가 존재합니다.

여기에 GRE Tunnel을 만들면 논리적으로 다음 연결이 추가됩니다.

⌘Cisco IOS
Router A ================= Router B
      10.10.10.1      10.10.10.2
             GRE Tunnel

즉, 실제 패킷은 기존 IP망을 지나지만 라우터 입장에서는 Tunnel100이라는 가상 인터페이스가 하나 생긴 것처럼 사용할 수 있습니다.

1-2. Tunnel 인터페이스 생성

첫 번째 라우터에서:

⌘Cisco IOS
enable
configure terminal
interface tunnel 100

100은 터널 번호입니다.

실습에서 ?를 입력했을 때:

⌘Text
<0-2147483647> Tunnel interface number

라고 나왔습니다.

즉 터널 인터페이스는:

⌘Text
Tunnel0
Tunnel1
Tunnel100
...

처럼 여러 개 만들 수 있습니다.

1-3. Tunnel 인터페이스에 IP 주소 설정

Router A:

⌘Cisco IOS
interface tunnel 100
ip address 10.10.10.1 255.255.255.0

Router B:

⌘Cisco IOS
interface tunnel 100
ip address 10.10.10.2 255.255.255.0

그러면 두 터널 끝점은 같은 네트워크에 속합니다.

⌘Cisco IOS
10.10.10.0/24

Router A             Router B
10.10.10.1 -------- 10.10.10.2

중요한 점은 10.10.10.x가 물리 Serial 주소가 아니라 Tunnel100이라는 논리 인터페이스의 주소라는 것입니다.

1-4. GRE 모드 설정

실습 명령:

⌘Cisco
tunnel mode gre ip

GRE는 Generic Routing Encapsulation입니다.

쉽게 말하면:

원래 패킷을 다른 IP 패킷 안에 한 번 감싸서 보내는 방식

입니다.

중요한 특징

GRE는 여러 종류의 트래픽을 터널 안으로 넣기 편하지만:

  • 암호화를 제공하지 않음
  • 데이터 기밀성을 제공하지 않음
  • 자체적인 강력한 사용자 인증 기능이 없음

따라서 보안이 필요한 환경에서는 GRE + IPsec 조합을 많이 학습합니다.

2. Tunnel Source와 Destination

터널에서 가장 중요한 두 명령입니다.

Router A:

⌘Cisco
tunnel source se0/3/0
tunnel destination 2.2.2.2

Router B:

⌘Cisco
tunnel source se0/3/1
tunnel destination 1.1.1.1

tunnel source

이 터널 패킷을 실제로 어느 인터페이스/주소에서 출발시킬 것인가?

를 지정합니다.

예:

⌘Cisco
tunnel source se0/3/0

tunnel destination

터널 반대쪽 끝의 실제 IP 주소가 무엇인가?

를 지정합니다.

예:

⌘Cisco
tunnel destination 2.2.2.2

반드시 구분하기

⌘Text
10.10.10.1 / 10.10.10.2
→ 터널 내부에서 사용하는 가상 IP

1.1.1.1 / 2.2.2.2
→ 터널 패킷이 실제 네트워크를 통과할 때 사용하는 외부 IP

3. GRE Tunnel 설정 전체 형태

Router A

⌘Cisco IOS
enable
configure terminal

interface tunnel 100
 ip address 10.10.10.1 255.255.255.0
 tunnel mode gre ip
 tunnel source se0/3/0
 tunnel destination 2.2.2.2
 exit

ip route 172.16.0.0 255.255.255.0 10.10.10.2

Router B

⌘Cisco IOS
enable
configure terminal

interface tunnel 100
 ip address 10.10.10.2 255.255.255.0
 tunnel mode gre ip
 tunnel source se0/3/1
 tunnel destination 1.1.1.1
 exit

ip route 192.168.100.0 255.255.255.0 10.10.10.1

4. 왜 Static Route를 Tunnel 주소로 설정했나?

Router A:

⌘Cisco
ip route 172.16.0.0 255.255.255.0 10.10.10.2

뜻:

172.16.0.0/24로 가려면 Tunnel 반대편 주소인 10.10.10.2로 보내라.

Router B:

⌘Cisco
ip route 192.168.100.0 255.255.255.0 10.10.10.1

뜻:

192.168.100.0/24로 가려면 Tunnel 반대편 주소인 10.10.10.1로 보내라.

그래서 논리적으로는:

⌘Text
192.168.100.0/24
        |
   10.10.10.1
        ║
        ║ GRE Tunnel
        ║
   10.10.10.2
        |
172.16.0.0/24

형태로 통신하게 됩니다.

5. Tunnel 상태 확인

실습 명령:

⌘SQL
show interface tunnel 100

정상적인 핵심 출력:

⌘Text
Tunnel100 is up, line protocol is up
Internet address is 10.10.10.2/24
Tunnel source 2.2.2.2 (...), destination 1.1.1.1
Tunnel protocol/transport GRE/IP

가장 먼저 볼 것

⌘Text
Tunnel100 is up, line protocol is up

즉:

⌘Text
up/up

이면 터널 인터페이스가 정상 상태입니다.

6. Router#do show ... 오류가 난 이유

기록에서:

⌘Cisco IOS
Router#do show int tunnel 100

을 입력했고 오류가 발생했습니다.

이유는 현재 프롬프트가:

⌘Cisco IOS
Router#

즉 Privileged EXEC Mode였기 때문입니다.

do는 설정 모드에서 EXEC 명령을 실행하기 위해 사용하는 명령입니다.

예:

⌘Cisco IOS
Router(config)#do show ip route
Router(config-if)#do show ipv6 interface brief

반면 이미:

⌘Cisco IOS
Router#

이면 그냥:

⌘SQL
show interface tunnel 100

이라고 하면 됩니다.

기억법

⌘Cisco IOS
Router#          → show ...
Router(config)#  → do show ...
Router(config-if)# → do show ...

7. tracert로 GRE 적용 전/후 비교

실습에서 첫 번째 tracert:

⌘Text
1  192.168.100.1
2  1.1.1.2
3  2.2.2.2
4  172.16.0.2

즉 실제 네트워크의 중간 라우터들이 보입니다.

이후 터널 경로를 이용했을 때:

⌘Text
1  192.168.100.1
2  10.10.10.2
3  172.16.0.2

처럼 터널의 반대편 주소가 논리적인 다음 홉으로 보였습니다.

핵심:

GRE를 만들었다고 실제 물리 경로가 사라진 것이 아닙니다.
실제로는 기존 네트워크를 통과하지만, 라우팅 관점에서는 터널이라는 논리적 링크를 사용하는 것입니다.

8. GRE의 한계: 암호화와 인증

수업 기록에:

⌘Text
암호화/인증 제공하지 않음

이라고 되어 있습니다.

이것이 바로 GRE의 중요한 단점입니다.

GRE는 캡슐화를 해줄 뿐, 데이터를 안전하게 보호하는 기술 자체는 아닙니다.

따라서 다음 단계에서 IPsec을 적용합니다.

⌘Text
GRE
= 논리적인 터널

IPsec
= 터널을 통과하는 데이터를 암호화/인증하여 보호

9. IPsec VPN 전체 구조

실습에서 사용한 흐름은 다음과 같습니다.

⌘Text
1. ACL로 보호할 트래픽 정의
2. ISAKMP/IKE Policy 설정
3. Pre-Shared Key 설정
4. IPsec Transform Set 설정
5. Crypto Map 설정
6. 외부 인터페이스에 Crypto Map 적용
7. 상태 확인

이 순서는 반드시 익혀두는 것이 좋습니다.

10. IPsec ACL

예:

⌘Cisco IOS
access-list 100 permit gre host 1.1.1.1 host 2.2.2.2

반대편:

⌘Cisco IOS
access-list 100 permit gre host 2.2.2.2 host 1.1.1.1

이 ACL은 일반적인 방화벽 차단 ACL과 조금 다르게 생각해야 합니다.

IPsec에서 Crypto Map에 연결되는 ACL은 주로:

어떤 트래픽을 IPsec으로 보호할 것인가?

를 정하는 Interesting Traffic 기준으로 사용됩니다.

수업에서는 GRE 트래픽을 대상으로 지정했습니다.

11. ACL 명령 오류

기록에서:

⌘Cisco IOS
access-list permit gre ...

이라고 입력했을 때 오류가 발생했습니다.

정확한 명령은:

⌘Cisco IOS
access-list 100 permit gre ...

입니다.

즉 access-list 뒤에 ACL 번호 100이 빠졌기 때문입니다.

12. ISAKMP / IKE 정책

실습:

⌘Cisco
crypto isakmp policy 10
 authentication pre-share
 encryption 3des
 hash md5

crypto isakmp policy 10

ISAKMP/IKE 협상 정책을 만듭니다.

10은 정책 우선순위입니다.

숫자가 작을수록 우선적으로 검사합니다.

authentication pre-share

상대방 인증 방법을 PSK(Pre-Shared Key)로 사용합니다.

쉽게 말하면:

두 라우터가 미리 같은 비밀번호를 알고 있고, 그 비밀번호를 기반으로 서로를 확인한다.

는 방식입니다.

encryption 3des

IKE 협상 과정에서 사용할 암호화 알고리즘을 지정합니다.

수업에서는:

⌘Text
3DES

를 사용했습니다.

참고

3DES는 학습용 구형 장비/Packet Tracer 실습에서 자주 등장하지만, 현대 실무 기준으로는 오래된 알고리즘입니다.

hash md5

무결성/해시 알고리즘으로 MD5를 사용합니다.

이 역시 현대 실무에서는 보안상 권장되지 않는 오래된 방식이지만, Packet Tracer 기초 실습에서는 명령 구조를 배우기 위해 사용될 수 있습니다.

13. Pre-Shared Key 설정

Router A:

⌘Cisco
crypto isakmp key 1234 address 2.2.2.2

Router B:

⌘Cisco
crypto isakmp key 1234 address 1.1.1.1

해석:

⌘Text
key 1234
→ 상대방과 공유할 비밀 키

address 2.2.2.2
→ 이 키를 사용할 상대방 IP

양쪽의 키가 서로 같아야 합니다.

14. IPsec Transform Set

실습:

⌘Cisco
crypto ipsec transform-set test esp-3des esp-md5-hmac

구성:

⌘Text
test
→ Transform Set 이름

esp-3des
→ 데이터 암호화

esp-md5-hmac
→ 데이터 무결성/인증

즉 IPsec이 실제 데이터를 어떤 방식으로 보호할지 정의합니다.

15. 기록에서 발견되는 Transform Set 확인 포인트

실습 입력에는:

⌘Cisco
crypto ipsec transform-set test esp-3des esp-md5-hmac

라고 되어 있습니다.

그런데 이후 show crypto ipsec transform-set 출력 일부에는:

⌘Text
esp-3des esp-sha-hmac

가 보입니다.

반면 show running-config에는 다시:

⌘Text
crypto ipsec transform-set test esp-3des esp-md5-hmac

가 남아 있습니다.

따라서 이 부분은 기록상 서로 일치하지 않습니다.

공부할 때는 최종 running-config를 현재 장비 설정의 가장 직접적인 확인 자료로 보는 것이 안전합니다.

확인 명령:

⌘Cisco IOS
show running-config
show crypto ipsec transform-set

16. Crypto Map

실습:

⌘Cisco
crypto map vpn-map 10 ipsec-isakmp

Crypto Map은 지금까지 만든 설정들을 한곳에 묶는 역할을 합니다.

다음 3가지를 연결합니다.

⌘Cisco
match address 100
set peer 2.2.2.2
set transform-set test

match address 100

ACL 100에 해당하는 트래픽을 IPsec 대상으로 사용합니다.

set peer

VPN 상대 라우터를 지정합니다.

⌘Cisco
set peer 2.2.2.2

set transform-set

어떤 암호화/무결성 방식을 사용할지 지정합니다.

⌘Cisco
set transform-set test

17. Crypto Map을 실제 인터페이스에 적용

설정만 만들어 놓아서는 실제 패킷에 적용되지 않습니다.

Router A:

⌘Cisco IOS
interface se0/3/0
 crypto map vpn-map

Router B:

⌘Cisco IOS
interface se0/3/1
 crypto map vpn-map

즉 실제 외부 트래픽이 나가는 인터페이스에 Crypto Map을 붙입니다.

18. IPsec 확인 명령어

오늘 사용한 중요한 확인 명령어:

⌘Cisco IOS
show crypto map
show crypto isakmp policy
show crypto isakmp sa
show crypto ipsec transform-set
show crypto ipsec sa

show crypto map

확인 대상:

  • Peer 주소
  • ACL 번호
  • Transform Set
  • 적용 인터페이스

show crypto isakmp policy

수업 출력:

⌘Text
encryption algorithm: Three key triple DES
hash algorithm: Message Digest 5
authentication method: Pre-Shared Key
Diffie-Hellman group: #1
lifetime: 86400 seconds

여기에서 IKE Phase 1 정책을 확인할 수 있습니다.

show crypto isakmp sa

IKE 보안 연관(Security Association)이 맺어졌는지 확인합니다.

실습 기록에서는 표에 실제 SA 항목이 나타나지 않았습니다.

이 경우 보통 아직 실제 보호 대상 트래픽을 발생시키지 않았거나, 협상이 완료되지 않은 상태일 수 있습니다.

19. IPsec 학습용 전체 명령 구조

Router A 예시

⌘Cisco IOS
access-list 100 permit gre host 1.1.1.1 host 2.2.2.2

crypto isakmp policy 10
 authentication pre-share
 encryption 3des
 hash md5
 exit

crypto isakmp key 1234 address 2.2.2.2

crypto ipsec transform-set test esp-3des esp-md5-hmac

crypto map vpn-map 10 ipsec-isakmp
 match address 100
 set peer 2.2.2.2
 set transform-set test
 exit

interface se0/3/0
 crypto map vpn-map

Router B는 출발지/목적지와 peer 주소를 반대로 설정합니다.

20. Telnet 원격 접속

수업에서는 라우터에 직접 콘솔로 접속하지 않고, PC에서 원격으로 접속하는 Telnet도 실습했습니다.

라우터:

⌘Cisco
line vty 0 4
login
password 1234
exit

enable password 1234

PC:

⌘Text
telnet 192.168.100.1

21. VTY가 무엇인가?

VTY(Virtual Teletype)는 라우터/스위치에 Telnet 또는 SSH 같은 원격 터미널 접속을 제공하는 가상 라인입니다.

⌘Cisco
line vty 0 4

는 VTY 0번부터 4번까지 총 5개 세션을 설정한다는 뜻입니다.

22. login과 password

기록에서:

⌘Cisco
login

을 먼저 입력하자:

⌘Text
Login disabled ... until 'password' is set

이라는 메시지가 나왔습니다.

의미:

로그인 인증을 사용하겠다고 했지만 아직 사용할 비밀번호가 설정되지 않았다.

따라서 일반적으로는:

⌘Cisco
line vty 0 4
password 1234
login

순서로 쓰면 이해하기 쉽습니다.

23. enable password

Telnet으로 처음 접속하면 보통:

⌘Cisco IOS
Router>

User EXEC Mode로 들어갑니다.

이후:

⌘Cisco
enable

을 입력해:

⌘Cisco IOS
Router#

Privileged EXEC Mode로 올라가려면 Enable 암호가 필요할 수 있습니다.

⌘Cisco
enable password 1234

가 그 암호를 설정합니다.

24. Telnet의 보안 주의점

Telnet은 계정 정보와 데이터가 암호화되지 않는 오래된 프로토콜입니다.

따라서:

  • Packet Tracer 기초 실습: Telnet 가능
  • 실제 네트워크 관리: SSH 권장

이라고 구분해서 기억하면 됩니다.

25. FHRP란?

수업 필기:

⌘Text
FHRP(First Hop Redundancy Protocol - 장애 대비)
HSRP / VRRP / GLBP

FHRP는 PC들이 사용하는 기본 게이트웨이를 이중화하기 위한 기술입니다.

일반적인 PC:

⌘Text
PC → Gateway 192.168.100.1

문제:

⌘Text
192.168.100.1 라우터 장애
→ PC가 다른 네트워크로 못 나감

그래서 두 라우터가 하나의 가상 게이트웨이 주소를 공유하게 합니다.

26. HSRP 기본 개념

HSRP는 Cisco의 FHRP 기술입니다.

예:

⌘Cisco IOS
Router A 실제 IP = 192.168.100.1
Router B 실제 IP = 192.168.100.2

Virtual IP     = 192.168.100.254

PC는 실제 라우터 IP를 게이트웨이로 쓰는 것이 아니라:

⌘Text
192.168.100.254

를 Gateway로 사용합니다.

그러면:

⌘Text
PC
 |
 | Gateway = 192.168.100.254
 |
 +---- Router A (Active)
 |
 +---- Router B (Standby)

처럼 동작합니다.

27. HSRP 기본 설정

Router A:

⌘Cisco IOS
interface gi0/0
standby 1 ip 192.168.100.254
standby 1 preempt
standby 1 priority 105

Router B:

⌘Cisco IOS
interface gi0/0
standby 1 ip 192.168.100.254
standby 1 preempt

기본 Priority는:

⌘Text
100

입니다.

따라서:

⌘Cisco IOS
Router A = 105
Router B = 100

이면 Router A가 Active가 될 가능성이 높습니다.

28. HSRP 그룹 번호

⌘Cisco
standby 1 ...

에서 1은 HSRP Group 번호입니다.

같은 HSRP 그룹으로 동작하려는 라우터는:

  • 같은 Group 번호
  • 같은 Virtual IP

를 사용해야 합니다.

29. HSRP Priority

수업 필기:

⌘Text
priority - 우선순위(default = 100)
우선순위가 높을수록 active 장비가 됨

예:

⌘Cisco IOS
Router A = 105
Router B = 100

→ Router A가 우선 Active

확인:

⌘Cisco IOS
show standby brief

실습 출력:

⌘Text
Gig0/0  1  105 P Active   local ...

여기에서:

⌘Text
105
→ Priority

P
→ Preempt 설정

Active
→ 현재 Active 라우터

입니다.

30. HSRP Preempt

수업 필기:

⌘Text
preemption - 원래 상태로 돌리는 것

조금 더 정확하게 설명하면:

더 높은 Priority를 가진 라우터가 다시 정상 상태가 되었을 때 Active 역할을 다시 빼앗아 올 수 있도록 하는 기능

입니다.

예:

⌘Text
R1 Priority 105
R2 Priority 100

정상:

⌘Text
R1 = Active
R2 = Standby

R1 장애:

⌘Text
R2 = Active

R1 복구 후 preempt가 설정되어 있으면:

⌘Text
R1 = 다시 Active
R2 = 다시 Standby

가 됩니다.

31. HSRP 상태 확인

⌘Cisco IOS
show standby brief
show standby

show standby에서 확인할 수 있는 정보:

  • 현재 State
  • Virtual IP
  • Active Router
  • Standby Router
  • Priority
  • Preempt 여부
  • Hello/Hold Timer
  • Tracking 상태

실습 예:

⌘Text
State is Active
Virtual IP address is 192.168.100.254
Preemption enabled
Active router is local
Standby router is 192.168.100.2
Priority 105

32. Active 라우터 장애 실험

실습에서 Active 라우터의 Gi0/0을:

⌘Cisco IOS
shutdown

했습니다.

그러자:

⌘Text
Active -> Init

등의 상태 변화가 발생하고, 반대편에서는:

⌘Text
Standby -> Active

로 전환되었습니다.

즉 HSRP의 핵심 목표인:

Active 장비 장애 시 Standby 장비가 Gateway 역할을 이어받는다.

를 확인한 것입니다.

33. HSRP와 OSPF 로그를 같이 본 이유

Gi0/0을 Shutdown하자 다음과 같은 OSPF 로그도 발생했습니다.

⌘Text
OSPF ... FULL to DOWN

이유:

하나의 인터페이스에서:

  • HSRP
  • OSPF Neighbor

가 동시에 동작하고 있었기 때문입니다.

인터페이스 자체가 내려가면 그 인터페이스 위에서 동작하던 여러 프로토콜이 동시에 영향을 받습니다.

34. HSRP Tracking

수업 필기:

⌘Text
tracking(추적)
기본값 10만큼 감소

설정:

⌘Cisco
standby 1 track se0/3/0

뜻:

HSRP가 Serial0/3/0 상태를 감시하라.

35. 왜 Tracking이 필요한가?

예:

⌘Text
       인터넷
         |
      Serial
         |
       R1
         |
LAN ----+---- R2

R1의 LAN 인터페이스는 살아 있는데 외부로 나가는 Serial 회선만 죽었다고 해봅시다.

Tracking이 없으면:

⌘Text
R1 LAN 인터페이스는 살아 있음
→ HSRP는 R1을 계속 Active라고 생각할 수 있음
→ PC들은 R1으로 보내지만 외부로 못 나감

Tracking을 설정하면:

⌘Text
Serial 장애 감지
→ R1 Priority 감소
→ R2의 Priority가 더 높아짐
→ R2가 Active로 전환 가능

해집니다.

36. Tracking Priority 감소

실습:

⌘Text
Priority 105

였던 라우터에서 Serial0/3/0 장애 후:

⌘Text
Priority 95 (configured 105)
Track interface Serial0/3/0 state Down decrement 10

가 나타났습니다.

계산:

⌘Text
105 - 10 = 95

즉 설정된 원래 Priority는 105지만 Tracking 때문에 현재 유효 Priority가 95가 된 것입니다.

주의

Priority가 낮아졌다고 반드시 즉시 Active가 바뀌는 것은 아닙니다.

상대 라우터의 Priority와 Preempt 설정, HSRP Timer 상태 등에 따라 실제 전환이 결정됩니다.

37. IPv6 기본 구조

IPv6 주소는 총:

⌘Text
128비트

입니다.

IPv6 예:

⌘Text
2001:2:2:2::1/64

IPv6는 :로 구분된 최대 8개의 블록으로 표현합니다.

각 블록:

⌘Text
16비트

따라서:

⌘Text
16비트 × 8 = 128비트

입니다.

38. IPv6 /64가 왜 64비트인가?

예:

⌘Text
2001:2:2:2::1/64

완전히 풀어쓰면:

⌘Text
2001:0002:0002:0002:0000:0000:0000:0001

앞의 네 블록:

⌘Text
2001 : 0002 : 0002 : 0002
 16      16      16      16

합계:

⌘Text
16 × 4 = 64비트

그래서 /64는:

⌘Text
앞 64비트 = 네트워크 부분
뒤 64비트 = 인터페이스(호스트) 부분

이라고 이해하면 됩니다.

39. IPv6 축약 규칙

수업에서 적은 핵심:

⌘Text
2001:0DB8:0000:0000:0000:0000:0000:0000
→ 2001:DB8::

규칙은 크게 두 개입니다.

규칙 1. 각 블록의 앞쪽 0 생략

⌘Text
0DB8 → DB8
0002 → 2
0000 → 0

예:

⌘Text
2001:0DB8:0345:0000:0000:0000:0000:0000

→

⌘Text
2001:DB8:345:0:0:0:0:0

규칙 2. 연속된 0 블록을 ::로 축약

⌘Text
2001:DB8:345:0:0:0:0:0

→

⌘Text
2001:DB8:345::

매우 중요한 규칙

::는 한 IPv6 주소 안에서 한 번만 사용할 수 있습니다.

왜냐하면 두 번 사용하면 생략된 0이 각각 몇 블록인지 알 수 없기 때문입니다.

40. IPv6 주소 종류

수업 필기에는 다음 내용이 있습니다.

⌘Text
Global 주소
Link-Local 주소
사이트 로컬 주소
Multicast
Anycast
Unicast
Broadcast 없음

Unicast

하나의 특정 인터페이스로 보내는 주소입니다.

Multicast

특정 그룹에 속한 여러 장비에게 보냅니다.

Anycast

같은 주소를 여러 장비가 사용할 수 있고, 라우팅상 가까운 장비 하나로 전달됩니다.

Broadcast

IPv6에는 IPv4에서 사용하던 Broadcast 개념이 없습니다.

필요한 그룹 전송은 Multicast로 처리합니다.

41. Link-Local 주소

IPv6 인터페이스에서 자주 보게 되는:

⌘Text
FE80::...

형태가 Link-Local Address입니다.

특징:

  • FE80::/10 범위
  • 같은 링크에서 통신할 때 사용
  • 라우터 간 Neighbor 관계 등에서 자주 사용
  • 일반 인터넷 라우팅용 Global Address와 역할이 다름

OSPFv3 라우팅 테이블에서도 다음 홉이:

⌘Text
via FE80::....

처럼 보일 수 있습니다.

정상입니다.

42. Dual Stack

수업 필기:

⌘Text
Dual Stack - 하나의 인터페이스에 두 개의 주소를 쓰는 것

정확히는 하나의 장비/인터페이스에서 IPv4와 IPv6를 동시에 운영하는 형태입니다.

예:

⌘Text
GigabitEthernet0/0

IPv4:
192.168.200.1/24

IPv6:
2001:3:3:3::1/64

IPv4 주소가 이미 있다고 해서 IPv6 주소를 넣으면 안 되는 것이 아닙니다.

둘은 동시에 존재할 수 있습니다.

43. IPv6 라우팅 활성화

실습에서 OSPFv3를 입력했을 때:

⌘Text
% IPv6 routing not enabled

오류가 발생했습니다.

해결:

⌘Cisco
ipv6 unicast-routing

이 명령은 전역 설정 모드에서 사용합니다.

⌘Cisco IOS
Router(config)#ipv6 unicast-routing

라우터가 IPv6 패킷을 인터페이스 사이에서 라우팅하도록 활성화하는 핵심 명령입니다.

44. 인터페이스에 IPv6 주소 설정

실습:

⌘Cisco IOS
interface se0/2/0
ipv6 address 2001:2:2:2::1/64
no shutdown

반대편 라우터:

⌘Cisco IOS
interface se0/2/0
ipv6 address 2001:2:2:2::2/64
no shutdown

두 주소는 같은 네트워크:

⌘Text
2001:2:2:2::/64

에 속합니다.

45. OSPFv3 설정

IPv6에서 OSPF를 사용할 때 오늘 실습 방식은:

⌘Cisco IOS
interface se0/2/0
ipv6 ospf 1 area 0

입니다.

여기서:

⌘Text
1
→ OSPF Process ID

area 0
→ OSPF Area 0

입니다.

IPv4 OSPF에서 자주 사용하던:

⌘Cisco IOS
router ospf 1
network ...

방식과 비교하면, 오늘 Packet Tracer의 OSPFv3 실습에서는 인터페이스에 직접 OSPF를 활성화했습니다.

46. OSPFv3 Router-ID

실습:

⌘Cisco
ipv6 router ospf 1
router-id 11.11.11.11

반대편:

⌘Cisco
ipv6 router ospf 1
router-id 12.12.12.12

중요:

11.11.11.11은 실제 IPv4 통신 주소라는 뜻이 아닙니다.

OSPF가 각 라우터를 구분하기 위한 32비트 식별자입니다.

IPv6 OSPF라도 Router-ID는 IPv4처럼 점으로 구분된 형식을 사용합니다.

47. IPv6 + OSPFv3 권장 설정 순서

앞으로는 다음 순서로 하면 실수를 크게 줄일 수 있습니다.

⌘Text
1. ipv6 unicast-routing
2. 인터페이스 선택
3. ipv6 address
4. no shutdown
5. ipv6 ospf 1 area 0
6. ipv6 router ospf 1
7. router-id 설정
8. 확인 명령어

예:

⌘Cisco IOS
enable
configure terminal

ipv6 unicast-routing

interface se0/2/0
 ipv6 address 2001:2:2:2::1/64
 no shutdown
 ipv6 ospf 1 area 0
 exit

ipv6 router ospf 1
 router-id 11.11.11.11
end

48. IPv6 / OSPFv3 확인 명령어

반드시 기억할 세 가지:

⌘Cisco IOS
show ipv6 interface brief
show ipv6 ospf neighbor
show ipv6 route

1. show ipv6 interface brief

확인:

  • IPv6 주소
  • 인터페이스가 up/up인지
  • Link-Local 주소

2. show ipv6 ospf neighbor

확인:

  • OSPFv3 Neighbor가 생겼는지
  • State가 FULL인지

정상 핵심:

⌘Text
FULL

3. show ipv6 route

확인:

  • 직접 연결 네트워크
  • OSPF로 배운 네트워크

49. IPv6 Route 코드

중요한 것 세 개만 먼저 익히면 됩니다.

⌘Text
C = Connected
L = Local
O = OSPF

예:

⌘Text
C 2001:2:2:2::/64

뜻:

이 라우터에 직접 연결된 네트워크

⌘Text
L 2001:2:2:2::2/128

뜻:

이 라우터 자신의 인터페이스 주소

⌘Text
O 2001:3:3:3::/64

뜻:

다른 라우터에게 OSPF로 배운 네트워크

50. 왜 어떤 라우터에는 O가 없을 수 있는가?

OSPF Neighbor가 FULL이라고 해서 반드시 양쪽 라우팅 테이블에 O가 있어야 하는 것은 아닙니다.

예:

⌘Text
R1 ----- R2 ----- LAN

R2에는:

  • R1-R2 Serial 네트워크
  • 자신의 LAN

이 모두 직접 연결되어 있을 수 있습니다.

그러면 R2에서는 둘 다:

⌘Text
C

입니다.

반면 R1은 R2 뒤쪽 LAN을 직접 연결하고 있지 않으므로:

⌘Text
O

로 배웁니다.

즉:

⌘Text
Neighbor FULL
→ OSPF 이웃 관계 정상

O route
→ 다른 라우터에게서 새로운 네트워크를 학습했을 때 표시

입니다.

51. IPv6 PC 설정

PC의 IPv6 LAN이:

⌘Text
2001:3:3:3::/64

라고 하면 예:

⌘Cisco IOS
Router Gi0/0:
2001:3:3:3::1/64

PC:
2001:3:3:3::100/64

Default Gateway:
2001:3:3:3::1

처럼 설정합니다.

원칙

PC와 Gateway는 반드시 같은 /64 네트워크에 있어야 합니다.

52. IPv6 Ping 문제를 찾는 순서

먼 목적지부터 Ping하지 말고 가까운 곳부터 확인합니다.

⌘Text
1. PC → 자신의 Gateway
2. PC → 바로 옆 라우터의 다른 인터페이스
3. PC → 다음 라우터
4. PC → 최종 목적지

예:

⌘Text
ping 2001:3:3:3::1
ping 2001:2:2:2::2

1번부터 안 되면 OSPF를 보기 전에:

  • PC IPv6 주소

  • Default Gateway
  • Switch 연결
  • Router Gi0/0 상태

를 먼저 확인해야 합니다.

53. L3 Switch의 Routed Port

수업 후반부에서 스위치 인터페이스에:

⌘Cisco IOS
ip address 5.5.5.5 255.255.255.0

를 입력했더니 처음에는 오류가 났습니다.

이유:

일반적인 스위치 포트는 기본적으로 Layer 2 Switchport이기 때문입니다.

L3 Switch에서는:

⌘Cisco
no switchport

를 입력하면 해당 포트를 Routed Port로 바꿀 수 있습니다.

그 후:

⌘Cisco IOS
ip address 5.5.5.5 255.255.255.0

를 설정할 수 있습니다.

54. no switchport란?

기본 스위치 포트:

⌘Text
Layer 2
→ MAC 주소 기반 Switching
→ VLAN에 속하는 포트

no switchport 적용:

⌘Text
Layer 3 Routed Port
→ Router 인터페이스처럼 IP 주소 부여 가능
→ Routing에 참여 가능

즉 L3 Switch에서는:

⌘Cisco IOS
interface fa0/1
 no switchport
 ip address 5.5.5.5 255.255.255.0

가 가능합니다.

55. L3 Switch에서 ip routing

기록에서:

⌘Cisco IOS
router ospf 1

을 입력했을 때:

⌘Text
IP routing not enabled

이 나왔습니다.

해결:

⌘Cisco
ip routing

그 후:

⌘Cisco IOS
router ospf 1

이 가능해집니다.

즉 L3 Switch를 라우터처럼 사용하려면:

⌘Text
Routed Port
+
ip routing
+
Routing Protocol

구조를 이해해야 합니다.

56. 모든 Switch가 no switchport를 지원하는 것은 아니다

다른 스위치에서는:

⌘Cisco
no switchport

를 입력해도 Routed Port로 바뀌지 않았습니다.

? 출력에는:

⌘Text
access
mode
nonegotiate
port-security
trunk
...

등만 나왔습니다.

이는 해당 장비/포트가 Layer 2 Switchport 기능 중심으로 동작하고, Routed Port 기능을 지원하지 않는 모델/환경이라는 의미로 볼 수 있습니다.

따라서:

⌘Text
L3 Switch
→ no switchport 가능

일반 L2 Switch
→ no switchport로 Routed Port 전환 불가

라고 구분해야 합니다.

57. L2 Switch 관리 IP: SVI

L2 Switch에서도 관리 목적으로 IP 주소가 필요할 수 있습니다.

이때 물리 포트에 IP를 주는 것이 아니라:

⌘Cisco IOS
interface vlan 1
ip address 192.168.100.50 255.255.255.0
no shutdown

처럼 SVI(Switch Virtual Interface)에 주소를 줍니다.

즉:

⌘Cisco IOS
Fa0/1
Fa0/2
...
→ 실제 Switching 포트

interface vlan 1
→ 스위치 자신을 관리하기 위한 논리 인터페이스

입니다.

58. L2 Switch의 ip default-gateway

실습:

⌘Cisco
ip default-gateway 192.168.100.1

L2 Switch는 일반적으로 라우터처럼 ip routing을 하지 않습니다.

따라서 관리 트래픽이 다른 네트워크로 나갈 때 사용할 Gateway를:

⌘Cisco
ip default-gateway

로 설정합니다.

구분

⌘Cisco IOS
L2 Switch
→ ip default-gateway

Router / L3 Switch with ip routing
→ Routing Table 사용

64. 오늘 수업에서 가장 중요한 개념 연결

GRE와 IPsec

⌘Text
GRE
→ 터널 생성은 잘함
→ 암호화는 안 함

IPsec
→ 암호화와 무결성/인증 제공

그래서
GRE + IPsec
→ 유연한 터널 + 보안

HSRP

⌘Text
라우터 1과 라우터 2
→ 실제 IP는 서로 다름

하지만 PC에게는
→ 하나의 Virtual IP를 Gateway로 제공

Tracking

⌘Text
LAN 인터페이스가 살아 있다고
라우터 전체 경로가 정상이라는 뜻은 아님

그래서 외부 Serial 같은 중요한 인터페이스도 추적

⌘Text

→ 같은 네트워크까지만 직접 통신

⌘Text
L2 Switch
→ VLAN / MAC 기반 Switching
→ 관리 IP는 SVI
→ ip default-gateway

L3 Switch
→ no switchport로 Routed Port 가능

67. 스스로 답해볼 복습 문제

문제 1

GRE Tunnel에 10.10.10.1을 설정하고 실제 Serial에 1.1.1.1을 설정했다면 두 주소의 역할 차이는?

정답

  • 10.10.10.1: 터널 내부 논리 인터페이스 주소
  • 1.1.1.1: 실제 네트워크를 통과할 때 사용하는 물리/외부 인터페이스 주소

문제 2

GRE만 사용했을 때 보안상 부족한 점은?

정답

GRE 자체는 데이터를 암호화하지 않으므로 기밀성 보호가 부족합니다. 그래서 IPsec을 함께 사용할 수 있습니다.

문제 3

crypto map 안에서 match address, set peer, set transform-set의 역할은?

정답

  • match address: 보호 대상 트래픽
  • set peer: VPN 상대방
  • set transform-set: 사용할 암호화/무결성 방식

문제 4

HSRP에서 Priority 105와 100 중 누가 Active가 되는가?

정답

일반적으로 Priority가 높은 105 장비가 Active가 됩니다.

문제 5

preempt의 역할은?

정답

더 높은 Priority를 가진 라우터가 복구되었을 때 기존 Active로부터 역할을 다시 가져올 수 있게 합니다.

문제 6

HSRP Tracking을 왜 사용하는가?

정답

LAN 인터페이스는 살아 있지만 외부 회선이 죽은 상황을 감지하여 Priority를 낮추고 다른 라우터로 Gateway 역할을 넘기기 위해 사용합니다.

문제 7

IPv6 주소의 전체 길이는?

정답

128비트.

문제 8

/64의 의미는?

정답

앞 64비트가 네트워크 Prefix이고 뒤 64비트가 인터페이스 식별 영역이라는 의미입니다.

문제 9

FE80::로 시작하는 주소는?

정답

Link-Local Address.

문제 10

show ipv6 route에서 C, L, O의 의미는?

정답

  • C: Connected
  • L: Local
  • O: OSPF로 학습

문제 11

OSPFv3 Neighbor가 FULL이면?

정답

두 라우터가 OSPFv3 이웃 관계를 정상적으로 형성하여 라우팅 정보를 교환할 수 있는 상태입니다.

문제 12

L3 Switch에서 물리 포트에 IP 주소를 직접 넣으려면?

정답

지원되는 L3 Switch에서:

⌘Cisco IOS
no switchport
ip address ...

로 Routed Port로 변환합니다.

문제 13

L2 Switch를 Telnet으로 관리하기 위해 IP를 어디에 주는가?

정답

물리 포트가 아니라 SVI:

⌘Cisco IOS
interface vlan 1

에 관리 IP를 설정합니다.

68. 오늘 내용을 공부하는 추천 순서

처음부터 모든 명령어를 외우려고 하지 마세요.

1단계 — 개념만

먼저 다음 질문에 말로 답할 수 있어야 합니다.

  • GRE는 왜 쓰는가?
  • GRE와 IPsec은 무엇이 다른가?
  • HSRP는 왜 필요한가?
  • VIP는 왜 쓰는가?
  • IPv6 /64는 무슨 뜻인가?
  • OSPFv3는 왜 필요한가?
  • L2와 L3 Switch는 어떻게 다른가?

2단계 — 설정 순서

각 기술의 설정 순서만 외웁니다.

⌘Text
GRE:
Tunnel 생성 → 주소 → Source → Destination → Route

IPsec:
ACL → IKE → Key → Transform Set → Crypto Map → Interface

HSRP:
VIP → Priority → Preempt → Tracking

IPv6 OSPF:
unicast-routing → IPv6 주소 → OSPF interface → Router-ID

Switch:
L3 = no switchport + ip routing
L2 = SVI + default-gateway

3단계 — 확인 명령어

설정보다 더 중요한 부분입니다.

⌘SQL
show ...

명령으로 "내 설정이 실제로 적용됐는지" 확인하는 습관을 들입니다.

69. 오늘 수업 핵심 한 문장 요약

오늘 수업은 터널링(GRE), 보안(IPsec), 원격 관리(Telnet), 게이트웨이 이중화(HSRP), IPv6와 OSPFv3, 그리고 L2/L3 스위치 차이를 하나의 네트워크 운영 관점에서 연습한 수업입니다.

명령어를 개별 암기하기보다:

⌘Text
"어떤 문제를 해결하려는 기술인가?"
        ↓
"어디에 어떤 설정을 넣는가?"
        ↓
"무슨 명령으로 정상 여부를 확인하는가?"

이 세 단계로 공부하면 훨씬 정리가 잘 됩니다.

70. 마지막 초압축 복습

GRE

C

O
= OSPF로 학습

= L3 Routed Port

ip default-gateway
= L2 Switch의 관리 트래픽 Gateway
