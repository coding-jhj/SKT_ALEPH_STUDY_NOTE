036. IPSec 암호화 정책과 VPN 장비 개념

1. IPSec 적용 개요

GRE 터널 위에 IPSec을 적용하면 데이터 암호화와 인증 기능을 사용할 수 있다. IPSec 설정은 크게 세 단계로 구성된다.

단계 구성 요소 역할
1단계 ACL(Access Control List) 암호화 대상이 되는 출발지·목적지 주소 지정
2단계 ISAKMP 정책 키 관리 프로토콜 및 암호화·해시 알고리즘 설정
3단계 크립토 맵(Crypto Map) 앞의 정책들을 하나로 묶어 인터페이스에 적용

2. ISAKMP (Internet Security Association Key

Management Protocol)

2-1. ISAKMP란

ISAKMP는 인터넷 보안 연계 키 관리 프로토콜이다. 인터넷에서 사용하는 키를 관리하는 프로토콜로, 키를 생성·유지·삭제하는 기능을 포함한다.

ISAKMP = Internet Security Association Key Management Protocol (인터넷 보안 연계 키 관리 프로토콜)

2-2. ISAKMP 정책에서 설정하는 항목
항목 내용
정책 식별 번호(Policy Number) 1~10000 범위의 정책 식별값
암호화 알고리즘(Encryption) 3DES, AES, DES 중 선택
해시 알고리즘(Hash) MD5, SHA 중 선택
2-3. 암호화 알고리즘 종류
알고리즘 설명
DES 56비트 암호화 방식
3DES DES를 3회 적용한 방식 (56비트 × 3)
AES 현재 가장 널리 사용되는 암호화 방식

암호화 알고리즘과 해싱 알고리즘은 모의 해킹 등 보안 관련 수업에서도 다시 등장하는 용 어이다. 현재는 VPN 터널에서 데이터 암호화를 위해 사용되는 개념임을 이해하는 수준으로 학습한다.

3. 트랜스폼 셋 (Transform Set)

트랜스폼 셋은 실제 IPSec으로 데이터를 주고받을 때 적용되는 암호화 및 인증 알고리즘 묶 음이다.

항목 역할
트랜스폼 셋 이름 관리자가 지정하는 정책 식별 이름
암호화 알고리즘 데이터 암호화 방식 지정 (예: ESP-3DES)
인증 알고리즘 상대방 인증 방식 지정 (예: ESP-MD5-HMAC)

인증 알고리즘: 상대방이 접속할 권한이 있는지를 확인할 때 사용하는 알고리즘 암호화 알고리즘: 주고받는 데이터 자체를 암호화할 때 사용하는 알고리즘

4. 크립토 맵 (Crypto Map)

크립토 맵은 앞서 설정한 ACL, ISAKMP 정책, 트랜스폼 셋을 하나로 묶어서 인터페이스에 적용하는 구성이다.

크립토 맵 구성 항목 내용
맵 이름(Map Name) 관리자가 지정하는 식별 이름
match address 적용 대상 주소를 ACL 번호로 지정
set peer VPN 연결 상대방(이웃)의 IP 주소
set transform-set 적용할 트랜스폼 셋 이름 지정

크립토 맵 설정이 완료되면, 해당 인터페이스에 crypto map 명령으로 적용한다. 적용 시 ISAKMP가 활성화(ON)되면서 키 관리 프로토콜이 동작을 시작한다.

5. 설정 확인 명령어

IPSec 관련 설정 내용은 다음 명령어로 확인할 수 있다.

명령어 확인 내용
show crypto ipsec transform-set 트랜스폼 셋 설정 내용
show crypto ipsec sa IPSec 키 교환 및 패킷 통계
show crypto isakmp policy ISAKMP 정책 내용 (알고리즘, 해시, 유효기간 등)
show crypto isakmp key 관리자가 설정한 인증 키값
show crypto map 크립토 맵 전체 설정 내용 (적용 인터페이스 포함)

6. VPN 전용 장비와 일반 라우터의 차이

6-1. 일반 라우터에서의 VPN 설정

일반 L3 라우터(예: Cisco 2811)에서도 소프트웨어 설정을 통해 VPN 라우터로 동작하게 할 수 있다. 다만, 암호화 정책, ISAKMP, 크립토 맵 등을 명령어로 직접 세부 설정해야 한다.

6-2. VPN 전용 장비

VPN 전용 장비는 기본 기능이 이미 내장되어 있으며, 관리자는 웹 인터페이스(GUI)를 통해 필요한 항목만 클릭·변경하여 설정할 수 있다.

구분 설정 방식
일반 라우터 명령어(CLI) 기반 세부 설정
VPN 전용 장비 웹 인터페이스(GUI)를 통한 간편 설정

7. 원격 접속(Telnet/SSH)

7-1. 원격 접속 개요

라우터나 스위치 장비에 물리적으로 직접 접속하지 않고, 네트워크를 통해 원격으로 접속하여 관리할 수 있다. 이때 사용하는 프로토콜이 Telnet과 SSH이다.

7-2. 원격 접속 전제 조건
조건 내용
enable 패스워드 enable password 또는 enable secret 중 하나 반드시 설정
VTY 라인 설정 line vty 0 4 에서 패스워드 설정
활성화된 인터페이스 활성화된 물리적 인터페이스가 있어야 접속 가능

원격 접속이 설정되면 해당 라우터의 모든 활성화된 인터페이스 IP 주소로 접속이 가능하다.

8. 사이트 투 사이트 VPN과 리모트 액세스 VPN

구분 내용
사이트 투 사이트 VPN 본사 전체 네트워크와 지사 전체 네트워크를 VPN으로 연결
리모트 액세스 VPN 개별 사용자(원격지)가 회사 내부 네트워크에 접속하는 방식

이번 수업에서 다룬 방식은 사이트 투 사이트 VPN이다. 리모트 액세스 VPN은 추후 보안 인프라 운용 관리 수업에서 별도로 다룬다.

100. DDoS 공격 기법과 Hping3 활용

1. DoS와 DDoS 개념

1-1. 서비스 거부 공격(DoS)

DoS(Denial of Service)는 서비스 거부 공격으로, 대상 시스템이 정상적으로 서비스를 제공하지 못하도록 자원을 소모시키는 공격이다. 웹서버가 있다면 그 웹서버가 제대로 일을 하지 못하도록 만드는 것이 서비스 거부 공격이다. 일반적으로 1대의 공격자가 1대의 대상 시스템을 공격하는 형태가 많다.

1-2. 분산 서비스 거부 공격(DDoS)

DDoS(Distributed Denial of Service)는 분산된 다수의 공격자(좀비넷)에서 1대의 대상 시스템으로 동시에 공격하는 방식이다.

좀비봇(좀비넷)은 악성 코드에 감염된 일반 사용자 PC로, 사용자 본인도 공격에 가담하고 있다는 사실을 모르는 경우가 많다.

DDoS 공격망의 구조:

최상위 제어 머신
      ↓
다수의 C2(Command & Control) 서버
      ↓
전 세계에 분산된 좀비 네트워크(수만~수백만 대)
      ↓
공격 대상(피해 시스템)

역추적을 하더라도 좀비봇 IP들만 나오고 최종 공격자를 찾기 어렵다. 좀비봇의 사용자는 자신이 공격에 가담하고 있다는 것조차 모르는 경우가 많다.

2. DDoS 공격 유형

2-1. 볼륨 공격 (Volume-Based Attack)

네트워크 대역폭 자체를 소진시키는 공격이다. 특정 서버가 아니라 네트워크 대역폭을 소진 시키기 위한 공격으로, UDP 트래픽 플러딩이 대표적이다.

2-2. SYN Flood

TCP SYN 패킷을 대량으로 전송하여 서버의 자원을 소모시키는 공격이다.

공격자 → SYN(계속 전송) → 피해 시스템
          피해 시스템이 SYN/ACK를 계속 보내면서 자원 소모
          (공격자는 ACK를 보내지 않음)

시간이 지날수록 피해 시스템의 속도가 점점 느려지다가 서비스를 하지 못할 상황까지 가게된다.

2-3. Ping of Death (ICMP Flood)

ICMP 패킷을 대량으로 전송하여 서버의 응답 자원을 소모시키는 공격이다.

관리자가 ICMP 패킷을 차단하지 않은 경우 서버는 핑에 계속 응답해야 하므로 자원을 소모하게 된다.

일반적인 Ping of Death는 요즘 보안 솔루션에서 패턴을 인지하여 차단한다. 그러나 패킷 용량을 크게 늘리거나, 조각화(Fragmentation)하거나, 출발지 주소를 변조하면 일부 시스템에서 성능 저하를 유발할 수 있다.

2-4. 다중 팩터 공격 (Multi-Vector Attack)

두 가지 이상의 기법을 혼합하여 공격하는 방식이다.

2-5. DDoS 도구 현황

GUI 도구들이 잘 개발되어 있어 누구나 쉽게 사용 가능하다. 공격 대상 IP, 포트, 공격 방식, 시간 등을 지정하고 실행하기만 하면 공격이 이루어진다. 대표적인 도구로 LOIC, HOIC, SLOWRIZER, XOIC, Hping3, Golden Eye 등이 있다.

⚠️ DDoS 공격 도구는 반드시 내부 VM 환경에서만 실습해야 한다. 실제 외부 사이트에 사용하는 것은 불법이다.

3. Hping3를 이용한 DDoS 실습

3-1. Hping3 개요

Hping3는 원래 네트워크 분석 도구이나, 옵션을 활용하여 DDoS 공격 실습에도 활용할 수 있다.

# Hping3 기본 실행 (프롬프트 진입)
sudo hping3
# 빠져나오기
Ctrl + C
3-2. 주요 옵션
옵션 설명
-S SYN 플래그 설정
-c <수> 전송 패킷 수 지정
--flood 최대 속도로 패킷 전송 (플러딩)
-q Quiet 모드 (통계만 출력)
-V 상세 출력 (Verbose)
--rand-source 출발지 IP를 랜덤으로 변경
-a <IP> 출발지 IP를 지정 주소로 스푸핑
-d <크기> 패킷 데이터 크기 지정 (바이트)
3-3. SYN Flood 공격
# SYN 플래그로 1000개 패킷 전송
sudo hping3 <대상IP> -S -c 1000

TCP SYN 패킷만 계속 보내면 피해 시스템은 SYN/ACK를 계속 되돌려 주어야 하므로 자원을 소모하게 된다.

3-4. 랜덤 소스 공격
# 출발지 IP를 랜덤하게 변경하며 공격
sudo hping3 <대상IP> --rand-source

출발지 주소가 패킷마다 랜덤하게 바뀌어 공격자를 특정하거나 단순히 해당 IP를 차단하는 것이 어려워진다.

3-5. 랜드(Land) 공격 (스머프 공격 / 스푸핑)

출발지 주소를 공격 대상의 IP와 동일하게 설정하는 공격이다.

# 출발지를 대상 IP와 동일하게 스푸핑
sudo hping3 <대상IP> -a <대상IP>

피해 시스템은 자기 자신이 보낸 것처럼 들어오는 패킷에 계속 응답을 자기 자신한테 하게되어 자원을 소모하게 된다.

# 출발지를 엉뚱한 주소로 스푸핑 (예: 7.7.7.7)
sudo hping3 <대상IP> -a 7.7.7.7
3-6. 대용량 패킷 플러딩
# 플러딩 + 데이터 크기 50000바이트
sudo hping3 <대상IP> --flood -d 50000

패킷 하나의 크기를 크게 주게 되면 공격 효과가 더 높아진다. 이때 의미 없이 용량을 채우기 위해 삽입된 데이터를 페이로드(Payload)라고 한다.

4. TCPdump를 이용한 공격 패킷 확인

4-1. TCPdump 개요

TCPdump는 실시간으로 패킷을 캡처하는 도구로, Wireshark와 같은 역할을 텍스트 기반으로 수행한다.

# 특정 인터페이스 지정하여 캡처
sudo tcpdump -i eth0
4-2. SYN Flood 패킷 확인

TCPdump로 캡처 중인 상태에서 Hping3 공격을 수행하면 플래그 값에 S (SYN)가 들어간 패킷들이 대량으로 포착된다.

4-3. 스푸핑 패킷 확인 (TCPdump)

-rand-source 옵션으로 공격 시 캡처 결과에서 출발지 주소가 패킷마다 다르게 표시되는 것을 확인할 수 있다.

a 7.7.7.7 옵션으로 공격 시 캡처 결과에서 출발지 주소가 모두 7.7.7.7 로 표시된다.

랜드 공격( -a <대상IP> ) 시 Wireshark에서 소스 주소와 목적지 주소가 모두 동일한 IP(피해 시스템 주소)로 표시된다.

5. 시스템 성능 모니터링

DDoS 공격 전후 피해 시스템의 성능 변화를 확인하기 위해 모니터링 도구를 사용한다.

도구 특징
top 가장 기본적인 실시간 성능 모니터링
htop top보다 직관적인 표시
btop htop보다 화려한 그래픽 표시 
# htop 설치 (Ubuntu 기준)
sudo apt install -y htop
# htop 실행
htop

공격 중에는 CPU 사용률과 메모리가 점진적으로 상승하며, 공격을 중지하면 원래 상태로 내려온다.

현재 실습은 1대(공격자)에서 1대(피해 시스템)로 진행하므로 체감 속도 저하에 시간이 걸린다. 15대 이상의 머신이 동시에 공격할 경우 수 분 내에 대상 시스템이 사용 불능 상태에 빠질 수 있다.

2. Nmap 스캐닝

2-1. Nmap 개요

Nmap은 대상 시스템의 열린 포트, 실행 중인 서비스, 버전 정보, 운영체제 등을 확인하기 위한 가장 대중적인 스캐닝 도구이다.

칼리 리눅스에는 텍스트 버전(nmap)과 그래픽 버전(Zenmap) 두 가지가 제공된다.

실무에서는 텍스트 버전(nmap)을 훨씬 더 많이 사용한다.

포트를 별도로 지정하지 않으면 상위 1000개 포트에 대해 스캐닝이 수행된다.

버전 정보가 확인되면 해당 버전에 알려진 취약점이 존재하는지 추가 분석이 필요하다. 보안 패치가 이루어지지 않은 시스템은 그 취약점을 그대로 가지고 있다.

2-2. 주요 옵션 목록
옵션 설명
-sn 포트 스캔 없이 호스트 탐색(핑 스캔)만 수행
-A 공격적 스캔 — OS 감지, 버전 감지, 스크립트 실
행 포함
-O 운영체제 감지만 수행
-sS TCP SYN 스캔 (스텔스 스캔)
-sU UDP 포트 스캔
-p- 0~65535번 전체 포트 스캔
-p <번호> 특정 포트 스캔
-T<0-5> 타이밍 옵션 (낮을수록 느리고 탐지 회피에 유리)
--script <이름> 특정 NSE 스크립트 지정 스캔
-v 상세 출력 
# 호스트 탐색만 (포트 스캔 없음)
sudo nmap -sn 192.168.100.0/24
# 공격적 스캔 (OS·버전·스크립트 포함)
sudo nmap -A 192.168.100.110
# 전체 포트 스캔
sudo nmap -p- 192.168.100.110
# 특정 포트만 스캔
sudo nmap -p 80,443 192.168.100.110
# 포트 범위 스캔
sudo nmap -p 1000-1100 192.168.100.110
# OS 감지만
sudo nmap -O 192.168.100.110

⚠️ -A 옵션은 공격적으로 스캐닝하므로 방화벽·탐지 장비에서 패킷이 차단될 수 있다. 실제 필드에서는 탐지 장비 앞단에서 차단될 가능성이 있다.

2-3. 포트 스캔과 서비스 확인 예시

A 옵션 스캔 결과에서 확인 가능한 정보:

출력 항목 설명
포트 번호 / 상태 22/tcp open , 80/tcp open 등
서비스 명 ssh , http , https 등
버전 정보 OpenSSH 9.6 , Apache httpd 2.4.58 등
운영체제 추정 Guesses 항목에 퍼센트와 함께 표시

2-4. SYN 스캔( sS ) 원리

sS 옵션은 TCP 3-Way Handshake를 완성하지 않는 방식이다.

클라이언트 → SYN → 서버
클라이언트 ← SYN/ACK ← 서버
클라이언트는 ACK를 보내지 않음

서버의 응답 여부를 통해 포트의 열림·닫힘 상태를 판단한다.

2-5. UDP 스캔

TCP는 핸드셰이킹 과정이 있지만, UDP는 비연결형이므로 별도의 핸드셰이킹이 없다.

sudo nmap -sU 192.168.100.110

UDP 스캔은 TCP 스캔보다 시간이 훨씬 오래 걸린다.

2-6. 타이밍 옵션 활용 목적

방화벽·탐지 장비가 앞단에 있을 때, 타이밍 옵션을 낮게 설정하면 포트 스캔 간격이 길어져 정상 트래픽으로 인식될 가능성이 높아진다.

높은 타이밍: 짧은 시간에 많은 패킷 → 탐지 장비에서 차단 가능성 높음
낮은 타이밍: 시간 간격을 두고 스캔 → 탐지 회피 가능성 높음

4. TCPdump를 이용한 패킷 캡처

4-1. TCPdump 개요

TCPdump는 실시간으로 패킷을 캡처하는 도구이다. 와이어샤크(Wireshark)와 같은 역할을 텍스트 기반으로 수행한다.

# 특정 인터페이스 지정

# 캡처 중지
Ctrl + C
옵션 설명
-i <인터페이스> 캡처할 인터페이스 지정
-w <파일> 캡처 내용을 파일로 저장
4-2. Nmap 스캐닝 패킷 확인

TCPdump를 한 터미널에서 실행 중인 상태에서 다른 터미널에서 Nmap 스캐닝을 수행하면, 스캐닝 패킷들이 TCPdump에 실시간으로 포착된다. 패킷의 플래그 값( S = SYN 등)으로 스캐닝 방식을 확인할 수 있다.

104. CTF 머신 풀이 입문 (Earth 머신)

1. CTF 개요

1-1. CTF란

CTF(Capture the Flag)는 문제 출제자가 시스템 안에 숨겨 놓은 플래그(깃발)를 찾는 보안 실습이다.

플래그 종류 설명
User Flag 일반 사용자 권한으로 획득 가능한 플래그
Root Flag 루트 권한 상승 후 획득 가능한 플래그

CTF 문제를 풀어보면서 리눅스 명령어 활용 범위가 넓어지고, 방어 측면에서 어떤 조치가 필요한지 이해할 수 있다.

VulnHub(vulnhub.com) 등에서 다양한 난이도의 CTF 머신을 다운로드할 수 있으며, OVA 파일은 VirtualBox에서 가상 시스템 가져오기로 바로 사용 가능하다.

1-2. CTF 풀이 기본 순서
1. 공격자(칼리)와 CTF 머신 간 통신 확인
2. CTF 머신 IP 주소 탐색
3. 포트 및 서비스 스캐닝 (Nmap)
4. 웹 서비스 수동 점검 및 디렉토리 스캐닝
5. 정보 수집 및 취약점 분석
6. 취약점 공격 및 쉘 획득
7. 권한 상승 후 루트 플래그 획득

처음에는 시간이 걸리지만 여러 머신을 풀어보면 나름의 풀이 루틴이 생긴다.

2. IP 주소 탐색

2-1. IP 탐색 명령어

9. SetUID 비트 개요

9-1. SetUID 개념

SetUID 비트가 설정된 파일을 실행하는 동안, 실행 계정은 해당 파일의 소유자 권한을 임시로 가진다.

예를 들어 passwd 명령어에 SetUID가 설정되어 있고 소유자가 root이면, 일반 사용자가

passwd 를 실행하는 동안만 root의 권한을 가지게 된다.

권한 표시에서 실행 권한에 s 가 표시되면 SetUID가 설정된 것이다.

# SetUID 설정된 파일 탐색
find / -perm -u=s -type f 2>/dev/null
# 파일 권한 확인
ls -l /usr/bin/passwd
# 예: -rwsr-xr-x root root ... /usr/bin/passwd

SetUID가 설정된 파일 목록을 정기적으로 점검하는 것이 보안 관리에 중요하다. 관리자가 설정하지 않은 항목이 있다면 취약점으로 이어질 수 있다.

9-2. Earth 머신에서 SetUID 파일 탐색
find / -perm -u=s -type f 2>/dev/null

결과 중 reset_root 라는 파일이 탐색된다. 소유자가 root이고 SetUID가 설정되어 있어 실행하면 root로서의 권한을 임시 획득할 수 있다.

7-1. getcap을 이용한 세부 기능 파일 탐색

getcap과 setcap 개념

명령어 기능
setcap 실행 파일에 특정 세부 기능(Capability)을 설정
getcap 실행 파일에 설정된 세부 기능을 조회

Linux Capability는 root 권한을 세분화하여 실행 파일에 부여하는 기능이다.

Capability가 설정된 파일은 root 권한 없이도 특정 작업을 수행할 수 있다.

이는 Set-UID/Set-GID와 구별되는 별도의 권한 체계이다.

# ← -r: 최상위 디렉토리에서 하위 디렉토리까지 재귀 조회
# ← 2>/dev/null: 오류 메시지 무시

/usr/bin/ping 네트워크 관련 Capability 설정됨 
ls -al
# ← /home/cyber/tar 파일의 소유주: root

107. HIDS(OSSEC) 구축

1. HIDS 개요

1-1. NIDS와 HIDS의 차이
구분 NIDS HIDS
약어 풀이 Network-Based IDS Host-Based IDS
탐지 범위 네트워크 전체 트래픽 엔드포인트 내부
주요 탐지 대상 포트 스캔, DDoS 등 네트워크

HIDS는 각 엔드포인트 시스템(노트북, 프린터, 서버 등)에 개별 설치가 필요하다는 단점 이 있지만, 시스템 내부의 위협을 심도 있게 다룰 수 있다는 장점이 있다.

1-2. EDR과의 관계

초창기 HIDS는 기본적인 탐지 기능만 수행하였다.

최근에는 EDR(Endpoint Detection and Response) 솔루션 영역까지 포함하는 방향으로 발전하고 있다.

EDR은 엔드포인트 시스템 내의 위협·변경·로그를 탐지하고 대응하기 위한 장비이다.

1-3. OSSEC 소개

OSSEC는 멀티 플랫폼 HIDS 솔루션이다.

클라이언트로 Linux, Windows, Mac 모두 연결 가능하다.

공식 사이트: ossec.net (실제 개발사: Atomicorp)

구조는 OSSEC 서버 + 에이전트 방식이며, 예전에 실습한 Zabbix(NMS)의 서버-에이 전트 구조와 유사하다.

108. IDS와 IPS

1. IDS와 IPS 개요

1-1. IDS (Intrusion Detection System)

IDS는 탐지(Detection)만 수행하는 장비다. 트래픽을 캡처·가로채기하여 룰에 의해 검사하 고, alert 액션을 통해 탐지 내역을 기록한다.

IDS는 실생활에서 CCTV에 비유할 수 있다. 도둑이 침입해도 CCTV에 기록될 뿐 실제로 막지는 못한다.

IDS의 동작 모드는 미러링 모드(Mirroring Mode) 또는 스니핑 모드(Sniffing Mode) 라고 부른다.

특징 설명
동작 방식 트래픽 캡처·가로채기 후 룰 기반 검사
탐지 방법 alert 액션으로 탐지 내역 기록
차단 여부 차단 불가 — drop 룰을 설정해도 탐지 내역에는
나타나지만 실제 패킷은 통과됨
1-2. IPS (Intrusion Prevention System)

IPS는 탐지와 동시에 차단(Prevention) 을 수행한다. 룰에 drop 액션이 설정된 경우 패킷 자체를 차단한다.

IPS는 실생활에서 군의 검문소나 기업 건물의 보안요원에 비유할 수 있다. 이상한 차량이 나 사람이 접근하면 즉시 제지·차단할 수 있다.

항목 IDS IPS
기능 탐지만 수행 탐지 + 차단 수행
동작 모드 미러링/스니핑 모드 인라인 모드
drop 룰 효과 탐지 기록만 남음, 패킷 통과 실제 패킷 차단
실생활 비유 CCTV 검문소·보안요원

2. IPS 동작 모드 — 인라인 모드(Inline Mode)

2-1. AF 패킷 DAQ (af_packet DAQ)

IPS를 인라인 모드로 구축할 때는 AF 패킷(af_packet) DAQ 모듈을 사용한다. 이 모듈은 Snort 3 설치 시 함께 설치되는 DAQ 라이브러리 내에 포함된 패키지 중 하나다.

AF 패킷 인라인 모드에서는 별도로 iptables 같은 규칙이 필요 없이, 내부적으로 브리징된 네트워크 단에서 탐지와 차단이 이루어진다.

2-2. NF 패킷 DAQ (nf_packet DAQ)

NF 패킷 모드를 이용해 IPS를 구축하면 물리적으로는 유사하지만 내부적으로는 iptables와 함께 동작한다. NF 패킷 방식은 IPS와 iptables(firewall-cmd)를 함께 사용해야 한다.

구분 AF 패킷 DAQ NF 패킷 DAQ
방식 인라인 모드 (최신) IP 테이블 연동 방식 (구형)
iptables 필요 여부 불필요 필요
동작 위치 브리징된 네트워크 단 커널 단에서 iptables와 연동
2-3. 인라인 모드 트래픽 흐름

인라인 모드에서의 트래픽 처리 흐름은 다음과 같다.

외부(Kali) → enp0s3 (외부 인터페이스)
             → 인터셉트(가로채기) + 인스펙트(실시간 감시)
             → AF 패킷 DAQ 모듈
             → 룰 검사: drop이면 차단 / pass이면 포워드
             → enp0s8 (내부 인터페이스) → 내부망
용어 의미
인터셉트(Intercept) 트래픽 가로채기
인스펙트(Inspect) 실시간 감시
drop 패킷 차단
pass 내부망으로 포워드

4-2. Snort 버전별 설정 파일 비교

4-3. snort.conf 파일 수정 (IPS 모드용 — 2.9.20 기준)

설정 파일 맨 아래에 다음 세 줄을 추가한다.

config daq: af_packet          ← DAQ 모듈을 af_packet으로 지정 (인라인 모드)
config daq_mode: inline        ← 인라인 모드로 동작
config logdir: /var/log/snort  ← 로그가 저장될 디렉토리 지정

Snort 3 버전을 사용하는 경우 snort.lua 파일 내에 IPS 항목이 있으며, 해당 항목에서 인라인 모드를 활성화하면 된다.

홈 네트워크 변수( HOME_NET )는 실제 운영 환경에서는 내부 네트워크 대역을 지정해야 한다. 룰 작성 시 이 변수를 사용하지 않고 직접 IP를 지정할 경우 큰 의미가 없다.

4-4. 설정 파일 문법 검사
sudo snort -T -c /etc/snort/snort.conf -i enp0s3:enp0s8
옵션 설명
-T 설정 파일 문법 테스트 (기능 동작 확인이 아님)
-c 설정 파일 경로 지정
-i enp0s3:enp0s8 브리지할 두 인터페이스를 콜론으로 연결하여 지
정

테스트 결과 Successfully validated 메시지가 나와야 한다. 에러가 발생하면 추가한 설정 부분의 철자, 콜론, 경로 등을 재확인해야 한다. 이 명령은 설정 파일의 문법 오류 여부만 검사하며, 실제 Snort 동작을 테스트하는 것이 아니다.

6-1. IPS 실행 명령어
sudo snort -A console -Q -c /etc/snort/snort.conf -i enp0s
3:enp0s8
옵션 설명

그 파일에만 기록)
-Q AF 패킷 DAQ를 이용한 인라인 모드(IPS)로 실행

6-2. 프로미스큐어스 모드와 트래픽 탐지 범위

109. Set UID GID 개념 및 CTF 머신(Lupin One) 권한

1. UID와 GID 개요

1-1. 기본 개념
개념 설명
UID (User ID) 사용자를 인식하는 고유한 값
GID (Group ID) 그룹을 인식하는 고유한 값
저장 위치 /etc/passwd 파일 — 세 번째 필드가 UID, 네
번째 필드가 GID
1-2. UID 값 범위
계정 종류 UID 범위
루트 계정 0 (고정)
일반 사용자 (Ubuntu) 1000번부터 순차 증가
일반 사용자 (구형 버전) 500번부터 시작하는 경우도 있음

공격자가 일반 사용자 계정으로 시스템에 접근한 후 /etc/passwd 파일을 수정할 수 있는 권한을 얻게 된다면, 해당 사용자의 UID·GID 값을 0 으로 변경함으로써 루트와 동일한 권한을 얻을 수 있다. 따라서 시스템 점검 시 루트 외에 UID가 0 인 사용자가 있는지 반드시 확인해야 한다.

2. Real UID / Effective UID

UID는 두 가지로 세분화된다.

구분 약어 의미
Real UID rUID 실제(Real) 사용자 ID — 로그인
한 사용자의 실제 ID
구분 약어 의미
Effective UID eUID 유효한(Effective) 사용자 ID —
현재 프로세스에서 실제로 적용
되는 권한

사용자가 로그인하면 rUID와 eUID는 동일한 값을 가진다. Set UID 비트가 설정된 파일을 실행하는 동안에는 rUID와 eUID가 일시적으로 일치하지 않는 상태가 발생하며, 이 시간 동안 eUID는 파일 소유자의 UID 값을 가지게 된다. GID도 동일한 원리로 동작한다.

3. Set UID 비트

3-1. 개념

Set UID 비트가 설정된 파일을 실행하면, 그 프로세스가 실행되는 동안만큼 실행한 사용자가 해당 파일의 소유자 권한으로 작업을 수행할 수 있다.

예시: happy 라는 일반 사용자가 소유자가 root 이고 Set UID 비트가 설정된 파일을 실행하면, 해당 프로세스가 실행되는 동안만큼 root 권한을 임시로 가지게 된다. 프로세스가 종료 되면 원래 권한으로 돌아간다.

Set UID 비트가 설정된 대표적인 파일: /usr/bin/passwd (패스워드 변경 명령어). 일반 사용자가 자신의 패스워드를 변경할 때 이 파일을 실행하는 동안 임시로 root 권한을 가지게 되어 /etc/shadow 파일을 수정할 수 있다. 이렇게 편의를 위해 설계된 기능이지만, 공격자에게 악용될 수 있다.

3-2. Set UID 비트 식별 방법
ls -l /usr/bin/passwd

실행 권한 위치에 x 대신 s 가 표시되면 Set UID 비트가 설정된 것이다.

표시 위치 의미
user 실행 권한 자리에 s Set UID 비트 설정
group 실행 권한 자리에 s Set GID 비트 설정
3-3. 수치 권한
비트 종류 수치
Set UID 4000
Set GID 2000

따라서 Set UID 비트가 설정된 rwxr-xr-x (755) 파일의 전체 권한 표기는 4755 , Set GID 는 2755 가 된다.

Set UID 비트 설정 방법은 다음과 같다.

chmod 4755 <파일명>    ← 수치로 Set UID 설정
chmod u+s <파일명>     ← 기호로 Set UID 설정
chmod g+s <파일명>     ← 기호로 Set GID 설정
3-4. 시스템 내 Set UID 파일 검색
find / -user root -perm /4000    ← 소유주가 root이고 Set UID
비트가 설정된 파일 검색

관리자는 평소에 Set UID 비트가 설정된 파일 목록을 백업·스크린샷 등으로 보관해 두어 야 한다. 점검 시 현재 목록과 비교하여 자신이 설정하지 않은 파일이 추가되어 있다면 공격자가 심어 놓은 것일 수 있다.

4. Set UID를 이용한 권한 상승 — 백도어(C 코드)

4-1. 동작 원리

루트 권한으로 작성한 프로그램에 Set UID 비트를 설정해 두면, 일반 사용자가 해당 파일을 실행하는 동안 루트 권한을 임시 획득한다.

일반적인 배시 셸( /bin/bash )을 단순 실행할 경우 프로그램이 즉시 종료되어 권한을 활용하 기 어렵다. 이를 해결하기 위해 C 코드로 작성한 프로그램을 컴파일하여 활용할 수 있다.

4-2. C 코드 백도어 예시
#include <stdio.h>
int main() {
    setuid(0);          ← UID를 0(root)으로 설정
    setgid(0);          ← GID를 0(root)으로 설정
    system("/bin/bash"); ← 배시 셸 실행
}

setuid(0) , setgid(0) : UID·GID 값을 0(root)으로 설정하는 함수

system() : 괄호 안의 값을 시스템에서 실행하는 미리 정의된 함수

4-3. C 코드 컴파일 방법

C 코드를 실행 가능한 파일로 만들기 위해 컴파일(Compile) 과정이 필요하다. 컴파일을 수행하는 도구를 컴파일러(Compiler) 라고 한다.

apt install -y gcc              ← GCC 컴파일러 설치
gcc -o backdoor backdoor.c      ← backdoor.c를 컴파일하여 bac
kdoor 실행 파일 생성
chmod 4755 backdoor             ← Set UID 비트 설정
옵션 설명
-o 출력(Output) 파일 이름 지정

5. Set UID를 이용한 권한 상승 — vi 편집기 활용

vi 편집기가 실행 중인 동안에는 해당 프로세스가 종료되지 않으므로, Set UID 비트가 설정된 vi 를 이용해 권한이 필요한 파일을 열어 읽거나 수정할 수 있다.

chmod 4755 /usr/bin/vi          ← vi에 Set UID 비트 설정 (ro
ot 계정에서)

일반 사용자가 이 vi 로 /etc/shadow 와 같이 root만 접근 가능한 파일을 열면, vi 프로세스가 실행되는 동안 Set UID 효과로 파일을 읽을 수 있다.

Set UID 비트가 설정된 more 명령으로도 /etc/shadow 파일을 읽을 수 있다. more 프로그램이 실행 중인 동안 루트 권한이 유지되기 때문이다.

6-2. sudo 명령어 개념

sudo 는 루트 권한으로 실행하는 것만이 아니라, 다른 계정의 권한으로 명령어를 실행할 때 사용하는 명령어다. 일반적으로 일반 계정에서 루트 권한으로 실행하기 위해 많이 사용한다.

sudo -u <사용자명> <명령어>    ← 지정한 사용자 권한으로 명령어 실
행

sudo -l 결과에서 특정 계정으로 특정 프로그램을 실행할 수 있다고 나타나면, 그 프로그램의 취약점을 활용한 권한 상승이 가능할 수 있다.

개념

파이썬은 인터프리트(Interpret) 언어로, 첫 줄부터 순서대로 실행된다. 파이썬 프로그램이

import 구문으로 외부 라이브러리를 불러올 때, 해당 라이브러리 파일에 쓰기 권한(w) 이 있다면 공격자가 그 파일의 내용을 수정하여 원하는 코드를 실행하도록 만들 수 있다. 이를 파이썬 라이브러리 하이재킹이라고 한다.

하이재킹은 프로그램이 원래 의도한 방향으로 실행되는 것이 아니라, 공격자가 원하는 방향으로 흐름을 바꾸는 것을 의미한다.

동작 원리

  → webbrowse.py에 os.system("/bin/bash") 코드가 삽입되어 있으면
  → 배시 셸이 생성됨 (이후 코드는 실행되지 않음)
라이브러리 파일 권한 확인

소유자와 그룹의 쓰기 권한( w )이 모두 있다면 파일 수정이 가능하다.

라이브러리 파일 수정 방법

os 모듈이 import되어 있는 줄 아래에 다음 코드를 추가한다.

os.system("/bin/bash")    ← os.system() 함수: 괄호 안의 값을
시스템에서 실행

os.system() 함수는 괄호 안의 입력 값을 시스템에서 실행하도록 해주는 미리 정의된 함수 다.

py

h")})})' > $TF/setup.py

5. 퍼징(Fuzzing)

5-1. 퍼징의 개념

퍼징은 소프트웨어의 취약점을 테스트하는 기법 중 하나다. 어떤 소프트웨어를 테스트하기 위해 무작위 입력 값을 연속으로 넣어 해당 소프트웨어에서 어떤 에러나 취약점이 있는지를 모니터링하여 허점을 찾아내는 것을 퍼징이라고 한다.

소스 코드를 분석하여 잘못된 것들이 있는지 알아보고 이러한 버그를 잡기 위한 것들이 퍼징 에 해당한다.

퍼징은 아무 입력 값이나 무작위로 대입해서 테스트하기 때문에 "덤 사이언스(Dumb Science)", 즉 바보 과학이라고도 부른다.

보안 분야에서 퍼징은 알고자 하는 부분에 대문자로 FUZZ 라고 입력하여 선택한 단어 목록을 대입하면서 맞는 것이 있는지 찾아내는 방식으로 사용된다.

5-2. ffuf를 이용한 경로 퍼징
sudo ffuf -u http://<대상 IP>/FUZZ -w <단어목록 파일 경로> -fs
0
옵션 설명
-u 퍼징 대상 URL ( FUZZ 위치에 단어가 대입됨)
-w 사용할 단어 목록 파일 경로
-fs 0 HTTP 응답 패킷 크기가 0인 항목 필터링 (내용
없는 응답 제외)
-t 스레드 수 지정 (예: -t 100 )

-fs 0 옵션은 두 가지 의미를 가진다. 첫째, 명령어에 지정한 파라미터들을 확인하라는 의미이며, 둘째, HTTP 응답 패킷의 크기가 0인 항목은 필터링하라는 의미다. 응답 크기가 0이면 해당 경로에 아무 내용도 없다는 뜻이므로 필터링 대상이 된다.

6. 웹 파라미터(Parameter) 개념

6-1. URL 파라미터 구조

웹 페이지에서 사용자가 검색하거나 입력을 했을 때, 그 값을 저장하여 전달하는 변수를 파 라미터라고 한다. URL에서는 다음과 같이 표현된다.

<http://example.com/search?q=입력값>
구성 요소 설명
? 파라미터 시작을 나타내는 구분자
q 파라미터 이름 (개발자가 임의로 지정 가능)
입력값 파라미터에 전달되는 값

파라미터 이름은 개발자에 따라 달라질 수 있다. 예를 들어 q 대신 happy 처럼 다른 이름을 사용해도 정상적으로 동작한다.

대부분의 웹 서비스에서 사용자가 검색하거나 값을 입력하면 이 물음표( ? )를 통해 파라미터 와 함께 값이 저장되도록 구성되어 있다.

6-2. 파라미터 퍼징

파라미터 이름을 모를 경우, 퍼징을 통해 유효한 파라미터 이름을 찾아낼 수 있다.

sudo ffuf -u http://<대상 IP>/secret/app1.php?FUZZ=/etc/pas

FUZZ 자리에 단어 목록의 값이 순서대로 대입되며, 유효한 파라미터가 존재하면 응답 크기가 0이 아닌 결과로 나타난다.

9. SSH 개인 키 해독 (ssh2john)

취득한 id_rsa 파일은 ssh2john 도구를 통해 해독하기 쉬운 형태로 변환한 후 패스워드 크 래킹에 활용할 수 있다.

chmod 600 id_rsa                          ← 파일 권한 변경
(필수)
ssh2john id_rsa > key.hash                ← 해독 가능한 형식
으로 변환, 결과를 key.hash에 저장

변환 후 begin · end 헤더 및 불필요한 공백이 제거된 형태의 해시 값이 생성된다.

10-1. 패스워드 생성

openssl passwd 명령을 통해 특정 문자열을 암호화된 패스워드 값으로 생성할 수 있다.

openssl passwd <원하는 패스워드>   ← 입력한 패스워드의 암호화된 해
시 값 출력
10-2. /etc/passwd 파일 수정

/etc/passwd 파일에서 루트( root ) 항목의 x 자리는 패스워드가 저장되는 위치다. 이 자리에 위에서 생성한 암호화된 값을 삽입하면 해당 값이 루트 계정의 패스워드로 설정된다.

vi /etc/passwd
# root:x:0:0:root:/root:/bin/bash
#      ↑ 이 x를 openssl passwd로 생성한 값으로 교체

수정 후 su root 명령으로 계정 전환 시, 설정한 패스워드를 입력하여 루트 권한을 획득할 수 있다.

이 실습이 가능한 이유는 CTF 출제자가 /etc/passwd 파일을 수정할 수 있도록 의도적으로 설정해 두었기 때문이다.

5-2. 특성

In-memory 데이터베이스: 하드디스크가 아닌 메모리(RAM) 내부에 데이터를 저장한다.

메모리에서 동작하기 때문에 데이터 액세스 및 처리 속도가 매우 빠르다.

용량이 작은 데이터를 고속으로 처리할 때 적합하다.

전원이 차단되면 메모리에 저장된 데이터가 소실된다.

대용량 데이터는 메모리 한계로 처리하기 어렵다.

그레이로그는 SIEM 솔루션으로, 여러 노드로 구성할 수 있으며 로그 데이터를 받아오는 데이터 노드가 핵심 시스템이다.

버프 스위트(Burp Suite)와 ZAP Proxy(OWASP ZAP)는 웹 모의해킹에 사용되는 프록시 도구이다.

2. 프록시 사용 원칙

2-1. 프록시 설정 기본 원칙

프록시 툴 사용 시 반드시 숙지해야 하는 원칙은 다음과 같다.

상황 웹 브라우저 설정
프록시 툴 실행 시 브라우저의 프록시 설정에서 프록시 서버 주소 지
정
프록시 툴 종료 시 브라우저의 프록시 설정을 No Proxy(프록시

⚠️ 프록시 툴을 종료하고도 브라우저 프록시 설정을 그대로 두면, 프록시 서버가 없으므로 웹 연결이 거부(Connection Refused)된다. 반드시 No Proxy로 되돌려야 정상적으

로 인터넷에 접속할 수 있다.

2-2. 프록시 미설정 시 발생하는 문제

버프 스위트가 실행되지 않은 상태에서 브라우저 프록시 설정이 남아 있으면 다음 오류가 발생한다.

프록시 서버에 의해 커넥션이 거부되었습니다.
(The connection was refused by the proxy server)

이 경우 해결 방법은 두 가지이다.

  1. 브라우저 프록시 설정을 No Proxy로 변경

  2. 프록시 역할을 하는 버프 스위트 또는 ZAP Proxy를 실행

3. 버프 스위트 오류 대응

3-1. 버프 스위트 에러 발생 시 대처

버프 스위트 사용 중 에러가 발생하는 경우 다음과 같이 처리한다.

1. 버프 스위트 종료
2. 브라우저 프록시 설정 → No Proxy로 변경
3. 새 터미널을 열어 작업 재개

⚠️ 버프 스위트를 종료하면 프록시 서버가 없어지므로, 브라우저 프록시 설정을 No Proxy로 반드시 변경해야 한다.

4. ZAP Proxy 소개

4-1. ZAP Proxy 특징

ZAP(Zed Attack Proxy)는 OWASP에서 제공하는 프록시 툴이다.

버프 스위트와 동일하게 웹 브라우저의 프록시 설정이 필요하다.

gobuster, dirbuster와 같은 스캐닝 기능도 수행할 수 있다.

프록시 툴로서 버프 스위트와 유사한 역할을 한다.

웹 취약점 점검 시 버프 스위트와 ZAP Proxy 모두 활용 가능하며, 향후 CTF 머신이나 웹 취약점 머신을 다룰 때 추가적으로 사용하게 된다.

120. Wazuh 환경 구축 및 구성 요소 이해

1. Wazuh 개요

1-1. Wazuh란

Wazuh(wazuh.com)는 SIEM(보안관제 모니터링 솔루션)이다. 로그 관리·분석 솔루션으 로서 시스템의 보안 상태를 모니터링하는 역할을 수행한다.

1-2. 최소 하드웨어 사양

Wazuh는 최소 하드웨어 사양을 만족하지 못할 경우 설치에 어려움이 발생할 수 있다.

⚠️ 하드디스크 용량이 50GB 미만인 경우, 설치 관련 명령어를 메모해 두었다가 용량 여유가 생겼을 때 진행한다.

2. 설치 스크립트 방식

2-1. 스크립트 설치 방식의 특징

Wazuh 공식 사이트(wazuh.com)에서 설치 스크립트를 제공한다. 스크립트 방식의 특징 은 다음과 같다.

명령어 한두 줄만으로 설치가 완료된다.

사전에 별도로 설치해야 할 항목이 없다.

스크립트 내부에서 필요한 패키지 설치, 설정이 모두 자동으로 이루어진다.

동일한 솔루션을 여러 머신에 배포할 때 스크립트를 재사용하면 효율적이다.

스크립트 실행 중 특별한 오류 없이 대기 상태로 보이더라도, 하드웨어 사양을 충족한 경우 시간이 지나면 다음 단계로 자동 진행된다. 임의로 Ctrl+C로 중단하지 않도록 주의한

다.

-o 기존 설치 위에 덮어쓰기 설치
-u 설치된 Wazuh를 완전히 제거(언인스톨)

⚠️ -i 옵션으로 강제 설치 시 설치 시간이 매우 오래 걸리고, 설치 완료 후에도 대시보드 접근 등 실제 운영에 어려움이 있을 수 있다.
