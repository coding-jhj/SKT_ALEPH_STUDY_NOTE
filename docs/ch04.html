1. 서브네팅(Subnetting)이란?

서브네팅(Subnetting)은 하나의 큰 네트워크를 여러 개의 작은 네트워크로 나누는 기술이다.

예를 들어 회사에 다음과 같은 부서가 있다고 하자.

  • 기획팀
  • 영업팀
  • 회계팀

원래 이들이 모두 하나의 네트워크를 사용하면:

⌘Text
192.168.100.0/24

전체 사용 가능 범위는 다음과 같다.

⌘Text
네트워크 주소 : 192.168.100.0
사용 가능 IP  : 192.168.100.1 ~ 192.168.100.254
브로드캐스트  : 192.168.100.255

이 하나의 네트워크를 부서별로 나누는 것이 서브네팅이다.

⌘Text
하나의 큰 네트워크
        ↓
여러 개의 작은 네트워크

네트워크를 더 많이 쪼갤수록:

  • 서브넷의 개수는 증가한다.
  • 각 서브넷에 들어갈 수 있는 호스트 수는 감소한다.
  • 브로드캐스트 도메인도 작아진다.

2. IPv4와 2진수

IPv4 주소는 총 32비트이고, 8비트씩 4부분으로 나뉜다.

⌘Text
192.168.16.100

각 숫자는 0~255 범위이며, 2진수로 표현하면 각각 8비트이다.

⌘Text
192      .168      .16       .100
11000000 .10101000 .00010000 .01100100

⌘Text

3. 서브넷 마스크와 Prefix

예:

⌘Text
192.168.16.100/24

/24는 앞의 24비트가 네트워크 부분이라는 뜻이다.

⌘Text
11111111.11111111.11111111.00000000

이를 10진수로 바꾸면:

⌘Text
255.255.255.0

즉:

⌘Text
/24 = 255.255.255.0

구조는 다음과 같다.

⌘Text
11111111.11111111.11111111 | 00000000
        네트워크 비트       | 호스트 비트
           24비트            |   8비트

4. 서브넷 마스크의 중요한 규칙

서브넷 마스크는 반드시:

⌘Text
1이 연속해서 나오고 → 그 뒤에 0이 연속해서 나와야 한다.

정상:

⌘Text
11111111.11111111.11111111.11000000

비정상:

⌘Text
11111111.11111111.11111111.10100000

즉 중간에 1 → 0 → 1처럼 섞일 수 없다.

5. 비트를 빌린다는 의미

기본 /24는 마지막 8비트가 모두 호스트 비트이다.

⌘Text
/24

                                ↑
                            호스트 8비트

여기서 호스트 비트 일부를 네트워크 비트로 바꾸면 서브넷이 생긴다.

예를 들어 1비트를 빌리면:

⌘Text
/25

11111111.11111111.11111111.10000000

서브넷 마스크는:

⌘Text
255.255.255.128

2비트를 빌리면:

⌘Text
/26

11111111.11111111.11111111.11000000

서브넷 마스크:

⌘Text
255.255.255.192

3비트를 빌리면:

⌘Text

11111111.11111111.11111111.11100000

서브넷 마스크:

⌘Text
255.255.255.224

6. 서브넷 개수 계산

빌린 비트 수를 n이라고 하면:

⌘Text
서브넷 개수 = 2^n

예를 들어 /24에서 /26이 되었다면:

⌘Text
26 - 24 = 2비트

따라서:

⌘Text

7. 호스트 수 계산

서브네팅 후 남은 호스트 비트의 개수를 h라고 하면:

⌘Text
사용 가능한 호스트 수 = 2^h - 2

왜 -2를 하는가?

각 서브넷에서 다음 2개의 주소는 호스트에게 줄 수 없기 때문이다.

  1. 첫 번째 주소 = 네트워크 주소
  2. 마지막 주소 = 브로드캐스트 주소

8. /25 예제

원래 네트워크:

⌘Text

⌘Text

⌘Text

19. 라우팅(Routing)이란?

라우팅은 서로 다른 네트워크 사이에서 패킷이 목적지까지 갈 경로를 결정하는 것이다.

예:

⌘Cisco IOS
PC A
 |
Router A
 |
Router B
 |
PC B

PC A와 PC B가 서로 다른 네트워크에 있다면 라우터가 경로를 알아야 한다.

라우팅 방식은 크게 두 가지이다.

20. Static Routing과 Dynamic Routing

Static Routing — 정적 라우팅

관리자가 직접 목적지 네트워크와 다음 경로를 설정한다.

특징:

  • 관리자가 직접 설정
  • 구조가 단순한 네트워크에 적합
  • 네트워크 변경 시 직접 수정해야 함
  • 불필요한 라우팅 업데이트가 없음

예:

⌘Cisco
ip route 192.168.20.0 255.255.255.0 10.0.0.2

의미:

⌘Text
192.168.20.0/24로 가려면
10.0.0.2 방향으로 보내라.

Dynamic Routing — 동적 라우팅

라우터끼리 라우팅 정보를 주고받으며 경로를 자동으로 학습한다.

대표적인 프로토콜:

  • RIP
  • OSPF
  • EIGRP
  • BGP

관리자는 어떤 라우팅 프로토콜을 사용할지 설정하고, 그 이후 경로 학습과 변경 대응은 프로토콜이 수행한다.

21. Routing Table

라우터는 Routing Table을 보고 패킷을 어디로 보낼지 결정한다.

Cisco에서 확인:

⌘Cisco IOS
show ip route

예:

⌘Text

여기서:

⌘Text
S = Static Route
⌘Text
[1/0]
 ↑ ↑
 AD Metric

22. AD와 Metric

AD — Administrative Distance

여러 라우팅 방식에서 같은 목적지 경로를 배웠을 때:

어떤 출처의 라우팅 정보를 더 믿을 것인지 나타내는 값

일반적으로 낮을수록 우선순위가 높다.

대표적인 값:

경로 AD
Connected 0
Static 1
EIGRP 내부 90
OSPF 110
RIP 120

Metric

같은 라우팅 프로토콜 안에서 여러 경로 중 어느 경로가 더 좋은지를 판단할 때 사용하는 비용이다.

프로토콜마다 계산 기준이 다르다.

예:

  • RIP → Hop Count
  • OSPF → Cost
  • EIGRP → 복합 Metric

따라서:

⌘Text
AD = 어떤 라우팅 정보 출처를 믿을지
Metric = 그 프로토콜 내부에서 어떤 경로가 좋은지

라고 이해하면 쉽다.

26. RIP — Routing Information Protocol

RIP는 대표적인 Distance Vector Routing Protocol이다.

경로 선택 기준:

⌘Text
Hop Count

즉 목적지까지 몇 개의 라우터를 거쳐야 하는지를 기준으로 경로를 선택한다.

27. RIP Hop Count 제한

RIP에서:

⌘Text
최대 정상 Hop Count = 15
⌘Text
16 Hop = Unreachable

따라서 큰 네트워크에는 적합하지 않다.

예:

⌘Cisco IOS
Router A → B → C → ... → 15 hop까지 가능

16 hop이 되면 도달할 수 없는 네트워크로 판단한다.

28. RIP의 단점

RIP의 대표적인 단점:

  • Hop Count만 보고 경로를 판단
  • 회선 속도를 고려하지 않음
  • 최대 15 hop 제한
  • 전체 라우팅 정보를 주기적으로 전송
  • 대규모 네트워크에 부적합
  • 수렴 속도가 비교적 느림

예를 들어:

⌘Text
경로 A: 2 hop, 매우 느린 회선
경로 B: 3 hop, 매우 빠른 회선

RIP는 단순히 hop 수만 보면 A를 선택할 수 있다.

29. RIP 업데이트 주기

RIP는 기본적으로 약:

⌘Text
30초마다

라우팅 업데이트를 보낸다.

여기서 주의할 점:

RIP는 OSPF나 EIGRP처럼 일반적인 의미의 Hello Packet을 사용하는 프로토콜이 아니다.

수업에서 말한 30초 주기는 정확히는:

⌘SQL
RIP Routing Update Timer

라고 이해하는 것이 좋다.

30. RIP 주요 Timer

Cisco RIP의 대표적인 기본 타이머:

Timer 기본값 의미
Update 30초 주기적으로 라우팅 업데이트 전송
Invalid 180초 일정 시간 업데이트가 없으면 경로를 유효하지 않다고 판단
Hold-down 180초 불안정한 경로 정보로 인한 변경을 억제
Flush 240초 라우팅 테이블에서 해당 경로 제거

핵심적으로:

⌘Text
30초  → 정기 업데이트
180초 → 업데이트가 오래 없으면 경로 문제로 판단
240초 → 결국 해당 경로 삭제

라고 먼저 기억하면 된다.

31. RIPv1과 RIPv2

RIPv1

  • Classful Routing Protocol
  • 라우팅 업데이트에 서브넷 마스크를 포함하지 않음
  • VLSM/CIDR 지원에 제약
  • Broadcast 방식 사용

RIPv2

  • Classless Routing Protocol
  • 서브넷 마스크 전송
  • VLSM/CIDR 지원
  • Multicast 224.0.0.9 사용

실습에서는 보통 RIPv2를 사용하는 것이 더 일반적이다.

1. GRE Tunnel

1-1. 터널이란?

터널(Tunnel)은 실제 물리 케이블을 새로 연결하는 것이 아니라, 기존 IP 네트워크 위에 논리적인 가상 연결을 하나 더 만드는 것입니다.

예를 들어 실제 네트워크가 다음과 같다고 가정합니다.

⌘Cisco IOS
LAN A
192.168.100.0/24
      |
    Router A
1.1.1.1
      |
   중간망
      |
2.2.2.2
    Router B
      |
172.16.0.0/24
LAN B

Router A와 Router B 사이에는 원래 1.1.1.x, 2.2.2.x 등의 실제 네트워크가 존재합니다.

여기에 GRE Tunnel을 만들면 논리적으로 다음 연결이 추가됩니다.

⌘Cisco IOS
Router A ================= Router B
      10.10.10.1      10.10.10.2
             GRE Tunnel

즉, 실제 패킷은 기존 IP망을 지나지만 라우터 입장에서는 Tunnel100이라는 가상 인터페이스가 하나 생긴 것처럼 사용할 수 있습니다.

1-2. Tunnel 인터페이스 생성

첫 번째 라우터에서:

⌘Cisco IOS
enable
configure terminal
interface tunnel 100

100은 터널 번호입니다.

실습에서 ?를 입력했을 때:

⌘Text
<0-2147483647> Tunnel interface number

라고 나왔습니다.

즉 터널 인터페이스는:

⌘Text
Tunnel0
Tunnel1
Tunnel100
...

처럼 여러 개 만들 수 있습니다.

1-3. Tunnel 인터페이스에 IP 주소 설정

Router A:

⌘Cisco IOS
interface tunnel 100
ip address 10.10.10.1 255.255.255.0

Router B:

⌘Cisco IOS
interface tunnel 100
ip address 10.10.10.2 255.255.255.0

그러면 두 터널 끝점은 같은 네트워크에 속합니다.

⌘Cisco IOS
10.10.10.0/24

Router A             Router B
10.10.10.1 -------- 10.10.10.2

중요한 점은 10.10.10.x가 물리 Serial 주소가 아니라 Tunnel100이라는 논리 인터페이스의 주소라는 것입니다.

1-4. GRE 모드 설정

실습 명령:

⌘Cisco
tunnel mode gre ip

GRE는 Generic Routing Encapsulation입니다.

쉽게 말하면:

원래 패킷을 다른 IP 패킷 안에 한 번 감싸서 보내는 방식

입니다.

중요한 특징

GRE는 여러 종류의 트래픽을 터널 안으로 넣기 편하지만:

  • 암호화를 제공하지 않음
  • 데이터 기밀성을 제공하지 않음
  • 자체적인 강력한 사용자 인증 기능이 없음

따라서 보안이 필요한 환경에서는 GRE + IPsec 조합을 많이 학습합니다.

8. GRE의 한계: 암호화와 인증

수업 기록에:

⌘Text

이라고 되어 있습니다.

이것이 바로 GRE의 중요한 단점입니다.

GRE는 캡슐화를 해줄 뿐, 데이터를 안전하게 보호하는 기술 자체는 아닙니다.

따라서 다음 단계에서 IPsec을 적용합니다.

⌘Text
GRE
= 논리적인 터널

IPsec
= 터널을 통과하는 데이터를 암호화/인증하여 보호

25. FHRP란?

수업 필기:

⌘Text
FHRP(First Hop Redundancy Protocol - 장애 대비)
HSRP / VRRP / GLBP

FHRP는 PC들이 사용하는 기본 게이트웨이를 이중화하기 위한 기술입니다.

일반적인 PC:

⌘Text
PC → Gateway 192.168.100.1

문제:

⌘Text
192.168.100.1 라우터 장애
→ PC가 다른 네트워크로 못 나감

그래서 두 라우터가 하나의 가상 게이트웨이 주소를 공유하게 합니다.

26. HSRP 기본 개념

HSRP는 Cisco의 FHRP 기술입니다.

예:

⌘Cisco IOS
Router A 실제 IP = 192.168.100.1
Router B 실제 IP = 192.168.100.2

Virtual IP     = 192.168.100.254

PC는 실제 라우터 IP를 게이트웨이로 쓰는 것이 아니라:

⌘Text
192.168.100.254

를 Gateway로 사용합니다.

그러면:

⌘Text
PC
 |
 | Gateway = 192.168.100.254
 |
 +---- Router A (Active)
 |
 +---- Router B (Standby)

처럼 동작합니다.

27. HSRP 기본 설정

Router A:

⌘Cisco IOS
interface gi0/0
standby 1 ip 192.168.100.254
standby 1 preempt
standby 1 priority 105

Router B:

⌘Cisco IOS
interface gi0/0
standby 1 ip 192.168.100.254
standby 1 preempt

기본 Priority는:

⌘Text
100

입니다.

따라서:

⌘Cisco IOS
Router A = 105
Router B = 100

이면 Router A가 Active가 될 가능성이 높습니다.

28. HSRP 그룹 번호

⌘Cisco
standby 1 ...

에서 1은 HSRP Group 번호입니다.

같은 HSRP 그룹으로 동작하려는 라우터는:

  • 같은 Group 번호
  • 같은 Virtual IP

를 사용해야 합니다.

29. HSRP Priority

수업 필기:

⌘Text
priority - 우선순위(default = 100)
우선순위가 높을수록 active 장비가 됨

예:

⌘Cisco IOS
Router A = 105
Router B = 100

→ Router A가 우선 Active

확인:

⌘Cisco IOS
show standby brief

실습 출력:

⌘Text
Gig0/0  1  105 P Active   local ...

여기에서:

⌘Text
105
→ Priority

P
→ Preempt 설정

Active
→ 현재 Active 라우터

입니다.

30. HSRP Preempt

수업 필기:

⌘Text
preemption - 원래 상태로 돌리는 것

조금 더 정확하게 설명하면:

더 높은 Priority를 가진 라우터가 다시 정상 상태가 되었을 때 Active 역할을 다시 빼앗아 올 수 있도록 하는 기능

입니다.

예:

⌘Text
R1 Priority 105
R2 Priority 100

정상:

⌘Text
R1 = Active
R2 = Standby

R1 장애:

⌘Text
R2 = Active

R1 복구 후 preempt가 설정되어 있으면:

⌘Text
R1 = 다시 Active
R2 = 다시 Standby

가 됩니다.

32. Active 라우터 장애 실험

실습에서 Active 라우터의 Gi0/0을:

⌘Cisco IOS
shutdown

했습니다.

그러자:

⌘Text
Active -> Init

등의 상태 변화가 발생하고, 반대편에서는:

⌘Text
Standby -> Active

로 전환되었습니다.

즉 HSRP의 핵심 목표인:

Active 장비 장애 시 Standby 장비가 Gateway 역할을 이어받는다.

를 확인한 것입니다.

33. HSRP와 OSPF 로그를 같이 본 이유

Gi0/0을 Shutdown하자 다음과 같은 OSPF 로그도 발생했습니다.

⌘Text
OSPF ... FULL to DOWN

이유:

하나의 인터페이스에서:

  • HSRP
  • OSPF Neighbor

가 동시에 동작하고 있었기 때문입니다.

인터페이스 자체가 내려가면 그 인터페이스 위에서 동작하던 여러 프로토콜이 동시에 영향을 받습니다.

34. HSRP Tracking

수업 필기:

⌘Text
tracking(추적)
기본값 10만큼 감소

설정:

⌘Cisco
standby 1 track se0/3/0

뜻:

HSRP가 Serial0/3/0 상태를 감시하라.

35. 왜 Tracking이 필요한가?

예:

⌘Text
       인터넷
         |
      Serial
         |
       R1
         |
LAN ----+---- R2

R1의 LAN 인터페이스는 살아 있는데 외부로 나가는 Serial 회선만 죽었다고 해봅시다.

Tracking이 없으면:

⌘Text
R1 LAN 인터페이스는 살아 있음
→ HSRP는 R1을 계속 Active라고 생각할 수 있음
→ PC들은 R1으로 보내지만 외부로 못 나감

Tracking을 설정하면:

⌘Text
Serial 장애 감지
→ R1 Priority 감소
→ R2의 Priority가 더 높아짐
→ R2가 Active로 전환 가능

해집니다.

36. Tracking Priority 감소

실습:

⌘Text
Priority 105

였던 라우터에서 Serial0/3/0 장애 후:

⌘Text
Priority 95 (configured 105)
Track interface Serial0/3/0 state Down decrement 10

가 나타났습니다.

계산:

⌘Text
105 - 10 = 95

즉 설정된 원래 Priority는 105지만 Tracking 때문에 현재 유효 Priority가 95가 된 것입니다.

주의

Priority가 낮아졌다고 반드시 즉시 Active가 바뀌는 것은 아닙니다.

상대 라우터의 Priority와 Preempt 설정, HSRP Timer 상태 등에 따라 실제 전환이 결정됩니다.

37. IPv6 기본 구조

IPv6 주소는 총:

⌘Text
128비트

입니다.

IPv6 예:

⌘Text
2001:2:2:2::1/64

IPv6는 :로 구분된 최대 8개의 블록으로 표현합니다.

각 블록:

⌘Text
16비트

따라서:

⌘Text
16비트 × 8 = 128비트

입니다.

38. IPv6 /64가 왜 64비트인가?

예:

⌘Text
2001:2:2:2::1/64

완전히 풀어쓰면:

⌘Text
2001:0002:0002:0002:0000:0000:0000:0001

앞의 네 블록:

⌘Text
2001 : 0002 : 0002 : 0002
 16      16      16      16

합계:

⌘Text
16 × 4 = 64비트

그래서 /64는:

⌘Text
앞 64비트 = 네트워크 부분
뒤 64비트 = 인터페이스(호스트) 부분

이라고 이해하면 됩니다.

39. IPv6 축약 규칙

수업에서 적은 핵심:

⌘Text
2001:0DB8:0000:0000:0000:0000:0000:0000
→ 2001:DB8::

규칙은 크게 두 개입니다.

규칙 1. 각 블록의 앞쪽 0 생략

⌘Text
0DB8 → DB8
0002 → 2
0000 → 0

예:

⌘Text
2001:0DB8:0345:0000:0000:0000:0000:0000

→

⌘Text
2001:DB8:345:0:0:0:0:0

규칙 2. 연속된 0 블록을 ::로 축약

⌘Text
2001:DB8:345:0:0:0:0:0

→

⌘Text
2001:DB8:345::

매우 중요한 규칙

::는 한 IPv6 주소 안에서 한 번만 사용할 수 있습니다.

왜냐하면 두 번 사용하면 생략된 0이 각각 몇 블록인지 알 수 없기 때문입니다.

40. IPv6 주소 종류

수업 필기에는 다음 내용이 있습니다.

⌘Text
Global 주소
Link-Local 주소
사이트 로컬 주소
Multicast
Anycast
Unicast
Broadcast 없음

Unicast

하나의 특정 인터페이스로 보내는 주소입니다.

Multicast

특정 그룹에 속한 여러 장비에게 보냅니다.

Anycast

같은 주소를 여러 장비가 사용할 수 있고, 라우팅상 가까운 장비 하나로 전달됩니다.

Broadcast

IPv6에는 IPv4에서 사용하던 Broadcast 개념이 없습니다.

필요한 그룹 전송은 Multicast로 처리합니다.

41. Link-Local 주소

IPv6 인터페이스에서 자주 보게 되는:

⌘Text
FE80::...

형태가 Link-Local Address입니다.

특징:

  • FE80::/10 범위
  • 같은 링크에서 통신할 때 사용
  • 라우터 간 Neighbor 관계 등에서 자주 사용
  • 일반 인터넷 라우팅용 Global Address와 역할이 다름

OSPFv3 라우팅 테이블에서도 다음 홉이:

⌘Text

처럼 보일 수 있습니다.

46. OSPFv3 Router-ID

실습:

⌘Cisco
ipv6 router ospf 1
router-id 11.11.11.11

반대편:

⌘Cisco

IPv6 OSPF라도 Router-ID는 IPv4처럼 점으로 구분된 형식을 사용합니다.

50. 왜 어떤 라우터에는 O가 없을 수 있는가?

OSPF Neighbor가 FULL이라고 해서 반드시 양쪽 라우팅 테이블에 O가 있어야 하는 것은 아닙니다.

예:

⌘Text

  • R1-R2 Serial 네트워크

그러면 R2에서는 둘 다:

⌘Text
C

입니다.

반면 R1은 R2 뒤쪽 LAN을 직접 연결하고 있지 않으므로:

⌘Text
O

로 배웁니다.

즉:

⌘Text
Neighbor FULL
→ OSPF 이웃 관계 정상

→ 다른 라우터에게서 새로운 네트워크를 학습했을 때 표시

입니다.

53. L3 Switch의 Routed Port

수업 후반부에서 스위치 인터페이스에:

⌘Cisco IOS
ip address 5.5.5.5 255.255.255.0

를 입력했더니 처음에는 오류가 났습니다.

이유:

일반적인 스위치 포트는 기본적으로 Layer 2 Switchport이기 때문입니다.

L3 Switch에서는:

⌘Cisco
no switchport

를 입력하면 해당 포트를 Routed Port로 바꿀 수 있습니다.

그 후:

⌘Cisco IOS
ip address 5.5.5.5 255.255.255.0

를 설정할 수 있습니다.

54. no switchport란?

기본 스위치 포트:

⌘Text
Layer 2
→ MAC 주소 기반 Switching
→ VLAN에 속하는 포트

no switchport 적용:

⌘Text
Layer 3 Routed Port
→ Router 인터페이스처럼 IP 주소 부여 가능
→ Routing에 참여 가능

즉 L3 Switch에서는:

⌘Cisco IOS
interface fa0/1
 no switchport
 ip address 5.5.5.5 255.255.255.0

가 가능합니다.

⌘Text

이 나왔습니다.

해결:

⌘Cisco

그 후:

⌘Cisco IOS

이 가능해집니다.

즉 L3 Switch를 라우터처럼 사용하려면:

⌘Text

+

+

구조를 이해해야 합니다.

56. 모든 Switch가 no switchport를 지원하는 것은 아니다

다른 스위치에서는:

⌘Cisco
no switchport

를 입력해도 Routed Port로 바뀌지 않았습니다.

? 출력에는:

⌘Text
access
mode
nonegotiate
port-security
trunk
...

등만 나왔습니다.

이는 해당 장비/포트가 Layer 2 Switchport 기능 중심으로 동작하고, Routed Port 기능을 지원하지 않는 모델/환경이라는 의미로 볼 수 있습니다.

따라서:

⌘Text
L3 Switch
→ no switchport 가능

일반 L2 Switch
→ no switchport로 Routed Port 전환 불가

라고 구분해야 합니다.

입니다.

67. 스스로 답해볼 복습 문제

문제 1

GRE Tunnel에 10.10.10.1을 설정하고 실제 Serial에 1.1.1.1을 설정했다면 두 주소의 역할 차이는?

정답

  • 10.10.10.1: 터널 내부 논리 인터페이스 주소
  • 1.1.1.1: 실제 네트워크를 통과할 때 사용하는 물리/외부 인터페이스 주소

문제 2

GRE만 사용했을 때 보안상 부족한 점은?

정답

GRE 자체는 데이터를 암호화하지 않으므로 기밀성 보호가 부족합니다. 그래서 IPsec을 함께 사용할 수 있습니다.

문제 3

crypto map 안에서 match address, set peer, set transform-set의 역할은?

정답

  • match address: 보호 대상 트래픽
  • set peer: VPN 상대방
  • set transform-set: 사용할 암호화/무결성 방식

문제 4

HSRP에서 Priority 105와 100 중 누가 Active가 되는가?

정답

일반적으로 Priority가 높은 105 장비가 Active가 됩니다.

문제 5

preempt의 역할은?

정답

더 높은 Priority를 가진 라우터가 복구되었을 때 기존 Active로부터 역할을 다시 가져올 수 있게 합니다.

문제 6

HSRP Tracking을 왜 사용하는가?

정답

LAN 인터페이스는 살아 있지만 외부 회선이 죽은 상황을 감지하여 Priority를 낮추고 다른 라우터로 Gateway 역할을 넘기기 위해 사용합니다.

문제 7

IPv6 주소의 전체 길이는?

정답

128비트.

문제 8

/64의 의미는?

정답

앞 64비트가 네트워크 Prefix이고 뒤 64비트가 인터페이스 식별 영역이라는 의미입니다.

문제 9

FE80::로 시작하는 주소는?

정답

Link-Local Address.

문제 10

show ipv6 route에서 C, L, O의 의미는?

정답

  • C: Connected
  • L: Local
  • O: OSPF로 학습

문제 11

OSPFv3 Neighbor가 FULL이면?

정답

두 라우터가 OSPFv3 이웃 관계를 정상적으로 형성하여 라우팅 정보를 교환할 수 있는 상태입니다.

문제 12

L3 Switch에서 물리 포트에 IP 주소를 직접 넣으려면?

정답

지원되는 L3 Switch에서:

⌘Cisco IOS
no switchport
ip address ...

로 Routed Port로 변환합니다.

문제 13

L2 Switch를 Telnet으로 관리하기 위해 IP를 어디에 주는가?

정답

물리 포트가 아니라 SVI:

⌘Cisco IOS
interface vlan 1

에 관리 IP를 설정합니다.

4. OSPF 기본 구성

OSPF 시작

⌘Cisco IOS
router ospf 1
  • 1 = OSPF Process ID
  • Process ID는 해당 라우터 내부에서 OSPF 프로세스를 구분하는 번호
  • 이웃 라우터와 Process ID가 반드시 같을 필요는 없음

Network 등록 예

⌘Cisco IOS
router ospf 1
 network 2.2.2.0 0.0.0.255 area 0
 network 10.10.10.0 0.0.0.255 area 1

뜻:

⌘Text
2.2.2.0/24에 해당하는 인터페이스 → Area 0에서 OSPF 동작
10.10.10.0/24에 해당하는 인터페이스 → Area 1에서 OSPF 동작

network 명령은 IP 주소를 새로 만드는 명령이 아니라, 어떤 인터페이스에서 OSPF를 활성화하고 그 네트워크를 광고할지 결정합니다.

5. Area 0 / Multi-Area / ABR

Area 0

⌘Text
Area 0 = Backbone Area

OSPF Multi-Area에서는 다른 Area들이 Backbone Area 0과 정상적으로 연결되는 구조가 기본입니다.

ABR

⌘Text
ABR = Area Border Router

두 개 이상의 Area를 연결하는 라우터입니다.

예:

⌘Text
R3
2.2.2.0/24    → Area 0
10.10.10.0/24 → Area 1

따라서 R3는 ABR입니다.

Virtual Link

Area 0과 정상적인 연속성을 확보하기 어려운 특수한 상황에서는 Virtual Link를 이용해 논리적으로 Backbone 연결을 구성할 수 있습니다.

초보 단계에서는 다음 정도로 기억하면 됩니다.

⌘Text
정상 설계 → Area 0 중심으로 구성
예외 상황 → Virtual Link 고려

Single Area 주의

Single-Area OSPF에서 Area 0을 쓰는 것이 일반적이고 권장되지만, 프로토콜상 반드시 Area 번호가 0이어야만 OSPF가 동작하는 것은 아닙니다.

6. Router ID

Router ID는 OSPF에서 라우터를 식별하는 값입니다.

선택 우선순위:

⌘Text
1. router-id로 직접 지정
2. Loopback 인터페이스 중 가장 높은 IP
3. 활성 일반 인터페이스 중 가장 높은 IP

처음 R3

⌘Text
Serial0/3/1        = 2.2.2.2
GigabitEthernet0/0 = 10.10.10.1

Loopback과 직접 지정된 Router ID가 없었으므로:

⌘Cisco IOS
Router ID = 10.10.10.1

Loopback 생성

⌘Cisco IOS
interface loopback 0
 ip address 5.5.5.5 255.255.255.0

OSPF 프로세스를 재시작한 뒤 Loopback이 Router ID 후보로 우선됩니다.

⌘Cisco IOS
Router ID = 5.5.5.5

직접 지정

⌘Cisco IOS
router ospf 1
 router-id 3.3.3.3

현재 실행 중인 OSPF에 적용하려면:

⌘Cisco

최종:

⌘Cisco IOS
Router ID = 3.3.3.3

clear ip ospf process와 삭제 차이

⌘Cisco

해석:

⌘Text
Neighbor ID = 상대 라우터의 Router ID
Address     = 실제 연결된 상대 인터페이스 IP

잘못 기억하기 쉬운 표현:

⌘Text

⌘Text

    ↓

    ↓

    ↓

    ↓
FULL

즉 Hello가 먼저입니다.

⌘Text

13. Redistribution이 필요한 이유

서로 다른 Routing Protocol은 기본적으로 각자 배운 경로를 자동으로 공유하지 않습니다.

예:

⌘Text
EIGRP 영역 ── 경계 라우터 ── OSPF 영역

이때 경계 라우터에서 Redistribution(재분배)을 설정하여 한 프로토콜의 경로를 다른 프로토콜에 전달할 수 있습니다.

14. OSPF → EIGRP 재분배

⌘Cisco IOS
router eigrp 100
 redistribute ospf 1 metric 1544 2000 255 1 1500

EIGRP는 외부에서 받은 경로에 사용할 Seed Metric이 필요합니다.

순서:

⌘Text
1544 = Bandwidth (Kbit/s)
2000 = Delay (10 microsecond 단위) → 20 ms
255  = Reliability (255 = 100%)
1    = Load
1500 = MTU (bytes)

즉:

⌘Text
redistribute ospf 1
→ OSPF 1에서 학습한 경로를 EIGRP 100으로 가져온다.

주의: 해당 라우터에서 OSPF 1이 실제로 존재하고 경로를 가지고 있어야 의미가 있습니다.

15. EIGRP → OSPF 재분배

OSPF를 다시 구성:

⌘Cisco IOS

 redistribute eigrp 100 subnets
 network 2.2.2.0 0.0.0.255 area 0

subnets:

기본적으로 OSPF로 재분배된 외부 경로는 O E2로 보일 수 있습니다.

예:

⌘Text

16. 경계 네트워크 중복 광고 주의

수업에서 강조한 핵심:

경계 라우터에서 같은 네트워크를 여러 Routing Protocol로 불필요하게 중복 광고하면 경로 선택이 복잡해질 수 있다.

⌘Cisco IOS

⌘Text
EIGRP 100
  ├─ 10.10.10.0/24
  └─ 5.5.5.0/24

OSPF 1
  └─ 2.2.2.0/24 Area 0

EIGRP ↔ OSPF는 Redistribution으로 교환

no network는 인터페이스 IP를 삭제하는 명령이 아닙니다.

⌘Text
EIGRP 참여만 제거
인터페이스 IP는 유지

20. ACL 설계 원칙

  1. 기본 통신이 되는지 먼저 확인하고 ACL은 마지막에 적용
  2. ACL은 위에서 아래로 검사
  3. 첫 번째 Match에서 검사 종료
  4. 구체적인 규칙을 위에 배치
  5. 넓은 규칙을 아래에 배치
  6. 마지막에는 보이지 않는 implicit deny any가 존재

⌘Cisco IOS

⌘Text

주의: 실제 Ping 왕복에서는 Echo Reply의 출발지/목적지가 요청과 반대 방향이므로, echo-reply 규칙을 만들 때는 방향을 확인해야 합니다.

24. permit ip any any 아래의 규칙 문제

출력:

⌘Text

60 deny icmp host 192.168.200.35 host 10.10.10.2 echo

이 구조에서는 60번 규칙이 사실상 적용되지 않습니다.

이유:

⌘Text

허용 후 ACL 검사 종료

60번까지 내려가지 않음

따라서:

⌘Cisco IOS

        ↓
permit ip any any

순서가 되어야 합니다.

34. NAT 기본 개념

⌘Text
NAT = Network Address Translation

IP 주소를 다른 IP 주소로 변환하는 기술입니다.

이번 실습에서는 ACL로 변환 대상 내부 주소를 지정하고, NAT Pool에서 변환에 사용할 주소 범위를 정의하는 Dynamic NAT 형태를 구성하기 시작했습니다.

큰 흐름:

⌘Text
Inside Local 주소
172.16.100.x
      ↓
ACL 10으로 변환 대상 선택
      ↓
NAT Pool dnat
1.1.1.1 ~ 1.1.1.254
      ↓
Inside Global 주소로 변환

35. NAT Pool 생성

도움말 확인:

⌘Cisco IOS
Router(config)#ip nat pool ?
  WORD  Pool name

Pool 이름을 dnat으로 지정:

⌘Cisco
ip nat pool dnat 1.1.1.1 1.1.1.254 netmask 255.255.255.0

구조:

⌘Text
ip nat pool
  dnat             → Pool 이름
  1.1.1.1          → 시작 주소
  1.1.1.254        → 끝 주소
  netmask
  255.255.255.0    → Pool의 네트워크 마스크

처음 다음처럼 입력했을 때:

⌘Cisco
ip nat pool dnat 1.1.1.1 1.1.1.254 255.255.255.0

오류가 난 이유는 255.255.255.0 앞에 netmask 키워드가 필요했기 때문입니다.

올바른 문법:

⌘Cisco
ip nat pool dnat 1.1.1.1 1.1.1.254 netmask 255.255.255.0

36. NAT 변환 대상 ACL

⌘Cisco IOS
access-list 10 permit 172.16.100.0 0.0.0.255

뜻:

172.16.100.0/24를 NAT 변환 대상으로 선택한다.

여기서 ACL은 보안 차단 목적이라기보다 NAT가 어떤 내부 주소를 변환할지 Match하는 용도입니다.

⌘Text
permit = NAT 대상에 포함

37. ACL 10과 NAT Pool 연결

⌘Cisco
ip nat inside source list 10 pool dnat

구성 요소:

⌘Text
ip nat inside source
→ Inside에서 출발한 Source Address를 변환

list 10
→ ACL 10에 Match되는 주소를 대상으로 함

pool dnat
→ dnat Pool의 주소 중 하나로 변환

즉 한 문장으로:

172.16.100.0/24 출발지 주소를 NAT Pool dnat의 1.1.1.1~1.1.1.254 주소 중 하나로 변환한다.

38. NAT는 아직 인터페이스 지정이 필요함

현재 입력한 명령만으로는 NAT 설정이 완전히 끝난 것이 아닙니다.

NAT를 사용할 인터페이스에:

⌘Cisco
ip nat inside

와:

⌘Cisco
ip nat outside

를 지정해야 합니다.

일반 구조:

⌘Text
172.16.100.0/24
      │
      │ Inside
      ▼
[ Router ]
      │
      │ Outside
      ▼
외부 네트워크

예시 형태:

⌘Cisco IOS
interface <172.16.100.0/24 쪽 인터페이스>
 ip nat inside

interface <외부망 쪽 인터페이스>
 ip nat outside

정확한 인터페이스는 해당 NAT를 설정하는 라우터의 show ip interface brief를 보고 결정해야 합니다.

1.1.1.1 ~ 1.1.1.254 /24

을 사용하기 전에 해당 주소 범위가 실제 토폴로지에서 다른 인터페이스 주소나 실제 장비 주소와 충돌하지 않는지 확인해야 합니다.

실습 토폴로지에서는 이미 1.1.1.0/24가 라우터 간 링크로 사용된 적이 있으므로, Pool 주소와 실제 인터페이스 주소가 중복되지 않는지 확인하는 것이 중요합니다.

수업에서 지정된 값이라면 강의 토폴로지 의도대로 진행하되, 실제 네트워크에서는 NAT Pool을 설계할 때 주소 충돌을 피해야 합니다.

1. NAT Inside / Outside 인터페이스 지정

NAT 설정은 Pool과 ACL만 만든다고 끝나는 것이 아닙니다.
라우터가 어느 쪽을 Inside(내부망), 어느 쪽을 Outside(외부망) 로 볼지 인터페이스에 지정해야 합니다.

이번 실습에서는:

⌘Cisco IOS
interface GigabitEthernet0/0
 ip nat inside
!
interface Serial0/3/0
 ip nat outside

로 설정했습니다.

의미:

⌘Text
GigabitEthernet0/0
→ NAT 내부망 쪽 인터페이스

Serial0/3/0
→ NAT 외부망 쪽 인터페이스

패킷 흐름을 단순화하면:

⌘Text
172.16.100.0/24
      │
      │ Inside
      ▼
GigabitEthernet0/0
      │
    [NAT]
      │
Serial0/3/0
      │ Outside
      ▼
외부 네트워크

3. Dynamic NAT이 실제로 동작한 결과

내부 PC 172.16.100.3에서 외부 쪽 주소로 Ping을 발생시킨 뒤:

⌘Cisco IOS
show ip nat translations

를 확인했습니다.

⌘Text
Pro  Inside global     Inside local       Outside local      Outside global

icmp 1.1.1.1:5         172.16.100.3:5     192.168.200.18:5   192.168.200.18:5
icmp 1.1.1.1:6         172.16.100.3:6     192.168.200.18:6   192.168.200.18:6
icmp 1.1.1.1:7         172.16.100.3:7     192.168.200.18:7   192.168.200.18:7
icmp 1.1.1.1:8         172.16.100.3:8     192.168.200.18:8   192.168.200.18:8

핵심 변환:

⌘Text
Inside local  : 172.16.100.3
Inside global : 1.1.1.1

즉 내부 PC의 실제 주소 172.16.100.3이 외부로 나갈 때 NAT Pool에서 1.1.1.1을 할당받았습니다.

⌘Text
172.16.100.3
      │
      │ NAT
      ▼
   1.1.1.1
      │
      ▼
192.168.200.18

이것이 Dynamic NAT입니다.

Dynamic NAT은 미리 특정 PC와 특정 Global IP를 고정하지 않고,
Pool에서 사용 가능한 주소를 필요할 때 할당합니다.

4. NAT 용어 4가지

show ip nat translations에서 가장 중요한 네 개의 주소 표현입니다.

Inside Local
⌘Text
172.16.100.3

내부 네트워크에서 실제로 사용하는 사설/내부 주소입니다.

내부 호스트의 원래 주소

Inside Global
⌘Text
1.1.1.1

Inside Local 주소가 외부 네트워크에 보일 때 사용하는 변환된 주소입니다.

NAT 이후 외부에서 보이는 내부 호스트 주소

Outside Global

예:

⌘Text
192.168.200.18

외부 호스트가 실제 외부 네트워크에서 사용하는 주소입니다.

Outside Local

이번 실습에서는:

⌘Text
192.168.200.18

처럼 Outside Global과 동일했습니다.

Outside Local은 내부 네트워크에서 바라보는 외부 호스트의 주소입니다.

일반적인 NAT 실습에서는 Outside Local과 Outside Global이 같은 경우가 많습니다.

5. Dynamic NAT 전체 설정 구조

이번 실습의 Dynamic NAT 설정을 하나로 보면:

⌘Cisco IOS
ip nat pool dnat 1.1.1.1 1.1.1.254 netmask 255.255.255.0

access-list 10 permit 172.16.100.0 0.0.0.255

ip nat inside source list 10 pool dnat

interface GigabitEthernet0/0
 ip nat inside

interface Serial0/3/0
 ip nat outside

각 명령의 역할:

⌘Text
ACL 10
→ 어떤 내부 주소를 NAT할 것인가?

Pool dnat
→ 어떤 Global IP 주소로 바꿀 것인가?

ip nat inside source list 10 pool dnat
→ ACL 10에 해당하는 출발지를 dnat Pool의 주소로 변환

ip nat inside
→ 내부 인터페이스 지정

ip nat outside
→ 외부 인터페이스 지정

즉 NAT 설정은 다음 네 요소가 맞아야 합니다.

⌘Text
① NAT 대상 ACL
② NAT Pool
③ ACL과 Pool 연결
④ Inside / Outside 인터페이스 지정

6. Static NAT 설정

다음으로 Static NAT을 설정했습니다.

⌘Cisco
ip nat inside source static 172.16.100.4 1.1.1.10

형식:

⌘Cisco
ip nat inside source static <Inside-Local> <Inside-Global>

이번 값:

⌘Text
Inside Local  = 172.16.100.4
Inside Global = 1.1.1.10

즉:

⌘Text
172.16.100.4  ↔  1.1.1.10

의 고정 1:1 매핑을 만든 것입니다.

Dynamic NAT과 달리 트래픽이 없더라도 이 매핑 자체는 설정에 존재합니다.

⌘Text

여기서 ---는 특정 TCP/UDP/ICMP 세션이 아니라

즉 아직 실제 통신을 하지 않았더라도:

⌘Text

매핑은 이미 존재합니다.

ACL(Access Control List, 접근제어목록)은 패킷을 조건에 따라 허용하거나 차단하는 정책입니다.

분류 기준

1. 필터링 기준
⌘Text
Standard ACL
→ 주로 출발지 IP 주소 기준

Extended ACL
→ 출발지 IP + 목적지 IP + 프로토콜 + 포트 등 세부 조건
2. 설정 방식
⌘Text

→ 번호로 관리

Named ACL
→ 이름으로 관리

ACL 검사 순서

ACL은:

⌘Text
첫 번째 규칙
   ↓
두 번째 규칙
   ↓
세 번째 규칙
   ↓
...

# VPN 기초 정리

1. VPN이란?

VPN은:

⌘Text
Virtual Private Network
= 가상 사설망

입니다.

인터넷과 같은 공용 네트워크를 사용하면서도, 논리적으로는 사설망처럼 안전한 통신 경로를 만드는 기술입니다.

쉽게 말하면:

⌘Text
공용 인터넷
     │
     │ 암호화된 VPN Tunnel
     ▼
사설 네트워크처럼 통신

하는 방식입니다.

VPN에서는 일반적으로 통신 내용을 암호화하고, VPN 양 끝단 또는 사용자 인증을 통해 허가된 장비/사용자만 연결하도록 구성합니다.

2. VPN의 대표적인 두 가지 형태

수업에서 우선 구분할 것은:

⌘Text
① Site-to-Site VPN
② Remote Access VPN

입니다.

3. Site-to-Site VPN

Site-to-Site VPN은:

서로 떨어져 있는 두 개 이상의 네트워크를 VPN Tunnel로 연결하는 방식

입니다.

예:

⌘Text
서울 본사 LAN
192.168.10.0/24
      │
 [VPN 장비]
      │
====== 인터넷 ======
      │
 [VPN 장비]
      │
부산 지사 LAN
192.168.20.0/24

두 지점의 VPN 장비가 Tunnel을 만들기 때문에, 내부 PC들은 VPN을 직접 실행하지 않아도 서로 통신할 수 있습니다.

예를 들어:

⌘Text
서울 PC
192.168.10.10
       ↓
   VPN Tunnel
       ↓
부산 Server
192.168.20.20

처럼 LAN-to-LAN 통신이 가능합니다.

pfSense 공식 문서에서도 Site-to-Site IPsec VPN은 두 네트워크를 라우터로 직접 연결한 것과 비슷하게 상호 연결하는 형태로 설명합니다.

주로 사용하는 상황

⌘Text
본사 ↔ 지사
회사 ↔ 데이터센터
사무실 A ↔ 사무실 B

처럼 네트워크 전체를 서로 연결할 때 사용합니다.

4. Remote Access VPN

Remote Access VPN은:

외부의 개별 사용자나 장비가 회사 내부 네트워크에 원격으로 접속하는 방식

입니다.

예:

⌘Text
회사 내부망
192.168.10.0/24
      │
 [VPN Server]
      │
==== 인터넷 ====
      │
      │ VPN Client
      ▼
재택근무 노트북

사용자는 노트북이나 스마트폰에서 VPN Client를 실행하고, 인증을 거쳐 회사 내부망에 접속합니다.

pfSense에서는 OpenVPN, IPsec, WireGuard 등의 방식으로 Remote Access VPN 구성이 가능합니다.

5. Site-to-Site와 Remote Access 비교

구분 Site-to-Site Remote Access
연결 대상 네트워크 ↔ 네트워크 사용자/장비 ↔ 네트워크
대표 상황 본사 ↔ 지사 재택근무자 ↔ 회사
VPN Client 일반 PC에 보통 불필요 사용자 장비에 필요할 수 있음
Tunnel Endpoint 양쪽 VPN 장비 VPN 서버 ↔ 사용자 Client
관리 목적 여러 LAN 연결 개별 원격 사용자 접속

기억:

⌘Text
Site-to-Site
→ 장소와 장소를 연결

Remote Access
→ 사람이 밖에서 내부망에 접속

6. VPN Tunnel

VPN에서는 흔히:

⌘Text
Tunnel

이라는 표현을 사용합니다.

실제 전용선을 새로 설치하는 것이 아니라, 인터넷 위에 논리적인 통신 경로를 만들어 사용하는 것입니다.

개념적으로:

⌘Text

A ----------------------------- B

VPN 사용

처럼 생각하면 됩니다.

1. 패킷이 움직이는 전체 그림

1.1 캡슐화

애플리케이션 데이터는 전송계층에서 TCP segment 또는 UDP datagram이 되고, 네트워크계층에서 IP packet, 데이터링크계층에서 Ethernet frame이 됩니다. 라우터는 L2 header를 벗기고 목적지 IP를 기준으로 다음 홉을 선택한 뒤 새 L2 header를 붙입니다.

계층 핵심 식별자 장비·프로토콜 예 확인 질문
Application 이름·요청 DNS, HTTP, SSH 어떤 서비스인가?
Transport port, TCP/UDP 22, 53, 80, 443 어느 프로세스인가?
Network source/destination IP IPv4, IPv6, ICMP 어느 네트워크인가?
Data Link MAC, VLAN Ethernet, 802.1Q 같은 broadcast domain인가?
Physical signal, cable copper, fiber, serial 링크가 올라왔나?

1.2 같은 서브넷과 다른 서브넷

같은 서브넷이면 호스트는 목적지 IP를 ARP 또는 IPv6 Neighbor Discovery로 MAC에 매핑해 직접 전송합니다. 다른 서브넷이면 기본 게이트웨이의 MAC으로 frame을 보내고, 라우터가 목적지 네트워크를 라우팅합니다.

⌘Text
PC-A -> (같은 subnet) -> PC-B
PC-A -> default gateway -> Router -> next hop -> 목적지 subnet

장애 발생 시 “ping이 안 된다”만 보지 않습니다. IP 주소 → mask → ARP/MAC → gateway → routing table → ACL/NAT/VPN 순서로 범위를 좁힙니다.

2. IPv4·서브네팅·CIDR

2.1 prefix 계산

/n은 앞에서부터 n개의 network bit가 1인 mask입니다. IPv4는 32 bit입니다.

Prefix Mask 전체 주소 일반적인 사용 가능 호스트
/24 255.255.255.0 256 254
/25 255.255.255.128 128 126
/26 255.255.255.192 64 62
/27 255.255.255.224 32 30
/30 255.255.255.252 4 2
/31 255.255.255.254 2 point-to-point 특례 확인
/32 255.255.255.255 1 단일 주소·host route

일반적인 LAN 계산식은 2^(32-prefix) - 2입니다. /31, /32, 장비별 point-to-point 처리는 예외이므로 장비 문서와 실습 결과를 확인합니다.

2.2 block size와 AND

예: 192.168.16.0/25의 마지막 octet block size는 256 - 128 = 128입니다. 네트워크는 0, 128에서 시작합니다.

  • 192.168.16.100/25 → 192.168.16.0/25
  • 192.168.16.200/25 → 192.168.16.128/25
  • 두 주소는 같은 192.168.16.0/24 안에 있지만 /25 기준 다른 subnet입니다.

계산 절차:

  1. prefix를 mask로 바꿉니다.
  2. IP와 mask를 bitwise AND 합니다.
  3. host bit를 모두 0으로 만든 값이 network address입니다.
  4. host bit를 모두 1로 만든 값이 broadcast address입니다.
  5. 두 호스트의 network address가 같을 때만 직접 통신으로 판단합니다.

CIDR과 prefix aggregation의 표준 기준은 RFC 4632입니다. 사설 주소 대역은 RFC 1918을 기준으로 기록합니다.

2.3 VLSM 설계

부서별 요구 호스트 수를 큰 순서로 정렬합니다. 각 요구량에 맞는 최소 prefix를 배정한 뒤 다음 미사용 block으로 이동합니다. 주소표에는 반드시 network / first usable / last usable / broadcast / gateway / VLAN을 함께 기록합니다.

4. Switching: VLAN·Trunk·STP·SVI

4.1 Access와 Trunk

⌘Cisco IOS

검증:

Access port는 한 VLAN에 속하고, trunk는 여러 VLAN tag를 전달합니다. Native VLAN·allowed VLAN·양쪽 trunk 설정 불일치는 통신 실패 원인이 됩니다.

4.2 Inter-VLAN routing

Router-on-a-Stick:

⌘Cisco IOS

 ip address 192.168.10.1 255.255.255.0
interface gigabitEthernet0/0.20

 ip address 192.168.20.1 255.255.255.0

L3 switch:

⌘Cisco IOS
ip routing
interface gigabitEthernet1/0/1
 no switchport
 ip address 10.0.0.1 255.255.255.252
 no shutdown
interface vlan 10
 ip address 192.168.10.1 255.255.255.0
 no shutdown

SVI는 VLAN의 L3 인터페이스입니다. VLAN이 존재하지 않거나 access/trunk 경로가 없으면 SVI가 살아 있어도 호스트 통신은 되지 않습니다.

5. Routing: 정적·동적·RIP

5.1 라우팅 테이블 읽기

⌘Cisco IOS
show ip route
show ip route 192.168.30.0
show ip protocols

라우터는 목적지 prefix가 가장 긴 경로를 우선 선택합니다. 같은 prefix 후보가 여러 개면 administrative distance로 출처 신뢰도를 비교하고, 같은 프로토콜 안에서는 metric으로 최적 경로를 비교합니다.

정적·기본 경로:

⌘Text
ip route 192.168.30.0 255.255.255.0 10.0.0.2
ip route 0.0.0.0 0.0.0.0 10.0.0.2

5.2 RIP v1/v2

RIP는 distance-vector 방식이며 hop count를 metric으로 사용합니다. RIPv2의 표준 정의는 RFC 2453입니다.

⌘Cisco IOS
router rip
 version 2
 no auto-summary
 network 10.0.0.0
 network 192.168.10.0

확인:

⌘Cisco IOS
show ip protocols
show ip route rip
debug ip rip

수업 노트의 send version 1 같은 문법은 인터페이스별 송신 버전 설정과 관련됩니다. 전체 라우터 모드의 version과 구분하고, show ip protocols 결과로 실제 동작을 확인합니다.

6. EIGRP·OSPF·Redistribution

6.1 EIGRP AS 100

⌘Cisco IOS
router eigrp 100
 network 10.0.0.0 0.0.0.3
 network 192.168.10.0 0.0.0.255
 no auto-summary
⌘Cisco IOS
show ip eigrp neighbors
show ip eigrp topology
show ip route eigrp

Wildcard mask는 subnet mask의 역입니다. network 범위를 너무 넓게 잡으면 의도하지 않은 인터페이스에서 adjacency가 형성될 수 있습니다.

6.2 OSPF Area 0

⌘Cisco IOS
router ospf 1
 router-id 1.1.1.1
 network 10.0.0.0 0.0.0.3 area 0
 network 192.168.10.0 0.0.0.255 area 0
⌘Cisco IOS
show ip ospf neighbor
show ip ospf interface brief
show ip ospf database
show ip route ospf

OSPF는 link-state 방식입니다. 인접 관계 → LSDB → SPF 계산 순서로 이해합니다. Broadcast network에서는 DR/BDR 선출이 발생합니다. router-id 변경 후에는 프로세스 재시작이 필요할 수 있으므로 실습 전후 상태를 기록합니다.

6.3 Redistribution 주의

EIGRP와 OSPF를 재분배할 때는 양방향 재분배가 loop·suboptimal path를 만들 수 있습니다. metric 변환, route tagging, filtering을 설계하지 않은 redistribute ...는 실습 성공처럼 보여도 운영 구성으로 사용할 수 없습니다.

7.1 DHCP

⌘Cisco IOS

show ip dhcp pool

DHCP server가 다른 subnet에 있으면 ip helper-address를 검토합니다. 클라이언트 IP·gateway·DNS를 각각 확인합니다.

7.2 NAT/PAT

⌘Cisco IOS
interface g0/0
 ip nat inside
interface g0/1
 ip nat outside

ip nat inside source static 192.168.10.10 203.0.113.10
access-list 10 permit 192.168.10.0 0.0.0.255
ip nat inside source list 10 interface g0/1 overload
⌘Cisco IOS
show ip nat translations
show ip nat statistics
clear ip nat translation *

NAT는 inside/outside 방향, 변환 대상 ACL, outside interface, return route를 함께 확인합니다. VPN traffic을 NAT하면 IPsec selector와 충돌할 수 있으므로 VPN exemption 또는 정책 순서를 별도 설계합니다.

7.3 ACL

ACL은 위에서 아래로 first match를 적용하고, 마지막에 implicit deny가 있습니다. wildcard mask와 적용 방향을 주소표에 함께 기록합니다.

⌘Cisco IOS
ip access-list extended WEB-IN
 permit tcp 198.51.100.0 0.0.0.255 host 192.168.10.10 eq 443
 deny ip any any log
interface g0/1
 ip access-group WEB-IN in
⌘Cisco IOS
show access-lists
show ip interface g0/1

permit ip any any는 앞의 차단 규칙을 무력화할 수 있습니다. 전체 허용은 격리된 진단 Lab에서만 임시 사용하고, 최종 ACL에는 필요한 source·destination·service만 남깁니다. Cisco ACL 공식 가이드는 Cisco IOS XE ACL Configuration Guide를 기준으로 합니다.

8. HSRP·FHRP

⌘Cisco IOS
interface g0/0
 ip address 192.168.10.2 255.255.255.0
 standby 10 ip 192.168.10.1
 standby 10 priority 110
 standby 10 preempt
 standby 10 track g0/1 20
⌘Cisco IOS
show standby brief
show standby

호스트 default gateway는 실제 라우터 주소가 아니라 virtual IP를 사용합니다. Cisco 문서에서 standby ip가 HSRP를 활성화하고 virtual IP가 선출에 사용됩니다. Cisco HSRP Guide

장애 Lab:

  1. R1/R2에 같은 virtual IP를 구성합니다.
  2. priority로 Active/Standby를 확인합니다.
  3. Active uplink을 shutdown합니다.
  4. tracking 감소와 재선출을 확인합니다.
  5. PC의 gateway는 바꾸지 않고 ping 지속 여부를 기록합니다.

9. GRE·IPsec VPN

9.1 GRE

⌘Cisco IOS
interface tunnel 0
 ip address 10.255.0.1 255.255.255.252
 tunnel source g0/1
 tunnel destination 203.0.113.2

GRE는 라우팅 가능한 논리 터널을 만들지만 자체적으로 confidentiality·integrity·peer authentication을 제공하지 않습니다. [공식 확인] GRE over IPsec은 GRE를 IPsec으로 보호하는 별도 구성입니다.

⌘Cisco IOS
show interfaces tunnel 0
show ip route
traceroute 10.20.0.1

9.2 IPsec 구성 흐름

일반적인 site-to-site 흐름은 다음과 같습니다.

  1. 흥미 트래픽 ACL 정의
  2. IKE/ISAKMP policy 정의
  3. PSK 또는 인증 방식 정의
  4. IPsec transform/proposal 정의
  5. crypto map에 peer·ACL·transform 연결
  6. 외부 interface에 crypto map 적용
  7. IKE/IPsec SA와 실제 통신 확인
⌘Cisco IOS
crypto isakmp policy 10
 encr aes
 authentication pre-share
 group 14
crypto isakmp key <LAB-PSK> address 203.0.113.2

access-list 110 permit ip 192.168.10.0 0.0.0.255 192.168.20.0 0.0.0.255
crypto ipsec transform-set LAB-SET esp-aes esp-sha-hmac
crypto map LAB-MAP 10 ipsec-isakmp
 set peer 203.0.113.2
 set transform-set LAB-SET
 match address 110
interface g0/1
 crypto map LAB-MAP
⌘Cisco IOS
show crypto isakmp sa
show crypto ipsec sa
show crypto session

실습 자료에 등장하는 3des, md5 등 legacy 알고리즘은 현재 권장 구성과 구분합니다. Packet Tracer 지원 여부는 버전별로 [확인 필요]입니다. Cisco IPsec 공식 문서는 Cisco Security for VPNs with IPsec를 사용합니다.

10. IPv6·NDP·SLAAC·OSPFv3

IPv6 주소는 128 bit입니다. 연속 zero group 축약, 각 group의 leading zero 제거 규칙을 연습합니다. link-local fe80::/10은 인접 통신과 routing protocol에 사용될 수 있으며 interface scope가 필요할 수 있습니다.

⌘Cisco IOS
ipv6 unicast-routing
interface g0/0
 ipv6 address 2001:db8:10::1/64
 ipv6 enable
 no shutdown
⌘Cisco IOS
show ipv6 interface brief
show ipv6 neighbors
show ipv6 route

IPv6는 ARP 대신 Neighbor Discovery를 사용합니다. RA를 통한 SLAAC, DHCPv6, 수동 주소 지정 차이를 구분합니다. 기준 문서는 RFC 8200 IPv6, RFC 4861 Neighbor Discovery, RFC 4862 SLAAC, RFC 5952 표현 규칙입니다.

OSPFv3는 구현에 따라 문법이 다릅니다.

⌘Cisco IOS
ipv6 router ospf 10
 router-id 1.1.1.1
interface g0/0
 ipv6 ospf 10 area 0

IOS XE address-family 문법 예:

⌘Cisco IOS
router ospfv3 10
 address-family ipv6 unicast
  router-id 1.1.1.1
interface g0/0
 ospfv3 10 ipv6 area 0

Cisco IOS XE 공식 문서는 OSPFv3의 IPv4/IPv6 unicast address family와 IPv6 unicast routing/interface IPv6 조건을 설명합니다. Cisco IPv6 Routing: OSPFv3
