CHAPTER 04

네트워크·Cisco Packet Tracer

기존 Cisco 실습 기록

범위: OSPF · EIGRP · Redistribution · ACL · FTP 테스트 · NAT
목적: 수업 중 실제로 입력한 명령과 출력 결과를 기준으로, 중복을 줄이고 왜 쓰는지 / 어떻게 확인하는지 / 어디서 틀리기 쉬운지까지 한 문서에 정리

# 1. 전체 실습 흐름

⌘Text
기존 EIGRP 제거
    ↓
OSPF 구성
    ↓
Area / Router ID / Neighbor / LSDB 확인
    ↓
Loopback과 Router ID 변경 실습
    ↓
EIGRP 100 + OSPF 1 동시 운용
    ↓
EIGRP ↔ OSPF Redistribution
    ↓
라우팅 테이블에서 O / O E2 확인
    ↓
Standard ACL
    ↓
Named ACL
    ↓
Extended ACL
    ↓
FTP / Web / Ping 정책 테스트
    ↓
NAT Pool + ACL을 이용한 Dynamic NAT 구성 시작

# 2. 실습 토폴로지 핵심

라우터 간 주요 네트워크:

⌘Text
R1 ---------------- R2 ---------------- R3
      1.1.1.0/24          2.2.2.0/24
        Area 0               Area 0

주요 LAN:

⌘Text
R1 쪽
192.168.200.0/28
192.168.200.16/28
192.168.200.32/28

R2 쪽
172.16.100.0/24

R3 쪽
10.10.10.0/24

R3는 2.2.2.0/24 = Area 0, 10.10.10.0/24 = Area 1에 참여했던 구성이므로 ABR(Area Border Router) 역할을 했습니다.

# 3. Cisco CLI 모드 구분

프롬프트를 보고 현재 모드를 구분해야 합니다.

⌘Cisco IOS
Router>                 User EXEC
Router#                 Privileged EXEC
Router(config)#         Global Configuration
Router(config-if)#      Interface Configuration
Router(config-router)#  Routing Protocol Configuration

do를 붙이는 경우

설정 모드 안에서 EXEC 명령을 실행할 때 사용합니다.

⌘Cisco IOS
Router(config)#do show ip route
Router(config-if)#do show access-list
Router(config-router)#do show run

반면 이미 Router#라면:

⌘Cisco IOS
Router#show ip route

처럼 입력해야 합니다.

잘못된 예:

⌘Cisco IOS
Router#do show ip route

Router#에서는 do가 필요 없으므로 오류가 납니다.

# 4. OSPF 기본 구성

OSPF 시작

⌘Cisco IOS
router ospf 1
  • 1 = OSPF Process ID
  • Process ID는 해당 라우터 내부에서 OSPF 프로세스를 구분하는 번호
  • 이웃 라우터와 Process ID가 반드시 같을 필요는 없음

Network 등록 예

⌘Cisco IOS
router ospf 1
 network 2.2.2.0 0.0.0.255 area 0
 network 10.10.10.0 0.0.0.255 area 1

뜻:

⌘Text
2.2.2.0/24에 해당하는 인터페이스 → Area 0에서 OSPF 동작
10.10.10.0/24에 해당하는 인터페이스 → Area 1에서 OSPF 동작

network 명령은 IP 주소를 새로 만드는 명령이 아니라, 어떤 인터페이스에서 OSPF를 활성화하고 그 네트워크를 광고할지 결정합니다.

# 5. Area 0 / Multi-Area / ABR

Area 0

⌘Text
Area 0 = Backbone Area

OSPF Multi-Area에서는 다른 Area들이 Backbone Area 0과 정상적으로 연결되는 구조가 기본입니다.

ABR

⌘Text
ABR = Area Border Router

두 개 이상의 Area를 연결하는 라우터입니다.

예:

⌘Text
R3
2.2.2.0/24    → Area 0
10.10.10.0/24 → Area 1

따라서 R3는 ABR입니다.

Virtual Link

Area 0과 정상적인 연속성을 확보하기 어려운 특수한 상황에서는 Virtual Link를 이용해 논리적으로 Backbone 연결을 구성할 수 있습니다.

초보 단계에서는 다음 정도로 기억하면 됩니다.

⌘Text
정상 설계 → Area 0 중심으로 구성
예외 상황 → Virtual Link 고려

Single Area 주의

Single-Area OSPF에서 Area 0을 쓰는 것이 일반적이고 권장되지만, 프로토콜상 반드시 Area 번호가 0이어야만 OSPF가 동작하는 것은 아닙니다.

# 6. Router ID

Router ID는 OSPF에서 라우터를 식별하는 값입니다.

선택 우선순위:

⌘Text
1. router-id로 직접 지정
2. Loopback 인터페이스 중 가장 높은 IP
3. 활성 일반 인터페이스 중 가장 높은 IP

처음 R3

⌘Text
Serial0/3/1        = 2.2.2.2
GigabitEthernet0/0 = 10.10.10.1

Loopback과 직접 지정된 Router ID가 없었으므로:

⌘Cisco IOS
Router ID = 10.10.10.1

Loopback 생성

⌘Cisco IOS
interface loopback 0
 ip address 5.5.5.5 255.255.255.0

OSPF 프로세스를 재시작한 뒤 Loopback이 Router ID 후보로 우선됩니다.

⌘Cisco IOS
Router ID = 5.5.5.5

직접 지정

⌘Cisco IOS
router ospf 1
 router-id 3.3.3.3

현재 실행 중인 OSPF에 적용하려면:

⌘Cisco
clear ip ospf process

최종:

⌘Cisco IOS
Router ID = 3.3.3.3

clear ip ospf process와 삭제 차이

⌘Cisco
clear ip ospf process

→ 설정 유지, OSPF 프로세스 재시작

⌘Cisco IOS
no router ospf 1

→ OSPF 1 설정 자체 삭제

# 7. OSPF Neighbor

확인:

⌘Cisco IOS
show ip ospf neighbor

예:

⌘Text
Neighbor ID     Pri  State    Address    Interface
172.16.100.1      0  FULL/-   2.2.2.1    Serial0/3/1

해석:

⌘Text
Neighbor ID = 상대 라우터의 Router ID
Address     = 실제 연결된 상대 인터페이스 IP
FULL        = 필요한 OSPF 정보 동기화 완료

중요:

⌘Text
Neighbor ID 172.16.100.1 ≠ Serial IP 2.2.2.1

Hello와 FULL의 관계

잘못 기억하기 쉬운 표현:

⌘Text
FULL이 되어야 Hello를 주고받는다.  X

정확한 흐름:

⌘Text
Hello 패킷 교환
    ↓
Neighbor 발견
    ↓
Adjacency 형성 과정
    ↓
LSDB 동기화
    ↓
FULL

즉 Hello가 먼저입니다.

대표 상태 흐름:

⌘Text
DOWN → INIT → 2-WAY → EXSTART → EXCHANGE → LOADING → FULL

로그 예:

⌘Text
%OSPF-5-ADJCHG: Process 1, Nbr 172.16.100.1 on Serial0/3/1 from LOADING to FULL, Loading Done

→ Neighbor 관계가 정상적으로 완성된 상태입니다.

# 8. Point-to-Point / Broadcast / DR·BDR

Serial

⌘Cisco IOS
Network Type = POINT-TO-POINT

두 라우터가 1:1로 연결되는 구조이므로 일반적으로 DR/BDR 선출이 필요 없습니다.

Ethernet

⌘Cisco IOS
Network Type = BROADCAST

여러 OSPF 라우터가 같은 네트워크에 있을 수 있으므로 DR/BDR 개념이 있습니다.

⌘Text
DR  = Designated Router
BDR = Backup Designated Router

Router ID와 DR은 다른 개념입니다.

⌘Cisco IOS
Router ID = 라우터 자체의 OSPF 식별자
DR        = 특정 Broadcast 네트워크에서의 대표 역할

# 9. LSDB / LSA

LSDB

⌘Text
LSDB = Link-State Database

OSPF가 알고 있는 링크 상태 정보를 저장하는 데이터베이스입니다.

확인:

⌘Cisco IOS
show ip ospf database

LSA

⌘Text
LSA = Link-State Advertisement

라우터들이 서로 전달하는 링크 상태 광고입니다.

ADV Router는 Advertising Router, 즉 해당 LSA를 광고한 라우터의 Router ID입니다.

# 11. 라우팅 테이블 코드

⌘Text
C    = Connected
L    = Local
D    = EIGRP
D EX = EIGRP External
O    = OSPF Intra-Area
O IA = OSPF Inter-Area
O E1 = OSPF External Type 1
O E2 = OSPF External Type 2

예:

⌘Text
O 172.16.100.0/24 [110/65] via 2.2.2.1

해석:

⌘Text
O          → OSPF로 학습
172.16...  → 목적지 네트워크
110        → Administrative Distance
65         → OSPF Cost
2.2.2.1    → Next Hop

OSPF 기본 AD:

⌘Text
110

Cost는 낮을수록 선호됩니다.

# 12. EIGRP 100으로 전환

OSPF를 제거한 뒤 EIGRP를 구성했던 단계:

⌘Cisco IOS
conf t
no router ospf 1
router eigrp 100
 network 2.2.2.0 0.0.0.255
 network 10.10.10.0 0.0.0.255
 no auto-summary

Loopback도 EIGRP에 포함:

⌘Cisco IOS
router eigrp 100
 network 5.5.5.0 0.0.0.255

# 13. Redistribution이 필요한 이유

서로 다른 Routing Protocol은 기본적으로 각자 배운 경로를 자동으로 공유하지 않습니다.

예:

⌘Text
EIGRP 영역 ── 경계 라우터 ── OSPF 영역

이때 경계 라우터에서 Redistribution(재분배)을 설정하여 한 프로토콜의 경로를 다른 프로토콜에 전달할 수 있습니다.

# 14. OSPF → EIGRP 재분배

⌘Cisco IOS
router eigrp 100
 redistribute ospf 1 metric 1544 2000 255 1 1500

EIGRP는 외부에서 받은 경로에 사용할 Seed Metric이 필요합니다.

순서:

⌘Text
1544 = Bandwidth (Kbit/s)
2000 = Delay (10 microsecond 단위) → 20 ms
255  = Reliability (255 = 100%)
1    = Load
1500 = MTU (bytes)

즉:

⌘Text
redistribute ospf 1
→ OSPF 1에서 학습한 경로를 EIGRP 100으로 가져온다.

주의: 해당 라우터에서 OSPF 1이 실제로 존재하고 경로를 가지고 있어야 의미가 있습니다.

# 15. EIGRP → OSPF 재분배

OSPF를 다시 구성:

⌘Cisco IOS
router ospf 1
 redistribute eigrp 100 subnets
 network 2.2.2.0 0.0.0.255 area 0

subnets:

EIGRP에서 가져온 서브넷 경로까지 OSPF로 재분배하도록 지정

기본적으로 OSPF로 재분배된 외부 경로는 O E2로 보일 수 있습니다.

예:

⌘Text
O E2 5.5.5.0/24     [110/20] via 2.2.2.2
O E2 10.10.10.0/24 [110/20] via 2.2.2.2

# 16. 경계 네트워크 중복 광고 주의

수업에서 강조한 핵심:

경계 라우터에서 같은 네트워크를 여러 Routing Protocol로 불필요하게 중복 광고하면 경로 선택이 복잡해질 수 있다.

그래서 2.2.2.0/24를 EIGRP에서 제거:

⌘Cisco IOS
router eigrp 100
 no network 2.2.2.0 0.0.0.255

최종 개념:

⌘Text
EIGRP 100
  ├─ 10.10.10.0/24
  └─ 5.5.5.0/24

OSPF 1
  └─ 2.2.2.0/24 Area 0

EIGRP ↔ OSPF는 Redistribution으로 교환

no network는 인터페이스 IP를 삭제하는 명령이 아닙니다.

⌘Text
EIGRP 참여만 제거

# 20. ACL 설계 원칙

  4. 구체적인 규칙을 위에 배치

# 23. Extended ACL 100 — ICMP 필터링

기존 Standard ACL 10 삭제:

⌘Cisco IOS

no access-list 10 permit any

Router#에서 바로 no access-list ...를 입력하면 Global Configuration 명령이므로 오류가 납니다.

ICMP 규칙

⌘Cisco IOS

access-list 100 deny icmp host 172.16.100.4 host 10.10.10.3 echo

ICMP:

⌘Text

주의: 실제 Ping 왕복에서는 Echo Reply의 출발지/목적지가 요청과 반대 방향이므로, echo-reply 규칙을 만들 때는 방향을 확인해야 합니다.

# 24. permit ip any any 아래의 규칙 문제

출력:

⌘Text

60 deny icmp host 192.168.200.35 host 10.10.10.2 echo

이 구조에서는 60번 규칙이 사실상 적용되지 않습니다.

이유:

⌘Text
패킷
 ↓

 ↓
허용 후 ACL 검사 종료
 ↓
60번까지 내려가지 않음

따라서:

⌘Cisco IOS
구체적인 deny/permit
        ↓
permit ip any any

순서가 되어야 합니다.

# 34. NAT 기본 개념

⌘Text
NAT = Network Address Translation

IP 주소를 다른 IP 주소로 변환하는 기술입니다.

이번 실습에서는 ACL로 변환 대상 내부 주소를 지정하고, NAT Pool에서 변환에 사용할 주소 범위를 정의하는 Dynamic NAT 형태를 구성하기 시작했습니다.

큰 흐름:

⌘Text
Inside Local 주소
172.16.100.x
      ↓
ACL 10으로 변환 대상 선택
      ↓
NAT Pool dnat
1.1.1.1 ~ 1.1.1.254
      ↓
Inside Global 주소로 변환

# 35. NAT Pool 생성

도움말 확인:

⌘Cisco IOS
Router(config)#ip nat pool ?
  WORD  Pool name

Pool 이름을 dnat으로 지정:

⌘Cisco
ip nat pool dnat 1.1.1.1 1.1.1.254 netmask 255.255.255.0

구조:

⌘Text
ip nat pool
  dnat             → Pool 이름
  1.1.1.1          → 시작 주소
  1.1.1.254        → 끝 주소
  netmask
  255.255.255.0    → Pool의 네트워크 마스크

처음 다음처럼 입력했을 때:

⌘Cisco
ip nat pool dnat 1.1.1.1 1.1.1.254 255.255.255.0

오류가 난 이유는 255.255.255.0 앞에 netmask 키워드가 필요했기 때문입니다.

올바른 문법:

⌘Cisco
ip nat pool dnat 1.1.1.1 1.1.1.254 netmask 255.255.255.0

# 36. NAT 변환 대상 ACL

⌘Cisco IOS
access-list 10 permit 172.16.100.0 0.0.0.255

뜻:

172.16.100.0/24를 NAT 변환 대상으로 선택한다.

여기서 ACL은 보안 차단 목적이라기보다 NAT가 어떤 내부 주소를 변환할지 Match하는 용도입니다.

⌘Text
permit = NAT 대상에 포함

# 37. ACL 10과 NAT Pool 연결

⌘Cisco
ip nat inside source list 10 pool dnat

구성 요소:

⌘Text
ip nat inside source
→ Inside에서 출발한 Source Address를 변환

list 10
→ ACL 10에 Match되는 주소를 대상으로 함

pool dnat
→ dnat Pool의 주소 중 하나로 변환

즉 한 문장으로:

172.16.100.0/24 출발지 주소를 NAT Pool dnat의 1.1.1.1~1.1.1.254 주소 중 하나로 변환한다.

# 38. NAT는 아직 인터페이스 지정이 필요함

현재 입력한 명령만으로는 NAT 설정이 완전히 끝난 것이 아닙니다.

NAT를 사용할 인터페이스에:

⌘Cisco
ip nat inside

와:

⌘Cisco
ip nat outside

를 지정해야 합니다.

일반 구조:

⌘Text
172.16.100.0/24
      │
      │ Inside
      ▼
[ Router ]
      │
      │ Outside
      ▼
외부 네트워크

예시 형태:

⌘Cisco IOS
interface <172.16.100.0/24 쪽 인터페이스>
 ip nat inside

interface <외부망 쪽 인터페이스>
 ip nat outside

정확한 인터페이스는 해당 NAT를 설정하는 라우터의 show ip interface brief를 보고 결정해야 합니다.

# 41. NAT 실습에서 주의할 점

이번 Pool:

⌘Text
1.1.1.1 ~ 1.1.1.254 /24

을 사용하기 전에 해당 주소 범위가 실제 토폴로지에서 다른 인터페이스 주소나 실제 장비 주소와 충돌하지 않는지 확인해야 합니다.

실습 토폴로지에서는 이미 1.1.1.0/24가 라우터 간 링크로 사용된 적이 있으므로, Pool 주소와 실제 인터페이스 주소가 중복되지 않는지 확인하는 것이 중요합니다.

수업에서 지정된 값이라면 강의 토폴로지 의도대로 진행하되, 실제 네트워크에서는 NAT Pool을 설계할 때 주소 충돌을 피해야 합니다.

1. NAT Inside / Outside 인터페이스 지정

NAT 설정은 Pool과 ACL만 만든다고 끝나는 것이 아닙니다.
라우터가 어느 쪽을 Inside(내부망), 어느 쪽을 Outside(외부망) 로 볼지 인터페이스에 지정해야 합니다.

이번 실습에서는:

⌘Cisco IOS
interface GigabitEthernet0/0
 ip nat inside
!
interface Serial0/3/0
 ip nat outside

로 설정했습니다.

의미:

⌘Text
GigabitEthernet0/0
→ NAT 내부망 쪽 인터페이스

Serial0/3/0
→ NAT 외부망 쪽 인터페이스

패킷 흐름을 단순화하면:

⌘Text
172.16.100.0/24
      │
      │ Inside
      ▼
GigabitEthernet0/0
      │
    [NAT]
      │
Serial0/3/0
      │ Outside
      ▼
외부 네트워크

3. Dynamic NAT이 실제로 동작한 결과

내부 PC 172.16.100.3에서 외부 쪽 주소로 Ping을 발생시킨 뒤:

⌘Cisco IOS
show ip nat translations

를 확인했습니다.

⌘Text
Pro  Inside global     Inside local       Outside local      Outside global

icmp 1.1.1.1:5         172.16.100.3:5     192.168.200.18:5   192.168.200.18:5
icmp 1.1.1.1:6         172.16.100.3:6     192.168.200.18:6   192.168.200.18:6
icmp 1.1.1.1:7         172.16.100.3:7     192.168.200.18:7   192.168.200.18:7
icmp 1.1.1.1:8         172.16.100.3:8     192.168.200.18:8   192.168.200.18:8

핵심 변환:

⌘Text
Inside local  : 172.16.100.3
Inside global : 1.1.1.1

즉 내부 PC의 실제 주소 172.16.100.3이 외부로 나갈 때 NAT Pool에서 1.1.1.1을 할당받았습니다.

⌘Text
172.16.100.3
      │
      │ NAT
      ▼
   1.1.1.1
      │
      ▼
192.168.200.18

이것이 Dynamic NAT입니다.

Dynamic NAT은 미리 특정 PC와 특정 Global IP를 고정하지 않고,
Pool에서 사용 가능한 주소를 필요할 때 할당합니다.

4. NAT 용어 4가지

show ip nat translations에서 가장 중요한 네 개의 주소 표현입니다.

Inside Local
⌘Text
172.16.100.3

내부 네트워크에서 실제로 사용하는 사설/내부 주소입니다.

내부 호스트의 원래 주소

Inside Global
⌘Text
1.1.1.1

Inside Local 주소가 외부 네트워크에 보일 때 사용하는 변환된 주소입니다.

NAT 이후 외부에서 보이는 내부 호스트 주소

Outside Global

예:

⌘Text
192.168.200.18

외부 호스트가 실제 외부 네트워크에서 사용하는 주소입니다.

Outside Local

이번 실습에서는:

⌘Text
192.168.200.18

처럼 Outside Global과 동일했습니다.

Outside Local은 내부 네트워크에서 바라보는 외부 호스트의 주소입니다.

일반적인 NAT 실습에서는 Outside Local과 Outside Global이 같은 경우가 많습니다.

5. Dynamic NAT 전체 설정 구조

이번 실습의 Dynamic NAT 설정을 하나로 보면:

⌘Cisco IOS
ip nat pool dnat 1.1.1.1 1.1.1.254 netmask 255.255.255.0

access-list 10 permit 172.16.100.0 0.0.0.255

ip nat inside source list 10 pool dnat

interface GigabitEthernet0/0
 ip nat inside

interface Serial0/3/0
 ip nat outside

각 명령의 역할:

⌘Text
ACL 10
→ 어떤 내부 주소를 NAT할 것인가?

Pool dnat
→ 어떤 Global IP 주소로 바꿀 것인가?

ip nat inside source list 10 pool dnat
→ ACL 10에 해당하는 출발지를 dnat Pool의 주소로 변환

ip nat inside
→ 내부 인터페이스 지정

ip nat outside
→ 외부 인터페이스 지정

즉 NAT 설정은 다음 네 요소가 맞아야 합니다.

⌘Text
① NAT 대상 ACL
② NAT Pool
③ ACL과 Pool 연결
④ Inside / Outside 인터페이스 지정

6. Static NAT 설정

다음으로 Static NAT을 설정했습니다.

⌘Cisco
ip nat inside source static 172.16.100.4 1.1.1.10

형식:

⌘Cisco
ip nat inside source static <Inside-Local> <Inside-Global>

이번 값:

⌘Text
Inside Local  = 172.16.100.4
Inside Global = 1.1.1.10

즉:

⌘Text
172.16.100.4  ↔  1.1.1.10

의 고정 1:1 매핑을 만든 것입니다.

Dynamic NAT과 달리 트래픽이 없더라도 이 매핑 자체는 설정에 존재합니다.

7. Static NAT 직후 Translation Table

Static NAT을 설정한 직후:

⌘Text

여기서 ---는 특정 TCP/UDP/ICMP 세션이 아니라

즉 아직 실제 통신을 하지 않았더라도:

⌘Text

ACL 핵심 원칙 요약

ACL(Access Control List, 접근제어목록)은 패킷을 조건에 따라 허용하거나 차단하는 정책입니다.

분류 기준

1. 필터링 기준
⌘Text
Standard ACL
→ 주로 출발지 IP 주소 기준

Extended ACL
→ 출발지 IP + 목적지 IP + 프로토콜 + 포트 등 세부 조건
2. 설정 방식
⌘Text
Numbered ACL
→ 번호로 관리

Named ACL
→ 이름으로 관리

ACL 검사 순서

ACL은:

⌘Text
첫 번째 규칙
   ↓
두 번째 규칙
   ↓
세 번째 규칙
   ↓
...

순서로 위에서 아래로 검사합니다.

첫 번째로 일치한 규칙에서 처리가 끝납니다.

따라서 일반적으로:

⌘Text
구체적이고 범위가 좁은 규칙
        ↓
넓고 포괄적인 규칙

순서로 배치하는 것이 좋습니다.

예:

⌘Cisco IOS
permit host 10.10.10.3 ...
deny 10.10.10.0/24 ...
permit ip any any

처럼 예외 Host를 먼저 처리합니다.

Implicit Deny

ACL 마지막에는 화면에 보이지 않는 기본 규칙이 존재합니다.

Standard ACL:

⌘Text
deny any

Extended ACL:

⌘Cisco IOS
deny ip any any

즉 아무 규칙에도 일치하지 않은 패킷은 기본적으로 차단됩니다.

그래서 특정 트래픽만 막고 나머지는 모두 허용하려면 명시적으로:

⌘Cisco
permit any

또는:

⌘Cisco IOS
permit ip any any

를 마지막에 추가해야 합니다.

# VPN 기초 정리

1. VPN이란?

VPN은:

⌘Text
Virtual Private Network
= 가상 사설망

입니다.

인터넷과 같은 공용 네트워크를 사용하면서도, 논리적으로는 사설망처럼 안전한 통신 경로를 만드는 기술입니다.

쉽게 말하면:

⌘Text
공용 인터넷
     │
     │ 암호화된 VPN Tunnel
     ▼
사설 네트워크처럼 통신

하는 방식입니다.

VPN에서는 일반적으로 통신 내용을 암호화하고, VPN 양 끝단 또는 사용자 인증을 통해 허가된 장비/사용자만 연결하도록 구성합니다.

2. VPN의 대표적인 두 가지 형태

수업에서 우선 구분할 것은:

⌘Text
① Site-to-Site VPN
② Remote Access VPN

입니다.

3. Site-to-Site VPN

Site-to-Site VPN은:

서로 떨어져 있는 두 개 이상의 네트워크를 VPN Tunnel로 연결하는 방식

입니다.

예:

⌘Text
서울 본사 LAN
192.168.10.0/24
      │
 [VPN 장비]
      │
====== 인터넷 ======
      │
 [VPN 장비]
      │
부산 지사 LAN
192.168.20.0/24

두 지점의 VPN 장비가 Tunnel을 만들기 때문에, 내부 PC들은 VPN을 직접 실행하지 않아도 서로 통신할 수 있습니다.

예를 들어:

⌘Text
서울 PC
192.168.10.10
       ↓
   VPN Tunnel
       ↓
부산 Server
192.168.20.20

처럼 LAN-to-LAN 통신이 가능합니다.

pfSense 공식 문서에서도 Site-to-Site IPsec VPN은 두 네트워크를 라우터로 직접 연결한 것과 비슷하게 상호 연결하는 형태로 설명합니다.

주로 사용하는 상황

⌘Text
본사 ↔ 지사
회사 ↔ 데이터센터
사무실 A ↔ 사무실 B

처럼 네트워크 전체를 서로 연결할 때 사용합니다.

4. Remote Access VPN

Remote Access VPN은:

외부의 개별 사용자나 장비가 회사 내부 네트워크에 원격으로 접속하는 방식

입니다.

예:

⌘Text
회사 내부망
192.168.10.0/24
      │
 [VPN Server]
      │
==== 인터넷 ====
      │
      │ VPN Client
      ▼
재택근무 노트북

사용자는 노트북이나 스마트폰에서 VPN Client를 실행하고, 인증을 거쳐 회사 내부망에 접속합니다.

pfSense에서는 OpenVPN, IPsec, WireGuard 등의 방식으로 Remote Access VPN 구성이 가능합니다.

5. Site-to-Site와 Remote Access 비교

구분 Site-to-Site Remote Access
연결 대상 네트워크 ↔ 네트워크 사용자/장비 ↔ 네트워크
대표 상황 본사 ↔ 지사 재택근무자 ↔ 회사

⌘Text

1. 패킷이 움직이는 전체 그림

1.1 캡슐화

애플리케이션 데이터는 전송계층에서 TCP segment 또는 UDP datagram이 되고, 네트워크계층에서 IP packet, 데이터링크계층에서 Ethernet frame이 됩니다. 라우터는 L2 header를 벗기고 목적지 IP를 기준으로 다음 홉을 선택한 뒤 새 L2 header를 붙입니다.

계층 핵심 식별자 장비·프로토콜 예 확인 질문
Application 이름·요청 DNS, HTTP, SSH 어떤 서비스인가?
Transport port, TCP/UDP 22, 53, 80, 443 어느 프로세스인가?
Network source/destination IP IPv4, IPv6, ICMP 어느 네트워크인가?
Data Link MAC, VLAN Ethernet, 802.1Q 같은 broadcast domain인가?
Physical signal, cable copper, fiber, serial 링크가 올라왔나?

1.2 같은 서브넷과 다른 서브넷

같은 서브넷이면 호스트는 목적지 IP를 ARP 또는 IPv6 Neighbor Discovery로 MAC에 매핑해 직접 전송합니다. 다른 서브넷이면 기본 게이트웨이의 MAC으로 frame을 보내고, 라우터가 목적지 네트워크를 라우팅합니다.

⌘Text
PC-A -> (같은 subnet) -> PC-B
PC-A -> default gateway -> Router -> next hop -> 목적지 subnet

장애 발생 시 “ping이 안 된다”만 보지 않습니다. IP 주소 → mask → ARP/MAC → gateway → routing table → ACL/NAT/VPN 순서로 범위를 좁힙니다.

2. IPv4·서브네팅·CIDR

2.1 prefix 계산

/n은 앞에서부터 n개의 network bit가 1인 mask입니다. IPv4는 32 bit입니다.

Prefix Mask 전체 주소 일반적인 사용 가능 호스트
/24 255.255.255.0 256 254
/25 255.255.255.128 128 126
/26 255.255.255.192 64 62
/27 255.255.255.224 32 30
/30 255.255.255.252 4 2
/31 255.255.255.254 2 point-to-point 특례 확인
/32 255.255.255.255 1 단일 주소·host route

일반적인 LAN 계산식은 2^(32-prefix) - 2입니다. /31, /32, 장비별 point-to-point 처리는 예외이므로 장비 문서와 실습 결과를 확인합니다.

2.2 block size와 AND

예: 192.168.16.0/25의 마지막 octet block size는 256 - 128 = 128입니다. 네트워크는 0, 128에서 시작합니다.

  • 192.168.16.100/25 → 192.168.16.0/25
  • 192.168.16.200/25 → 192.168.16.128/25
  • 두 주소는 같은 192.168.16.0/24 안에 있지만 /25 기준 다른 subnet입니다.

계산 절차:

  1. prefix를 mask로 바꿉니다.
  2. IP와 mask를 bitwise AND 합니다.
  3. host bit를 모두 0으로 만든 값이 network address입니다.
  4. host bit를 모두 1로 만든 값이 broadcast address입니다.
  5. 두 호스트의 network address가 같을 때만 직접 통신으로 판단합니다.

CIDR과 prefix aggregation의 표준 기준은 RFC 4632입니다. 사설 주소 대역은 RFC 1918을 기준으로 기록합니다.

2.3 VLSM 설계

부서별 요구 호스트 수를 큰 순서로 정렬합니다. 각 요구량에 맞는 최소 prefix를 배정한 뒤 다음 미사용 block으로 이동합니다. 주소표에는 반드시 network / first usable / last usable / broadcast / gateway / VLAN을 함께 기록합니다.

3. Cisco IOS CLI와 Packet Tracer

3.1 모드 전환과 저장

⌘Cisco IOS
Router> enable
Router# configure terminal
Router(config)# hostname R1
R1(config)# end
R1# copy running-config startup-config

핵심 상태 확인:

⌘Cisco IOS
show running-config
show startup-config
show ip interface brief
show interfaces description
show cdp neighbors detail
show version

running-config는 RAM, startup-config는 재부팅 후 읽는 설정입니다. 실습 종료 전 저장 여부를 확인합니다.

3.2 인터페이스 기본 구성

⌘Cisco IOS
interface gigabitEthernet0/0
 description LAN-A
 ip address 192.168.10.1 255.255.255.0
 no shutdown
exit

administratively down은 shutdown 상태입니다. down/down은 케이블·상대편·물리 링크를 먼저 확인합니다. up/down은 encapsulation, clocking, keepalive, 상대편 설정을 확인합니다.

Serial DCE/DTE 실습에서는 DCE 쪽에 clock rate가 필요할 수 있습니다.

⌘Cisco IOS
show controllers serial 0/0/0
interface serial0/0/0
 clock rate 64000

장비 모델과 Packet Tracer 버전에 따라 인터페이스 이름·지원 명령이 다릅니다. 명령이 없으면 무리하게 대체하지 말고 모델을 기록합니다.

4. Switching: VLAN·Trunk·STP·SVI

4.1 Access와 Trunk

⌘Cisco IOS
vlan 10
 name USERS
interface fastEthernet0/1
 switchport mode access
 switchport access vlan 10
 spanning-tree portfast
exit

interface gigabitEthernet0/1
 switchport mode trunk
 switchport trunk allowed vlan 10,20,30

검증:

⌘Cisco IOS
show vlan brief
show interfaces trunk
show spanning-tree
show mac address-table dynamic

Access port는 한 VLAN에 속하고, trunk는 여러 VLAN tag를 전달합니다. Native VLAN·allowed VLAN·양쪽 trunk 설정 불일치는 통신 실패 원인이 됩니다.

4.2 Inter-VLAN routing

Router-on-a-Stick:

⌘Cisco IOS
interface gigabitEthernet0/0.10
 encapsulation dot1Q 10
 ip address 192.168.10.1 255.255.255.0
interface gigabitEthernet0/0.20
 encapsulation dot1Q 20
 ip address 192.168.20.1 255.255.255.0

L3 switch:

⌘Cisco IOS
ip routing
interface gigabitEthernet1/0/1
 no switchport
 ip address 10.0.0.1 255.255.255.252
 no shutdown
interface vlan 10
 ip address 192.168.10.1 255.255.255.0
 no shutdown

SVI는 VLAN의 L3 인터페이스입니다. VLAN이 존재하지 않거나 access/trunk 경로가 없으면 SVI가 살아 있어도 호스트 통신은 되지 않습니다.

5. Routing: 정적·동적·RIP

5.1 라우팅 테이블 읽기

⌘Cisco IOS
show ip route
show ip route 192.168.30.0
show ip protocols

라우터는 목적지 prefix가 가장 긴 경로를 우선 선택합니다. 같은 prefix 후보가 여러 개면 administrative distance로 출처 신뢰도를 비교하고, 같은 프로토콜 안에서는 metric으로 최적 경로를 비교합니다.

정적·기본 경로:

⌘Text
ip route 192.168.30.0 255.255.255.0 10.0.0.2
ip route 0.0.0.0 0.0.0.0 10.0.0.2

5.2 RIP v1/v2

RIP는 distance-vector 방식이며 hop count를 metric으로 사용합니다. RIPv2의 표준 정의는 RFC 2453입니다.

⌘Cisco IOS
router rip
 version 2
 no auto-summary
 network 10.0.0.0
 network 192.168.10.0

확인:

⌘Cisco IOS
show ip protocols
show ip route rip
debug ip rip

수업 노트의 send version 1 같은 문법은 인터페이스별 송신 버전 설정과 관련됩니다. 전체 라우터 모드의 version과 구분하고, show ip protocols 결과로 실제 동작을 확인합니다.

6. EIGRP·OSPF·Redistribution

6.1 EIGRP AS 100

⌘Cisco IOS
router eigrp 100
 network 10.0.0.0 0.0.0.3
 network 192.168.10.0 0.0.0.255
 no auto-summary
⌘Cisco IOS
show ip eigrp neighbors
show ip eigrp topology
show ip route eigrp

Wildcard mask는 subnet mask의 역입니다. network 범위를 너무 넓게 잡으면 의도하지 않은 인터페이스에서 adjacency가 형성될 수 있습니다.

6.2 OSPF Area 0

⌘Cisco IOS
router ospf 1
 router-id 1.1.1.1
 network 10.0.0.0 0.0.0.3 area 0
 network 192.168.10.0 0.0.0.255 area 0
⌘Cisco IOS
show ip ospf neighbor
show ip ospf interface brief
show ip ospf database
show ip route ospf

OSPF는 link-state 방식입니다. 인접 관계 → LSDB → SPF 계산 순서로 이해합니다. Broadcast network에서는 DR/BDR 선출이 발생합니다. router-id 변경 후에는 프로세스 재시작이 필요할 수 있으므로 실습 전후 상태를 기록합니다.

6.3 Redistribution 주의

EIGRP와 OSPF를 재분배할 때는 양방향 재분배가 loop·suboptimal path를 만들 수 있습니다. metric 변환, route tagging, filtering을 설계하지 않은 redistribute ...는 실습 성공처럼 보여도 운영 구성으로 사용할 수 없습니다.

7. DHCP·NAT·PAT·ACL

7.1 DHCP

⌘Cisco IOS
ip dhcp excluded-address 192.168.10.1 192.168.10.20
ip dhcp pool USERS
 network 192.168.10.0 255.255.255.0
 default-router 192.168.10.1
 dns-server 8.8.8.8
⌘Cisco IOS
show ip dhcp binding
show ip dhcp pool

DHCP server가 다른 subnet에 있으면 ip helper-address를 검토합니다. 클라이언트 IP·gateway·DNS를 각각 확인합니다.

7.2 NAT/PAT

⌘Cisco IOS
interface g0/0
 ip nat inside
interface g0/1
 ip nat outside

ip nat inside source static 192.168.10.10 203.0.113.10
access-list 10 permit 192.168.10.0 0.0.0.255
ip nat inside source list 10 interface g0/1 overload
⌘Cisco IOS
show ip nat translations
show ip nat statistics
clear ip nat translation *

NAT는 inside/outside 방향, 변환 대상 ACL, outside interface, return route를 함께 확인합니다. VPN traffic을 NAT하면 IPsec selector와 충돌할 수 있으므로 VPN exemption 또는 정책 순서를 별도 설계합니다.

7.3 ACL

ACL은 위에서 아래로 first match를 적용하고, 마지막에 implicit deny가 있습니다. wildcard mask와 적용 방향을 주소표에 함께 기록합니다.

⌘Cisco IOS
ip access-list extended WEB-IN
 permit tcp 198.51.100.0 0.0.0.255 host 192.168.10.10 eq 443
 deny ip any any log
interface g0/1
 ip access-group WEB-IN in
⌘Cisco IOS
show access-lists
show ip interface g0/1

permit ip any any는 앞의 차단 규칙을 무력화할 수 있습니다. 전체 허용은 격리된 진단 Lab에서만 임시 사용하고, 최종 ACL에는 필요한 source·destination·service만 남깁니다. Cisco ACL 공식 가이드는 Cisco IOS XE ACL Configuration Guide를 기준으로 합니다.

8. HSRP·FHRP

⌘Cisco IOS
interface g0/0
 ip address 192.168.10.2 255.255.255.0
 standby 10 ip 192.168.10.1
 standby 10 priority 110
 standby 10 preempt
 standby 10 track g0/1 20
⌘Cisco IOS
show standby brief
show standby

호스트 default gateway는 실제 라우터 주소가 아니라 virtual IP를 사용합니다. Cisco 문서에서 standby ip가 HSRP를 활성화하고 virtual IP가 선출에 사용됩니다. Cisco HSRP Guide

장애 Lab:

  1. R1/R2에 같은 virtual IP를 구성합니다.
  2. priority로 Active/Standby를 확인합니다.
  3. Active uplink을 shutdown합니다.
  4. tracking 감소와 재선출을 확인합니다.
  5. PC의 gateway는 바꾸지 않고 ping 지속 여부를 기록합니다.

9. GRE·IPsec VPN

9.1 GRE

⌘Cisco IOS
interface tunnel 0
 ip address 10.255.0.1 255.255.255.252
 tunnel source g0/1
 tunnel destination 203.0.113.2

GRE는 라우팅 가능한 논리 터널을 만들지만 자체적으로 confidentiality·integrity·peer authentication을 제공하지 않습니다. [공식 확인] GRE over IPsec은 GRE를 IPsec으로 보호하는 별도 구성입니다.

⌘Cisco IOS
show interfaces tunnel 0
show ip route
traceroute 10.20.0.1

9.2 IPsec 구성 흐름

일반적인 site-to-site 흐름은 다음과 같습니다.

  1. 흥미 트래픽 ACL 정의
  2. IKE/ISAKMP policy 정의
  3. PSK 또는 인증 방식 정의
  4. IPsec transform/proposal 정의
  5. crypto map에 peer·ACL·transform 연결
  6. 외부 interface에 crypto map 적용
  7. IKE/IPsec SA와 실제 통신 확인
⌘Cisco IOS
crypto isakmp policy 10
 encr aes
 authentication pre-share
 group 14
crypto isakmp key <LAB-PSK> address 203.0.113.2

access-list 110 permit ip 192.168.10.0 0.0.0.255 192.168.20.0 0.0.0.255
crypto ipsec transform-set LAB-SET esp-aes esp-sha-hmac
crypto map LAB-MAP 10 ipsec-isakmp
 set peer 203.0.113.2
 set transform-set LAB-SET
 match address 110
interface g0/1
 crypto map LAB-MAP
⌘Cisco IOS
show crypto isakmp sa
show crypto ipsec sa
show crypto session

실습 자료에 등장하는 3des, md5 등 legacy 알고리즘은 현재 권장 구성과 구분합니다. Packet Tracer 지원 여부는 버전별로 [확인 필요]입니다. Cisco IPsec 공식 문서는 Cisco Security for VPNs with IPsec를 사용합니다.

10. IPv6·NDP·SLAAC·OSPFv3

IPv6 주소는 128 bit입니다. 연속 zero group 축약, 각 group의 leading zero 제거 규칙을 연습합니다. link-local fe80::/10은 인접 통신과 routing protocol에 사용될 수 있으며 interface scope가 필요할 수 있습니다.

⌘Cisco IOS
ipv6 unicast-routing
interface g0/0
 ipv6 address 2001:db8:10::1/64
 ipv6 enable
 no shutdown
⌘Cisco IOS
show ipv6 interface brief
show ipv6 neighbors
show ipv6 route

IPv6는 ARP 대신 Neighbor Discovery를 사용합니다. RA를 통한 SLAAC, DHCPv6, 수동 주소 지정 차이를 구분합니다. 기준 문서는 RFC 8200 IPv6, RFC 4861 Neighbor Discovery, RFC 4862 SLAAC, RFC 5952 표현 규칙입니다.

OSPFv3는 구현에 따라 문법이 다릅니다.

⌘Cisco IOS
ipv6 router ospf 10
 router-id 1.1.1.1
interface g0/0
 ipv6 ospf 10 area 0

IOS XE address-family 문법 예:

⌘Cisco IOS
router ospfv3 10
 address-family ipv6 unicast
  router-id 1.1.1.1
interface g0/0
 ospfv3 10 ipv6 area 0

Cisco IOS XE 공식 문서는 OSPFv3의 IPv4/IPv6 unicast address family와 IPv6 unicast routing/interface IPv6 조건을 설명합니다. Cisco IPv6 Routing: OSPFv3
