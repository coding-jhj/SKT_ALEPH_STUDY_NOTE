4-2. subprocess 모듈

subprocess 모듈을 사용하면 파이썬에서 리눅스 명령어를 그대로 실행할 수 있다.

# 내부 라이브러리 임포트
import subprocess
# ping 명령어 실행 (-c 1: 1회 전송, -W 1: 1초 타임아웃)
result = subprocess.run(
    ['ping', '-c', '1', '-W', '1', server],
    stdout=subprocess.DEVNULL,
    stderr=subprocess.DEVNULL
)
# 반환값 0: 성공, 0 이외: 실패

stdout=subprocess.DEVNULL 은 리눅스의 > /dev/null 과 동일하게 출력 결과를 화면에 표시 하지 않는 역할을 한다.

            # 경고: CPU 인계치 초과
        if mem.percent > 80:
            # 경고: 메모리 공간 부족

6. 로그 백업 및 정리 스크립트

6-1. 스크립트 실행

실행 결과: 로그 파일을 tar.gz으로 압축 백업하고, 30일이 경과한 백업 파일은 자동 삭제한다.

6-2. 코드 주요 내용
# 내부 라이브러리 임포트
import os
import tarfile
import time
from datetime import datetime
# 변수 설정
target_dir = './.workspace/log'       # 백업할 로그 디렉토리
backup_dir = './backup_store'          # 백업 저장 디렉토리
retention_days = 30                    # 보관 기간 (일)
# 오늘 날짜로 백업 파일명 생성 (%Y: 연도, %m: 월, %d: 일)
today = datetime.now().strftime('%Y%m%d')
backup_file = f'backup_{today}.tar.gz'
# tar.gz으로 압축 백업
with tarfile.open(backup_path, 'w:gz') as tar:
    tar.add(target_dir)
# 30일 경과 파일 삭제
# retention_days * 86400 (1일 = 86400초) 기준

실제 운용 서버에서는 로그 파일이 지속적으로 생성되어 디스크 용량을 차지한다. 법적으로 로그 보관 의무가 있는 기업은 보관 기간을 별도로 설정하여 운용해야 한다.

8. 사용자 계정 필터링 및 CSV 생성 스크립트

8-1. 스크립트 실행
sudo python3 user_report.py

실행 결과: /etc/passwd 파일에서 로그인 가능한 계정을 필터링하여 login_users_report.csv 파일로 저장한다.

8-2. 코드 주요 내용
# 내부 라이브러리 임포트
import csv
input_file = '/etc/passwd'
out_file = './login_users_report.csv'
login_users = []  # 로그인 가능한 계정 저장 리스트
with open(input_file, 'r') as f:
    for line in f:
        # 빈 줄 또는 주석 건너뜀
        if line.startswith('#') or not line.strip():
            continue
        # 콜론(:)을 기준으로 필드 분리 (awk -F ':' 와 동일)
        parts = line.strip().split(':')
        # 리스트 인덱스: 0=사용자명, 2=uid, 5=홈디렉토리, 6=로그
인셸
        username = parts[0]
        uid = parts[2]        # 세 번째 필드 → 리스트 인덱스 2
        home_dir = parts[5]
        login_shell = parts[6]
        # /bin/bash 또는 /bin/sh 셸을 가진 계정만 필터링
        if '/bash' in login_shell or '/sh' in login_shell:
            login_users.append([username, uid, home_dir, lo
gin_shell])
# csv 모듈의 writer 함수로 CSV 파일 저장
with open(out_file, 'w') as f:
    writer = csv.writer(f)
    writer.writerows(login_users)

split(':') 함수는 셸 스크립트의 awk -F ':' 와 동일하게 콜론을 기준으로 문자열을 분 리한다. 파이썬 리스트는 0부터 인덱스가 시작하므로 세 번째 필드(uid)는 인덱스 2가 된다.

3. Tkinter GUI 프로그래밍 기초

3-1. Tkinter 개요

Tkinter는 파이썬에서 GUI(그래픽 사용자 인터페이스) 프로그램을 만들기 위한 라이브러리 다. 파이썬 설치 시 기본으로 포함되어 있는 내부 모듈이므로 별도 설치가 필요 없다.

# Tkinter 임포트
from tkinter import *
3-2. 기본 창(프레임) 생성
from tkinter import *
# 창(프레임) 생성 - Tk 클래스 사용
root = Tk()
# 창 제목 설정
root.title('테스트 프로그램')
# 창 크기 설정 (가로 x 세로, 단위: 픽셀)
root.geometry('640x480')
# 창이 닫히기 전까지 계속 표시 (메인 루프)
root.mainloop()

root : 생성된 창이 저장된 변수

geometry('640x480') : 가로 640, 세로 480 픽셀로 창 크기 지정

mainloop() : 창이 계속 화면에 표시되도록 반복하는 함수

3-3. 위젯 — 버튼(Button)
# 버튼 생성

    fg='...'        # 전경색 (foreground, 글자색)
)
# 버튼을 화면에 배치 (pack 필수)

3-4. 위젯 — 레이블(Label)

구성 요소 설명
창 제목 상단에 프로그램 이름 표시

4-2. 메뉴 바 구성
import os
from tkinter import *
root = Tk()
root.title('윈도우즈 메모장')
root.geometry('640x480')
# 전체 메뉴 바 생성
menu = Menu(root)
# 파일 메뉴 항목 생성 (tearoff=0: 메뉴 분리 비활성화)

menu_file.add_separator()                               #
구분선 추가
menu_file.add_command(label='끝내기', command=root.quit)

# 메뉴 바 적용
root.config(menu=menu)

메뉴 구성 방식:

함수 역할
Menu(root) 전체 메뉴 바 생성
Menu(menu, tearoff=0) 특정 메뉴 항목 생성
add command(label='이름', command=함수)
_		 클릭 시 실행할 명령어가 있는 항목 추가
add separator()
_		 메뉴 항목 사이에 구분선 추가
add cascade(label='이름', menu=메뉴변수)
_		 상위 메뉴에 하위 메뉴 연결
root.config(menu=menu) 창에 메뉴 바 적용

command=root.quit 은 Tkinter에서 기본으로 제공하는 창 종료 함수이므로 별도 정의가 필요 없다.

⚠️ command 에 지정한 함수가 코드에 정의되어 있지 않으면 실행 시 오류가 발생한다. 인 터프리트 언어이므로 함수는 사용하기 전에 먼저 정의해야 한다.

2. 파이썬 가상 환경 (Virtual Environment)

2-1. 가상 환경이 필요한 이유

가상 환경이란 독립된 파이썬 실행 환경으로, 해당 환경 내에서만 작업이 이루어지고 외부 환경에는 영향을 주지 않는다.

가상 환경이 필요한 이유는 다음과 같다.

문제 상황 설명
버전 호환성 Ubuntu 24.04에는 파이썬 3.12가 기본 설치되
어 있으나, 프로젝트에 따라 다른 버전이 필요할
수 있다
두 개 이상의 프로젝트 운용 프로젝트별로 서로 다른 파이썬 버전이나 라이브
러리가 필요한 경우 충돌이 발생할 수 있다
운영체제 영향 방지 가상 환경 없이 패키지를 설치·삭제하면 실제 우분
투 운영체제에 영향을 줄 수 있다

가상 환경을 사용하면 각 환경이 독립적으로 동작하므로, 다른 환경에 영향을 미치지 않는다.

2-2. 가상 환경 디렉토리 구조

가상 환경 생성 후 디렉토리 구조는 다음과 같다.

~/
└── python_practice/        # 실습 디렉토리
    └── venv/               # 가상 환경 디렉토리
        ├── bin/            # 실행 파일 (python3, python3.12, pip, pip3, pip3.12)
        └── lib/            # 라이브러리 저장소

bin/ 디렉토리: 파이썬 실행 명령어 위치

lib/ 디렉토리: 설치된 라이브러리 파일 저장

3. 가상 환경 설정 실습

3-1. 실습 디렉토리 생성
# 실습용 디렉토리 생성
mkdir python_practice
# 디렉토리 목록 확인
ls
# 실습 디렉토리로 이동
cd python_practice
# 숨김 파일 포함 목록 확인 (아무것도 없는 상태)
ls -a
3-2. 가상 환경 생성
# 가상 환경 생성 시도 (venv 모듈이 없을 경우 오류 발생)
python3 -m venv venv

⚠️ venv 모듈이 설치되어 있지 않으면 오류 메시지가 나타난다. 이 경우 먼저 venv 도구를 설치해야 한다.

# venv 도구 설치
sudo apt install python3-venv
# 설치 후 가상 환경 재생성
python3 -m venv venv
# 생성 확인
ls
ls venv/

명령어에서 -m venv 의 의미:

v : virtual (가상)

env / venv : environment (환경)

3-3. 가상 환경 활성화
# 가상 환경 활성화 (source 명령어 사용)
source venv/bin/activate

활성화 후에는 프롬프트 앞에 (venv) 와 같이 가상 환경 이름이 표시된다.

가상 환경이 생성되었다고 해서 자동으로 활성화되는 것은 아니다. 반드시 source 명령어로 활성화해야 한다.

3-4. pip 설치 및 가상 환경 연결 확인
# pip 위치 확인
which pip
which pip 결과 의미
/usr/bin/pip 가상 환경이 제대로 연결되지 않은 상태
~/python practice/venv/bin/pip
_		 가상 환경에서 정상 실행 중인 상태 
# pip 설치 (가상 환경 연결이 안 된 경우)
sudo apt install -y pip
# 설치 후 다시 확인 (sudo 없이)
which pip

⚠️ which pip 실행 결과가 가상 환경 경로( ~/python_practice/venv/bin/pip )가 아니라 시스템 기본 경로( /usr/bin/pip )로 나온다면, 가상 환경이 제대로 동작하지 않는 것이다. 이 경우 venv 디렉토리 내 파일을 삭제하고 다시 생성하는 것이 좋다.

가상 환경의 bin/ 디렉토리에서 확인 가능한 실행 파일:

파일명 설명
python3 파이썬 3 실행 파일
python3.12 파이썬 3.12 실행 파일
pip pip 패키지 관리자
pip3 pip3 패키지 관리자
pip3.12 pip3.12 패키지 관리자
3-5. 가상 환경 비활성화 및 재진입
# 가상 환경 비활성화
deactivate

비활성화 후에는 프롬프트가 일반 우분투 셸로 돌아온다.

# 가상 환경 재진입
source venv/bin/activate

재진입 후에는 반드시 which pip 로 가상 환경 경로에서 실행되고 있는지 확인해야 한다.

개념 정의 도서관 비유

124. 파이썬 설치 가이드

파이썬 버전

버전 Version

소프트웨어가 개발 되는 과정에서 발생한 변경 사항과 발전 과정의 산출물(output)을 체계 적으로 표현하는 중요한 수단.

숫자로 표기되며, 각 숫자 별로 다음과 같은 의미를 가지고 있음.

주 버전.마이너 버전.패치 버전 (Major.Minor.Patch)

3.12.4

주 버전 (Major): 큰 기능 추가나 프로그램의 큰 흐름 변경이 있을 때.

마이너 버전 (Minor): 새로운 기능이 추가되지만 기존 기능과 호환될 때.

패치 버전 (Patch): 버그 수정 등 사소한 개선이 있을 때.

파이썬 설치

1. 내 컴퓨터 사양 확인

[설정] → [시스템] → [정보]장치 사양 탭에서 시스템 종류 확인

시스템 종류에 따른 설치 버전 확인

64비트 운영 체제, x64 기반 프로세서 : Windows installer (64-bit)

32비트 운영 체제, x32 기반 프로세서 : Windows installer (32-bit)

2. 내 컴퓨터 계정명 확인

만약 내 컴퓨터의 계정 이름이 한글로 되어 있다면, 영어로 변경하는 것을 권장

3. 파이썬 설치 파일 다운로드

  3. 1번에서 확인한 운영체제 버전에 맞는 설치 파일 다운로드

  4. 관리자 권한으로 실행 하여 설치
