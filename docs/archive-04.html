# 1. Windows 핵심 프로세스와 서비스

1.1 프로세스 계층

⌘Text
SYSTEM
  ↓
SMSS.EXE (Master)
  ├─ Session 0
  │   ├─ CSRSS.EXE
  │   └─ WININIT.EXE
  │       ├─ SERVICES.EXE → SVCHOST.EXE
  │       ├─ LSASS.EXE
  │       └─ LSAISO.EXE
  └─ Session 1
      ├─ WINLOGON.EXE → USERINIT.EXE → EXPLORER.EXE
      └─ CSRSS.EXE

이 구조를 배우는 이유는 이름 암기가 아니라 정상적인 부모-자식 관계, 실행 경로, 계정, 실행 시점을 이해하기 위해서입니다.

1.2 SMSS.EXE

SMSS는 Session Manager Subsystem, 즉 세션 관리자입니다.

  • 이미지 경로: %SYSTEMROOT%\System32\smss.exe
  • 부모: System
  • Master Instance 1개와 Session별 Instance
  • Local System 계정
  • Master는 Boot 후 초기에 실행

Session 0은 Service 환경, Session 1은 User Interface 환경과 연결됩니다. User 전환이나 Remote Desktop을 사용하면 추가 Session이 생길 수 있습니다.

1.3 Windows 로그인

  1. WINLOGON이 로그인 화면 표시
  2. User가 ID/PASSWORD 입력
  3. WINLOGON → LSASS로 Credential 전달
  4. LSASS가 인증 검증
  5. Domain 환경이면 Kerberos로 DC와 통신
  6. VBS 활성화 시 LSAISO가 Credential 보호와 관련
  7. 인증 성공 후 Security Token 생성
  8. USERINIT이 User Profile Load
  9. USERINIT이 EXPLORER 실행
⌘Text
User → WINLOGON → LSASS → Security Token → USERINIT → EXPLORER
                    ├─ Local: SAM
                    └─ Domain: Kerberos → DC

로그인은 Password 확인만이 아니라 인증된 사용자의 권한 정보를 담은 Token을 만들고 User 환경을 시작하는 과정입니다.

1.4 SERVICES.EXE / SVCHOST.EXE

SERVICES.EXE는 Service Control Manager 역할을 하며 WININIT.EXE에 의해 실행됩니다.

SVCHOST.EXE는 여러 Service DLL을 Hosting하는 Process입니다. PDF는 -k Parameter로 DcomLaunch, RPCSS, netsvcs 같은 Service Group을 지정할 수 있다고 설명합니다.

SVCHOST가 여러 개 존재할 수 있으므로 개수만으로 악성을 판단하지 말고 Path, Parent, Service, Account를 같이 확인합니다.

SPOOLSV.EXE는 Print 작업, TASKHOST/TASKHOSTW는 예약 작업 실행·관리와 관련됩니다.

1.5 EXPLORER.EXE

WINLOGON → USERINIT → EXPLORER 흐름으로 User Interface가 시작됩니다.

Explorer는 File Explorer, Taskbar, Start Menu, Desktop을 제공합니다.

  • 이미지 경로: %SYSTEMROOT%\explorer.exe
  • 부모: userinit.exe
  • 계정: 로그인한 User
  • 시작: 로그인 직후

PDF는 User 권한 악성 Program 실행, 자동 시작, Memory 삽입 등의 위협 가능성을 언급합니다.

보안에서는 Process Tree와 속성을 함께 확인합니다.

2.3 TCPView

실행 중인 TCP/UDP Connection과 관련 Process를 GUI로 보여줍니다.

확인: Protocol, Local/Remote Address, Port, State, Process.

PDF는 비정상 Connection, Backdoor, C2 Channel 식별 등의 활용을 제시합니다.

2.4 tasklist

⌘Powershell
tasklist
tasklist /v
tasklist /fi "imagename eq svchost.exe"
tasklist /svc
  • /v: 상세 정보
  • /fi: Filter
  • /svc: Service-Process Mapping
  • /s: Remote System

PDF 실습은 /svc 결과에서 Service가 N/A인 경우가 있는지도 질문합니다. 결과를 외우기보다 왜 그런지 추가 조사하는 습관이 핵심입니다.

2.5 PowerShell

⌘SQL

PID, PPID, Name, ExecutablePath를 확인합니다.

질문:

  • Parent-Child 관계가 일반적인가?
  • 실행 Path가 일반적인가?

2.6 netstat

⌘Powershell
netstat -anbo

Network Port, State, Owner Process, Remote Connection을 확인합니다.

  • LISTENING: 연결 요청 대기
  • ESTABLISHED: TCP Connection 성립

PDF는 불필요한 Port나 허용되지 않은 Remote Connection을 확인하라고 제시합니다.

2.7 Services

확인 항목:

  • Service Name / Description
  • Status
  • Startup Type
  • Log On Account
  • Dependencies
  • Executable Path

보안에서는 자동 실행 여부, 담당 Process, 실행 Account, Path가 일반적인지를 봅니다.

# 3. Registry · UAC · Privilege · Integrity Level

3.1 Registry

주요 도구:

Tool File 특징

Registry Editor regedit.exe GUI REG reg.exe CLI PowerShell powershell.exe Cmdlet

PDF는 Derived Key를 Master Key의 Shortcut/View/Mapping 개념으로 설명합니다. HKCU는 HKEY_USERS 아래 원본과, HKCR은 HKLM\SOFTWARE\Classes와 연결되는 식입니다.

REG.EXE

⌘SQL
reg query   조회
reg add     추가/수정
reg delete  삭제
reg copy    복사
reg export  내보내기
reg import  가져오기
reg save    Hive 저장
reg load    Hive Load

3.2 UAC

User Account Control은 관리자 수준 작업에 명시적 승인을 요구합니다.

PDF 핵심:

  • Windows Vista부터 도입
  • Administrators Group 계정도 Program이 기본적으로 항상 최고 권한으로 실행되지 않도록 제한
  • Principle of Least Privilege 기반
  • 악성코드의 무분별한 관리자 권한 사용 방지가 목적

3.3 Privilege

Process가 System에 수행할 수 있는 특정 작업입니다.

예: Backup, Shutdown, 다른 Process Memory 접근.

많은 이름이 Se로 시작합니다.

⌘Powershell
whoami /priv

PDF는 Windows 10 이상에서 약 40\~45개 정도의 Privilege가 존재한다고 설명합니다.

3.4 Integrity Level

PDF의 5단계:

SYSTEM → HIGH → MEDIUM → LOW → UNTRUSTED

  • SYSTEM: Kernel/Core Service
  • HIGH: 일반적으로 관리자 Process
  • MEDIUM: 일반 User Process 기본
  • LOW: Sandbox 등 제한 환경
  • UNTRUSTED: 가장 낮은 수준

기본 원칙은 자신보다 높은 Integrity Level의 Object를 수정할 수 없고 같거나 낮은 수준만 수정할 수 있다는 것입니다.

Privilege와 Integrity Level

  • Privilege = 어떤 특별 작업을 수행할 수 있는가?
  • Integrity Level = Process/Object의 신뢰 등급은 어느 정도인가?

PDF의 svchost 실습은 Process Explorer Properties에서 실제 Privilege와 Integrity Level을 확인하는 흐름으로 이어집니다.

Cron은 반복적이고 자동화된 작업을 실행하는 Scheduling Service입니다.

활용: Maintenance, Backup, Log 정리, Monitoring.

5.1 Crontab 위치

⌘Text
사용자별: /var/spool/cron/crontabs

Cron Job: /etc/cron.d

5.2 구조

⌘Text
분 시간 일 월 요일 명령어

예:

⌘Shell

5.4 보안 문제

PDF는 다음을 제시합니다.

  • Root 권한 Cron Job의 과도한 권한
  • 외부 File Download/Execute 등 악성 Command
  • Crontab File 권한 오류로 인한 변조

# 6. OSI 7계층과 TCP/IP

6.1 OSI 7 Layer

Layer 핵심 역할

7 Application User와 직접 상호작용, Network Service 6 Presentation Format 변환, 암/복호화, 압축 5 Session Session 생성·유지·종료 4 Transport 신뢰성, Error Recovery, Port 3 Network Routing, IP, Packet 전달 2 Data Link Frame, MAC, Error 감지 1 Physical 전기적/물리적 Signal

OSI는 개념적 Reference Model입니다. PDF는 실제 Internet은 TCP/IP Protocol Suite 기반으로 동작한다고 설명합니다.

6.2 TCP/IP 4계층

TCP/IP 역할 대표

Application User Service HTTP, HTTPS, FTP, SMTP, DNS, SSH Transport 신뢰성/속도 TCP, UDP Internet 주소와 경로 IP, ICMP, ARP Network Interface 물리 Network Ethernet, Wi-Fi, PPP

TCP/IP는 단일 Protocol이 아니라 여러 Protocol이 함께 동작하는 Protocol Suite입니다.

# 7. 전통적인 Network Security Solution

PDF의 대표 Solution:

  • Firewall
  • WAF
  • IDS/IPS

7.1 Firewall

Internal/External Network 사이에서 Traffic을 Filter합니다. 설정된 Security Policy에 따라 허용/차단합니다.

PDF는 전통적 Firewall이 주로 IP Address와 Port를 기준으로 동작하며 TCP/IP의 Internet/Transport 영역과 연결해 설명합니다.

7.2 WAF

Web Application 앞에서 HTTP/HTTPS Traffic을 분석합니다.

Application Layer의 SQL Injection 같은 Web Attack을 탐지·차단하는 데 초점을 둡니다.

7.3 IDS / IPS

Network 침입과 비정상 Pattern/행위를 탐지합니다. IPS는 자동 차단까지 수행할 수 있습니다.

PDF의 핵심은 각 Solution이 볼 수 있는 공격 범위가 다르므로 하나만으로 모든 위협에 대응할 수 없다는 것입니다.

예시 표:

공격 유형 Firewall WAF IDS/IPS

Port Scanning 탐지 가능 불가 가능 SQL Injection 불가 가능 가능 DDoS 가능 불가 가능 Webshell Upload 불가 가능 가능 내부 이상 Traffic 불가 불가 가능

이 표는 PDF가 제시한 교육용 비교입니다. 핵심 학습 포인트는 계층별 방어를 조합한다는 것입니다.

# 8. 암호학 기초

8.1 기본 용어

  • Plaintext: 암호화 전 Message
  • Ciphertext: 암호화 후 Message
  • Encryption/Decryption Algorithm: 변환 규칙
  • Key: Algorithm에 전달되는 비밀 값/Parameter
⌘Text
Plaintext + Algorithm + Key → Ciphertext

8.2 Symmetric vs Asymmetric

Symmetric Cryptography

Encryption Key와 Decryption Key가 동일합니다.

PDF 예: - Block Cipher: DES, 3DES, IDEA, Blowfish, Twofish, AES - Stream Cipher: RC4, ChaCha20, FISH, SEAL - Authenticated Encryption: AES-GCM, ChaCha20-Poly1305, AES-CCM

PDF는 빠른 처리 속도가 장점이지만 동일 Key를 안전하게 공유해야 하는 문제가 있다고 설명합니다.

Asymmetric Cryptography

Encryption/Decryption에 서로 다른 Key를 사용하며 Public Key와 Private Key Pair를 이용합니다.

PDF의 분류 예: - Factorization: RSA 등 - Discrete Logarithm: ElGamal, Diffie-Hellman, DSA - Elliptic Curve: ECDH, ECDSA - Lattice: NTRU, LWE, Ring-LWE, CRYSTALS-Kyber

PDF는 Key 배포 문제 해결과 안전한 Key Exchange, Digital Signature 활용을 강조합니다.

8.3 둘을 함께 쓰는 이유

PDF는 현대 Security System에서 비대칭 방식으로 안전한 Key 공유를 한 뒤, 동기화된 Key를 이용해 대칭 암호로 실제 통신하는 흐름을 설명합니다.

⌘Text
Asymmetric / Key Exchange
        ↓
Session Key 합의
        ↓
Symmetric Encryption으로 실제 Data 통신

# 9. SSH

9.1 SSH Version

PDF는 SSH-1과 SSH-2를 비교하며 SSH-2 사용을 권장합니다.

항목 SSH-1 SSH-2

Key Exchange RSA Public Key 기반 DH, ECDH, Curve25519 등 Integrity CRC-32 HMAC Encryption DES, 3DES, RC4 등 AES, ChaCha20-Poly1305 등 기능 Port Forwarding, SCP 안정성 향상, SFTP 추가

9.2 Server-Client 연결 4단계

TCP Handshake가 끝난 뒤 PDF는 SSH 연결을 네 단계로 설명합니다.

1. Version Exchange

Client와 Server가 SSH Version 정보 교환.

2. Key Exchange Initialization

양쪽이 지원하는 Encryption, Hash, Compression 등의 Algorithm 목록을 교환하고 사용할 Algorithm을 협상.

3. Key Exchange

SSH-2에서 기본적으로 Diffie-Hellman 계열 Key Exchange를 이용해 암호화 통신에 사용할 대칭 Key를 동기화하는 단계로 설명됩니다.

4. Service Request & Authentication

Client 인증. Password, Public Key, Keyboard-interactive 등을 지원.

9.3 Cyber Security 관점

Defender / Administrator

  • 안전한 Remote Server 관리
  • 중요 Infra 통신의 Confidentiality
  • Public Key Authentication
  • MFA
  • SFTP/SCP를 통한 암호화 File Transfer

Attacker

PDF는 Credential을 획득한 공격자가 SSH를 다음에 악용할 수 있다고 설명합니다.

  • 지속적인 Remote Access
  • Network Access Control 우회/측면 이동
  • 암호화 Channel을 통한 Data Exfiltration

따라서 암호화된 Traffic이라는 사실만으로 그 Traffic의 목적까지 안전하다고 판단할 수는 없습니다.
