3. SELinux 파일 권한 — chcon 명령어

3-1. chcon 개요

일반적인 파일 권한( chmod )과 별도로, SELinux(보안 모듈)는 파일에 대한 추가적인 보안 컨 텍스트를 관리한다. 웹 서비스가 특정 파일에 쓰기 작업을 수행하려면 SELinux 컨텍스트 권 한도 적절하게 설정되어야 한다. chcon -t httpd_sys_script_rw_t config.php ← 웹 서비스에 c onfig.php 읽기·쓰기 권한 부여 옵션 의미 -t SELinux 타입 지정 httpd_sys_script_rw_t 웹 서비스(httpd)가 읽기·쓰기 가능한 타입 chmod 로 파일 권한을 변경해도 SELinux 컨텍스트가 맞지 않으면 웹 서비스에서 파일에 쓸 수 없다. 이 경우 chcon 명령으로 SELinux 컨텍스트를 추가로 설정해야 한다.

064. LogAnalyzer, wget 명령어, 압축 파일 형식, 쉘 스크립트 개념

파일 형식, 쉘 스크립트 개념

1. LogAnalyzer 개요

1-1. LogAnalyzer란

LogAnalyzer는 PHP 기반의 웹 애플리케이션으로, MariaDB에 저장된 rsyslog 로그 데이 터를 웹 인터페이스에서 시각화하여 보여준다.

1-2. 필요 구성 요소
  • LogAnalyzer가 정상적으로 동작하려면 다음 요소가 갖춰져 있어야 한다.
  • 요소
  • 설명
  • APM (Apache, PHP, MariaDB)
  • 웹 서버 기반 환경
  • PHP-MySQL 연결 패키지
  • PHP와 데이터베이스를 연결하기 위한 패키지
  • httpd (Apache) 서비스
  • 웹 서비스가 실행 중이어야 웹 페이지 접근 가능

2. wget 명령어 — 셸에서 파일 다운로드

2-1. wget 개요

wget 은 웹 브라우저 없이 셸(CLI)에서 파일을 다운로드할 수 있는 명령어다. GUI 환경이 없 는 서버에서 파일을 내려받을 때 사용한다. dnf install -y wget ← wget이 없을 경우 설치 wget [다운로드 URL] ← 현재 작업 디렉토리에 다운로드 wget -P /tmp [다운로드 URL] ← 다운로드 경로를 /tmp로 지정 -P 옵션을 사용하면 다운로드 경로를 직접 지정할 수 있다. 지정하지 않으면 현재 작업 디렉토리에 저장된다.

3. 압축 파일 형식 — tar와 gz

3-1. tar 파일

tar 는 여러 개의 파일이나 디렉토리를 하나의 파일로 묶는 것이다. 압축은 아니며, 묶기만 한다.

3-2. gz (gzip) 파일

.gz 확장자는 gzip 형식으로 압축된 파일을 의미한다.

3-3. tar.gz 파일
  • 확장자
  • 의미
  • .tar
  • 여러 파일/디렉토리가 하나로 묶여 있음
  • .gz
  • gzip으로 압축되어 있음
  • .tar.gz
  • 묶기(tar) + 압축(gz)이 동시에 적용된 아카이브

4. 셸 스크립트(Shell Script)

4-1. 셸 스크립트 개요

.sh 확장자로 끝나는 파일은 셸 스크립트 파일이다. SQL 스크립트와 마찬가지로, 스크립트 란 파일 안에 있는 명령어들을 위에서부터 한 줄씩 순서대로 일괄 처리하는 것을 의미한다.

4-2. 쉬뱅(Shebang)

셸 스크립트 파일의 맨 첫 줄에는 #!/bin/sh 또는 #!/bin/bash 와 같이 사용할 셸을 정의하는 구문이 온다. 이를 쉬뱅(shebang) 또는 c 방(#!) 이라고 한다.

!/bin/sh ← 사용할 셸 정의 (shebang)

067. rsyslog를 활용한 로그 전송

1. 중앙 집중형 로그 서버의 필요성

1-1. 로컬 로그 관리의 한계

로그는 해킹 분석 및 시스템 분석 시 가장 필요한 데이터다. 그러나 각 시스템에서만 로그가 저장된다면 다음과 같은 문제가 발생한다. cat , last 등의 명령어를 통해 그때그때마다 개별 시스템에서 직접 확인해야 하므로 관리가 어렵다. 로그가 분산되어 있어 통합 분석이 불가능하다.

1-2. 중앙 집중형 로그 서버의 구조
  • 이러한 문제를 해결하기 위해 로그 서버를 별도로 구축하여 클라이언트에서 발생하는 로그
  • 를 실시간으로 수집한다. 구성 흐름은 다음과 같다.
  • 단계
  • 구성 요소
  • 역할
  • 1단계
  • 클라이언트 (rsyslog)
  • 이벤트 발생 → 로그를 서버로 전송
  • 2단계
  • 로그 서버 (rsyslog)
  • 클라이언트 로그를 수신하여 DB에 저장
  • 3단계
  • 데이터베이스 (MariaDB)
  • 로그를 구조화하여 저장
  • 4단계

  • DB의 로그를 시각화하여 제공
1-3. 로그 서버 활용의 장점

DB에 저장되므로 SQL 질의나 웹 인터페이스를 통해 언제든지 로그를 조회·검색할 수 있다. 또한 로그를 시각화하여 관리자가 더 효율적으로 로그를 분석할 수 있다. 향후 SIEM(보안 정보 및 이벤트 관리) 솔루션으로 발전 가능하다. ⚠️ 1단계(클라이언트 → 서버) 연결이 확인되지 않으면 이후 DB 저장, 웹 시각화 작업이 모두 의미 없다. 단계별 확인이 필수다.

1-4. 백업 로그 서버

로그는 중요하기 때문에 주 로그 서버 외에 백업 로그 서버를 추가로 구성하여 이중화하는 것이 일반적이다.

068. Syslog Facility Priority의 개념, 로그 레벨 이해

Syslog Facility/Priority의 개념, 로그 레벨 이해

1. Syslog 개요

1-1. Syslog의 구성 요소

Syslog는 로그 메시지를 분류하고 관리하기 위해 두 가지 주요 요소로 구성된다: Facility: 로그가 발생한 출처나 카테고리 Priority: 로그의 우선순위 또는 심각도

2. Facility (시설/카테고리)

2-1. Facility의 정의

Facility는 로그가 어디서 발생했는지를 나타내는 분류 항목이다. 로그 메시지의 출처를 식 별하는 데 사용된다.

2-2. 주요 Facility 종류
  • Facility
  • 설명
  • AUTH
  • 인증과 관련된 로그 (사용자 로그인, 비밀번호 관련)
  • LPR
  • 프린터 서비스와 관련된 로그
  • Syslog 대몬 자체에서 발생하는 로그
  • Local 0-7
  • 사용자 정의 목적으로 사용 가능한 로그 카테고리
2-3. Facility의 역할

어떤 로그가 AUTH로 지정되어 있으면 인증 관련 로그임을 알 수 있다. 마찬가지로 LPR이 면 프린트 관련 기록임을 식별할 수 있다. 따라서 로그를 빠르게 분류하고 원하는 항목을 찾 는 데 도움이 된다.

3. Priority (우선순위/심각도)

Syslog Facility/Priority의 개념, 로그 레벨 이해

3-1. Priority의 개념

Priority는 로그의 우선순위 또는 심각도(Severity Level)를 나타낸다. 발생한 문제가 시스 템에 미치는 영향의 정도를 표현한다.

3-2. Priority 레벨 (0-7)
  • 레벨
  • 이름
  • 설명
  • 영향도
  • Emergency (이머젠시)
  • 시스템 사용 불가능한 긴급 상황
  • 매우 높음
  • Alert
  • 즉시 조치가 필요한 상황
  • 매우 높음
  • Critical
  • 심각한 상황
  • 높음
  • Error
  • 오류 발생
  • 중간
  • Warning
  • 경고 상황
  • 중간
  • Notice
  • 일반적인 알림
  • 낮음
  • Informational
  • 정보성 메시지
  • 낮음
  • Debug
  • 디버깅 정보
  • 최하위
3-3. 심각도의 의미

어떤 일이 발생했을 때, 그 문제가 시스템에 얼마만큼 영향을 미칠 것인가를 나타내는 것이 심각도이다. Emergency 레벨이 발생하면 시스템에 아주 긴급한 문제가 있다는 의미이고, 적극적인 조치를 하지 않으면 시스템이 정상적으로 동작하지 않는다.

3-4. Warning 레벨의 일반적 사용

대부분의 서비스가 구동될 때, 로그 관련 심각도는 기본적으로 Warning 레벨로 정해져 있 다. 이는 일반적인 운영 환경에서의 표준 레벨이다.

3-5. Debug 레벨의 특징

Debug 레벨은 가장 낮은 우선순위를 가지므로, 개발 또는 문제 해결 시 상세한 정보를 확인 할 때 사용된다.

4. Facility와 Priority의 조합

4-1. 로그의 완전한 분류

로그 메시지는 Facility와 Priority의 조합으로 완전하게 분류된다: Facility는 로그의 출처(어디서)를 나타낸다 Priority는 로그의 중요도(얼마나 심각한지)를 나타낸다 Syslog Facility/Priority의 개념, 로그 레벨 이해

4-2. 로그 처리의 실제 적용

로그 관리 정책에서: 특정 Facility의 특정 Priority 이상만 기록하도록 설정할 수 있다 Emergency 레벨의 로그는 즉시 관리자에게 알림을 보낼 수 있다 낮은 Priority의 로그는 보존 기간을 짧게 설정할 수 있다

5. Syslog 설정 원리

5-1. 로그 분류의 중요성

비트 수가 클수록 해독이 어렵다. 최신 리눅스 버전은 대부분 $6$ (SHA-512)를 사용하며, 구버전(CentOS 7 이전 등)일수록 낮은 알고리즘이 사용될 수 있다.

4-2. 솔트(Salt)의 역할

솔트는 동일한 패스워드라도 암호화된 결과값이 달라지도록 랜덤하게 추가되는 값이다. 솔트 없이 동일한 알고리즘으로 동일한 문자열을 해시하면 결과값이 항상 동일하다. 공격자가 알고리즘을 알고 있으면, 미리 계산한 해시값 목록(레인보우 테이블)으로 패스 워드를 역추적할 수 있다. 솔트를 적용하면, 동일한 패스워드라도 계정마다 솔트 값이 달라 해시 결과가 다르게 나 와 역추적이 어렵다. ⚠️ 솔트(Salt) 개념은 정보보안기사 시험에서 출제되는 항목이다.

6-1. 기본 생성 권한

6-2. umask 값 변경과 보안

7. 파일 권한 변경 (chmod)

파일이나 디렉토리의 권한은 chmod 명령어로 변경할 수 있다. chmod 777 test.txt ← test.txt에 rwxrwxrwx 권한 부여

8. 소유주 및 그룹 변경 (chown, chgrp)

파일의 소유주와 그룹도 루트 계정에서 변경할 수 있다. chown root ttt.txt ← ttt.txt의 소유주를 root로 변경 chgrp root ttt.txt ← ttt.txt의 그룹을 root로 변경 chown : change owner (소유주 변경) chgrp : change group (그룹 변경)

9. 계정 관리와 스크립트 활용

계정 현황 점검을 위해 /etc/passwd 나 /etc/shadow 파일을 매번 수동으로 확인하는 것은 비 효율적이다. 실무에서는 관리에 필요한 명령어들을 스크립트로 작성하여 실행함으로써 결과 를 자동으로 확인하는 방식을 사용한다.

5. echo 명령어

077. 파일 조작·검색·출력 명령어, 표준 입출력과 리디렉션

출력과 리디렉션

1. rm 명령어 (파일·디렉토리 삭제)

rmdir 은 빈 디렉토리만 삭제할 수 있다. 내부에 파일이 존재하는 디렉토리를 삭제하려면 rm 명령어를 사용한다. rm -rf 디렉토리명 ← 내용물이 있는 디렉토리 강제 삭제 rm -ri 디렉토리명 ← 삭제 여부를 대화형으로 묻고 삭제 옵션 설명 -r 디렉토리와 하위 내용 모두 삭제 -f 삭제 여부를 묻지 않고 강제 삭제 -i 대화형(interactive)으로 삭제 여부를 묻고 진행 옵션은 명령어 뒤에 위치해야 하며, 명령어 앞에는 둘 수 없다.

2. mv 명령어 (이동 및 이름 변경)

mv 는 파일 또는 디렉토리를 이동하거나 이름을 변경할 때 사용한다. 이동 시 원본 위치에서 는 삭제된다. mv 원본파일 대상경로/파일명 ← 이동 (이름을 동일하게 유지) mv 원본파일 새이름 ← 이름 변경 mv 원본파일 대상경로/새이름 ← 이동과 이름 변경 동시 수행

3. file 명령어 (파일 유형 확인)

file 명령어는 파일의 종류(텍스트 파일, 바이너리, 디렉토리 등)를 출력한다. 악성코드 분 석 등에서도 활용된다.

file /etc/passwd ← 단일 파일 유형 확인 file /etc/passwd /etc/shadow ← 여러 파일 유형 동시 확인

4. tac 명령어 (역순 출력)

tac 은 cat 의 역방향 동작으로, 파일 내용을 마지막 줄부터 역순으로 출력한다. cat /var/log/messages ← 파일 내용을 정순 출력 tac /var/log/messages ← 파일 내용을 역순 출력 (최신 로그가 먼저 표시) 로그 파일처럼 양이 많고 최신 내용을 먼저 확인하고 싶을 때 유용하다.

5. sort 명령어 (정렬)

sort 는 파일 내용을 정렬하여 출력한다. 기본값은 알파벳·숫자 오름차순이다. sort /etc/passwd ← 알파벳 오름차순 정렬 sort -r /etc/passwd ← 역순 정렬 다양한 정렬 기준(알파벳, 숫자, 역순, 특정 열 기준 등)을 옵션으로 지정할 수 있다.

6. nmcli 명령어 (네트워크 설정 CLI)

nmcli 는 네트워크 설정을 명령행(CLI) 방식으로 수행하는 도구이다. nmtui (텍스트 UI 방 식)와 같은 역할을 수행한다. nmcli connection up 인터페이스명 ← 특정 인터페이스 활성화 ⚠️ nmtui 와 nmcli 두 도구를 동시에 사용하여 주소를 설정하면, 동일 주소가 중복 등록 되거나 통신 오류가 발생할 수 있다. 반드시 하나의 도구로만 설정한다.

8. whereis 명령어 (명령어 위치 검색)

whereis 는 명령어의 실행 파일, 소스, 매뉴얼 페이지 경로를 출력한다. whereis ls ← ls 명령어의 위치 확인 whereis -b ls ← 이진파일(실행파일) 경로만 확인 ls 명령어를 내리면, whereis 로 확인한 경로의 실행 파일이 실행되어 결과가 출력된다.

9. grep 명령어 (문자열 검색)

grep 은 파일 내에서 특정 문자열을 검색한다. 일부 문자열만 입력해도 관련 내용이 모두 출 력된다. 로그 파일처럼 내용이 방대한 경우 특히 유용하다. grep "root" /etc/passwd ← /etc/passwd에서 "root" 포함 행 출력 grep -i "root" /etc/passwd ← 대소문자 구분 없이 검색 grep -w "root" /etc/passwd ← 정확히 "root"라는 단어만 검색 옵션 설명 -i 대소문자 무시(case-insensitive) -w 정확한 단어(word) 단위 검색

3. sudo 명령어

우분투 서버에서는 root 계정으로 직접 로그인하는 대신, 일반 사용자 계정에서 sudo 명령 을 앞에 붙여 관리자 권한으로 명령을 실행한다. sudo 명령어 ← 해당 명령을 관리자(root) 권한으로 실행 sudo 없이 관리자 권한이 필요한 명령을 실행하면 Permission denied 오류가 발생한다. 이 경우 명령 앞에 sudo 를 추가하면 된다.

sudo 는 관리자 권한이 필요한 작업에만 사용하고, 일반 작업은 일반 사용자 권한으로 수 행하는 것이 보안상 안전하다.

4. ping 유틸리티 설치

우분투 서버 최소 설치 환경에서는 ping 명령이 기본으로 설치되어 있지 않을 수 있다. 이 경우 iputils-ping 패키지를 설치해야 한다. sudo apt install iputils-ping ← ping 명령 사용을 위한 패키지 설치

5. 파일 권한과 sudo의 관계

리눅스에서 파일 권한은 ls -l 명령으로 확인할 수 있다. 파일 소유자가 root이고 일반 사용 자에게 쓰기 권한이 없는 경우, 해당 파일을 편집하려면 sudo 가 필요하다. ls -l 파일경로 ← 파일 권한 확인 (rw- 등으로 표시) 권한이 root에게만 부여된 파일(예: 네트워크 설정 파일)은 반드시 sudo 로 편집해야 한다.

8. AWK

8-1. 개념

AWK는 텍스트 기반의 표·데이터를 공백(또는 지정 구분자)을 기준으로 필드(열)로 분리하여 분석하고 추출하는 프로그래밍 언어이다. 이름 유래: Aho(에이호), Weinberger(웬버거), Kernighan(커링한) — 세 개발자의 이 름 첫 글자.

8-2. 기본 문법

awk '{ 행동 }' 파일명 awk '조건 { 행동 }' 파일명

8-3. 필드 참조

공백을 구분자로 사용하는 경우: awk '{ print $1, $3 }' user.txt

$1: 첫 번째 필드, $3: 세 번째 필드

다른 구분자(예: : )를 사용하는 경우: awk -F: '{ print $1 }' /etc/passwd

-F: 구분자 지정 (콜론을 구분자로 사용)

8-4. 조건을 포함한 예제

user.txt에서 세 번째 필드(나이)가 30 이상인 행의 1·3번째 필드만

출력 awk '$3 >= 30 { print $1, $3 }' user.txt

8-5. 특정 문자열이 포함된 행 추출

ip address | awk '/inet / { print $2 }'

'inet '이 포함된 행에서 두 번째 필드(IP 주소) 출력

(원본 유지) sed 's/disabled/enable/g' server.conf

원본 파일 자체를 수정하려면 -i 옵션 추가

sed -i 's/disabled/enable/g' server.conf ⚠️ -i 옵션 없이 실행하면 변경된 내용이 화면에만 출력되고 원본 파일은 수정되지 않는 다.

9-4. 특정 줄 삭제

sed '2d' server.conf ← 두 번째 줄을 삭제하여 출력 (원본 유 지)
