1. 서브네팅 (Subnetting) 개요

상세 실습은 추후 별도 진행 예정 서브넷 마스크 값을 조정하여 네트워크 부분을 나누는 작업 서브넷 마스크 값에 따라 네트워크 범위가 달라짐 효율적인 IP 주소 할당, 보안 구역 분리 등의 장점이 생김 CMD에서 ipconfig 로 확인 가능한 Subnet Mask 값과 연관

4. IPX/SPX 프로토콜

TCP/IP와 유사하게 주소 + 전송을 담당하는 프로토콜 조합 IPX: 주소 담당 (IP와 동일한 역할) SPX: 전송 담당 (TCP와 동일한 역할) IPX = InterPacket eXchange (패킷 교환 프로토콜) 과거 게임방 내부 네트워크(예: 스타크래프트 IPX 연결) 등에 활용 현재는 TCP/IP의 빠른 발전으로 사용 범위가 점차 축소되는 추세

6. 캡슐화와 역캡슐화

6-1. 캡슐화 (Encapsulation) — 송신 측

데이터가 상위 계층 → 하위 계층으로 이동할 때, 각 계층마다 헤더(Header) 정보가 추 가됨 원본 데이터보다 실제 전송되는 데이터의 크기가 더 커짐 비유: 알약 캡슐 — 약효 분말(원본 데이터)을 캡슐(헤더)로 감싸는 과정, 또는 포장이사 시 그릇을 신문지·뽁뽁이로 겹겹이 싸는 것

6-2. 역캡슐화 (Decapsulation) — 수신 측

수신 측에서는 하위 계층 → 상위 계층으로 이동하며, 각 계층의 헤더를 하나씩 제거 최종적으로 원본 데이터를 복원 비유: 이사한 집에서 신문지·뽁뽁이를 벗겨내고 원래 그릇을 꺼내는 것

  • └─ 파일 압축/암호화 (6계층: 프레젠테이션)

  • └─ 내부 전송 (2계층: 데이터링크)
  • └─ UTP 케이블 → ISP(KT, LG U+ 등) 전송 (1계층: 물리)
  • [수신 측] 다음 메일 사용자

2. VTP (VLAN Trunking Protocol) 개요

2-1. 등장 배경

스위치가 여러 대(예: 10대)인 환경에서 VLAN이 변경될 때마다 모든 스위치에 일일이 접속해서 동기화해야 하는 문제 부서 신설·폐지·통폐합 등 VLAN 구성은 수시로 변경됨 → VLAN 정보를 자동으로 동기화해주는 프로토콜이 필요 → VTP

2-2. VTP 동작 조건
  • 조건
  • 설명
  • VTP 도메인 이름 동일
  • 같은 도메인 이름을 가진 스위치끼리만 정보를 동기화
  • VTP 패스워드 동일
  • 패스워드가 일치할 때만 동기화 허용
  • 스위치 간 연결 포트가
  • Trunk
  • VLAN 정보가 트렁크 포트를 통해 전달됨

4. Revision Number (리비전 넘버)

VTP 동기화에 사용되는 버전 번호 VLAN 관련 명령어를 내릴 때마다 1씩 증가 클라이언트는 서버의 Revision Number가 자신보다 높으면 → 최신 정보를 요청하여 동기화 장비 전원을 껐다 켜면 Revision Number가 초기화됨 예시: A 스위치(서버): vlan 100 → Revision 1 name test → Revision 2 B 스위치(클라이언트): Revision 0 → 서버의 2를 받아 동기화 → Revision 2

4. 서브네팅 공식

  • 서브넷 마스크의 0 비트를 1 비트로 변경하여 네트워크를 분할하는 작업
  • 공식 1 — 생성되는 네트워크(집)의 수
  • 네트워크 수 = 2ⁿ (n = 변경된 비트 1의 개수)
  • 공식 2 — 각 네트워크에서 할당 가능한 IP 수
  • 할당 가능한 IP 수 = 2ⁿ - 2 (n = 남아 있는 비트 0의 개수)
  • (- 2 = 네트워크 주소 + 브로드캐스트 주소 제외)
  • 서브네팅 예제 — /24를 /26으로 분할

  • 문제 상황 예시 (학내망)

  • 같은 네트워크에 있으면 학생이 선생님 PC에 접근하기 쉬움 → 보안 취약
  • 물리적 분리 vs VLAN
  • 방법

  • 단점

  • 추가 인터페이스·회선 비용 발생

  • 다른 VLAN끼리 통신하려면 반드시 L3 장비(라우터) 를 거쳐야 함 → 보안성 향상

  • 1 ÷ 2 = 0 나머지 1
  • → 역순으로 읽기: 1110

각 자릿수의 값: 128 | 64 | 32 | 16 | 8 | 4 | 2 | 1 설정 저장/CLI 팁/VLAN/서브넷

  • 1000 0000 → 128
  • 1111 1111 → 255 (모든 비트가 1)

012. 트렁킹 서브인터페이스 다른 VLAN 간 통신

트렁킹/서브인터페이스/다른 VLAN 간 통신

1. 트렁킹 (Trunking) 개념

트렁킹: VLAN 정보가 포함된 데이터들이 다닐 수 있는 전용 통로를 만드는 것 스위치↔스위치, 스위치↔라우터 구간에 설정 트렁킹이 없으면 VLAN 정보가 전달되지 않아 다른 스위치의 동일 VLAN끼리도 통신 불가 VLAN 태깅 (802.1q) 트렁크 구간에서 데이터에 VLAN 번호를 식별하는 태그를 붙여 전송 받는 쪽에서 태그를 확인하여 어느 VLAN에서 온 데이터인지 구분 캡슐화 방식: IEEE 802.1q (dot1q) 비유: 옷에 붙은 태그처럼, 각 VLAN 데이터에 식별 정보를 마킹 네이티브 VLAN (Native VLAN) 태그가 없는 데이터가 속하는 VLAN 기본값: VLAN 1 A 스위치와 B 스위치의 네이티브 VLAN은 반드시 일치해야 함 (불일치 시 통신 오류) 기본값 1로 맞춰져 있으므로 별도 설정하지 않아도 됨

2. 트렁킹 확인 명령어

  • Switch# show interfaces trunk
  • 트렁크로 동작 중인 포트 목록 확인
  • 캡슐화 방식(802.1q), 상태(trunking) 확인
  • 트렁킹/서브인터페이스/다른 VLAN 간 통신

트렁크 설정한 포트가 show vlan 에서 빠져 있어야 정상 링크가 죽어 있으면(빨간 불) 트렁크 포트로 인식 안 됨

5-1. 재분배의 정의와 목적

5-2. 경계 라우터(Border Router, BR) 역할

정의: 두 개 이상의 AS 도메인에 동시에 속한 라우터 라우터 C 또는 라우터 E 중 하나를 BR로 선택 → 해당 BR에서만 재분배 설정

BR의 조건: 두 개 이상의 AS Number로 설정된 라우팅 프로토콜 구성 다른 AS 도메인의 경로 정보를 받아들일 준비

5-3. 라우터 C에서의 재분배 설정

라우터 C를 BR로 선택한 경우: 라우터 C 설정: ┌─────────────────────────────────────────┐ │ router eigrp 10 │ │ network 20.20.20.0 0.0.0.255 │ │ network 192.168.200.0 0.0.0.255 │ │ redistribute eigrp 20 │ ← AS 20 경로 재분배 │ no auto-summary │ │ │ │ router eigrp 20 │ │ network 40.40.40.0 0.0.0.255 │ │ redistribute eigrp 10 │ ← AS 10 경로 재분배 │ network 192.168.250.0 0.0.0.255 │ │ no auto-summary │ └─────────────────────────────────────────┘ 경계 대역 광고 (AS 10, AS 20 양쪽에서 공용): 라우터 C의 AS 10 설정에 추가: network 40.40.40.0 0.0.0.255 라우터 C의 AS 20 설정에 추가: network 20.20.20.0 0.0.0.255 경계 대역은 양쪽 AS에서 모두 광고하여 양방향 통신 확보

015. EIGRP 설정과 기본 구조

1. EIGRP의 개념 및 역할

1-1. EIGRP 프로토콜 개요

Enhanced Interior Gateway Routing Protocol EIGRP는 IGRP의 개선된 버전으로, RIP의 단순한 홉 카운트 기반 메트릭을 극복하고 대역 폭, 지연, 신뢰성 등 다중 요소를 고려하여 더 정확한 경로 선택이 가능한 다이나믹 라우팅 프 로토콜이다. 대규모 네트워크 환경에서 효율적으로 동작한다.

2. EIGRP 설정 필수 요소

2-1. AS(Autonomous System) Number의 정의
  • EIGRP 설정의 핵심은 AS Number라는 식별자이다:
  • router eigrp
  • AS Number의 특성:
  • 특성
  • 설명
  • 범위
  • 1~65,535
  • 역할
  • 같은 AS Number를 가진 라우터들만 라우팅 정보 교환
  • 중요성
  • 모든 EIGRP 라우터는 동일한 AS Number 사용 필수
  • 네트워크 정의
  • 하나의 라우팅 도메인을 정의
  • AS Number의 의미:
  • 하나의 네트워크 도메인 정의
  • 같은 AS Number가 아니면 이웃 라우터 관계(Neighbor Relationship) 형성 불가
  • 내부 테스트 네트워크에서는 임의로 설정 가능

⚠️ 이웃 라우터 관계 형성의 필수 조건: 동일한 AS Number

  • 라우팅이 설정된 경우:
  • 서로 다른 네트워크 간의 데이터 이동 가능
  • 인터넷을 통한 원격 접속 실현

2. 스태틱 라우팅(Static Routing)

2-1. 스태틱 라우팅의 기본

정의: 관리자가 직접 라우팅 경로를 설정하는 방식이다.

2-2. 라우팅 경로 설정 명령어

configure terminal ← 설정 모드 진입 ip route [목적지네트워크] [서브넷마스크] [경유지] ← 경로 설정 exit ← 설정 모드 종료 설정 예시: ip route 192.168.100.0 255.255.255.0 10.10.10.10 ← 192.168.100.0/24 네트워크로는 10.10.10.10으로 보낸다

2-3. 라우팅 설정의 핵심 개념
  • 목적지 네트워크 지정
  • 항목
  • 설명
  • 네트워크 주소 사용
  • 개별 호스트가 아닌 전체 네트워크 주소
  • 예시
  • 192.168.100.0 (192.168.100.0/24 대역 모든 호스트 포함)
  • 포함 범위
  • 192.168.100.1 ~ 192.168.100.254
  • 경유지(Next Hop) 지정
  • 경유지의 정의: 목적지로 가기 위해 패킷을 보낼 다음 장비의 IP 주소

  • 설정 원칙:

  • 목적지 방향으로의 다음 장비 = 경유지로 지정

  • 최종 목적지의 IP를 경유지로 지정하면 안 된다. 바로 연결된 다음 라우터의 IP를 경유지
  • 로 지정해야 한다.
  • 올바른 설정 예:
  • 상황
  • 경유지
  • 이유
  • A → B → C
  • B의 IP
  • B가 다음 장비이므로
  • B에서 C로
  • C의 IP
  • C가 다음 장비이므로

  • ↓
  • 경유지로 패킷 전송
  • ↓
  • (반복...)
  • ↓
  • 목적지 도달
  • 핵심 원칙:
  • 항목

  • 다음 장비까지만 관심
  • 다음 일의 책임
  • 다음 라우터가 담당

2-5. 라우팅 설정 실패의 예

경로가 중간에 끊긴 경우: 상황: A → B → C 경로에서 B 라우터가 경로를 모를 때

  • A 라우터: C로 가려면 B로 보낸다 (정상)
  • B 라우터: C로 가는 경로를 모른다 (문제!)
  • 결과: C로 도달 불가
  • 결론: 모든 라우터에서 정확한 경로 설정이 필수이다.

6. 네트워크 통신 검증

6-1. 핑(Ping) 테스트
  • ping [목적지IP주소] ← 목적지 주소로 핑 전송
  • 핑의 목적:
  • 네트워크 경로 확인
  • 목적지 도달 가능 여부 확인
  • 라우팅 경로 검증
6-2. 통신 성공 조건
  • 2개 라우터 간 통신 (A ↔ B)
  • A 라우터 하위 PC → B 라우터 하위 PC
  • 필요 경로 설정:
  • 라우터
  • 설정 필요 사항
  • A 라우터
  • B 네트워크로의 경로 설정
  • B 라우터
  • A 네트워크로의 경로 설정
  • 3개 라우터 간 통신 (A ↔ B ↔ C)
  • 추가 경로 설정:
  • 라우터
  • 설정 필요 사항
  • A 라우터
  • C 네트워크로의 경로 설정
  • B 라우터
  • C 네트워크로의 경로 설정 (중간 라우터 역할)
  • C 라우터
  • A, B 네트워크로의 경로 설정
6-3. 첫 번째 패킷 손실(Loss)
  • 현상: 첫 번째 핑은 실패, 이후는 성공
  • 원인: ARP(Address Resolution Protocol) 요청
  • 단계
  • 설명
  • 1차 통신
  • MAC 주소를 모르므로 ARP 요청 소요
  • 이후 통신
  • 캐시에 저장되어 정상 통신
  • 첫 번째 패킷이 손실되는 것은 정상이다. ARP 요청을 위해 시간이 필요하기 때문이다.

7. 라우팅 설정의 중요성

7-1. 통신 가능의 필수 조건
  • 통신이 성공하려면 다음 모든 조건이 만족되어야 한다.
  • 조건
  • 내용
  • 주소 설정 정확성
  • IP 주소와 서브넷마스크 정확
  • 경로 설정 정확성
  • 모든 라우터에서 올바른 경로 설정
  • 인터페이스 활성화
  • no shutdown 설정
  • 하나라도 틀리면 통신이 불가능하다.
7-2. 설정 오류 확인 방법
  • 주소 설정 오류 확인:
  • show running-config ← 현재 실행 중인 설정 전체 표시
  • 확인 사항:
  • 각 인터페이스의 IP 주소 확인
  • 서브넷마스크 정확성 확인
  • no shutdown 설정 여부 확인
7-3. 경로 설정 확인 방법
  • 경로 설정 확인:
  • show ip route ← 라우팅 테이블 표시
  • 확인 사항:
  • 목적지 네트워크가 테이블에 추가되었는지 확인
  • 경유지 주소가 정확한지 확인
  • Static(S) 표시로 스태틱 경로 확인
