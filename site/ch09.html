CHAPTER 09

중복과 상충 정리

같은 주제가 여러 노트에 흩어져 있습니다. 지우지 않고 어디에 무엇이 있는지를 여기 모읍니다. 같은 명령이라도 노트마다 환경이 달라서, 합쳐 버리면 어느 환경의 이야기인지 잃어버리기 때문입니다.

아래 숫자는 각 노트에서 해당 키워드가 등장한 횟수입니다. 문서를 기계로 세어 얻은 값이며, 중요도가 아니라 분산 정도를 보는 용도입니다.

네트워크(1부)는 다른 노트와 겹치지 않습니다. 겹침은 전부 리눅스 서버·DB 쪽입니다.

주제별로 어느 노트를 볼 것인가

MariaDB — 다섯 노트에 나뉘어 있음

가장 심하게 흩어진 주제입니다. 목적에 따라 갈라 보십시오.

알고 싶은 것 볼 노트
SQL 문법, 문자셋(한글 깨짐), 논리 백업·복원, 복제 8/27 MariaDB
계정이 이름@호스트인 이유, GRANT/REVOKE, VIEW 오류 8/28 메모리·계정 4~6장
PHP PDO로 원격 DB 붙이기, 호스트별 권한 설계, prepared statement 8/28 팀웹
서버랩에서 MariaDB를 처음 세우는 절차, mariadb-secure-installation Rocky 서버랩 16장
rsyslog 로그를 MariaDB에 적재 8/25 NFS·Samba 후반부

중복이지만 남겨 둔 이유: 같은 GRANT 문이라도 8/27은 복제 계정, 8/28 팀웹은 웹 애플리케이션 계정입니다. 권한 범위와 접속 호스트가 완전히 다릅니다.

Apache / PHP — 세 노트

알고 싶은 것 볼 노트
설치·기동·문서 루트·HTTPS 인증서·php-fpm 구조 Rocky 서버랩 12~15장
팀 프로젝트용 가상호스트, DB 설정 파일을 문서 루트 밖에 두는 이유 8/28 팀웹
LogAnalyzer 웹 설치 과정에서의 SELinux 문제 8/25 NFS·Samba

SELinux — 두 노트, 접근 방식이 다름

  • 8/25 NFS·Samba: 왜 막혔는지 메커니즘부터 보고 끄지 않고 해결하는 방법(semanage, setsebool)
  • Rocky 서버랩: DNS zone 파일 권한, 웹 디렉터리 컨텍스트 등 개별 상황별 대응

먼저 8/25의 메커니즘 설명을 읽고, 서버랩은 사례집으로 쓰는 것이 빠릅니다.

firewalld — 세 노트에 조각으로

세 노트 모두 firewall-cmd --permanent --add-service=... && firewall-cmd --reload 형태입니다. 서비스 이름만 다릅니다. 부록 명령어 색인에서 firewall-cmd로 찾으면 전부 모여 나옵니다.

확인이 필요한 지점

아래는 이 책을 엮으면서 발견한, 하나로 정리하기 전에 사실 확인이 필요한 항목입니다. 추측으로 통일하지 않고 남겨 둡니다.

  1. 서버 노트 네 편이 전부 같은 192.168.16.0/24 대역인데 호스트 번호가 제각각입니다. 문서를 기계로 세어 확인한 실제 사용 주소는 다음과 같습니다.
노트 주로 쓰인 호스트
Rocky 서버랩 .131, .77, .137, .136
8/25 NFS·Samba .81, .92, .40
8/28 팀웹 .117(DB), .46(클라이언트), .111(WEB)
8/28 메모리·계정 .100

같은 대역을 여러 실습이 나눠 쓴 것이라, 노트를 넘나들 때 IP를 그대로 따라 치면 다른 장비를 건드립니다. 자기 환경의 주소로 바꿔서 실행하십시오. 어느 실습이 어느 호스트를 점유했는지는 확인이 필요합니다(같은 VM을 재사용했는지 기록이 없습니다). 2. it인프라의이해 슬라이드 4개는 본문이 비어 있습니다. 이미지 슬라이드라 대조하지 못했습니다. 3. 커리큘럼 지도의 분류는 파일명 기준입니다. 한 강의가 두 주제에 걸치면 앞 규칙으로 갔습니다. 예: 038~040번은 번호상 네트워크 구간에 있지만 내용은 Rocky Linux 설치라 리눅스 서버로 분류했습니다.
