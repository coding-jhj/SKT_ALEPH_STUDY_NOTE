085. ZFW

1. Zone-Based Firewall 개요

1-1. 개념

Zone-Based FW(ZFW)는 일반 라우터 장비를 실제 방화벽 장비처럼 동작하도록 만드는 기능이다. 기존 ACL 정책보다 강력한 보안 정책을 적용할 수 있으며, 인터페이스를 물리적 영역(Zone)으로 구분하여 관리한다. 기존 ACL은 인터페이스별로 정책을 적용하지만, ZFW는 Zone이라는 논리적 영역 단위로 트래픽을 분류하고 제어한다. ZFW는 이후 학습할 ASA(시스코 방화벽), PF Sense 등 전용 방화벽 솔루션의 Zone 개 념을 이해하기 위한 기초가 된다. 리눅스의 firewall-cmd 명령어에서도 Zone 개념이 동 일하게 사용된다.

4-1. Class-map (트래픽 분류)
  • Class-map은 ACL 정책을 참조하여 어떤 트래픽인지 분류하는 역할을 한다.
  • class-map type inspect [이름]
  • match access-group name [ACL 이름]
  • match access-group 뒤에 ACL 이름을 지정하면, 해당 ACL에 일치하는 트래픽을 이
  • Class-map으로 분류한다.
  • ACL에서 세부 프로토콜(HTTP만, 텔넷만 등)을 지정하면, Class-map도 해당 트래픽
  • 만 분류한다.
  • ACL 예시

리치 룰(Rich Rule)은 firewalld에서 제공하는 세부적인 접근 제어 정책 설정 명령어이다. 출발지 IP, 목적지 IP, 프로토콜, 포트 등을 조합하여 구체적인 트래픽 제어 정책을 작성할 수 있다.

리치 룰 전체 식은 작은따옴표( ' )로 감싸며, 세부 값은 큰따옴표( " )로 지정한다.

2-1. VPCS (Virtual PC Simulator)

VPCS는 GNS3에서 제공하는 가상 PC 역할의 장비이다. 도구 모음에서 End devices 항 목 안에 위치하며, 드래그 앤 드랍으로 토폴로지에 추가할 수 있다. VPCS에서 사용 가능한 주요 명령어는 다음과 같다. 명령어 설명 ? 사용 가능한 명령어 목록(도움말) 출력 ip <서브넷마스크> <게이트웨이> IP 주소 설정. IP, 서브넷 마스크, 게이트웨이 주소 를 순서대로 입력 show 현재 설정된 IP 주소 정보 확인 (IPv6 링크로컬 주 소 포함) save 현재 IP 주소 설정을 저장 (장비 재시작 후에도 유 지) ping <목적지 IP> 대상 IP로 ICMP 패킷을 전송하여 통신 여부 확인 VPCS에 IP를 설정하는 예시는 다음과 같다. ip 10.10.70.100 255.255.255.0 10.10.70.1 위 명령은 IP 10.10.70.100 , 서브넷 마스크 255.255.255.0 , 게이트웨이 10.10.70.1 을 설정 한다. 설정 후 save 명령으로 저장하지 않으면 전원 재시작 시 설정이 초기화된다.

⚠️ VPCS는 텔넷(telnet) 접속이 지원되지 않는다. 원격 접속 테스트가 필요할 경우 VPCS 대신 라우터 장비(예: R3)를 활용해야 한다.

2-2. 이더넷 스위치 (Ethernet Switch)

도구 모음의 Switches 항목에서 Ethernet Switch를 토폴로지에 추가할 수 있다. 이더넷 스위치는 추가하는 즉시 자동으로 동작하며 별도의 설정이 필요하지 않다. 이더넷 스위치의 콘솔 창을 열면 CLI가 아닌 GUI 메뉴 창이 표시되며, 명령어를 통한 세부 설정이 불가능하다. VLAN 설정 등 스위치 명령어 설정이 필요한 경우에는 이더넷 스위치 대 신 IOS 기반의 이더스위치 라우터(L3 스위치) 장비를 사용해야 한다.

3. 보안 도구 사용 시 법적 주의사항

Wireshark(패킷 캡처 툴)과 Nmap 등 스캐닝 툴은 허락 없이 임의의 외부 사이트나 타인의 시스템에 사용할 경우 불법이다. 스캐닝이란 특정 시스템에 대해 어떤 포트가 개방되어 있는지, 어떤 취약점이 있는지를 사전 조사하는 과정이다. 이는 침입자가 대상 시스템을 분석하는 과정과 동일하다. Wireshark를 통한 패킷 캡처 역시 네트워크상에서 주고받는 정보를 수집하는 것이므로, 허 락 없이 타인의 네트워크에서 사용하면 정보 도용 문제가 발생한다. ⚠️ 이러한 이유로 보안 실습은 반드시 허가된 가상 환경(가상 머신) 내에서만 진행하며, 외부 일반 사이트나 타인의 시스템에 임의로 사용해서는 안 된다.

5. 호스트 PC와 GNS3 장비 연결

5-1. 연결 목적

GNS3 내 장비와 호스트 윈도우 PC를 연결하면 다음이 가능하다. 호스트 PC의 웹 브라우저로 GNS3 내 장비의 웹 대시보드(예: ASDM)에 접속 호스트 PC의 Putty 등 SSH/Telnet 클라이언트로 GNS3 내 장비에 원격 접속

5-2. Cloud 장비를 이용한 연결 방법

GNS3의 End Device 패널에 있는 Cloud 장비를 토폴로지에 배치하고, 연결하고자 하는 인터페이스(Management 포함)에 연결한다. Cloud 장비 위에서 우클릭 → Configure 진입 시 호스트 PC의 네트워크 어댑터 목록이 나 타난다. 이 중 연결에 사용할 어댑터를 선택하고 Add 후 Apply → OK한다.

5-3. 루프백 어댑터(Loopback Adapter) 필요성

실제 네트워크 어댑터(이더넷)를 GNS3 장비와 직접 연결할 경우 해당 어댑터의 IP를 변경 해야 하므로 인터넷 연결이 끊길 수 있다. 이를 방지하기 위해 논리적인 어댑터인 루프백 어댑터를 별도로 생성하여 GNS3 연결에 사 용한다.

5-4. 루프백 어댑터 생성 방법 (Windows)

1. 장치 관리자 실행

2. 네트워크 어댑터 선택 → 상단 메뉴 동작 → 레거시 하드웨어 추가

3. 마법사에서 목록에서 직접 선택한 하드웨어 설치 선택 → 다음

4. 목록에서 네트워크 어댑터 선택 → 다음

5. 제조업체 Microsoft 선택 → 목록에서 Microsoft KM-TEST 루프백 어댑터 선택

6. 다음 → 마침

생성된 루프백 어댑터는 논리적인 어댑터이므로 IP를 변경해도 실제 인터넷 연결에 영향을 주지 않는다.

133. PFSense 개요 및 설치

1. PFSense 개요

PFSense는 방화벽이 기본 역할이며, 여기에 다양한 패키지를 추가 설치하면 IPS, Anti- DDoS 등 여러 기능을 통합적으로 수행할 수 있는 UTM(Unified Threat Management) 장비로 동작한다. PFSense는 두 가지 버전이 있다. 버전 설명 PFSense Plus 유료 구매 버전. Netgate 공식 사이트에서 제공 PFSense CE Community Edition. 무료 오픈소스 버전. 이 교 과목에서 사용 이 교과목에서는 PFSense CE 2.7.2 버전을 사용하며, ISO 파일을 기준으로 VirtualBox 에 설치한다.

7. 방화벽 임시 해제 ( pfctl )

PFSense는 기본적으로 방화벽 기능이 활성화되어 있어, 초기 설정 과정에서 웹 대시보드에 접속이 안 될 수 있다. 이 경우 콘솔 8번 메뉴(Shell)에서 방화벽 기능을 임시로 비활성 화한다. pfctl -d # ← 방화벽 비활성화 (Disable) pfctl -e # ← 방화벽 활성화 (Enable) 웹 대시보드 로딩이 느리거나 넘어가지 않을 때도 pfctl -e 후 pfctl -d 를 다시 입력하면 해결되는 경우가 많다. ⚠️ pfctl -d 는 임시 조치이다. 설정 완료 후에는 다시 활성화( pfctl -e )하여 방화벽 기 능이 정상 동작하도록 해야 한다.

135. PFSense 라우팅 설정 및 방화벽 룰

1. PFSense 라우팅 설정 개요

PFSense에서 서로 다른 네트워크 간의 통신이 이루어지려면 라우팅 설정이 필요하다. PFSense는 정적 라우팅(Static Route)을 지원하며, 설정 순서는 게이트웨이 등록 → 정적 경로 설정 순이다. 게이트웨이가 먼저 등록되어 있어야 정적 경로 설정 시 게이트웨이 목록이 드롭다운에 표시 된다. 경로: System → Routing

2. 게이트웨이(Gateway) 설정

경로: System → Routing → Gateways 탭 각 인터페이스에 연결된 다음 장비(업스트림)의 IP 주소를 게이트웨이로 등록한다. WAN·LAN 인터페이스에 대한 게이트웨이가 이미 등록되어 있는지 확인한다. 인터페이스 게이트웨이 예시 설명 WAN (EM0) 2.2.2.1 WAN 쪽에서 나가는 트래픽의 다음 장비(R2) LAN (EM1) 1.1.1.1 LAN 쪽에서 나가는 트래픽의 다 음 장비(R1) 게이트웨이가 목록에 없으면 Add 버튼으로 추가한다. 인터페이스별 게이트웨이가 등록 되지 않으면 정적 경로 설정 시 해당 인터페이스가 목록에 표시되지 않는다.

5. 방화벽 룰 작성

Add 버튼(↑ 위에 삽입, ↓ 아래에 삽입)을 클릭하여 룰을 추가한다.

5-1. 주요 설정 항목
  • 항목
  • 설명
  • Action
  • Pass (허용), Block (차단), Reject (거부)
  • Interface
  • 이 룰이 적용될 인터페이스 (WAN, LAN 등)
  • Address Family
  • IPv4, IPv6 또는 둘 다
  • Protocol
  • TCP , UDP , ICMP , Any 등
  • Source
  • 출발지 IP 또는 네트워크
  • Source Port

  • 출발지 포트 ( Any 또는 특정 포트)

  • 항목

  • 설명
  • Destination
  • 목적지 IP 또는 네트워크
  • Destination Port
  • 목적지 포트 ( Any 또는 특정 포트·범위)
  • Log
  • 체크 시 이 룰에 매칭된 패킷을 로그로 기록
  • Description
  • 룰 설명 이름 (선택)
5-2. 소스·데스티네이션 주소 유형
  • 유형
  • 설명
  • Any
  • 모든 주소
  • Address or Alias
  • 단일 IP 주소 지정 (서브넷 비트 수 32 = 단일 호
  • 스트)
  • Network
  • 특정 네트워크 대역 지정
  • LAN subnet 등
  • 해당 인터페이스에 연결된 서브넷 자동 참조
5-3. Invert Match (반전 매칭)

소스·데스티네이션 항목 옆의 Invert 체크박스를 체크하면 지정한 주소를 제외한 나머지 주 소에 룰이 적용된다. 예: 목적지를 1.1.1.1 로 지정 후 Invert 체크 → 1.1.1.1 이 아닌 모든 목적지에 적용

5-4. 포트 범위(Port Range)

특정 포트 범위에 대해 룰을 적용할 때 사용한다. 예: 1000~1500번 포트를 허용하려면 Port Range 필드에 1000 과 1500 을 입력한다.

5-5. 운영체제별 필터 (Advanced 옵션)

Advanced 옵션에서 OS 항목을 이용하면 트래픽을 발생시킨 장비의 운영체제(Windows, macOS 등)에 따라 룰을 적용할 수 있다.

5-6. 룰 순서 변경

드래그 앤 드롭 또는 추가 시 방향(↑/↓)을 선택하여 룰의 순서를 조정한다. 특정 룰은 기본 (시스템) 룰로 고정되어 제일 위로 이동하지 않을 수 있다.

6. 전체 통신 허용 룰 예시 (테스트용)

  • 초기 테스트 목적으로 WAN·LAN 전 구간에서 모든 트래픽을 허용하는 룰을 추가한다.
  • Action: Pass
  • Interface: WAN (또는 LAN)
  • Address Family: IPv4
  • Protocol: Any
  • Source: Any
  • Destination: Any
  • → Save → Apply Changes
  • 이렇게 설정하면 해당 인터페이스를 통해 들어오는 모든 트래픽이 허용된다. 전체 통신이 정
  • 상적으로 확인된 후 세부 룰로 교체·수정한다.

7. 특정 트래픽 허용 룰 예시 (세부 제어)

출발지 192.168.200.150 에서 목적지 1.1.1.1 의 HTTP(80) 포트로 가는 트래픽만 허용하는 룰 예시: Action: Pass Interface: WAN Address Family: IPv4 Protocol: TCP Source: Address or Alias → 192.168.200.150 / 32 Source Port: Any Destination: Address or Alias → 1.1.1.1 / 32 Destination Port: HTTP (80) → Save → Apply Changes ⚠️ WAN에서 특정 트래픽을 허용하더라도, 해당 트래픽이 LAN 인터페이스를 통과할 때 LAN 룰에도 허용 설정이 있어야 전체 구간 통신이 가능하다.

8. 방화벽 룰 로그 확인

  • 경로: Firewall → Rules → 해당 룰의 통계 숫자 클릭
  • 각 룰에 매칭된 패킷 수와 바이트 수가 표시된다. 클릭하면 세부 로그 메시지를 확인할 수 있
  • 다.
  • 로그 상태
  • 의미
  • Established
  • 패킷이 정상적으로 통과됨
  • Blocked
  • 패킷이 차단됨

이를 통해 어떤 트래픽이 허용·차단되고 있는지 확인하고, 룰 설정의 오류 여부를 점검할 수 있다. 시스코 장비의 show access-list 명령에서 매치 카운트를 확인하는 것과 동일한 개념 이다. 특정 인터페이스의 로그만 보려면 Filter 옵션에서 인터페이스를 선택한다.

9. PFSense에서 OSPF 설정 불필요

GNS3 토폴로지에서 PFSense는 OSPF 라우팅을 별도로 설정하지 않는다. PFSense에서 는 정적 경로(Static Route)만 설정하면 되며, 나머지 라우터(R1, R2)에서 OSPF 또는 정적 라우팅을 통해 경로를 설정한다.
