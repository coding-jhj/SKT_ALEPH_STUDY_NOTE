038. Rocky Linux IP 주소 수동 설정 및 원격 접속 도구(PuTTY) 소개

원격 접속 도구(PuTTY) 소개

1. 브릿지 모드에서 IP 자동/수동 할당

1-1. IP 자동 할당이 이루어지는 경우

VirtualBox의 브릿지 모드를 적용하면, VM이 호스트 컴퓨터의 네트워크 정보를 가져와 연 결하므로 대부분 IP가 자동으로 할당된다.

1-2. IP 자동 할당이 이루어지지 않는 경우

다음 상황에서는 IP가 자동으로 할당되지 않을 수 있다.

원인 설명
호스트 IP 수동 설정 호스트 컴퓨터가 IP를 수동(정적)으로 설정한 경우
브릿지 연결 문제 호스트로부터 주소 정보를 브릿지로 전달받지 못하는 경우

이 경우 VM 안에서 IP 주소를 수동으로 설정해야 한다.

2. 리눅스 IP 주소 수동 설정 — NMTUI

2-1. 네트워크 매니저(Network Manager) 사용 권장

Rocky Linux 9부터는 네트워크 설정 파일을 직접 편집하는 방식을 권장하지 않는다. 대신 네트워크 매니저(NM, Network Manager)를 통한 설정을 권장한다.

네트워크 매니저를 통한 설정 방법은 두 가지이다.

명령어 설명
nmtui 텍스트 기반 메뉴 UI (방향키·스페이스바로 설정)
nmcli 명령어 기반 설정

예전에는 /etc/network/scripts/ 하위의 인터페이스 설정 파일(ifcfg-인터페이스명)을 직 접 편집하는 방식을 사용했으나, Rocky Linux 9부터는 이 방식을 권장하지 않는다.

2-2. 수동 IP 설정 시 입력 항목

VM에 수동으로 IP를 설정할 때 필요한 정보는 호스트 컴퓨터의 네트워크 정보를 기준으로 한다.

항목 설명
IP 주소 범위 내에서 사용 중이지 않은 주소 선택
서브넷 마스크 호스트 컴퓨터와 동일하게 설정
게이트웨이 호스트 컴퓨터와 동일하게 설정
DNS 서버 호스트 컴퓨터와 동일하게 설정

⚠️ IP 주소를 제외한 서브넷 마스크, 게이트웨이, DNS 서버는 호스트 컴퓨터의 값과 동 일하게 설정해야 한다. 임의로 변경하면 인터넷 연결이 되지 않는다.

2-3. 사용 가능한 IP 주소 확인 방법

VM에 할당할 IP 주소가 이미 사용 중인지 확인하려면 윈도우 명령 프롬프트에서 ping을 사 용한다.

ping [할당하고자 하는 IP]

응답이 없으면(Request Timeout) → 사용 중이지 않으므로 할당 가능 응답이 오면(Reply from) → 이미 사용 중이므로 다른 IP 선택 ⚠️ 동일 네트워크에서 같은 IP를 두 장비에 할당하면 IP 충돌이 발생한다. 반드시 사용 중 이지 않은 주소를 확인하고 할당해야 한다.

2-4. 호스트 컴퓨터 네트워크 정보 확인

호스트(윈도우) 컴퓨터의 IP, 서브넷, 게이트웨이, DNS 확인 방법:

ipconfig /all ipconfig 만 입력하면 기본 정보만 표시되고, /all 옵션을 추가하면 DNS 서버 주소까지 포함한 전체 정보를 확인할 수 있다.

3. IP 설정 완료 후 확인

설정이 완료되면 리눅스 터미널에서 다음 명령으로 적용된 IP 주소를 확인한다.

ip address ← 인터페이스별 IP 주소 확인 이후 인터넷 연결 여부를 확인한다.

ping 8.8.8.8 ← 외부 IP로 통신 테스트 ping www.google.com ← 도메인 이름으로 통신 테스트 확인 후 Ctrl + C 로 ping을 중지한다.

4. 원격 접속 도구 — PuTTY

4-1. PuTTY란

PuTTY는 무료 원격 접속 도구로, Telnet·SSH 등을 통해 원격 장비에 접속할 때 사용한다.

특성 내용
비용 무료
용도 Telnet, SSH 원격 접속
장점 용량이 적고 다양한 접속 환경 지원
4-2. PuTTY를 사용하는 이유

VirtualBox VM 화면 내에서 직접 작업할 경우 글자 크기 조절 등이 불편하다. PuTTY로 원 격 접속하면 글자 크기, 색상 등을 자유롭게 설정하여 편리하게 작업할 수 있다.

Rocky Linux 설치 시 root 사용자의 SSH 원격 접속 허용 옵션을 체크해야 PuTTY로 root 계정 접속이 가능하다.

4-1. 브릿지 모드란

VirtualBox VM의 네트워크 설정에서 브릿지(Bridge) 모드를 선택하면, VM이 호스트 컴 퓨터와 동일한 네트워크에 연결된다. 즉, 호스트 컴퓨터가 사용하는 네트워크 대역에서 VM 도 독립적인 IP를 할당받아 사용한다.

브릿지 모드 결과 내용
VM의 네트워크 대역 호스트 OS와 동일한 네트워크 대역
브릿지 모드 결과 내용
IP 할당 방식 자동(DHCP) 또는 수동(정적)
외부 인터넷 접속 가능
호스트와의 통신 가능
4-2. 브릿지 모드에서 IP 자동 할당이 안 될 경우

호스트 컴퓨터의 네트워크 설정이 수동(정적)으로 되어 있는 경우, VM에 IP가 자동으 로 할당되지 않을 수 있다. 이 경우 VM에서 수동으로 IP를 설정해야 한다.

브릿지 모드가 정상 동작하면 ip address 명령 결과에 IPv4 형식의 주소가 표시된다.

044. APM 패키지 설치, systemctl 서비스 관리, 방화벽 설정

스 관리, 방화벽 설정

1. DNF 패키지 관리 도구

최신 버전의 리눅스에서는 기존 YUM 외에 DNF라고 하는 새로운 패키지 관리 도구가 추가 되었다. YUM과 DNF 모두 사용 가능하며, 본 수업에서는 DNF를 기준으로 진행한다.

dnf install -y 패키지명 ← 패키지 설치 (-y는 모든 확인에 YES 자동 응답) dnf remove -y 패키지명 ← 패키지 삭제 -y 옵션을 사용하지 않으면 설치 중 "이 정도 공간이 필요한데 설치하시겠습니까? (yes/no)" 와 같은 확인 질문이 반복적으로 나타난다. -y 는 이 모든 과정에 yes로 자동 응답하는 옵션이다.

옵션의 위치는 순서와 무관하다. dnf install 패키지명 -y 와 dnf -y install 패키지명 모두 동일하게 동작한다.

2. APM 패키지 설치

APM은 Apache + PHP + MariaDB의 조합이다. 리눅스용은 LAMP, 윈도우용은 WAMP 라고도 한다.

구성 요소 역할 패키지 이름
A (Apache) 웹 서버 httpd
P (PHP) 웹 프로그래밍 언어 php
M (MariaDB) 데이터베이스 서버 mariadb-server

dnf install -y httpd php mariadb-server ← APM 패키지 일괄 설치 설치가 완료되면 Complete! 메시지가 출력된다. 패키지 설치 시 의존성 패키지(Python, Perl 등)가 함께 자동으로 설치된다.

3. 설치된 버전 확인

httpd -v ← Apache 버전 확인 (소문자 v) httpd -V ← Apache 버전 및 옵션 상세 확인 (대문자 V) php -v ← PHP 버전 확인 mysql --version ← MariaDB 버전 확인 (mysql 명령어 사용 가능) mariadb --version ← MariaDB 버전 확인 MariaDB는 MySQL과 동일하다. MySQL을 다룰 줄 알면 MariaDB도 다룰 수 있으며, 반대의 경우도 마찬가지이다.

4. systemctl — 서비스 관리 명령어

systemctl 은 System Control의 줄임말로, 리눅스에서 서비스(데몬)를 시작·중지·상태 확 인하기 위한 명령어이다.

명령 동작
systemctl start 서비스명 서비스 시작
systemctl stop 서비스명 서비스 중지
systemctl restart 서비스명 서비스 재시작
systemctl status 서비스명 서비스 현재 상태 확인

systemctl status httpd ← 웹 서비스 상태 확인 systemctl start httpd ← 웹 서비스 시작 systemctl status httpd ← 시작 후 상태 재확인 상태 확인 시 주요 메시지

메시지 의미
active (running) 서비스 정상 실행 중
inactive (dead) 서비스 중지 상태

서비스가 중지 상태(dead)이면 외부 클라이언트가 해당 서비스에 접속할 수 없다.

systemctl status 실행 중 종료하려면 Ctrl+C 를 누른 후 엔터를 입력한다.

서비스 파일이 특정 경로에 존재하지 않으면 systemctl로 제어가 불가능하다. 이 경우 관 리자가 직접 서비스 파일을 해당 경로에 등록해야 한다.

5. 방화벽 개념과 포트

5-1. 포트(Port)란

포트는 항구와 유사한 개념이다. 데이터가 목적지 서버까지 정상적으로 도착했더라도, 서버 관리자가 해당 서비스의 포트를 막아 놓으면 클라이언트는 접속할 수 없다.

프로토콜 기본 포트 번호
HTTP 80
HTTPS (HTTP over SSL) 443
SSH 22

HTTPS는 HTTP에 보안성을 높인 프로토콜이다.

5-2. 방화벽(firewalld) 상태 확인

리눅스에서는 firewalld 가 기본값으로 실행 중이다.

systemctl status firewalld ← 방화벽 서비스 상태 확인 firewalld가 기본으로 실행 중이기 때문에, 별도로 열어주지 않은 포트는 모두 차단된 상 태이다. SSH(22번 포트)는 기본값으로 허용되어 있다.

서비스 이름 뒤에 붙는 d 는 데몬(Daemon) 을 의미한다. 데몬은 백그라운드에서 동작하 는 프로세스의 일종이다.

5-3. 방화벽 포트 허용 — firewall-cmd

firewall-cmd 는 셸에서 방화벽 정책을 설정하는 명령어이다.

서비스 이름으로 허용 firewall-cmd --permanent --add-service=http # 포트 번호로 허용 firewall-cmd --permanent --add-port=80/tcp # 방화벽 설정 적용 (변경사항 저장) firewall-cmd --reload # 현재 방화벽 정책 목록 확인 firewall-cmd --list-all

옵션 의미
--permanent 영구 적용 (재부팅 후에도 유지)
--add-service 서비스 이름으로 허용 추가
--add-port 포트 번호/프로토콜로 허용 추가
--reload 변경사항 저장 및 적용
--list-all 현재 방화벽 정책 전체 목록 표시

--permanent 옵션 없이 설정하면 현재 상태에서는 적용되지만, 시스템 재부팅 후 설정이 초기화된다. 영구 적용을 위해 --permanent 를 함께 사용한다.

방화벽 설정 변경 후 반드시 --reload 로 적용해야 --list-all 에 반영된다.

오류 메시지에 'unrecognized argument'가 표시되면 옵션 철자가 잘못된 것이다. 에러 메시지에 잘못된 부분이 함께 표시된다.

1. VirtualBox 가상머신 복제

여러 대의 리눅스 서버가 필요한 경우, 매번 처음부터 설치하는 것 외에 복제 기능을 활용할 수 있다. 복제는 어느 정도 작업에 익숙해진 후 사용을 권장한다.

4-2. cd — 디렉토리 이동

링크 파일은 다른 경로에 있는 파일과 연결되어 있는 파일이다. 리눅스에서는 하드 링크와 소프트 링크 두 가지가 있다.

7. 파일 권한 체계

7-1. 권한의 3요소
기호 의미 숫자 값
r read (읽기) 4
w write (쓰기 / 편집) 2
x execute (실행) 1
- 해당 권한 없음 0
7-2. 권한 구역 3분류

권한 필드는 소유자(owner) — 그룹(group) — 기타(other) 순서로 표기된다.

rwx r-x r-x ↑ ↑ ↑ 소유자 그룹 기타 예: rwx r-x r-x = 755, rw- r-- r-- = 644 읽는 방법 예시 drwxr-xr-x root root NetworkManager → NetworkManager 디렉토리에 대해 root 소유자는 읽기·쓰기·실행, root 그룹 사용자는 읽기·실행, 기타 사용자는 읽기·실행 권한을 가진다.

그룹 이름이 'root'라도 root 사용자만 해당되는 것이 아니라, 관리자가 그 그룹에 소속시 킨 모든 사용자가 그룹 권한을 가진다.

7-3. 권한 변경 — chmod

chmod 755 test.txt ← test.txt를 755 권한으로 변경 chmod 644 test.txt ← test.txt를 644 권한으로 변경 ⚠️ 보안 관점에서 무조건 높은 권한을 부여하는 것은 바람직하지 않다. 계정 보안의 핵심 은 사용자별로 적절한 권한을 관리하는 것이다.

8. 디렉토리 및 파일 생성

mkdir test ← test 디렉토리 생성 (Make Directory) touch test.txt ← 내용 없는 빈 파일 생성 파일/디렉토리 생성 시 기본 권한이 자동으로 부여된다.

1. YUM 패키지 관리 도구

YUM은 리눅스에서 패키지를 설치·관리하기 위한 도구이다. 어떤 프로그램이 실행되기 위해 서는 해당 프로그램 하나만 동작하는 것이 아니라, 그 프로그램을 실행하기 위한 수많은 다 른 패키지들이 함께 실행되어야 한다. YUM은 이러한 의존성 관계를 자동으로 파악하고 버 전 호환성을 맞춰 가며 패키지를 관리할 수 있는 도구이다.

YUM이 없던 초창기에는 관리자가 모든 패키지 버전 호환성을 직접 확인하며 일일이 설치해 야 했기 때문에 리눅스가 어렵게 느껴졌다. YUM의 등장 이후 패키지 설치가 크게 간편해졌 다.

yum update -y ← 패키지 전체 업데이트 (-y는 모든 확인 질문에 YES 자동 응답)

⚠️ YUM 업데이트는 시간이 많이 걸리므로, 수업 완전히 마친 후 진행하는 것을 권장한 다.

3. 주 DNS와 보조 DNS

3-1. 주 DNS (Primary / Master)

여러분이 설정하고 있는 DNS 서버는 주 DNS(Primary DNS, 1차 DNS) 이다. 클라이언트 의 도메인 질의를 받아 응답하는 역할을 한다.

3-2. 보조 DNS (Secondary / Slave)

보조 DNS(Secondary DNS, 2차 DNS)*는 주 DNS를 백업하는 역할을 한다.

구분 설명
주 DNS (Master) 1차 DNS, 클라이언트의 질의에 응답
보조 DNS (Slave) 2차 DNS, 주 DNS를 백업

보조 DNS는 주 DNS와 정보가 동기화되어 있어야 하며, 이 동기화 과정을 존 전송(Zone Transfer)이라고 한다. 주 DNS가 문제가 발생하거나 점검 중일 때 보조 DNS가 대신 응 답한다.

allow-update { none; } 설정은 보조 DNS와의 존 전송 허용 여부를 지정한다. 보조 DNS 가 없는 경우 none 으로 설정한다.

4. 존(Zone) 파일 개념

4-1. 존 파일 종류

DNS 네임서버의 존(Zone, 영역)에는 두 가지 방향이 있다.

존 종류 설명
정방향 존 (Forward Zone) 도메인 → IP 주소로 변환 (도메인으로 IP를 찾을 때)
역방향 존 (Reverse Zone) IP 주소 → 도메인으로 변환 (IP로 도메인을 찾을 때)
4-2. 존 파일 경로

BIND 설치 시 존 파일은 /var/named/ 디렉토리 아래에 위치한다. 네임서버 관련 모든 파일 이 이 디렉토리 아래에 저장된다.

/var/named/ ← BIND 존 파일 저장 디렉토리

4-3. named.conf에 존 설정 추가

named.conf 파일 하단에 존 설정 항목을 추가한다.

zone "test.com" { ← 관리할 도메인 이름 type master; ← 주 DNS이므로 master, 보조 DNS이면 slave file "test.com.zone"; ← 실제 존 파일 이름 (named.conf에서 지정한 이름과 동일해야 함)

allow-update { none; }; ← 보조 DNS로의 존 전송 허용 여부 (없으면 none) };

⚠️ file 에 지정한 파일 이름과 실제로 생성하는 존 파일의 이름이 반드시 일치해야 한 다. 이름이 다르면 오류가 발생한다.

5. 레코드(Record) 개요

5-1. 레코드란

존 파일 안에 들어가는 한 줄 한 줄을 레코드라고 한다. 도메인과 IP를 매핑하거나 네임서버 에 관련된 정보를 담는다.

레코드 종류 설명
SOA 네임서버의 기본 정보. 존 파일에 반드시 포함되어야 하는 필수 레코드
NS 네임서버를 지정하는 레코드. 존 파일에 반드시 포함되어야 하는 필수 레코드
A 도메인을 실제 IP 주소로 연결하는 레코드
MX 메일 서버를 지정하는 레코드
CNAME 도메인의 별칭을 지정하는 레코드
PTR 역방향 존에서 IP를 도메인으로 연결하는 레코드
5-2. 도메인 구매

실제 서비스에서 사용하는 도메인은 가비아 등 호스팅 사이트에서 비용을 지불하고 구매해 야 한다. 내부 실습에서는 현재 사용되지 않는 도메인(예: test.com )으로 테스트가 가능하 다.

내부 네임서버에만 등록된 도메인은 외부의 공용 DNS에서 조회되지 않는다. 따라서 해당 네임서버를 DNS로 설정한 클라이언트에서만 도메인으로 접속이 가능하다.

052. DNS 서버 개념과 구축 환경 준비

1. DNS 개념 및 구성요소

1-1. DNS란

DNS(Domain Name System)*는 IP 주소와 도메인 간에 서로 매핑된 정보를 가지 고 있는 시스템이다.

시스템이 인지하는 주소는 IP 주소이고, 사람이 편리하게 인식하는 주소는 도메인(예: 네이 버 닷컴, 구글 닷컴)이다. DNS는 이 두 가지를 연결하는 역할을 한다.

1-2. DNS 구성요소
구성요소 설명
IP 주소 시스템이 인식하는 주소
도메인 사람이 편리하게 사용하는 주소 (예: naver.com, google.com)
네임서버(NS) IP와 도메인의 매핑 정보를 레코드화하여 관리하는 서버
1-3. DNS 서버 구축 전제 조건

DNS 서버를 구축하기 전에 HTTP 웹 서버가 정상적으로 구축되어 있고 IP 주소로 접속이 가능한 상태여야 한다. IP 주소로 접속이 되지 않으면 도메인으로도 접속이 불가능하다.

IP 주소로 접속이 되는 상태에서 DNS 서버를 구축하면, 동일한 서버에 도메인 이름으로 도 접속할 수 있게 된다.

2. 호스트 파일 (Hosts File)

2-1. 호스트 파일의 개념

예전에는 접속해야 할 사이트가 많지 않았기 때문에, 메모장과 같은 호스트 파일을 만들어 IP와 도메인을 직접 관리하였다. 현재도 윈도우 시스템에 호스트 파일이 존재한다.

호스트 파일의 형태는 다음과 같다.

예시 140.xxx.xxx.xxx www.google.com ← IP와 도메인을 한 줄씩 매핑하여 관리 현재는 접속해야 할 외부 주소가 매우 많아졌기 때문에, 이러한 목록들을 레코드화하여 관리 하는 시스템이 네임서버이고, 이를 전체적으로 DNS라고 한다.

2-2. DNS 조회 순서 (재귀적 질의)

도메인을 입력하면 시스템은 다음 순서대로 IP 주소를 찾는다.

순서 조회 대상 설명
1 호스트 파일 로컬에 저장된 도메인-IP 매핑 파일을 가장 먼저 참조
2 캐시 이전에 조회한 결과가 저장된 캐시를 참조
3 로컬 DNS 설정된 1차 DNS 서버에 질의
4 재귀적 질의 로컬 DNS에 없을 경우 루트 DNS부터 순차적으로 질의

재귀적 질의 과정에서는 로컬 DNS가 전 세계 모든 도메인 정보를 가지고 있지 않기 때문에, 루트 DNS부터 TLD, 권한 네임서버 순으로 단계적으로 질의한다.

2-3. TLD (Top Level Domain)

TLD(Top Level Domain)*는 최상위 도메인을 의미한다. 도메인에서 오른쪽에 위치 한 부분이 범위가 큰 쪽이다.

예: www.naver.com.kr 에서 오른쪽 부분( kr , com )이 최상위 도메인에 해당한다.

루트 DNS는 가장 오른쪽에 있는 범위가 큰 최상위 도메인에 대한 정보를 가지고 있으며, 하 위 도메인으로 단계적으로 질의가 이루어진다.

3. 호스트 파일 변조 공격

3-1. 공격 원리

악성 프로그램이 호스트 파일을 변조할 경우, 정상적인 도메인에 접속하더라도 공격자가 만 들어 놓은 피싱 사이트로 연결된다.

공격 예시:

구분 설명
정상 상태 www.naver.com → 정상 서버 IP (예: 100.100.100.100)
변조 후 www.naver.com → 피싱 사이트 IP (예: 200.200.200.200)

클라이언트는 www.naver.com 을 입력하면 호스트 파일을 가장 먼저 참조하기 때문에, 변조된 IP로 라우팅되어 피싱 사이트에 접속하게 된다. 피싱 사이트는 네이버 사이트와 유사하게 만 들어져 있어 일반 사용자가 구별하기 어렵고, 아이디와 비밀번호를 입력하는 순간 정보가 공 격자에게 유출된다.

⚠️ 인터넷에서 파일을 다운받거나 프로그램을 실행할 때 백신 툴에서 "호스트 파일을 변 조하려고 합니다"라는 경고 메시지가 표시될 경우, 이는 호스트 파일 변조를 통한 DNS 연결 조작 시도임을 의미하므로 주의해야 한다.

4. DNS 서버 구축 환경 구성

4-1. 두 대 VM 구성

DNS 서버 구축 실습에서는 두 대의 가상머신이 필요하다.

머신 역할 IP 예시
HTTP 서버 웹 서버 역할 (기존 구축 머신) 192.168.100.101
DNS 서버 네임서버 역할 (복제 또는 새로 생성한 머신) 192.168.100.102

두 머신이 동일한 IP로 설정되어 있으면 주소 충돌이 발생하므로, DNS 서버의 IP를 변경해 야 한다.

4-2. OVA 파일 (가상 시스템 내보내기/가져오기)

VirtualBox에서 가상 시스템 복제가 되지 않을 경우, OVA 파일을 이용하는 방법이 있다.

구분 설명
내보내기 VirtualBox 파일 메뉴 → 가상 시스템 내보내기 → 포맷 설정에서 모던 네트워크
어댑터 MAC 주소 포함 선택 → 완료
결과 파일 확장자 .ova 인 파일이 생성됨
가져오기 파일 메뉴 → 가상 시스템 가져오기 → 생성된 OVA 파일 선택 → 완료

OVA 파일은 가상 머신을 이미지화하여 저장한 것으로, 다른 장소에서 동일한 환경을 이어서 사용할 때도 활용할 수 있다.

5. IP 주소 설정 — nmtui

5-1. nmtui란

nmtui는 Rocky Linux에서 IP 주소 설정에 사용하는 도구이다. 복제된 VM의 IP가 기존 서 버와 동일한 경우 nmtui로 IP를 변경한다.

nmtui ← IP 주소 설정 도구 실행

5-2. NetworkManager 재시작

nmtui로 IP 주소를 변경한 후, 변경된 IP를 즉시 적용하려면 NetworkManager 서비스를 재시작해야 한다.

systemctl restart NetworkManager ← 변경된 IP 주소 즉시 적용 NetworkManager 재시작 후에도 IP가 변경되지 않으면 물리적으로 리부팅이 필요할 수 있다.

각 시스템의 IP 주소가 다르게 설정되어 있어야 두 머신 간 통신이 정상적으로 이루어진 다. IP 주소 설정 후 두 머신 간 핑(ping) 테스트를 통해 통신이 되는지 확인해야 한다.

053. FTP 기본 구조, 동작 방식, vsftpd 설정 파일 이해

설정 파일 이해

1. HTTPS 접속 확인

1-1. 셀프 인증서 접속 시 동작

공인 기관으로부터 발급받지 않은 셀프 서명 인증서로 HTTPS를 구축한 경우, 웹 브라우저 접속 시 "인증서를 신뢰할 수 없음" 경고 메시지가 표시된다. 이는 서버가 비정상적인 것이 아니라, 브라우저가 해당 인증서를 공인 기관에서 발급된 것으로 인식하지 못하기 때문이다.

경고 메시지를 무시하고 "안전하지 않음으로 이동"을 선택하면 접속 가능하다.

주소 표시줄의 인증서 정보에서 발급된 인증서의 세부 정보(버전, 유효기간, 발급 기관 정보 등)를 확인할 수 있다.

⚠️ 공인 인증서가 없는 사이트 또는 인증서가 올바르지 않은 사이트는 접속하지 않는 것 이 보안상 안전하다. 도용의 위험이 존재하기 때문이다.

2. FTP 개요

2-1. FTP란

FTP(File Transfer Protocol)*는 파일 전송 프로토콜의 약자로, 서버와 클라이언트 사이에서 파일을 업로드하거나 다운로드할 때 사용하는 통신 규약이다.

FTP 서버에 파일(영화, 음악, 문서 등)을 저장해두고, 외부에서 해당 서버에 접속하여 파일 을 다운로드하거나 서버로 업로드하는 방식으로 활용된다.

2-2. FTP의 보안 문제

FTP는 HTTP, Telnet과 마찬가지로 데이터를 평문(암호화 없음)으로 전송한다. 따라 서 데이터 전송 중 도청 위험이 존재한다.

이 문제를 해결하기 위해 보안이 강화된 두 가지 방식이 존재한다.

프로토콜 설명
FTPS FTP에 SSL/TLS 보안을 추가한 방식
SFTP SSH 기반의 파일 전송 프로토콜 (SSH 서버가 있으면 별도 설정 불필요)

현재는 FTP와 Telnet을 사용하지 않는 것을 권장한다. 반드시 FTPS 또는 SFTP를 사용 해야 한다.

3. FTP 포트 및 동작 방식

3-1. FTP 기본 포트

FTP 서비스는 내부적으로 두 개의 포트를 사용한다.

포트 번호 역할
21번 제어 채널 — 전송 중 발생하는 문제를 제어하는 역할
20번 데이터 채널 — 실제 파일 데이터가 전송되는 채널

통상적으로 "FTP의 기본 포트는 21번"이라고 말하며, 내부에서 20번 포트도 함께 동작한 다.

3-2. 액티브 모드와 패시브 모드

FTP는 전송 방식에 따라 액티브(Active) 모드와 패시브(Passive) 모드 두 가지로 구분된 다.

구분 설명
액티브 모드 FTP가 기본적으로 제공하는 포트(20, 21번)를 통해 파일을 주고받는 방식
패시브 모드 클라이언트 네트워크 환경(방화벽, UTM 정책 등)에 의해 기본 포트 접속이 차단
될 경우, 1024번 이상의 포트를 사용하여 서버에 접속할 수 있도록 하는 방식

서버 설정은 정상이지만 특정 클라이언트 네트워크에서만 접속이 안 될 경우, 클라이언트 측의 방화벽 또는 UTM 정책 문제일 가능성이 높다. 이때 패시브 모드로 전환하여 테스트 해볼 수 있다.

FTP 클라이언트 프로그램에서는 액티브/패시브 모드를 선택하는 옵션을 제공하는 경우가 많다.

4. vsftpd 패키지

4-1. vsftpd란

vsftpd(Very Secure FTP Daemon)*는 리눅스에서 많이 사용되는 FTP 서버 소프 트웨어 패키지이다. ProFTPD 등 여러 패키지가 존재하지만, 그 중 vsftpd가 널리 사용 된다.

054. FTPS 구축과 패시브 모드

1. SFTP 개요

1-1. SFTP와 숨김 파일

SFTP(SSH File Transfer Protocol)*는 SSH 프로토콜 기반의 파일 전송 방식이 다. SSH 서버가 이미 운영 중이라면 별도 패키지 설치 없이 SFTP를 사용할 수 있다.

FileZilla에서 SFTP로 접속하면 파일 목록 중 이름 앞에 점( . )이 붙은 항목이 표시될 수 있 다. 리눅스에서 파일명 앞에 점( . )이 붙은 것은 숨김 파일이다. 터미널에서 숨김 파일을 포함 하여 목록을 보려면 ls -a 옵션을 사용한다.

ls -a ← 숨김 파일을 포함한 전체 목록 표시

2. FTPS 개요 및 HTTPS와의 차이점

2-1. FTPS란

055. HTTP와 HTTPS의 차이, 서버 인증서의 개념과 구조

서의 개념과 구조

1. HTTP와 HTTPS 개요

1-1. HTTP란

HTTP는 Hypertext Transfer Protocol의 약자로, 웹 브라우저와 서버 사이에 데이터를 전송할 때 사용하는 통신 규약이다.

HTTP 연결에서는 데이터가 Plain Text(평문) 형식으로 주고받아진다. 평문이란 암호화가 되지 않은 상태로 전송되는 데이터를 의미하며, 제3자가 해당 데이터를 도청하거나 내용을 쉽게 파악할 수 있다는 문제점이 있다.

1-2. HTTPS란

HTTPS는 HTTP에서 보안성을 높인 프로토콜로, HTTP 뒤에 보안성을 높였다는 의미가 붙 은 형태이다.

HTTPS는 TLS(Transport Layer Security) 또는 SSL(Secure Sockets Layer) 프로 토콜을 통해 인증과 암호화 기능을 활성화한다. 서버 인증서를 통해 서버가 공인된 기관으로 부터 인증서를 발급받은 경우에만 데이터 통신이 이루어지도록 하여 보안성을 확보한다.

현재 대부분의 웹사이트는 HTTPS가 구현되어 있으며, HTTP만 지원하거나 인증서에 문제 가 있는 사이트에 접속할 경우 웹 브라우저에서 경고 메시지가 표시된다.

보안성 낮음 (도청 위험) 높음
서버 인증 없음 서버 인증서 필요
웹 브라우저 표시 주의 요함 정상 연결

2. 서버 인증서

2-1. 서버 인증서의 역할

HTTPS를 구현하려면 서버에 서버 인증서를 설치해야 한다. 서버 인증서는 마치 개인이 사 용하는 공동인증서나 금융인증서와 유사한 개념이다.

서버 인증서는 아무 곳에서나 발급받을 수 없으며, 공인된 기관으로부터 발급받아야 한다. 발 급 비용과 유효기간은 규모와 내용에 따라 수십만 원에서 수천만 원까지 다양하다.

서버 인증서 발급 절차는 다음과 같다.

1. 서버 관리자가 인증서 발급 기관에 서버 정보를 포함한 발급 요청을 제출한다.

2. 인증서 발급 기관이 해당 정보를 확인하고 서버 인증서를 발급한다.

3. 서버 관리자가 발급된 인증서를 웹 서버 설정에 등록한다.

4. 이후 HTTPS 프로토콜을 통해 암호화된 데이터 전송이 이루어진다.

2-2. 인증서 유효기간

인증서에는 유효기간이 존재한다. 유효기간은 비용에 따라 1년, 3년 등으로 구분되며, 실제 환경에서는 비용에 따라 서버 인증서의 유효기간이 달라진다.

⚠️ 셀프로 발급한 인증서는 공인된 기관으로부터 발급받은 것이 아니기 때문에, 웹 브라 우저에서 "인증서를 신뢰할 수 없음" 또는 "연결이 안전하지 않음" 경고 메시지가 표시된 다. 내부 테스트 목적으로만 사용 가능하다.

3. OpenSSL을 이용한 셀프 인증서 생성 개념

3-1. OpenSSL이란

OpenSSL은 비용을 들이지 않고 셀프로 테스트용 인증서를 만들 수 있는 도구이다. 공인된 기관에서 발급받은 인증서가 아닌 셀프 방식으로 인증서를 만들기 때문에, 내부 테스트 환경 에서만 유효하다.

3-3. 도메인과 IP 주소의 관계

실제 웹 서비스에서는 도메인 이름(예: www.google.com)으로 접속하지만, 모든 시스템은 IP 주소를 통해 통신한다. 도메인은 사람이 사용하기 편하도록 만들어 놓은 것이며, IP 주소 로 직접 접속하는 것도 가능하다.

하나의 도메인에 여러 IP 주소가 연결될 수 있는데, 이는 대규모 서비스(예: 구글, 네이버)의 경우 단일 서버가 아닌 다수의 웹 서버가 운영되고 있음을 의미한다.

IP 통신에 참여하는 모든 시스템은 IP 주소가 있기 때문에, 도메인이 없더라도 IP 주소를 통해 접속이 가능하다.

5. FTP 클라이언트 프로그램 — 파일질라

5-1. 파일질라 개요

FTP 서버에 접속하여 파일을 업로드·다운로드하기 위해서는 FTP 클라이언트 프로그램을 사용하는 것이 편리하다. 파일질라는 많이 사용되는 FTP 클라이언트 프로그램 중 하나이다.

파일질라는 클라이언트 버전과 서버 버전으로 구분된다.

구분 설명
파일질라 Client FTP 서버에 접속하여 파일을 주고받는 클라이언트 프로그램
파일질라 Server 윈도우 PC를 FTP 서버로 동작하게 하는 서버 프로그램

리눅스 서버가 이미 FTP 서버 역할을 하고 있으므로, 윈도우 호스트 PC에는 클라이언트 버 전을 설치하면 된다.

파일질라는 무료 버전과 유료 버전으로 구분되며, 무료 버전으로도 기본적인 FTP/SFTP/FTPS 접속 테스트가 모두 가능하다.

5-2. FTP 접속 시 주의사항

일반 FTP로 접속하면 파일질라가 다음과 같은 경고 메시지를 표시한다.

"TLS 기반 FTP를 지원하지 않는다. 계속할 경우 비밀번호와 파일이 인터넷을 통해 일 반(평문)으로 전송된다." 이 경고는 현재 연결이 암호화되지 않았음을 의미한다. 따라서 FTP를 반드시 사용해야 하는 환경이라면, 보안을 위해 SFTP 또는 FTPS를 통해 접속해야 한다.

3. TTL (Time To Live) 개념

3-1. TTL이란

TTL(Time To Live)*은 패킷이 네트워크에서 살아있는 시간을 나타내는 값이다. 핑 (ping)을 때렸을 때 응답 메시지 마지막에 TTL 값이 표시된다.

패킷이 라우터(홉)를 하나씩 거칠 때마다 TTL 값이 1씩 감소한다. TTL 값이 0이 되면 패킷 이 드롭(폐기)된다.

3-2. TTL 제한을 두는 이유

TTL 제한이 없으면 경로를 찾지 못한 패킷이 루핑(Looping)을 계속하면서 전체 네트워크 에 부하를 일으킨다. TTL 제한은 이러한 상황을 방지하기 위한 장치이다.

운영체제(리눅스, 윈도우 등)에 따라 기본 TTL 값이 다르다.

7. DNS 서비스 시작 및 방화벽 허용

7-1. 방화벽에서 DNS 허용

DNS 서비스에 외부 클라이언트가 질의할 수 있도록 방화벽에서 허용한다. DNS의 기본 서 비스 포트는 53번이며, 주로 UDP를 통해 동작한다.

firewall-cmd --permanent --add-service=dns ← 방화벽에 DNS 서비스 영구 허용 firewall-cmd --reload ← 방화벽 정책 재적용 firewall-cmd --permanent --list-all ← 허용 목록 확인 (DNS가 포함되어 있어야 함)

포트 번호로 허용할 경우: 53/udp

7-2. DNS 서비스 시작

named는 BIND 서비스의 이름이다.

systemctl start named ← named 서비스 즉시 시작 systemctl enable named ← 재부팅 후에도 named 서비스 자동 시작 등록

명령 역할
systemctl start named 지금 즉시 서비스를 시작
systemctl enable named 서버 재부팅 시 서비스가 자동으로 시작되도록 등록

8. 클라이언트 DNS 설정 변경 (윈도우)

8-1. DNS 서버 주소 변경 방법

클라이언트(윈도우 PC)에서 내가 구축한 네임서버로 도메인 질의를 하려면, 윈도우의 DNS 서버 주소를 구축한 VM의 IP로 변경해야 한다.

설정 경로: 어댑터 옵션 변경 → 해당 네트워크 어댑터 우클릭 → 속성 → IPv4 속성 → 기본 설정 DNS 서버

설정 항목 변경 값
기본 설정 DNS 서버 구축한 DNS 서버(네임서버) VM의 IP 주소
보조 DNS 서버 보조 DNS가 없으면 비워둔다

DNS 서버 주소를 변경하면 www.test.com 입력 시 변경된 네임서버에 질의하고, 해당 네임 서버에 등록된 IP를 응답받아 웹 서버에 접속된다.

테스트 완료 후 원래의 DNS 서버 주소로 되돌려야 인터넷 접속이 정상적으로 동작한다. DNS를 구축한 VM의 IP로 변경된 상태에서는 외부 인터넷 접속에 문제가 발생할 수 있 다.

059. NFS 서버 구축

1. NFS 개요

1-1. NFS란

NFS(Network File System)는 리눅스와 리눅스 간에 특정 디렉토리(자원)를 네트워크를 통해 공유할 수 있도록 해주는 파일 시스템이다.

1-2. NFS 핵심 구성 요소
서비스 역할
nfs-server NFS 파일 공유의 핵심 서비스
nfs-lock 공유 파일에 대한 잠금(Lock) 처리 서비스
rpc-bind 원격(Remote)에서 프로시저 호출(Procedure Call)이 들어왔을 때 NFS에 연결
되는 포트를 결정하는 바인딩/맵핑 서비스

RPC(Remote Procedure Call)는 원격에서 호출이 들어왔을 때 연결되는 포트를 실제 로 결정하는 역할을 한다.

2. 실습 환경 구성

두 대의 시스템을 사용하여 한 대는 서버, 한 대는 클라이언트 역할로 구성한다.

서버 (예: IP 192.168.100.101) ←→ 클라이언트 (예: IP 192.168.100.102)

⚠️ 서버에서 해야 할 작업을 클라이언트에서 수행하거나, 그 반대의 경우가 발생하지 않 도록 작업 중 현재 시스템의 역할을 반드시 확인한다.

3. 호스트네임 설정

3-1. 현재 호스트네임 확인 및 변경

hostnamectl status ← 현재 호스트네임 확인 hostnamectl set-hostname <이름> ← 호스트네임 변경 설정 후 바로 반영되지 않을 경우, 다른 계정으로 전환했다가 다시 root로 돌아오면 변경된 호스트네임이 적용된다.

su <일반계정명> ← 일반 계정으로 전환 su - ← 다시 root로 복귀 호스트네임이 구분되어 있으면 서버/클라이언트 혼동을 방지할 수 있다.

4. NFS 패키지 설치

서버와 클라이언트 모두에 nfs-utils 패키지를 설치한다.

서버 및 클라이언트 공통 dnf install -y nfs-utils ← NFS 유틸리티 패키지 설치

5. 서버 설정

5-1. 서비스 시작

서버에서 실행 systemctl start nfs-server ← NFS 서버 서비스 시작 systemctl start rpc-bind ← RPC 바인드 서비스 시작

5-2. 공유 디렉토리 생성 및 권한 설정

mkdir /nfs-server ← 최상위 디렉토리 아래에 공유용 디 렉토리 생성 chmod 757 /nfs-server ← 권한 설정 (클라이언트에서 접근 가 능하도록)

권한 숫자 의미:

숫자 의미
4 read (읽기)
2 write (쓰기)
1 execute (실행)
7 read + write + execute (모든 권한)
5 read + execute
5-3. /etc/exports 파일 설정

/etc/exports 파일은 NFS 서버에서 어떤 클라이언트가 어떤 디렉토리에 어떤 권한으로 접 근할 수 있는지를 지정하는 설정 파일이다.

vi /etc/exports # /etc/exports 설정 형식 /nfs-server 192.168.100.102(rw,sync,no_root_squash) # ↑ 서버 공유 디렉토리 경로 # ↑ 접근 허용할 클라이언트 IP # ↑ 괄호 안: 접근 권한 옵션 (IP와 붙여서 작성)

5-4. exports 주요 옵션
옵션 설명
rw 읽기/쓰기 허용
ro 읽기 전용
sync 변경 사항을 실시간으로 동기화
async 비동기 방식으로 동기화
no root squash
_ _		 클라이언트의 root 사용자를 서버의 root 사용자로 맵핑
root squash
_		 클라이언트의 root 사용자를 일반 사용자로 맵핑
secure 1024 포트 이하에서만 연결 허용
insecure 1024 포트 이상도 연결 허용
5-5. exports 파일 적용

exportfs -a ← /etc/exports 설정 내용을 적용 exportfs ← 현재 적용된 exports 내용 확인

6. 방화벽 설정

NFS 기본 포트인 2049번(TCP)을 방화벽에서 허용한다.

firewall-cmd --permanent --add-port=2049/tcp ← NFS 포트 영 구 허용 # 또는 서비스명으로 허용 firewall-cmd --permanent --add-service=nfs firewall-cmd --reload ← 설정 적용 firewall-cmd --list-all ← 허용 목록 확인

Samba 서버 구축 준비

1. NFS 클라이언트 설정

1-1. 클라이언트 서비스 시작

클라이언트에서는 nfs-server 서비스는 필요하지 않으며, rpc-bind 서비스만 시작한다.

클라이언트에서 실행 systemctl start rpc-bind ← RPC 바인드 서비스 시작

1-2. 클라이언트 측 공유 디렉토리 생성

서버의 공유 디렉토리와 동기화할 디렉토리를 클라이언트에 생성한다.

mkdir /nfs-client ← 최상위 디렉토리 아래에 동기화용 디렉토리 생성

2. mount 명령어 — NFS 마운트

2-1. mount 개념

mount 명령어는 시스템에 외부 장치(DVD, USB 등)나 네트워크 자원을 연결할 때 사용한 다. 반대로 연결을 해제할 때는 umount 명령어를 사용한다.

2-2. NFS 마운트 명령어

클라이언트에서 실행 mount -t nfs 192.168.100.101:/nfs-server /nfs-client # ↑ 타입: nfs # ↑ 서버 IP ↑ 서버 공유 디렉토리 경로 # ↑ 클라이언 트 마운트 포인트

구성 요소 설명
-t nfs 마운트 타입을 NFS로 지정
서버IP:/서버디렉토리 서버 IP와 공유 디렉토리를 콜론( : )으로 구분하여 지정
/nfs-client 클라이언트에서 연결될 로컬 디렉토리 경로

⚠️ exports 파일에는 서버의 IP가 들어갔고, mount 명령어에는 서버의 IP가 들어간다. 혼동하지 않도록 주의한다.

df ← 디스크 마운트 현황 확인 df -h ← 용량 단위로 가독성 있게 출력 (예: 8G, 2.3G)

df 출력 결과에서 서버IP:/nfs-server 형태로 마운트된 항목이 표시되면 연결이 성공한 것 이다.

점검 항목 확인 내용

NFS는 통상적으로 리눅스와 리눅스 간에 자원을 공유하기 어려운 환경에서, 네트워크 파일 시스템을 통해 특정 디렉토리를 공유하여 실시간 동기화를 가능하게 한다. 업무용 문서나 데 이터를 다른 시스템에 동기화하여 백업 용도로 활용할 수도 있다.

6-1. Samba란

Samba는 리눅스와 윈도우 간에 파일 및 자원을 공유하기 위해 사용하는 서버이다.

6-2. Samba 핵심 프로세스 및 포트
프로세스 사용 포트 역할

7. Samba 패키지 설치

삼바 서버 역할을 할 리눅스 시스템에 다음 세 개의 패키지를 설치한다.

mkdir /samba-test ← 최상위 디렉토리 아래에 공유용 디렉토리 생성 chmod 777 /samba-test ← 윈도우에서 접근 가능하도록 최고 권한 부여

useradd samba-user ← 삼바 접속에 사용할 리눅스 계정 생성

리눅스 시스템 로그인 패스워드와 삼바 서버 접속 패스워드는 별개이다.

passwd samba-user ← 리눅스 시스템 로그인용 패스워드 설정 smbpasswd -a samba-user ← 삼바 서버 접속용 패스워드 설정 (-a: 추가)

동일한 사용자라도 시스템 로그인 패스워드와 삼바 접속 패스워드는 달라도 된다. 윈도우 에서 삼바 서버에 접속할 때는 smbpasswd로 설정한 패스워드를 사용한다.

설치 후 기본으로 공유되는 섹션이 포함되어 있다.

섹션 이름 설명

2. 공유 섹션 추가

2-1. 공유 섹션 설정 항목

smb.conf 파일에 공유 섹션을 추가하는 방법은 다음과 같다.

[samba-share] ← 외부(윈도우)에서 보여지는 공유 이름 comment = 설명문 ← 공유 이름에 대한 설명 (주석) path = /samba-test ← 실제 공유되는 디렉토리 경로 browseable = yes ← 탐색기에서 공유 디렉토리가 보여지도록 설정 writable = yes ← 쓰기(서기) 가능 여부 guest ok = yes ← 일반 사용자(게스트)의 접근 허용 여부 create mask = 0777 ← 윈도우 사용자가 파일 생성 시 적용되는 권한 directory mask = 0777← 윈도우 사용자가 디렉토리 생성 시 적용되는 권한

옵션 설명

5. SELinux 설정

Samba 서버와 윈도우 간 접속이 원활하게 이루어지려면 SELinux를 비활성화(Disabled) 상태로 설정해야 한다.

sestatus ← 현재 SELinux 상태 확인 설정 파일에서 Disabled로 변경한 후 재부팅하면 적용된다.

⚠️ 모든 테스트가 끝나고 시스템 종료 전에 SELinux 설정을 Disabled로 변경하면, 다음 부팅 시 자동으로 적용된다.

6. 방화벽 설정

firewall-cmd --permanent --add-service=samba ← Samba 서 비스 영구 허용 firewall-cmd --reload ← 적용 firewall-cmd --list-all ← 허용 목록 확인 방화벽에서 Permanent 옵션으로 설정된 항목은 재부팅 후에도 자동으로 유지된다.

7. 윈도우에서 Samba 서버 접속

7-1. 접속 방법

윈도우에서 실행창(Win + R)을 열고 다음과 같이 Samba 서버의 IP를 입력한다.

\\192.168.100.101 ← Samba 서버 IP 입력 후 확인 접속 성공 시 smb.conf에서 설정한 공유 이름(예: samba-share )이 탐색기에 표시되며, 더블 클릭하면 공유 디렉토리 내부로 진입한다.

7-2. 양방향 동기화 확인
작업 결과
리눅스에서 파일 내용 수정 윈도우 탐색기에서 수정된 내용 즉시 반영
윈도우에서 파일 내용 수정 리눅스에서 cat 명령어로 확인 시 수정 내용 반영
윈도우에서 폴더/파일 생성 리눅스 공유 디렉토리에서 ls 명령어로 확인 가능

이처럼 윈도우에서 접속하여 파일을 생성, 수정, 삭제하는 모든 작업이 리눅스 삼바 서버 의 공유 디렉토리와 실시간으로 동기화된다.

062. 리눅스 서비스 구축 흐름과 DNS 레코드 체계

드 체계

1. 서비스 구축 전체 흐름

1-1. 다중 서버 구성 개요

NAME 서버, 웹 서버, FTP 서버가 각각 별도의 IP 주소를 가지고 운영된다고 가정할 때, 각 서비스는 공통된 절차를 따라 구축된다.

단계 내용
1단계 관련 패키지 설치
2단계 설정 파일 구성
3단계 서비스 상태 확인
4단계 방화벽에서 해당 포트 또는 서비스 허용 및 적용

2. 서비스 관리 명령어 (systemctl)

2-1. 주요 명령어

systemctl status <서비스명> ← 서비스 상태 확인 systemctl start <서비스명> ← 서비스 시작 systemctl restart <서비스명> ← 서비스 재시작 systemctl enable <서비스명> ← 부팅 시 자동 시작 등록 systemctl disable <서비스명> ← 부팅 시 자동 시작 해제

3. 오류 진단 — journalctl

서비스 시작 또는 재시작 시 오류가 발생할 경우, 다음 명령어로 오류 내용을 확인할 수 있다.

journalctl -xe ← 오류 발생 위치와 원인을 빨간색으로 표시하여 출 력 빨간색으로 표시된 부분을 확인하면 설정 파일의 철자 오류나 누락된 항목 등을 파악할 수 있다.

⚠️ 처음에는 오류 메시지의 내용을 파악하기 어렵지만, 반복적으로 오류를 수정해 나가 다 보면 메시지만 보고도 원인을 빠르게 파악할 수 있게 된다.

4. 방화벽 설정 (firewall-cmd)

4-1. 기본 흐름

서비스가 정상적으로 시작된 이후에는 방화벽에서 해당 포트 또는 서비스가 허용되어 있는 지 확인해야 한다.

firewall-cmd --list-all ← 현재 방화벽 허용 목록 확인 firewall-cmd --permanent --add-port=<포트번호>/tcp ← 포트 영구 허용 firewall-cmd --permanent --add-service=<서비스명> ← 서비스 명으로 영구 허용 firewall-cmd --reload ← 변경 사항 적용 (reloa d 필수)

방화벽에서 허용만 하고 reload를 하지 않으면 적용되지 않는다.

5. IP 주소 기반 서비스 동작 확인

방화벽까지 설정이 완료되면 각 서비스는 IP 주소 기반으로 동작하는 상태가 된다. IP 주소로 동작이 확인되지 않으면 NAME 서버와의 연결 상태를 검증할 수 없다.

6. DNS 레코드 체계

6-1. DNS Zone 파일 구성 요소

존 파일에는 최소한 SOA 레코드와 NS 레코드가 포함되어야 한다.

레코드 종류 역할
SOA (Start of Authority) 해당 존의 권한 정보, 기본 포함 레코드
NS (Name Server) 도메인의 네임서버를 지정
A 도메인명과 IPv4 주소를 맵핑
CNAME (Canonical
Name)		 도메인의 별칭(Alias)을 다른 도메인으로 연결
MX (Mail Exchanger) 메일 서버를 지정
PTR (Pointer) IP 주소를 도메인명으로 맵핑 (역방향 조회, Reverse Zone에서 사
용)
AAAA 도메인명과 IPv6 주소를 맵핑
6-2. A 레코드 설정 예시

정방향 Zone 파일 예시 NS IN A <네임서버 IP> www IN A <웹서버 IP> ftp IN A hong IN A <웹서버 IP> ← CNAME 대신 A 레코드로 별칭 처럼 사용 가능

6-3. 역방향 Zone (PTR 레코드)

역방향 Zone 파일 예시 IN PTR <도메인명>.

PTR 레코드는 역방향 존(Reverse Zone)에서 IP 주소를 기준으로 도메인명을 조회할 때 사용된다.

이 외에도 다양한 레코드 유형이 존재하며, 구축 환경과 목적에 따라 추가적인 레코드를 사용해야 하는 경우가 있다.

7. 패스워드 관리

현재 비밀번호를 알고 있는 상태에서 root 계정 또는 다른 계정의 패스워드를 변경하려면 다 음 명령어를 사용한다.

passwd ← 현재 로그인한 계정의 패스워드 변경 passwd <계정명> ← 특정 계정의 패스워드 변경 (관리자 권한 필요)
